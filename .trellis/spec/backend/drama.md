# 短剧剧本与分镜

## 适用范围

内置插件 `drama` 将作品章节改编为可编辑的剧本、角色造型、场景、道具和分镜。管理员在全站启用插件后，作品内的「改编 → 短剧」入口可用。停用保留业务数据，备份与作品生命周期继续处理这些数据。

## 接口与存储

接口统一位于 `/api/v1/plugins/drama`。作品可以有多部剧，资产属于剧，集通过关联表选用资产。数据库迁移为 `0083`。

| 操作 | 接口或字段 |
| --- | --- |
| 建剧和建集 | `POST /projects/{pid}/series`、`POST /series/{sid}/episodes` |
| 原文快照 | `chapter_ids` 指定同书连续章节，按章节顺序复制正文。手填 `source_text` 可以覆盖初始快照。删除章节将来源 ID 置空，保留原标题和正文 |
| 剧级与集级素材库 | `GET /series/{sid}/assets`、`GET /episodes/{eid}/assets`，响应包含 `characters[].looks`、`scenes`、`props` |
| 整集分镜排序 | `PUT /episodes/{eid}/shots/order`，提交 `{revision, shot_ids}`，包含本集每条分镜且各出现一次 |
| 任务受理 | `POST /episodes/{eid}/tasks`，剧级素材提示词也可用 `POST /series/{sid}/tasks`。使用核心任务详情、流与取消接口 |
| 文档导出 | `GET /episodes/{eid}/export?format=md\|docx&parts=script,shots`，可单选一部分。按当前顺序渲染数据库已保存的内容，沿用作品导出权限 |
| 跨实例备份 | 单书格式 v19 登记 13 张表，导入时重映射章、小说角色、世界观地点、剧集、素材及分镜引用 |

## 行为约定

- 每部作品最多 20 部剧，每部剧最多 200 集。每集最多 20 个连续来源章节、6 万字原文、200 条分镜。镜头时长 2 至 30 秒。
- 小说角色优先按姓名匹配，其次按别名。小说地点只匹配本书地点类型的条目。存在歧义时保留未关联状态。小说设定仅提供初值，后续修改短剧资产独立保存。
- 每个角色至少一套造型，恰好一套默认。分镜可以引用同剧造型、场景、道具。同一剧的多个集可复用资产。
- `drama.rewrite` 返回剧本，实时发布生成文本。`drama.extract` 合并资产，`drama.storyboard` 替换当集分镜，`drama.prompts` 按目标写入图片或视频提示词。结构化输出先解析、校验，并核对模型返回的引用。
- 受理和执行沿用作品授权与模型绑定，任务调用进入用量统计。写入在终态事务内完成。若期间有人修改相关内容，任务返回 `applied: false` 和草稿，界面显示差异风险后允许明确采纳。提交草稿时再次核对修订号和归属。
- 分批任务的断点绑定输入材料，重试沿用原模型和权限。成功重试仅提交一次最终结果。运行中取消后，保留原剧本、素材和分镜。

## 错误与边界

| 条件 | 契约 |
| --- | --- |
| 插件停用 | 框架返回 403 和 `plugin_disabled` |
| 无权访问作品、试图选其他作品的章节 | 隐藏资源，拒绝请求 |
| 保存旧修订、顺序基于旧集版本 | 409，保留本地编辑，重新读取后由用户选择 |
| 章节不连续、排序漏项或重复、分镜引用其他剧的资产 | 拒绝整笔变更 |
| 删除关联的小说设定 | 保留短剧资产并解除关联 |
| 作品回收、恢复、彻底删除 | 回收时停止作品访问，恢复可读，彻底删除时外键级联清除短剧资料 |

## 示例与常见错误

选择第二、三章建集后修改第三章，建集时复制的原文仍然可以复查。两个编辑者同时改同一条镜头，第二次保存须显示冲突。以浏览器显示的集序号代替数据库 ID、直接按传入资产 ID 写入或在流式生成期间逐段覆盖正式剧本，都会破坏以上契约。

## 回归入口

`test_drama_workflow.py` 走正式 HTTP、后台执行和 SSE；`test_drama_task_guards.py` 验证协作授权、取消、并发修改与断点；`test_drama_transfer.py` 验证迁移、备份重映射与级联；`test_drama_episodes.py`、`test_drama_assets.py` 和 `test_drama_prompts.py` 分别覆盖手动编辑、设定关联和模型输出校验。前端插件目录保留路由、章节选择、素材及分镜的回归用例。

## 素材库的角色造型图片

数据库版本 `0084` 为造型保存图片历史。在剧或集的任务入口提交 `{"kind":"drama.image","targets":[{"type":"look","id":7}]}`，一次对应一个造型。受理时核对图片模型、协作授权和预算。同一造型的生成任务互斥。服务端先用已保存的图片提示词；留空时，用可见的角色外貌、造型描述和短剧风格组装输入。非默认造型可复用该角色默认造型的选定图，实际图片字节作为参考图随请求发送。

- 每个造型保留最多 10 条图片历史。成功生成的第一张图自动选定，后续结果可在历史中选用。任务失败或取消时保留可读原因，并释放预留的媒体资源。
- 素材库列表携带默认展示图与历史计数，缩略图通过作品媒体接口读取。打开历史时再调用 `GET /assets/look/{id}/images`。选图使用 `PATCH /asset-images/{id}` 和 `{"is_selected":true}`，删除使用同一路径的 DELETE。删除当前选定图后选用剩余可用版本。
- 图片及缩略图的归属是本作品的 `drama` 插件。查看者可看图，生成、选用和删除仍需相应权限；停用后媒体读取被拒。单书备份仅保留造型资料和提示词。整库恢复图片需要同一时间点的数据库与媒体存储。
- 回归入口为 `test_drama_look_image_workflow.py`、`test_drama_image_task.py`、`test_drama_look_images.py` 和 `test_drama_image_lifecycle.py`。断言包括参考图属于相同角色、历史结果与原图对应、用量入账、预算不足不发送，以及清理原图和缩略图。

## 剧集工作台模型选择

工作台首行显示文本、图片和视频三类选择。数据库迁移 `0085` 按账号和剧集存储偏好。作品协作者各自保存个人配置，单书迁移排除私人偏好。删除配置时对应引用置空。

- `GET /episodes/{eid}/models` 返回本人的 `{text, image, video}`。各值为个人配置 ID 或 `null`。PATCH 可单独更新任一字段；显式 `null` 清除该项，其他项保留。两类请求均支持核对页面账号的身份头。
- 配置属于其他账号或不存在返回 404，错误模型类型返回 400。查看者不能修改。协作者借用作者的默认模型沿用作品授权与任务受理逻辑。
- 改写、提取、拆分镜、生成图片或视频提示词均使用文本选择；实际生成造型图使用图片选择。任务明确携带所选 `ai_config_id`，配置选择仍在加载或保存时应等待确认。视频选择可以提前保存。
