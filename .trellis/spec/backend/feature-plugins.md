# 内置功能插件

## 登记

内置模块随应用版本发布。后端在 `app/plugins/builtins.py` 的 `REGISTERED` 中登记 `PluginManifest`。每份清单提供标识、名称、简介、版本、API 路由和任务处理器。应用启动时构建注册表，并校验以下边界。

| 字段 | 约束 |
| --- | --- |
| 标识 | 匹配 `[a-z][a-z0-9_]{1,31}`，在整个应用中唯一 |
| 路由 | 挂在 `/plugins/{id}` 或其子路径，路径段精确匹配插件标识 |
| 任务类型 | 使用插件标识加点号作为前缀，注册时拒绝与核心或其他处理器重名的类型 |

注册错误必须在应用装配时指出冲突项。测试将示例清单注入应用，生产登记表仅收录随版本发布的插件。空登记表是受支持的安装状态。

## 持久状态与数据范围

`0080` 新增 `feature_plugin_states`，以 `plugin_id` 作主键，记录 `enabled`、正整数 `revision`、`updated_at` 和 `last_operation_id`。没有记录时对外返回停用、修订号 0。管理列表和公开配置都基于应用已登记的标识生成。共享数据库的任一实例提交开关后，其他实例的下一次请求就应读到持久值。

停用保留模块的业务数据。整库快照收录开关，单书备份只处理作品数据。[整库备份](./admin-backups.md)

### 从 0080 降级到 0079

迁移在数据库写锁内检查兼容性。出现下列任一情况时终止降级并保留数据：

- 操作日志中有 `feature_plugin.enable` 或 `feature_plugin.disable`。
- 角色创建、更新或删除的审计摘要中含 `plugins.read` 或 `plugins.update`，包括授权已撤销但历史日志仍引用这些权限的情况。
- 超级管理员角色以外的角色仍持有上述任一权限。
- `feature_plugin_states` 中仍有状态行，即使当前已停用或启停日志已清理，降级也会丢失修订号。
- `tasks.kind` 或 `task.cancel_request` 审计摘要的 `task_kind` 含 0079 无法读取的类型。审计允许旧版已支持的 `unknown`。

这些检查通过后，迁移从超级管理员角色移除两项权限、推进角色修订号与全站授权修订号，并删除插件状态表。降级前应保存整库快照。遇到审计记录阻塞时，保留快照并核对需要回退的版本，避免删除历史来绕过检查。

## 作品备份和外键归属

- 在清单的 `transfer_rules` 按外键依赖顺序登记 `app.services.project_transfer.rules.TableRule`。表名使用插件标识加下划线前缀，与 ORM 模型一致且全局唯一。`not_exported` 为排除的表记录原因。
- `transfer_catalog()` 返回当前应用的规则。离线导入和导出使用安装的内置清单。停用开关只影响创作入口。
- `transfer_validator(tables)` 在导入时核对跨行约束，例如角色默认造型与分镜素材同剧。`transfer_snapshot(db, project_id)` 用于出包前后复核数据；期间发生变化则返回冲突，用户可重试。
- `transfer_notice(db, project_id)` 可在有权导出本书的用户打开备份窗口时，按本书实际数据返回一条排除项说明或 `None`。作品备份对已登记且停用的插件同样展示说明。
- 核心实体被删除时，按已登记的可空外键和作品过滤条件核对归属。删除来源章节时可保留本书剧集，解除小说角色或地点关联时可保留本书素材。发现跨作品引用须拒绝操作。

## 管理接口

| 请求 | 权限 | 成功响应 |
| --- | --- | --- |
| `GET /api/v1/admin/plugins` | `plugins.read` | `{items: [...]}`，按登记顺序返回 |
| `PATCH /api/v1/admin/plugins/{plugin_id}`，提交 `{revision, enabled}` | `plugins.update` | 当前插件的最新状态 |

管理项包括 `id`、`name`、`description`、`version`、`enabled`、`revision`、`updated_at`。管理响应和公开配置采用 `Cache-Control: no-store`。PATCH 严格校验布尔值、修订号与字段集合，权限写屏障内检查修订号。只有状态实际改变才推进修订号并写 `feature_plugin.enable` 或 `feature_plugin.disable` 审计，与状态变更同事务提交。

## 请求和后台任务

- 挂载插件路由时统一核验启用状态。模块自己的作品授权和数据归属检查在其业务入口继续执行。
- 公开 `GET /api/v1/auth/config` 的 `enabled_plugins` 仅返回已登记且已启用的标识。服务端分别在请求、新建任务、重试、继续和领取执行时核对持久开关。
- 停用时在同一事务为该插件排队、运行和暂停任务的当前执行轮次登记取消，复用 `AdminCancellationDrain`。执行者在后续事件或调度扫描时检查取消，沿原路径收尾并释放资源。快速重新启用也不会清除旧轮次的取消意图。插件处理器的 `on_abort` 必须支持对暂停轮次重复调用时安全回退。
- 按注册表的精确类型识别任务归属。标识允许下划线，直接将标识拼入 SQL `LIKE` 会误取消名称相近的插件任务。

### 任务终态与多批订阅

处理器若声明 `atomic_finalization = True`，所有业务写入必须与成功终态共用一个事务。提交前的权限复核失败应回滚该事务，由任务引擎在原执行身份下记失败并释放资源。需要在协作者订阅中推进断点的处理器可实现 `checkpoint_successor(original, later)`。核心核对执行身份、模型、可见性及游标；处理器还须证明输入材料相同并且已完成批次只追加。短剧分镜用两批真实 SSE 订阅覆盖这一契约。

需为任务预留业务记录时，可实现 `bind_queued(db, task)`，在受理事务中将记录绑定到已分配的任务 ID。可选的 `finalize_failure(db, task)` 在赢得失败终态更新后的同一事务清理预留记录及未关联媒体。两个钩子均由引擎提交事务。插件处理器声明 `admission_model_type = "image"` 时，重试必须核对原受理图片配置与授权；未声明时沿用文本模型。造型图的失败、取消与重试回归见 `test_drama_image_task.py`。

## 错误与回归断言

| 场景 | 预期 |
| --- | --- |
| 新登记的插件尚未启用 | 访问插件接口或新建该插件任务得到 403，原因码为 `plugin_disabled` |
| 只读管理员尝试修改开关 | 403，状态和修订号保持原值 |
| 修改未登记插件或提交格式错误 | 分别返回 404、422 |
| 两位管理员基于同一修订号提交不同变更 | 首次成功更新之后，旧修订号得到 409 `stale_revision` |
| 一个任务运行，另一个排队，此时停用 | 两者均取消，既有业务数据在重新启用后仍可读取 |
| A、B 两个应用共用数据库 | 在 A 启用或停用后，B 紧接着的访问按新状态处理 |
| 无登记项 | 列表和公开标识为空，核心任务、MCP 和作者常用入口照常工作 |
