# 跨进程任务订阅

## 适用入口

公开入口 `GET /api/v1/tasks/{task_id}/stream?task_key=…` 使用请求所在实例完成身份和权限校验。数据库中的 `Task.worker_key` 标识当前持有人。C3 的请求 worker 可以接管取消收尾，只有仍持原执行现场的调度 worker 能发布运行中的事件。部署条件见[部署与迁移](./deployment-migrations.md)。

## 接口与身份

- `task_workers.peer_url` 是发现地址。每个应用监听一次，HTTP 请求租约和调度租约分别登记同一地址。换代会生成新的 worker key。
- `peer.subscribe(target, payload)` 通过已认证的连接接收有序帧。内部会话绑定双方代次、握手挑战、请求摘要及随机订阅号。每条消息校验方向和序号；公开 API 只输出原有 SSE 数据。
- `TaskEngine.live_output_hub(...)` 按任务键、入队轮次、执行键、存活的调度 worker 及本地执行体核对活动值。其他实例的详情、列表、输出及管理监控从持久行投影。配额沿用数据库执行名额。

## 配置与数据契约

`TASK_PEER_ENABLED` 控制监听。默认本机 UDS 位于私有短路径目录，可用 `TASK_PEER_SOCKET_DIR` 指定。同机运行多个进程时目录须共享。私网 TCP 的监听、通告、端口及允许网段分别由 `TASK_PEER_BIND_HOST`、`TASK_PEER_ADVERTISE_HOST`、`TASK_PEER_PORT`、`TASK_PEER_NETWORKS` 提供。实际端口绑定后才进入登记；TCP 传输依靠部署提供机密性。API 根路径、OpenAPI、单书传输和数据库版本不因内部协议变化而升级。

每个进程最多接受 64 条内部连接，也最多向其他进程建立 64 条连接。握手期限为 2 秒，每条订阅最多有一个未确认的逻辑帧。从首次发送起，确认和同帧重核共用 10 秒预算。等待下一帧的空闲期限为 22 秒，以容纳原有 15 秒心跳。

内部协议控制记录上限为 64 KiB，序列化后的单帧上限为 8 MiB。发送按 64 KiB 分块，每块等待底层缓冲可写。收到第一字节后须在 5 秒内读完整条记录。超过传输限额或截止时间会关闭该订阅，公开连接按任务与原读者的状态决定能否继续回放。

领取交接最多保留 32 个轮次，每轮自领取起至多 15 秒、512 个事件和 2 MiB 缓存预算。到期或超限时释放该轮原帧。作者可从原轮次的数据库快照衔接，协作者须有当下可验证的帧来源或可回放的持久状态。

## 授权及状态

| 情形 | 对客户端的结果 |
| --- | --- |
| 同一执行者、同一原读者、通道健康 | 由执行端生成快照、增量、结构事件与终态。一个订阅最多有一个待确认的逻辑帧。 |
| 协作者帧已在途，原令牌、邀请、模型或内容可见性发生变化 | 接入端在真实 ASGI 写出事务里重新核对原绑定、认证帧来源以及仍可变的读条件；核对失败只返回固定错误。 |
| 合法后继需要重核 | 释放本端数据库锁，向同一连接请求重核同序号、同载荷的原帧。最终公开写入前再次校验。 |
| 运行中断开内部连接 | 作者用按原绑定重新投影的持久快照覆盖当前展示。协作者运行中正文缺少活动来源时收到受控拒绝。 |
| 已暂停或有确定终态 | 使用原持久投影与原任务轮次，发快照并以一个 `paused`、`done` 或 `error` 收尾。结果仍不确定的任务保留原语义。 |

## 正常、边界与故障样例

排队中的订阅跨进程遇到批量领取时，从原执行的有界缓存接上首个章节事件。已经终结的同一轮可以按持久状态回放。旧 hub 即使具有相同整数任务 ID，也不能覆盖新轮次的数据。内部通道断开只使订阅降级，进程失联和任务的业务终态仍分别按租约与收据判断。

## 测试判据

以两个独立实例和真实客户端验证直连与经对端的非心跳帧。把权限提交固定在执行端签发与接入端写入之间，观察最终 SSE 字节；再阻塞已持锁的公开写入，验证权限写事务的提交时序。覆盖默认 SQLite、SQLite WAL 和专用 PostgreSQL。最后一个增量后让模型保持静默，直接比较两端公开 `/output` 返回时间。对端断线、超时或溢出还应观察连接、待确认帧和原订阅的释放。

## 锁顺序示例

如果执行端拿着 SQLite WAL 的写屏障等待浏览器确认，接入端可能正在等待同一个屏障。正确顺序是执行端限时写出完整内部帧并释放事务，接入端取得自己的发送租约、完成公开写入并释放事务，随后在锁外确认。接入端已经尝试写出字节时发生的错误直接中止该连接。
