# 连载与存稿工作台

## 1. 适用范围

变更作品内的章节定稿、按章排期、存稿天数、渠道登记、已发布稿导出或备份格式时，须一并核对读者正文、当前草稿及项目授权。生成状态由章节生成流程独立维护。

## 2. 接口和存储

路由前缀为 `/api/v1/projects/{project_id}/serialization`。列表使用 `offset`、`limit` 和稳定排序，详情才包含正文。

| 接口 | 关键输入和输出 |
| --- | --- |
| GET /overview、GET /days/{day} | 概览按 `month=YYYY-MM` 返回目标、存稿、天数、余章及月内每天的计划／首发章数。日期详情返回两份分页清单。 |
| PUT /goal | `daily_goal` 为正整数或 null，`expected_revision` 对照作品目标版本。 |
| GET /chapters、GET /chapters/{id} | 可按状态、日期或库存筛选。详情返回 `scene_id`、条目版本、已保存草稿及可选定稿。传 `edition_id` 可查看指定稿次。 |
| PATCH /chapters/{id} | 必须携带 `expected_scene_id` 和 `expected_revision`。未传的状态或日期保持原值，`planned_date=null` 清除排期。 |
| POST /chapters/{id}/editions | 额外传 `expected_content_revision` 与 `expected_fingerprint`，冻结确认时读者可见的章号、标题、正文和排版。 |
| POST /chapters/{id}/publications | 传 `expected_revision`、`edition_id`、渠道、实际时间及请求 UUID，返回发布记录 ID。 |
| GET /chapters/{id}/editions/{edition_id}/export | 按作品、章节及所选有效稿次读取原稿，首发登记前即可下载 UTF-8 TXT。 |
| GET /publications、GET /publications/{id}、GET /publications/{id}/export | 支持按渠道和现存章节筛选。详情可对比草稿，下载格式为 txt、md、docx。 |

迁移 0064 建立 `serialization_goals`、`serialization_entries`、`serialization_editions` 和 `serialization_publications`。冻结章号使用物理列 `chapter_no_at_confirmation`，避免被章节重排规则改写。

## 3. 跨层契约

- 有效定稿允许继续修改草稿。重新定稿使新版本成为默认待发稿，普通章节版本清理不影响定稿。可见内容指纹只覆盖章号、标题、原文及排版。作者备注、标记与场景规划都不属于发布正文。
- 章节数字 ID 在 SQLite 上可能被复用。用预览中的真实场景身份在章锁内核验章节归属，包括该场景已经退场的情况。日期或编辑状态变化使用条目修订号。草稿正生成时允许安排日期和登记已有定稿。
- 存稿等于有有效定稿且没有任何发布记录的现存章节数。按章取最早的实际发布时间，再按北京时间归日。补录较早发布会移动首发所属日。改期、补发和同章重定稿都不额外扣库存。
- 登记绑定指定定稿。重复提交同一操作者、作品、请求 UUID 和内容可取既有收据。相同 UUID 配上其他内容时产生冲突。不同平台可以同时登记同一章。回退编辑状态会撤下当前待发稿，曾发布过的旧稿仍可用于补录。
- 工作台读、写、下载分别使用 `content.read`、`content.edit` 和 `export`。下载冻结正文后释放读事务，文件渲染结束再次核对原授权。前端复核账号和页面请求代次后才启动下载。
- 删掉源章后保留发布记录及其引用的原稿，隐藏草稿比较。历史按条目 ID 区分原章与重建章。单书备份 v15 将连载数据作为核心组恢复，移除原实例的请求重试身份。
- Agent 调整细纲或撤销新建空章前检查将被删除的章节。若带人工排期、已编辑的状态或定稿，其既有撤销快照无法重建这些资料，操作返回冲突。只有默认值的空条目随章清理。

## 4. 校验与错误

| 情况 | 处理 |
| --- | --- |
| 非法目标、未知写入字段、日期格式错误或缺少必需基线 | 422。 |
| 空白正文定稿、未来时间登记发布 | 拒绝写入，并提示使用有效正文或计划日期。 |
| 章身份、条目修订号或草稿预览过期 | 409，重新读取后再确认。 |
| 目标稿次跨章、跨作品或不可见 | 拒绝读取或登记，不交付其他作品的正文。 |
| 只有历史发布、源章已删 | 显示原章名和平台，可下载已发版本。 |

## 5. 基准与边界样例

日更 2 章，10 章定稿未发，显示 5 天。将第一章的定稿 A 发布到一个平台，再用新定稿 B 登记另一平台，库存为 9 章，可支撑 4 天余 1 章。选择第一条记录导出必须得到 A。两个平台的实际更新时间跨月时，只有最早的一天计入首发数。

## 6. 验证入口

后端 `tests/test_serialization_*.py` 覆盖迁移、删章、定稿指纹、并发重放、权限、备份、日期边界与三种真实附件。并发及备份用例在 SQLite 和显式配置的独立 PostgreSQL 测试 schema 中执行。前端 `src/api/serialization.test.ts`、`src/components/serialization/` 和 `src/pages/project/serializationWorkbench.test.ts` 核对请求与状态。浏览器从作品导航进入，检查日期、定稿、两平台登记、历史下载以及窄屏操作。

## 7. 常见错误与正确读取方式

将发布记录数从定稿章数直接减去，会让同章第二个平台再扣一次。统计时从现存章节出发，检查有无有效定稿及任一发布记录。导出历史时若再次按源章读取当前正文，修订 B 会覆盖读者看到的 A。应按发布记录绑定的冻结定稿构建导出文件。

## 发布前词表检查

| 操作 | 输入与结果 |
| --- | --- |
| GET / PUT `/api/v1/publication-terms` 和 `/api/v1/admin/publication-terms` | GET 返回 `{terms, revision}`；PUT 提交 `{terms, expected_revision}`，返回保存后的内容与版本。同表重复、空白或超长词条返回 422，旧版本返回 409。每表最多 1000 个词，每词最多 128 个码点。 |
| 既有定稿、发布登记 POST | 首次命中返回 409 和 `serialization_preflight_required`；`preflight` 包含 `hits`、总数、分页及 `confirmation_token`。保留原请求体，带上该凭据确认。旧凭据可产生 `stale_serialization_preflight`，现有身份或稿件冲突仍沿用原错误。 |
| POST 加 `?preflight_offset=N` | 仅读取第 N 个命中起的一页，最多 50 条。重新取页后若凭据已变，界面须显示新一轮核对。 |
| GET `.../chapters/{chapter_id}/editions/{edition_id}/export` | 首发前可获取有效定稿，已发布过的旧稿也可补录；附件渲染后再次复核导出授权。 |

- 个人词表与账号绑定，全站词表由具备对应动作权限的管理员维护。整库备份保留两级词表和修订号。单书导入后使用目标作者的词表。
- 定稿检查已保存草稿的章名与可见正文，登记检查所选不可变稿次。两份词表中相同的字面词去重，不同词重叠和同词多次出现均保留；每个位置以 Unicode 码点的左闭右开区间表示。例如“😀甲甲”中第二个“甲”的区间是 [2, 3)。
- 有命中时，写接口返回 409，由操作者核对后带确认凭据重试。确认绑定操作者、动作、作品、章节、稿件与两份有效词表的版本，发布还绑定提交目标。稿件或词表版本变化后重验；已成功登记的相同请求仍返回原收据。
- 词表从作品作者取用。协作者只拿到实际稿件中的命中及位置。以操作人的个人词表代替作者词表会让同一本书得到不同结果。
- 通用 TXT 供作者手动投稿。下载、进入平台审核队列均不写发布记录。作者确认远端已发布后沿用原登记和首发统计。
