# 个人写作统计与码字目标

## 适用范围

新增正文写入入口、调整作品权限、修改连载工作台时，需要核对操作者、已保存读者正文和保存事务三个边界。手写和站内 AI 分别按人、作品、北京时间自然日累计。

## 数据表与接口

- `writing_daily_stats` 以账号、作品、日期为键。场景正文和字数增量在同一事务提交。一次整章写入先按场景算差异，再汇总。
- `writing_goals` 按账号和作品保存目标与修订号。关闭目标保留修订号。`writing_stats_tracking` 保存实例启用时刻。本地创建的作品取启用和建书两者较晚的时间。单书导入时保留原建书时间，同时在本实例写入 `projects.writing_stats_started_at`。导入作品以本次导入时刻和实例启用时刻中较晚者为起点；再次单书导出时排除这一列。
- 路由前缀为 `/api/v1/projects/{project_id}/writing-stats`。`GET /overview` 需要 `content.read`；`PUT /goal` 需要 `content.edit`。两者都从当前认证身份取账号。

## 跨层契约

概览中的 `days` 返回指定闭区间内每天的手写和 AI 字数。启用前两栏均为 null，启用后无产出填 0，部分覆盖日有单独标记。`today_manual_words`、`today_ai_words`、`period_manual_words`、`streak_days` 始终基于服务端今天。周一开始新的一周，今天尚无手写时，连续天数从昨天往前计算。

设置目标提交 `period`、`target_words` 和 `expected_revision`。周期取 `day` 或 `week`，首次修订号为 0。关闭时周期与字数同时传 null。返回的目标含新修订号。个人码字目标以字计，作品的连载日更目标以章计。作品备份导入时从零统计；整库备份保留个人记录。

## 校验与错误

| 条件 | 结果 |
| --- | --- |
| 日期倒置、结束日在未来、区间超过 366 天 | 422 |
| 目标周期与字数不配对或目标非正整数 | 422 |
| 使用过期目标修订号，包括关闭之前的版本 | 409，重新读取后再修改 |
| 只读协作者设置目标、撤权后读取 | 按作品访问规则拒绝 |

## 计量样例

把“春风吹过山岗”改为“暖风吹过山坡”，手写增加 2。删除原文、仅改空白、还原历史和移动已有场景增加 0。当天手写 2,000 字、AI 落稿 5,000 字、日目标 3,000 字，目标还差 1,000 字。删除源章保留已记写作量。

规范化空白后，纯插入或纯删除按子序列比较。剔除两侧独有字符、保留相同首尾后，较短一侧不超过 8,192 字且两侧长度乘积不超过 6,400 万时，用全局最长公共子序列精确计数。超出预算的大段按相同文本锚点分块，较短一侧在 2,048 字以内的块按最长公共子序列计数。两侧均超过阈值且找不到锚点时按相对位置切块；跨块的大幅挪写可能与全局最短编辑距离不同。这样可以限制长段整篇改写在保存事务内的运算量。

## 验证入口

后端 `tests/test_writing_stats_*.py` 核对差异计算、正文入口、身份隔离、并发累加、版本冲突、迁移和接口。前端 `WritingStatsPanel*.test.ts` 核对目标、趋势、冲突与作品切换。浏览器从「连载与存稿」同时核对个人字数和存稿天数。

## 接入正文写入时

生成日志有 5,000 字、读者正文只采纳 2,000 个新字时，AI 增加 2,000。用生成日志总量累加会把放弃的候选也统计进去。应取通过权限、版本及任务校验后实际写入的场景正文，与写入前的读者正文比较。整理入口复用保存函数时须显式排除，避免恢复、转换或重放增加统计。
