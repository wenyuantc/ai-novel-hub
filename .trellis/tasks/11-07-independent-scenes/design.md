# 独立场景、场景 POV 与标签：技术设计

状态：in_progress。用户已在最终规划摘要之后明确回复“开始”，批准当前设计；执行中若需实质改变产品行为，应返回规划重新审阅。

## 1. 目标、边界与主要选择

目标是让场景成为章内实际写作单元，同时维持章节级阅读、导出、任务、分析及旧资料兼容。保持 FastAPI／SQLAlchemy 模块化单体和现有 React／Ant Design 工作台，不引入分布式服务、新状态管理框架或富文本编辑器。

完整用户合同见 prd.md；源码依据见 research/current-boundaries.md 及 integration-contracts.md。几个不可替代的技术选择：

1. 场景为正文权威，章正文为受控投影，不提供两份独立可写事实。
2. 一章一个内容／结构 revision，规划仍使用项目 planning_revision；所有交叉写入同事务核验。
3. PlanningUnit 扩展 scene 来源与逐项继承语义，复用现有标签目录和类型化关联。
4. 场景身份不可复用；正文历史增加结构快照，旧版本不伪造结构。
5. 整章 AI 逐场景生成提案，当前章整体提交；批量断点仍以章为边界。

### 不扩大的领域

场景必须属于已有章节，空正文草稿章也可提前规划。未建章细纲保留现有章级规划，不再创建第二套“未来场景”身份。场景写作仍继承原章节／项目写作风格；POV 不自行决定第一／第三人称。

章级自动分析和记忆仍是章级，结果按章末写回；不新增 AI 自动拆场景、自动场景分析或字符级时间锚点。跨章移动、富文本和完整自动保存不在本期。

## 2. 数据所有权和持久模型

### 2.1 新迁移与主要数据

以当前唯一 head 0038 为父新增 0039；实施前重新检查 head，如被其他工作占用须更新编号并重新核对全部格式声明。

| 数据 | 所有权与约束 |
|---|---|
| scenes | 稳定 id，所属 chapter，标题（与章节标题相同的 200 字限制）、正文、作者摘要、顺序、非正文分隔信息、active／退场状态及时间戳。Scene ID 在 SQLite 使用 AUTOINCREMENT，PG 使用正常序列；普通结构操作不物理回收身份。 |
| chapters.content_revision | 非负、单调递增；正文、摘要、场景结构和本地覆盖变化都推进。状态抢占／释放不冒充作者内容版本。 |
| chapters.content / word_count | scene_service 唯一维护的聚合投影；字数仍由 count_words 按非空白字符计算。 |
| planning_units.scene_id | 唯一可空 FK；与本单元 chapter_id／plan_id 互斥，章＋细纲的既有双向绑定不变；退休检查覆盖新来源。 |
| planning_units.source_level | 保留 chapter 或 scene 的来源层级，旧行默认 chapter；来源退场后仍能识别，不能把场景继承规则套到旧章孤立规划或跨层重挂。 |
| 场景规划覆盖模式 | PlanningUnit 对 POV、标签、角色／world／organization／career／relationship 分别记录 inherit 或 override。override 的空值／空集合表示明确清空；省略表示不改。只用于 scene 单元，旧章／细纲单元保持原语义。 |
| planning_unit_characters | 新的本地场景角色关联，复用 Character 真 FK；章级角色权威仍为 ChapterCharacter，不能相互反写。其余类型复用现有关联表。 |
| chapter_versions.scene_snapshot | 可空、带独立 schema_version 的结构 JSON；null 表示真实旧纯文本历史。包含场景身份、顺序、分隔、正文／摘要及本地规划模式／值，不保存独立时间线事实作为可回滚正文数据。 |
| setting_progressions.scene_id | 新 scene 锚点；与 chapter／planned 锚点严格互斥，场景所属章与主体必须同作品。保留 start／end、sort_order 与保护状态。 |

Scene 归属通过所属 Chapter 校验，不允许用户 PATCH chapter_id。新表按既有注册表通过章归属取项目范围，不引入可由前端任填且与 Chapter 不一致的第二个 project_id 事实。

活动场景的同章顺序唯一，非负，使用当前实际列表顺序，不把顺序号作身份。重排先在事务内释放排序冲突到安全临时区间，再落最终顺序；检查整数范围，不能靠延迟 flush 碰运气。所有只读入口保持 no_autoflush。

### 2.2 初始场景与升级

- 所有旧章（含空章、回收站作品中的章）原文逐字符进入一个初始场景；章身份、关联、状态、旧历史和时间戳不因回填被改写。不推断摘要／POV／边界。
- 新章默认一个初始场景；带正文建章用原文，空章用空文本。公共写原语覆盖普通、大纲／细纲建章、拆书、旧备份、向导和 Agent 的实际建章路径。
- 旧规划保持章默认，初始场景使用继承状态。旧章级事件仍在章边界，不改挂为场景事件。
- 不用“首次 GET 时补场景”代替迁移。迁移完成后的缺场景状态是应定位的写入口／导入错误，不允许无提示的读时修复。
- SQLite 优先原位加列／新增表，不能直接重建 chapters 或 planning_units 父表触发子记录级联。确需 batch 重建约束时，复用已验证的 0036 外键保护／校验模式，扩展到实际重建表的序列与全部子行，前后核对身份、时间戳、foreign_key_check 和高水位；PG 另验真实约束。不能把关闭外键留给运行期。

## 3. 正文原语与事务边界

建议新增 models/scenes.py、schemas/scene.py、services/scene_service.py，必要时将纯投影／位置计算拆成小模块；不把业务写入塞进路由或 ORM 隐式事件。

核心责任：

~~~text
用户／任务／旧接口
  → 校验 actor、作品、章、目标 Scene 与预期 revision
  → scene_service 的初始化／正文／结构写入原语
  → 统一重建章正文与字数、推进 revision
  → 结构版本、规划／时间线钩子、审计
  → 原有 service 提交
~~~

下层原语只 flush；最外层 service 拥有 commit／rollback。锁序沿用授权 gate／User → 作品生命周期／可见性既有锁序 → 章 → 子记录，不反向取系列锁。任何目标、引用、版本或时间线校验失败整体回滚。

### 无损拼接

用单一服务端函数生成正文和码点区间表，区分真实正文字符与结构分隔。初始单场景正文精确等于旧章正文；指定光标拆分用原始文本切片，新右片不增加字符；新增独立场景默认空行分隔，合并带回原分隔。首场景变化时分隔不得变成被丢掉的作者正文。

前端不另造 join 规则，不以 trim 或相同字数替代逐字符一致性断言。快照记录足够信息，可恢复零字、纯空白与无正文变化的结构操作。

### 旧正文入口

- 旧 PATCH content：单场景时委托同一正文原语；多场景整段覆盖返回 409 scene_target_required，不自动分摊、合并或写兼容投影。非正文属性的旧 PATCH 保持可用。
- 旧局部改写／Agent 替换：可证明范围完全属于一个活动场景时转换为该场景内偏移；跨场景、落在结构分隔或边界歧义时，预览前／采纳前明确拒绝并要求选择场景。
- 新编辑器和新任务均发送 revision。旧单场景客户端未提供时保持旧入口的锁／版本冲突保护，不宣称它获得完整多端自动合并能力。
- 所有写入均重算投影与字数，更新章最近编辑信息；阅读进度仍不因读取变化。

## 4. HTTP 与 schema 合同

新 API 均位于 /api/v1/projects/{pid}/chapters/{cid} 下，通过现有 CurrentUser 和 service 鉴权；人工读写使用 get_manageable_project，AI 配置／任务使用严格 owner 边界。

固定后缀（如 resolve-position）在动态 /{sid} 路由之前注册，避免被当作 Scene ID 拒绝。

| 方法／后缀 | 合同 |
|---|---|
| GET /scenes | 分页活动 SceneBrief，带 content_revision、planning_revision、total；列表不携全场景正文。只读不写库。 |
| GET /scenes/{sid} | SceneOut：正文／摘要、身份、原始覆盖及有效规划来源、两类 revision。须同时验证 pid／cid／sid。 |
| POST /scenes | expected_content_revision、可选插入位置／标题／正文；默认继承章规划。返回新 Scene 及新 revision。 |
| PATCH /scenes/{sid} | expected_content_revision，title/content/summary 的严格部分更新；不接收客户端字数或 chapter_id。 |
| POST /scenes/reorder | expected_content_revision＋完整同章活动 ID 顺序；重复／缺漏／跨章 ID 整批拒绝。 |
| POST /scenes/{sid}/split | revision、码点 offset；校验原始正文和引用。精确边界不拆成无意空片；返回更新后的两个稳定场景。 |
| POST /scenes/merge-preview；POST /scenes/merge | 同章相邻 ID、revision；预检返回冲突／阻塞项和签名；提交携预期规划版本及明确元数据选择，重新预检。无跨章 move。 |
| DELETE /scenes/{sid} | revision；版本化退场而非身份复用；有未处理保留锚点／独立规划时拒绝并列出阻塞项。最后一个场景不删成无来源正文，提示清空正文或保留空场景。 |
| GET /scenes/resolve-position | 根据章正文指纹与码点位置解析 Scene；过期或跨边界明确返回失效／整章预览，不猜测归属。 |
| GET /scenes/{sid}/setting-context | 同一解析器的人工有效设定预览，返回真实 scene 位置和旧资料校准警告。 |
| POST /scenes/{sid}/generate、/polish、/revise | 返回 202 Task；复用原请求的模型／风格／Skill／建议参数，目标由路径固定，不接受矛盾目标。 |
| POST /scenes/{sid}/rewrite；/rewrite/apply | 同步 SSE 预览＋明确采纳；偏移限当前 Scene，绑定 revision、原文、before、日志和实际目标。 |

项目级场景网格使用分页 SceneBrief 目录，不为展示批量读取所有章节正文。所有列表保留真实排序、总数和当前版本；跨页读到版本变动时显示重载提示，不拼成伪一致列表。

新增 schema 采用严格正整数／有界字符串／extra forbid，集合不接受重复 ID。成功写响应返回新版本；新增 DELETE 不丢弃需要消费的版本响应。错误使用现有 AppError 层级，不回显原稿／密钥。

新场景 AI／局部操作的写请求同样携带预期内容版本，规划写入／结构预检涉及规划时另带预期规划版本。目标由路径和严格内部 target 解码确定，不能被宽松模型忽略后悄悄变成整章。

页大小不是场景总数上限。排序提交完整同章 ID 时，客户端收集同一版本的本章轻量身份列表，不只提交当前显示页；版本变化须重新核对。项目级网格目录明确为 GET /projects/{pid}/scenes，返回分页轻量场景资料而非整书正文。

### 统一错误码

| 条件 | 响应 |
|---|---|
| 不可见作品／不存在或不属于该章的场景 | 404 |
| 已可见但不可编辑／不可用本人 AI | 沿用 403／owner 隔离 |
| 重复 ID、非法覆盖模式、偏移／集合形状错误 | 422 |
| 旧内容／结构 revision | 409 stale_scene_revision，返回 current_revision，不返回他人正文 |
| 旧规划 revision／预检过期 | 409 stale_planning_revision 或 scene_preview_changed |
| 跨场景旧正文操作 | 409 scene_target_required |
| 运行任务／批量范围锁冲突 | 409，复用既有生成／范围锁错误 |
| 拆并／删除／恢复存在保留引用 | 409 scene_reference_conflict，列出可见阻塞项 |
| 元数据需作者明确解决 | 409 scene_merge_conflict |
| AI 上下文快照变动 | 409 scene_context_changed，保留原正文，允许重新发起 |

## 5. 规划、继承与矩阵

扩展 SourceKind＝chapter|plan|scene|detached，真实来源 ID 不混用；章级行和场景行不当成重复的同一规划单元。

统一 resolve_scene_planning 先在一致版本内加载父章默认和场景原始覆盖，逐项选出最终值，再供卡片、矩阵、预览和 AI 共用。仅标签变化不新增 AI 剧情指令；清空手动关联不等于禁止自动检测或绕过 always／never。

- 场景未持有规划记录时可返回虚拟继承值，GET 不物化单元。
- 场景角色覆盖只替代本场景的手动候选，不反写章选角；上下文内部再次读取章 cast 的入口必须显式接收最终集合，避免反向注入已被覆盖的值。
- POV 加入正确的场景参考，不同时注入相互冲突的章 POV。关系仍使用稳定时间线 ID；系列条目仍需本书采用。
- 矩阵增加场景粒度与章分组，继续支持全部现有设定类型、批量操作和冲突核对；展示有效值及继承／覆盖标记，明确作用范围。
- 正文追踪在场景行统计该场景正文；章行仍是整章统计，不把继承的手动关联当确定正文出场。
- 场景来源接入现有支线节点／交汇和只读预览；交织提供独立 scene 轴，不与章节或未建章细纲轴混算距离。章级规划作为共同背景，不要求每个场景重复完成整章节点。
- 章／细纲建章、删除来源、重展开、大纲快照的既有稳定绑定继续工作；大纲快照不回滚场景正文。场景来源退场保留身份和规划资料，不用同名新场景认领。
- 场景退场时保留 Scene 及其来源层级，规划可按不可用来源／待关联展示并从实际 AI 排除。显式重连只允许同章、同层且通过版本／占用检查的目标；父章真删除后没有可证明归属时不提供跨章自动认领。原章级待关联流程不受场景规则误伤。
- 场景自定义、章默认变化及相关来源变更都推进相应 revision；跨入口修改不绕过同一校验器。

## 6. 场景位置与设定演变

扩展 StoryPosition 和 Progression anchor 判别联合。scene 输入只接收 Scene ID／start|end；服务端解析章和顺序；保留 chapter／planned 的旧合同。

比较序列为：章号 → 旧章 start → 同号实际章／场景 start/end → 旧章 end。同号实际章按既有显示次序排场景，旧章级事件相互顺序完全不变；protection、sort_order、event ID 在同一精确位置内继续稳定排序。

场景写作／改写采用 scene start；显式 end 变化只在该场景之后使用。章级旧预览仍表示章窗口边界，不偷偷变成第一个／最后一个场景的预览。

排序、结构恢复、插章／改号／删章以及场景退场都调用统一故事位置重验。完整历史出现非法成员／关系／职业阶段等状态时整体回滚；当前投影、字段值和提示一致。孤儿仍保留可见、可显式重绑，不按序号／章号自动复活。

所有承载位置的 schema、字段有效值／分类查询、卡片／系列投影、分析写回、备份与 effects 检查新联合类型；不能只改请求模型和纯 resolver。

## 7. 结构操作与历史

### 7.1 拆分、合并、退场

- 普通手动拆分保留原左场景身份，新建右场景；右片沿用原本地覆盖意图，摘要不由 AI 推断，右摘要初始为空，原摘要留左并提示作者校对。
- 存在无法证明归属的场景演变、支线节点或交汇时先要求处理，不静默分给左片／右片。首版接受严格拒绝，不用隐式迁移代替作者决定。
- 合并仅限相邻活动场景。不同 POV／摘要／本地覆盖必须明确选择；存在中间时间锚点，或未处理独立节点／交汇时拒绝，作者先在原界面重绑／移动后再操作。
- 正文与元数据版本先完整保存；被合并／移除场景退场，稳定身份仍在。纯文本提及是派生定位，改稿／排序后按指纹失效规则重算。

### 7.2 新旧版本

旧纯文本行不改格式。当前单场景恢复旧正文时只改该场景正文；当前多场景只允许查看／对比，或明确选择一个场景提取整份旧稿，展示差异并确认，其他场景不变。

新版结构快照保存原始本地值和继承状态，不把有效继承结果固化为独立覆盖。恢复显示结构／正文变化和引用影响，要求当前 revision；不回退章默认、独立节点／交汇或时间线事件。如恢复会使独立资料失联，拒绝并提示处理。

恢复前保存结构基线，恢复自身生成新版本，revision／绑定代次不倒退。历史中的 Scene 和规划绑定必须属于同章、身份可证明且未被另行改挂；不能只凭 ID 自动复活。

手动版本合并窗口仍为 10 分钟，但只对相同结构的普通正文手写合并。结构操作、覆盖模式变化、清空和恢复强制保留可撤销边界；空正文不再成为跳过结构历史的理由。

## 8. AI 作业、局部改写与自动分析

### 8.1 目标与任务

沿用 chapter.generate／polish／revise 和章资源键。input.request 新增严格的 target 判别对象（chapter 或 scene＋scene_id），缺失则按旧整章请求处理；重试重新鉴权、校验目标并沿用原 Skill 快照。Task 标题、链接、进度和日志指出真实场景。

单场景任务也占用整章写资源，首版不做同章场景并行生成。结构／手写操作复用生成状态和批量范围保护；局部预览不抢后台任务，但采纳必须重新检查目标和版本。

### 8.2 上下文与提示词

scene_context_service（或在现有 builder 中等价的明确边界）接受目标 Scene、统一有效规划和 StoryPosition，供预览／生成／润色／重写／局部五类操作共用：

1. 取目标摘要、局部正文、正确的前场景衔接材料和章背景，不把后场景正文作为默认衔接输入。
2. 解析场景手动引用／POV、应用现有 AI 可见策略及字段隐藏，再按 scene start 投影有效设定。
3. 所有模板接收锁定的场景范围块；默认模板明确只处理目标场景。旧覆盖缺变量仍补齐一次，并保持共享预算与可见截断提示。
4. 预览与实际发送使用同一结果结构，捕获 content_revision、planning_revision、相关时间线／字段版本和可见性 stamp。出站继续使用原 guard_provider；场景快照失效不允许降级发送旧载荷。

不承诺识别作者大纲、自由文本、Skill／知识库中的全部剧透，也不保证模型绝对遵循创作要求；验收控制实际输入、目标范围和采纳写入。

### 8.3 整章与批量

整章 generate 依次处理全部活动场景；polish／revise 处理有正文的目标场景，空场景原样保留，全空时沿用空正文错误。场景身份、顺序、摘要和元数据不由这些任务修改。

显式场景生成使用该场景目标字数；整章生成的总目标按目标场景均分，余数按顺序分配，预览展示分配结果。不能在同一请求中把总目标偷偷重复用于每个场景；不足以给每个目标分配正值时调用前报错。重写缺省对显式 Scene 目标及多景章以各景原文字数为目标；旧章级入口且只有一个活动景时保留 `max(原字数, 300)` 的兼容下限。空景仍保留不调用模型，实际各景目标与生成记录一致。

各场景结果为提案：前场景完成稿可作为后场景衔接输入，但最终正文不逐场景提交。全部主生成成功、快照仍一致后，在一个短事务保存目标正文、章投影、版本、日志与状态。主失败／提交前取消保留旧章；已真实提交的极晚取消以保存事实为准。续写失败 warning 只影响额外续写，不伪装成缺失某场景的完整成功。

批量仍一章完成后才推进 checkpoint／分析；已完成前章不因当前章失败回滚。当前章失败重试重新生成该章，不增加未承诺的场景断点恢复系统。

### 8.4 分析、记忆与局部操作

整章 AI 完整成功后按现有开关触发一次章级分析，批量复用原阶段；不对每个场景重复触发全章分析。独立场景生成／手改使旧章分析过期，提示重跑现有章分析，不把局部结果自动当全章末事实。章节分析读正确的章初资料，自动写回仍在章末。

局部五种操作限一个明确 Scene；码点与 UTF-16 复用 textOffset。采纳绑定 Scene ID、revision、原文／before 和日志，前后文只取允许范围；旧跨场景选区在调用前拒绝。只采纳目标范围，不覆盖其他场景。
