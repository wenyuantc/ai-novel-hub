# C4 实施与验收清单

C4 功能分支从包含 C3 的本地提交 `aabd3c3` 派生。下表按实施步骤列出需要观察的行为，实际运行的环境、用例数和测量值记在[验收记录](research/verification.md)。[设计](design.md) · [验收标准](prd.md)

## 实施顺序

- [x] 先为双应用建立对照夹具。A、B 独立创建 app、连接池、运行时和真实内网连接，共用专用文件库或专用 PostgreSQL。用屏障控制领取、首帧、原始事件发布、A 签发、B 进入物理发送、授权写入提交与退出；测试端保存实际 SSE。采集本地直连的既有序列作为对照。
- [x] 接入私有监听和双租约登记。复用 `main.lifespan`、`WorkerLease.register`、`RequestWorker` 与 C1 活性读取。完成 UDS、TCP、限额/超时、双向签名、nonce、序号和控制消息的测试。在引入业务帧前验证部分启动失败、调度重启换代以及仅 HTTP 进程。
- [x] 增加按原轮次选择本地或对端的路由、排队交接、有限保留和锁外订阅清理。保持现有快照/订阅的原子性，在 A 生成公开事件；B 不对增量重新拆分合并。先以作者、单章生成、批量和智能体落实 AC1、AC4、AC7。
- [x] 完成受控流的原始绑定、A 原生来源、只读帧前提、B 的实际 ASGI 锁内写出。逐类对照 `stream_kind_open`、`verify_stream_frame` 和现有持久回放。验证原帧在有效后继和终态窗口内仍可送达。未经证明的远端输入无法创建本地来源或扩大 handler 开放范围。此步骤通过双库、两种撤权顺序和失败路径后再接入对外协作者订阅。
- [x] 接入断线后的作者库内跟随和协作者受控结束，保留终态/暂停回放、收据未知、删除、账号变更、重连次数以及重置快照语义。通道丢失与任务执行丢失分别验证。
- [x] 收紧详情、列表、输出、管理监控对本地 hub 的使用；补上没有后续事件时的输出节流写回，核对阶段、准入名额及同轮待核对状态。改动前后用同一组事件比较写入次数。覆盖过期尾沿定时器、真实 reset、批量切章、提交失败和换代。
- [x] 在原业务事务提交之后发送有限、可合并的唤醒。接收端重查库内原意图，补齐无通知时成员和静默订阅的周期复查。已确认、回滚、提交结果不明、重复消息、离线与恢复分别测试。C3 的取消时限、名额释放和审计条数继续由原流程决定。
- [x] 从实际前端订阅客户端核对正常、降级、重连和权限错误。运行前后端全量门禁，更新被本功能改变的 README 和 Trellis 规范。把命令、版本、计数、跳过原因、数据库模式以及两进程实际端口的脱敏结果记入本任务的验收记录。

## 对照表

| 验收 | 必须观察到的结果 |
| --- | --- |
| AC1 | 在同一可重复事件节奏下比较直连和转发的全部非心跳事件、数据和顺序，含 reset、章节、工具、提案及结束。另以高频增量核对公开文本和结构事件位置；分别覆盖首帧前、生成一半、排队到领取、短任务在交接期间终结。通道逐帧与 A 对应订阅的实际输出相同。 |
| AC2 | 在知识库或拆书任务对照作者能查看、协作者仍受限，具有管理员身份的协作者也走受控管线。对真实协作者分别执行撤权、降级、关闭作者模型、改密、停用、重邀。A 已发而 B 尚未取锁时先提交权限变更，浏览器不得收到标记正文。另一顺序中 B 持锁发送时变更提交必须等待。数据库发生变化但用户仍是 editor 的模型、可见性和提案案例，也要在 B 检出。批量/向导合法后继、正常模型和终态回放是正向对照。 |
| AC3 | 缺签名、签名或载荷损坏、旧时间、重放、错端/错代/错订阅、缺帧和截断均不交付内容。用公开端口和 OpenAPI 检查内部操作不可调用；对存在及不存在的任务观察同一未鉴权结果。捕获日志中无签名、正文和模型凭据。 |
| AC4 | 分别中断 A→B、终止 A 进程及停止调度但保留 HTTP。作者能看到最新持久快照和一个实际终态；运行中协作者缺来源时受控结束，恢复连接并保留权限后重连可恢复。专测 pause、成功未发布、合法中断、已取消、结果仍待核对、同 ID 新入队，以及回放期间再次撤权。 |
| AC5 | 在 B 注入旧 hub 和旧轮次，核对公共输出、列表、详情、管理员监控及配额。仅发最后一条增量或仅发进度后静默，测量 A/B 可见时间。包括 reset 清空、同一短前缀重新出现、变短后无新字符、批量阶段切换、埋有私密值的管理阶段，以及迟到写回与终态竞争。 |
| AC6 | 健康双端从持久提交起计时，1 秒内分别观察 A 领取、处理取消信号、复核失效成员和应用新设置。禁用通道后，在刚结束一次调度轮询时发起相同行为，最迟下一轮开始处理。测试恢复时重复提示、调度停止但 HTTP 仍持订阅或消费设置、无 token 的静默成员撤权，以实际行为证明结果。 |
| AC7 | 真客户端断开、空闲断开、慢读、队列/字节额度耗尽、超长快照、应用退出时观察 A/B 活连接、订阅者与后台工作归零。两条连续帧均大于套接字写缓冲且浏览器慢读时，WAL 模式仍能发送。故意丢失确认、只送半帧、只送心跳时测量截止时间，检查库中终态仍会收尾。确认强引用的已结束 hub 能交接且能在限额内回收。让一个短任务在 B 发现领取前结束并触发垃圾回收，验证正常窗口的事件顺序和过期后的降级。心跳周期内退订；正常退出清除自有 UDS，强杀重启能安全使用新地址。 |
| AC8 | 原单进程订阅和已开放 handler 的证据用例全部通过；一个进程的 HTTP/调度有两条登记，订阅本机仍发起零对端连接。 |
| AC9 | 正常与降级两条路径真实走前端解析、展示与重连逻辑。快照覆盖、reset 清空、结构化事件、无重复终态、一次权限错误重试均按已有行为。实际运行 lint、build、Vitest，按差异补测试。 |
| AC10 | SQLite 文件全套回归，AC2 在 SQLite 默认日志和 WAL 均验证；专用 PostgreSQL 16 串行运行 AC2 及 C4 数据库竞争用例，检查执行数。Ruff 通过。 |

## 验证命令与故障定位

实施与评审前另读后端规范原文的相关章节：`.trellis/spec/backend/error-handling.md` 的「后台任务与 SSE 契约」、`database-guidelines.md` 的「后台任务表」及 `quality-guidelines.md` 的「PostgreSQL 隔离测试库与环境变量」。专题研究给出具体符号和用例。

后端工作目录为 `backend/`。增加 C4 测试时统一使用 `test_c4_*.py`，执行时检查通配符确实匹配。隔离 PostgreSQL 16 依项目质量规范提供 `AINOVEL_POSTGRES_TEST_URL`，仅连本机测试专库，双库使用分开的命令。

```sh
uv run pytest -n 0 -q tests/test_c4_*.py
uv run pytest -n 0 -q tests/test_tasks.py tests/test_task_stream_*.py tests/test_task_sse_*.py tests/test_collaboration_stream_*.py tests/test_sqlite_shared_frame_lease.py
uv run pytest -n 0 -q tests/test_batch_stream_progress.py tests/test_chapter_stream_performance.py tests/test_c3_*cancellation.py tests/test_task_worker_recovery_crash.py tests/test_system_settings_cross_process.py tests/test_system_settings_publication_races.py tests/test_user_quotas.py
uv run ruff check .
env -u AINOVEL_POSTGRES_TEST_URL uv run pytest -n 4 --dist loadfile --durations=20
```

PostgreSQL 专项从独立环境串行执行 `uv run pytest -n 0 -q -rs tests/test_c4_*.py tests/test_collaboration_stream_agent_postgresql.py`，逐项检查预期运行的 PG 用例确实执行。实际双 OS 进程演练覆盖 UDS、私网 TCP、浏览器连接、定点断开和进程强杀。SQLite、PG 竞争和 AC6 的计时测量分别隔离运行。若已有时间敏感的单进程文件需要独立串行，记录原因，按 node ID 验证分组并集等于全量且无重复。

在 `frontend/` 依次执行 `npm run lint`、`npm run build`、`npm test`。用开发或测试浏览器打开真正的任务页，记录直连、经 B、通道中断、协作者授权变更后的可见文字和终态。仓库根执行 `git diff --check`；对比公开 OpenAPI、数据库迁移头、生产启动参数以及 README 描述。

## 回退和交付

任一两跳授权或 WAL 竞争测试未通过时，已有单进程发送路径仍是回退入口。按[设计](design.md)收回监听和活动连接，核对原任务、库内正文和业务收据。验收后另行确认 C4 本地提交与归档；把实际联网要求交给 C7，生产继续使用一个 worker。
