# C4 内部监听、执行者登记与断线

研究日期为 2026-11-24。范围包括已有代码、锁定依赖、官方运行时文档和本机传输探针。本页给出规划依据，C4 的业务验收另在实施阶段执行。

## 登记与生命周期

| 实际入口 | 对 C4 的约束 |
| --- | --- |
| `backend/app/main.py:113–139` | lifespan 使用 `AsyncExitStack`，先启动请求 worker，再按 `start_task_engine` 决定是否启动调度。每个应用实例各自拥有连接、监听和清理对象。 |
| `backend/app/services/task_engine/workers.py:254–315`、`workers.py:341–374` | 每次登记新建 UUID，有可能在提交已成功后丢失回执。登记应在创建行时写入已绑定的地址；核验丢失的回执时比对本次 UUID 和预期地址。停止登记和回收名额沿用原流程。 |
| `backend/app/services/task_engine/request_worker.py:94–125,128–191` | 普通订阅读取不会自动加入 HTTP 排空集合。请求 worker 可在排空旧工作后独立换代；独立监听需要自己追踪连接、处理协程和上游生成器。 |
| `backend/app/services/task_engine/engine.py:337–365,400–435`、`backend/tests/test_c3_worker_activity.py:24,129` | 调度器自带另外一份租约，会重新登记，也能在 HTTP 仍服务时单独停止。原 worker 键失效后，同一地址上的新调度器只能处理新代次。 |
| `backend/app/models/entities.py:812–824,884`、`backend/app/services/task_engine/workers.py:66–85,102–137,317–336` | `peer_url` 已存在且可空。任务的 `worker_key` 指向当轮实际持有人。SQLite 续约写配对侧库，PostgreSQL 根据数据库时间和围栏字段判活。主库中的地址、主机名、PID 都不能证明对方可执行。 |

推荐每个应用 lifespan 持有一个由标准库 asyncio 实现的监听。先注册清理回调，绑定并取得实际地址，再启动两个 worker。两份有效登记可指向同一地址，按各自的代次分别验真。只有持有任务本轮执行权的进程能提供来源帧；请求进程可以在自己的调度器停止时作为订阅者。广播可按地址合并，接收方仍需核查指定代次和允许的操作。本机两份登记不构成需要转发的远端。生命周期结束时先停止接入、回收内部流和发送任务，再释放相关数据库连接。对中途启动失败、重复停止、仅启动请求 worker 分别验收。

C3 的请求 worker 也可能成为接管者，见 `engine.py:615–671`。此时任务行的 worker 键可以指向它，但它只负责恢复收尾，缺少可证明的原执行现场。由同一监听接受目标为请求 worker 的订阅时，必须再次核对本轮真实执行与 hub 来源；只负责接管时按库等待终态，不能为这个请求创建空 hub 并充当原执行者。

绑定失败或通道临时不可用时记录固定的诊断信息，登记空地址并使用数据库兜底。注册了监听但后续初始化失败时回收已绑定资源。空地址也是旧进程兼容入口。本方案只使用 C1 已有的列，无需为传输另建迁移或消费进度表。回滚时先让任务按既有规则收尾，再换回旧版单 worker；C4 的完成本身不会改变生产部署的进程数。

ASGI 的生命周期属于接受请求的事件循环，多进程下每个子进程各执行一次。不要在导入模块或 Uvicorn 父进程时绑定。Uvicorn 0.54.0 的内部顺序是先停止接受外部连接、等当前响应完成，再调用 lifespan shutdown（项目环境 `uvicorn/server.py:281–311`）。验收应分别观察客户端主动断开后的释放，以及应用真正退出后的资源回收。有长期 SSE 连接时，不能假定公共服务器先进入 lifespan shutdown 来结束该连接。[ASGI lifespan 规范](https://asgi.readthedocs.io/en/latest/specs/lifespan.html)

## 同机和跨实例的地址

- 项目运行时指定 Python 3.12，生产依赖已有 Uvicorn 和 FastAPI；httpx 在项目中显式归为开发依赖，见 `backend/pyproject.toml:5–33,36–40`；`backend/uv.lock:1341` 锁定 Uvicorn 0.54.0。标准库 `start_unix_server` / `start_server` 和配套连接接口可在同一事件循环工作，公共 FastAPI 路由和 OpenAPI 无需增加内部操作。[Python 3.12 asyncio streams](https://docs.python.org/3.12/library/asyncio-stream.html)
- 同机选择短的、当前服务账号独享的目录，目录权限 0700，每次进程启动使用新的随机 socket 文件名，文件权限 0600。建立监听前验证目录所有者、权限、路径类型及实际可绑定长度。只接受该部署配置的目录内的合法 socket。正常退出时按本进程建成的文件设备号和 inode 核对后删除。强杀后无法运行清理器；有残留时新实例使用新名字，清理旧文件必须核实旧代次已结束、归属匹配且文件仍为原 socket。不可批量删除其他进程的地址。
- 多实例通过部署配置明确私网绑定地址和每实例可达的通告地址。多个 worker 同一台机器可分别绑定内核分配的端口，将实际端口连同能唯一到达该实例的主机名登记。已有网络只开放固定范围时应按部署允许的可达端口分配，不能靠所有进程复用同一地址端口。域名均衡到多个实例、指向不可达容器内部端口、通告通配地址或跨主机使用回环地址，都不能保证按登记访问原进程。C7 记录实际部署的 DNS、内网端口和网络隔离条件。
- 对地址使用专用解析器，只接受本部署认可的传输、UDS 根目录或配置允许的私网目标，控制连接/握手/首次响应/空闲超时，拒绝重定向和 URL 自带凭证。数据库登记只提供发现信息，连通性仍由实际握手验证。HMAC 保护身份和完整性，TCP 部署的链路保密性来自其受信私网或加密隧道；有旁路读者的网络不能直接传送正文。收到不支持协议版本或缺少地址的旧登记走相同降级。

## 请求与回传的身份

沿用 `backend/app/main.py:143–148` 的域分离密钥派生习惯，从部署 JWT 密钥派生 C4 专用密钥。内部操作仅接受白名单项目，例如订阅和标识唤醒。请求签名覆盖协议版本、方向、操作、收发双方 worker 代次、请求或订阅随机数、时间有效期和完整请求体。保留首次 HTTP 授权得到的用户身份与 token 版本，以及 `stream_lease.py:144–192` 的原作品、原任务 UUID、排队轮次、成员和任务授权等绑定；可用规范编码的摘要绑定帧和请求。内部消息不携带外部会话 cookie、JWT 或模型密钥。

防重放可用每连接短期服务器随机挑战，一条连接只允许一项操作且原挑战仅消费一次；挑战和请求随机数都纳入签名。若改用接收端随机数缓存，必须在完整验签后一次性占用、覆盖整个时钟容差区间，并在容量达到上限时拒绝新请求，避免提前淘汰仍可重放的标识。重启或调度/请求代次替换后拒绝旧目标。对于真正执行或返回任务存在性的操作，先验签，再检查发送者与本地接收者有效代次及当前任务身份。统一拒绝未知操作、错误绑定和不合规消息，日志只记录固定原因与非敏感计数。

每个回传记录都要证明来自同一部署和本次握手，并关联请求、原订阅绑定、双方代次、任务及当次执行、方向、连续帧序号、帧类型与内容摘要。B 在验真和完整接收前不能把任何一段直接发给客户端。握手、结束、错误、心跳与正文要能区分；截断、乱序、缺帧、换代或重复帧均进入相应的中断处理。仅有请求签名不能证明响应来源。部署内服务共享密钥意味着此协议的信任边界是共享该密钥的应用实例；它不提供不可信应用之间的身份隔离。

## 背压和清理

`backend/app/services/task_engine/hub.py:12–24,86–106` 给每个本地订阅 1000 个队列位置，溢出订阅会被摘除。`engine.py:3967–3979,4032–4035` 在消费端检测溢出并在 finally 解除订阅。新增通道还需限制并发握手、并发订阅和接收控制消息字节数。在计入容量前不要为每个等待者创建永久协程。每条转发流只保留一个待处理逻辑帧，逐块读取、写入并使用有期限的 `drain()`。握手和控制值可设小上限；活动输出的数据库列是 `Text`（`entities.py:904`），64 KiB 默认行读取限制不能当成业务快照大小。对超过传输块长的合法快照分块、保留单帧顺序、在完整验真后交给现有发送层。要以现有可合法产生的大快照验证字节、内存及降级边界，不能静默截断正文。

受控流在 A 的原来源核验、锁内向内部通道写出一帧之后即释放本地租约；B 完整收到并验证后才在自己的帧租约中向公共连接写出。A 不在自身数据库事务中等待 B 的公共发送完成或 B 取得数据库锁。具体执行体来源变化和授权判据见同任务的逐帧授权研究。`stream_lease.py:349–429,434–480` 已有每帧时间上限、异常时释放和对已经开始发送的帧中止连接的分支。公网写了一部分后禁止补发同一帧或接着拼入降级快照。只有内部帧已损坏但尚未对外写出时才能在帧边界切换。

B 的 generator finally 始终关闭上游连接并等待有界的关闭完成；A 在握手后并行监听 EOF，以免安静的订阅只能等待下一条内容。当 EOF、超时、连接取消或应用停止时，撤销读取与发布协程，显式关闭订阅并移除连接登记，只回收本次订阅。活动连接关闭后再等服务器完全关闭，清理函数自身要能抵抗正在传播的取消。不能让挂起的 ACK、慢客户端或释放失败阻塞数据库撤权。

## 探针与验收

在本机项目解释器 Python 3.12.10 下，分别用标准事件循环和 uvloop 0.23.0 实测 UDS 与回环 TCP。四组均能以长度前缀收发 196608 字节的载荷；客户端主动关闭时，服务端均在 1 秒限时内检测到 EOF，活连接集合恢复为空。两种事件循环在 UDS 的监听及活动连接完全关闭后均保留 socket 文件，需要显式 unlink。另用工作区内较长的绝对路径绑定时，macOS 返回 `AF_UNIX path too long`。这些探针只验证传输原语，没有运行应用级权限、收据与多进程业务测试。[Python 3.12 server 生命周期](https://docs.python.org/3.12/library/asyncio-eventloop.html#server-objects)

| 验收条件 | 观察点 |
| --- | --- |
| 初始化、异常恢复、正常关闭、强杀 | 两份 worker 登记和同一地址；启动中途失败无存活 socket；仅停止调度后原 HTTP 代次仍可订阅；重启换代拒绝旧键；强杀旧监听不可连接，新 socket 不被旧清理删除。 |
| UDS / TCP 两个真实应用进程 | 验证实际登记与连接目标，长路径、无目录权限、不可达、对端换代均可降级；对外 OpenAPI 没有内部操作，公共端口执行内部操作不能获得数据；装有前端静态文件时也测，`main.py:92–99` 会为部分任意 GET 返回 SPA 首页。 |
| 认证、完整性与资源 | 双向签名绑定，重复握手/请求、帧错订阅/签名/次序、长大快照、恶意长度、握手不完成、慢读及断开均有界；读取错误后没有部分正文流出，日志不含帧原文及签名。 |
| 撤权并发 | A 的内部发送和 B 的最后公开写出间可插入确定的撤权提交；B 拒绝已在途的旧内容。A 慢写、B 慢写、SQLite 两种日志模式和 PostgreSQL 上撤权最后都能提交，两个进程的连接、生成器和帧租约都能回收。 |
