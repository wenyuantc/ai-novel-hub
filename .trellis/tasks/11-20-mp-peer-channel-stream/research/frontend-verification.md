# C4 前端验收

## 订阅客户端

同一条公开 SSE 从实时转发切换为持久快照后，服务端可以多次发送 `snapshot`。客户端如果每次都用最新快照重置计时，长时间健康的连接恰好在收到快照后断开，也会继续消耗此前的失败预算。现在每条连接从首个快照开始计算稳定时长，原有退避和次数上限继续生效。

新增 `frontend/src/api/tasks.test.ts` 的“稳定连接在转发途中改发持久快照，之后断线仍能重新订阅”用例。固定时钟下，第一次请求返回 503，第二次先给实时增量，已运行 6 秒后用较短的持久快照覆盖正文，随后断开。旧实现抛出“连接意外中断”。修复后第三次请求收到最终快照和完成事件，期间客户端两次分别按首次故障等待 1 秒。这个用例注入了 SSE 响应和时钟。

前端 `npm run lint`、`npm run build` 和 `npm test` 均通过。全量 Vitest 共 264 个测试文件、1,836 个用例。单跑 `src/api/tasks.test.ts` 和 `src/hooks/useTaskStream.test.ts` 共通过 44 个用例。

## Chrome 任务输出弹窗

使用生产构建和 Chrome 157.0.8103.80，登录临时账号，在作品的章节页打开“后台任务” → “查看输出”。每组独立启动两个 Uvicorn 进程，共用新迁移的 SQLite 库。A 运行调度器，B 提供 HTTP。两端都启动真实私有监听。模型使用本机受控的 OpenAI 兼容 HTTP 服务，按测试指令依次发送三段中文。浏览器通过应用的公开 API 操作，没有为转发、快照或撤权伪造 SSE 帧。

| 场景 | 页面及网络观察 |
| --- | --- |
| 执行端直连 | A 的页面依次显示三段文字、完整正文及“已完成”。Chrome 只请求一次公开流，服务端从首个快照开始发送三个增量和一次 `done`。 |
| 跨进程转发转为持久快照 | A（PID 3947）执行从 B（PID 5542）发起的章节任务。两端弹窗同时显示“暮色落在书页上。”，B 已经收到 `snapshot → delta → progress`。只关闭 A 的私有监听和已有私有连接，保留任务及两个 HTTP 服务。B 的同一次 HTTP 200 随后发来四个 `snapshot` 和一个 `done`。页面先更新为“暮色落在书页上。海岸的灯塔亮起。”，结束时两端均显示“暮色落在书页上。海岸的灯塔亮起。远航的故事落定。”和“已完成”。每个页面共发起一次公开流请求。 |
| 撤销协作者 | 编辑者从 B 打开自己发起的生成任务，弹窗显示首段文字。作者在 A 通过公开 API 移除该成员，返回 204。B 公开流随后发出一个受控 `error`，浏览器复查同一任务详情获得 404。输出弹窗关闭，已读首段从页面消失，后续两段均未显示。Chrome 共发起一次公开流请求。 |
| 协作者授权有效、私有连接短时中断 | 在 A 关闭已经建立的私有连接并保持监听。B 首次公开流以受控 `error` 结束。Chrome 复查该任务详情得到 200，随后重新订阅一次。第二条流收到 `snapshot → delta → delta → done`，弹窗恢复显示第二段，并以完整正文和“已完成”收尾。A 记录到两次私有订阅，B 的两次公开流均返回 200。 |
| 公开网络一直不可用 | Chrome 端只对任务的公开流请求注入连接重置，实际页面、登录和生成任务仍使用真实服务。页面先显示“连接中断，正在重连…”。首次尝试之后，实际 8 次重连的间隔依次为 1,006、2,008、4,004、8,006、15,004、15,002、15,003、15,004 毫秒。随后弹窗显示“网络错误，无法连接服务器”。额外观察 16 秒，请求总数仍为 9。 |

五组浏览器演练均正常退出，浏览器未报告未捕获的页面异常。公开断网场景的流请求在 Chrome 端被中断，其他四组均读取应用发出的真实流。原始观测 JSON、公开事件名和页面截图分别保存在本次机器临时目录 `/tmp/ainovel-c4-ui.tpF5OTec` 下的 `direct3`、`owner1`、`editor2`、`member-recover` 和 `retry1`。
