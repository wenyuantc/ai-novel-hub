# C4 实施验收

## 变更前对照

基线为 C3 收尾提交 `aabd3c3`。在独立的基线检出中，两个应用实例使用同一临时 SQLite 文件和不同的任务引擎。通过公开 HTTP 接口创建作品、章节和生成任务。受控模型先给出一段正文，停顿 2.3 秒，再由测试放行。执行实例的 `/output` 此时已有正文，第二个实例的 `/output` 仍返回空字符串。

在第二个实例请求同一任务的公开 SSE 路由并收到快照后放行模型。执行实例的任务详情已返回 `succeeded`。测试把第二个实例的心跳间隔设为 50 毫秒，接下来约 300 毫秒内观察到 6 个心跳，未收到 `done`。这条基线探针以同一 Python 进程中的两个应用及 ASGI 传输运行，耗时 4.86 秒。正式双进程验收另行记录。

基线公开 OpenAPI 来自实际应用，含 415 个路径。按 UTF-8、键排序、无额外空白的 JSON 计算，SHA-256 为 `648c9f60829c4f526ad4cf02ceefa95c33c269042d3bca102e4290610ebf91af`。数据库迁移头为 0068，Docker 默认启动一个 Uvicorn worker。

## 真实进程和浏览器

两个独立 Uvicorn 使用同一临时数据库和受控模型服务。作者分别连接两个公开端口，默认日志配合本机套接字、WAL 配合 TCP 时，两条流的事件、数据及顺序逐帧相同。强杀实际执行进程后，接入端在原连接发送持久快照和一个中断终态，重连得到同一结局。另一次在两端都已送达首段后撤权，公开连接只送出固定拒绝，后续标记正文没有出现。[双进程验收记录](process-verification.md)

在 Chrome 任务页仅切断内部连接并保留两个 HTTP 服务，作者页面收到持久快照并显示完整正文和一次完成提示。编辑者仍有权限时，断线后复查详情并重订阅一次。撤权时，复查返回 404，已显示的内容从页面清除。另用 Chrome 模拟持续断网，观察到八次退避重试后停止。五组浏览器演练均正常结束。前端 lint、构建和 Vitest 通过，264 个测试文件共 1,836 项。[前端验收记录](frontend-verification.md)

另一项双进程演练专门核对强杀后的文件清理。存活进程在 30.16 秒时确认另一进程的两份租约均失效，60.05 秒时清除了旧套接字和归属文件。期间存活进程的文件 inode 相同，公开健康接口返回 200，正常退出后其自有文件也已清理。[传输复核记录](transport-implementation-review.md)

在 C4 应用重新生成的 OpenAPI 与基线规范逐字节相同，仍为以上 415 个公开路径和同一哈希。Alembic 仅报告 `0068` 一个迁移头。Dockerfile 保留单个 Uvicorn 进程的生产启动命令。

## 原协作者的授权竞争

在两个应用、两个公开 HTTP 端口上执行 `tests/test_c4_authorization_races.py`。SQLite 共 24 项通过，用时 63.86 秒，包含默认日志和 WAL。专用 PostgreSQL 16.15 在不同 schema 串行执行同一文件，选择 `-k 'not sqlite-wal'`，14 项通过，用时 84.28 秒。未选中的 10 项专门开启 SQLite WAL。

一组在执行端已经签发、接入端尚未向浏览器写出时变更权限，覆盖撤权、降级、关闭作者模型授权、改密、停用、重新邀请，以及模型、内容可见性和提案变化。另一组阻塞接入端已持有发送锁的公开写入，观察执行端确实尝试写入授权变更，记录公开字节写出与数据库提交的先后。合法授权和保留原提案的对照可继续发送，知识库任务仍遵守原有读者范围。其他跨两跳的合法后继、断点和持久投影见[授权复核](guard-implementation-review.md)。

## 跨进程唤醒及写入次数

以接入端数据库根事务真正提交为时间起点。SQLite 在线时，执行端在 0.053–0.063 秒内领取新任务，本人取消在 0.012 秒内发出信号，管理员取消耗时 0.076 秒，撤权停止静默执行耗时 0.014 秒，设置发布耗时 0.021 秒。关闭通道后，生产默认 5 秒轮询下，观测到任务在 4.975 秒领取、管理员取消在 4.989 秒发出信号、设置在 4.963 秒生效。测试在数据库提交前后标记扫描轮次，并分别记录开始扫描、发现变更和实际处理的时刻。这些是本次本机观测值。10 项唤醒与 10 项原单帧发送时限用例串行通过。

在 C3 基线和 C4 分别运行既有的 `test_successful_chapter_batches_bound_real_validation_and_output_writes`。两次都将同样的 1,024 个片段送入真实单章任务，并把输出节流间隔设为 0 以观察每批写入。两次均有 2 次增量验证、2 次刷写验证和 3 次包含正文的 SQL 更新，最终保存的正文逐字相同。

SQLite 新增专项中，模型只发最后一段文字后保持静默。从执行端看见该段文字算起，数据库提交耗时 1.974 秒，接入端通过 `/output` 观察到更新耗时 1.985 秒。只改变阶段时，提交耗时 1.980 秒，接入端 HTTP 采样耗时 2.009 秒，清空阶段的读回耗时 1.981 秒。节流窗口为 2 秒，HTTP 采样另含请求与采样间隔。两端配额、同号残留 hub、批量切章以及权威租约已失效但本机心跳尚未发现的情况均通过。

另用已保存的真实章节收据检验失联恢复。执行端在发布终态前停止，接入端从原 HTTP 连接发出一个 `done`，标明已保存且未发布；重连得到同一最终快照及终态。此例与强杀后判为中断的用例有不同的数据库事实。[收据及故障演练](process-verification.md)

## PostgreSQL 16 专项

使用临时 PostgreSQL 16.15 容器和本机专用 `ainovel_test` 数据库。每个使用 PostgreSQL 的用例单独创建并清理 schema。执行 `pytest -n 0 -q -rs tests/test_c4_*.py tests/test_collaboration_stream_agent_postgresql.py`，共 121 项通过，用时 570.04 秒，无失败、错误或跳过。此计数包含明确指定 SQLite WAL 的对照和无需数据库的协议单测。需要实际行锁竞争的 AC2 另按上文的 14 项单独核对。

同一两秒节流测量中，文字、单独阶段变更分别在 1.958、1.955 秒提交；接入端 HTTP 分别在 2.016、1.991 秒观测到，清空阶段在 2.034 秒读回。已有保存收据的跨端接管用例在 PostgreSQL 上耗时 8.695 秒。两种数据库的指标通过 pytest 的测试属性写入 JUnit XML；pytest 对该属性与 xunit2 的兼容性给出一条提示，XML 中实际含五个测量值。

将 SQLite 回归中按数据库条件跳过的节点逐一交给同一 PostgreSQL 16 专库，8 个文件的 30 项全部通过，用时 166.20 秒。JUnit 中的 30 个节点与 SQLite 跳过清单完全一致，其中 1 项也包含在上述 121 项中。

## SQLite 全量回归

首次完整分组共收集 7,416 个节点。C4 专项中的 110 项串行通过。10 项跨进程唤醒和原有 10 项单帧时限用例另组串行通过。其余 7,286 项使用四个 pytest worker 按文件分配，有一个既有智能体用例超过 5 秒时限，任务当时仍在调用项目概览工具。此次四路并行组有 7,236 项通过、30 项按数据库条件跳过、19 项预期失败和上述一项失败。

保留原测试的 5 秒时限、工具调用数及结果断言，将整个 `test_agent_runtime.py` 单独运行，20 项全部通过。超时用例的 JUnit 总耗时在本次串行测试中为 2.631 秒，在单独检出的 C3 基线上为 2.473 秒。下述最终分组按文件将这 20 项与并行组分开。

最终验收将其余 7,266 项按文件分成六组，以四个 worker、`--dist loadfile` 全部重新执行。六组分别收集 1,206、1,257、1,329、1,195、1,240、1,039 项，退出码全部为 0。将六组与前述三个串行组的 JUnit 节点逐一比对，9 个分组无重叠，合计与整套收集的 7,416 个节点完全一致。最终 **7,367 项通过，30 项按数据库条件跳过，19 项预期失败，实际失败和错误均为 0**。19 项沿用已有标记，分别来自平台 Key 原身份 11 项、智能体 MCP 或执行身份 7 项及 SQLite 用户 ID 复用 1 项。

可从 `backend/` 使用以下命令复跑相同的 SQLite 用例集合。最后一行覆盖本次分成六组的全部文件。先取消 `AINOVEL_POSTGRES_TEST_URL`，再执行以下命令。

```sh
uv run pytest -n 0 -q tests/test_c4_*.py
uv run pytest -n 0 -q tests/test_agent_runtime.py tests/test_task_sse_frame_guard.py
uv run pytest -n 4 --dist loadfile -q --ignore-glob='tests/test_c4_*.py' --ignore=tests/test_agent_runtime.py --ignore=tests/test_task_sse_frame_guard.py
```
