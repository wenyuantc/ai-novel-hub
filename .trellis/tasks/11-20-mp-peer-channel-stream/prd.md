# C4 进程间内部通道与实时流转发

> 遵循[父任务设计第 5 节](../11-20-multiprocess-task-scheduling-deploy-drill/design.md)与用户决策 D2。C1 执行者租约、C2 调度约束及 C3 跨进程取消均已归档。C4 接续 C3 的本地分支基线 `aabd3c3`。十项验收对应的设计和测试分别列于[技术设计](design.md)和[实施清单](implement.md)。

## Goal

用户从任一服务进程打开同一任务，均可看到有序的实时输出和任务结局。撤权提交后，接入进程不再向原协作者写出新的受保护内容。内部通道故障时，作者仍能跟随已保存的进度，协作者获得可验证的回放或可重连的受控结束。

## 基线与现状

以下行号来自父任务初次盘点。C3 合入后的对应入口为 `TaskEngine.subscribe`、`_TaskFrameGuardedResponse._send_frame` 和 `TaskEngine.notify_collaboration_change`；三个专题记录给出当前符号与位置。

- 实时文本、进度、订阅者队列都在执行进程的内存 hub（`backend/app/services/task_engine/hub.py:38-69`；`engine.py:246`）。
- 订阅落在非执行进程时：作者流在一帧快照后只有心跳，任务在别处结束也收不到终止帧；协作者流因没有可证明的帧来源以 `permission_denied` 结束（`engine.py:3183-3185,3225-3229,3372-3392,3430-3442`）。已结束任务的持久回放在任何进程都正确（`engine.py:3221-3251`；`stream_evidence.py:399-429`）。
- 协作者受控流的帧来源证明是进程内对象（`stream_evidence.py:128-130,161-162`），每帧在「实际发送租约」内按订阅原绑定复核授权，租约由数据库锁构成（`api/sse.py` 的 `_FrameGuardedResponse`；`stream_lease.py:195-291`）。
- `/output`、`TaskOut` 的进度覆盖、管理员监控在本进程有 hub 时读 hub，残留 hub 会给出旧值（`task_service.py:324-334,909-916`；`admin_task_service.py:101-105`）。
- 唤醒只在进程内：`notify()`、协作成员变更通知、系统设置发布（`engine.py:337-341,2893-2917`；`system_settings_service.py:68`）。
- 前端订阅有重连逻辑，快照会整体覆盖已累积文本（`frontend/src/hooks/useTaskStream.ts`）。

## Requirements

- **R1 内部通道**：每个进程提供只供同一部署内其他进程访问的通道，并把地址登记在自己的执行者登记上。同机多进程使用本机套接字；多实例使用部署配置通告的内网地址。
- **R2 内部鉴权**：内部请求必须携带由部署密钥派生的签名并带防重放要素，接收方校验失败即拒绝；内部接口不出现在对外路由与开放接口文档中；日志不记录签名与帧内容。
- **R3 流转发保真**：订阅落在非执行进程且执行者存活时，客户端收到的事件类型、顺序与内容与直接订阅执行进程一致，包括快照、增量、阶段、进度、批量的章节事件、智能体的工具与提案事件、终止帧。
- **R4 撤权零泄露保持**：协作者被撤权、降级、关闭作者模型授权、改密或停用后，没有任何后续帧经转发到达其客户端；转发进程在向客户端写出每一帧时独立复核该读者的授权。
- **R5 降级路径**：执行者不存活、通道不可达或转发中断时，流不挂起：作者流退回按库内值刷新并在任务结束时发出与持久回放一致的终止帧；协作者流在能证明可发送时同样退回，否则以受控错误结束并可由客户端重连恢复。
- **R6 活动任务读取一致**：`/output`、任务列表与详情的进度和阶段、管理员监控在任一进程返回一致结果，滞后不超过输出节流间隔；非执行进程不再采信本地残留 hub。
- **R7 跨进程唤醒**：新建或继续任务、取消请求、协作成员变更、系统设置保存后，经通道唤醒相关进程以缩短延迟；唤醒丢失不影响最终结果。
- **R8 资源有界**：转发连接随客户端断开而释放；执行进程不因转发订阅无限堆积；通道监听随进程停止关闭并清理套接字文件。
- **R9 单进程行为保持**：单进程下不建立任何转发，现有流的帧序列、心跳与错误语义不变。

## 研究结论

- 受控帧要在执行端证明原始来源，再在接入端的实际客户端写入期间重验原读者和内容条件。两端各自限时持锁。协作者运行中的库内正文单独不能证明其发布来源，排队快照、暂停和终态各有自己的核验规则。[逐帧授权与背压](research/frame-authorization.md)
- 每个应用进程独立监听，同机使用受权限保护的套接字，多实例使用可直达目标进程的私网地址。请求与调度两份租约独立换代，监听覆盖应用生命周期。私网部署和端口条件交给 C7。[监听、通告与清理](research/transport-lifecycle.md)
- 两秒输出节流和五秒调度轮询均需覆盖没有新模型输出的场景。接管后的实际收据决定终态，作者断线不会改变任务本身。[活动读取、降级与唤醒](research/reads-wake-fallback.md)

上述五个研究问题的结论已进入设计，独立复核覆盖两跳授权、快任务交接、断线和资源回收。[独立复核记录](research/independent-review.md)

## Acceptance Criteria

- [x] **AC1** 双应用测试：任务在 A 执行，作者经 B 订阅，收到的事件序列与经 A 订阅逐帧相同（心跳除外），以终止帧结束。覆盖单章生成、批量、智能体轮次三类。（R3）
- [x] **AC2** 双应用中，协作者经 B 正常收到 A 的帧。分别测试撤权、降为查看者、关闭作者模型授权、改密和停用。变更在 A 签发之后、B 写出之前提交时，客户端只得到固定拒绝；B 已在发送时，撤权提交等该次发送完成。测试同时记录服务端发送顺序和客户端实际帧。（R4）
- [x] **AC3** 篡改或缺失内部签名、重放旧请求、从对外端口访问内部路径，均被拒绝且不泄露任务是否存在。（R2）
- [x] **AC4** 转发建立后切断内部通道：作者流退回库内值并继续，任务结束时收到终止帧；协作者流按设计退回或以受控错误结束，重连后恢复。对可证实中断的强杀样例，流在接管收尾后以中断终止帧结束；已有业务收据的样例按实际结果结束。（R5）
- [x] **AC5** B 上残留该任务的本地 hub 时，B 的 `/output`、列表、详情及管理员监控读取当前轮次的值。最后一次增量或阶段变化后没有新事件时，正常可写数据库下两端仍在节流间隔内一致。两端配额页显示相同的全局占用。（R6）
- [x] **AC6** 在 B 创建任务、取消 A 上的任务、变更协作成员、保存系统设置，A 在 1 秒内做出反应；关闭通道后同样的操作在一个轮询周期内生效。（R7）
- [x] **AC7** 客户端断开后，A 上对应的转发订阅在一个心跳周期内释放；进程停止后本机套接字文件被删除。（R8）
- [x] **AC8** 现有流与订阅测试文件全部通过（`test_tasks.py` 的 hub 与订阅用例、`test_task_stream_*.py`、`test_task_sse_*.py`、`test_collaboration_stream_*.py`）。（R9）
- [x] **AC9** 前端订阅在转发与降级两种路径下显示正常：`npm run lint`、`npm run build`、`npm test` 通过；若前端需要改动，补对应用例。
- [x] **AC10** PostgreSQL 16 上串行通过 AC2 对应用例；SQLite 上 AC2 同样通过；SQLite 全量回归与 `ruff` 通过。

## Out of Scope

- 用数据库事件表或消息队列承载流（已在决策 D2 中排除）。
- 跨实例的会话保持或负载均衡器配置；只在 C7 的文档中说明前提。
- 知识库索引、拆书导入对协作者的流开放范围不变（继续失败关闭）。
- 把 `/output` 等读路径也改为实时转发；它们读库即可满足一致性要求。
