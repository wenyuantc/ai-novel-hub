# Research: Agent 外部调用的发起进程、结果与作品删除

- Query: 应用 A 已受理一项外部工具调用，B 何时可以判中断，何时可以删除作品？
- Scope: internal，C3 的 R5、R7、R8、R9 和 AC6、AC8、AC9。
- Date: 2026-11-23

### C3 建议的判定与提交边界

1. 在产生新 `executing` 的同一事务写入实际处理请求的 worker UUID 与不可复用的调用 UUID。手动路径使用 HTTP 所在应用的有效工作者代次，自动路径保留原执行身份。可复用 C3 的请求清理记录并绑定原任务、提案及作品，保持一次调用一条记录。登记未知时回读精确身份；确认之前不得发包。发送钩子在现有锁序内验证原登记及其有效租约，覆盖已提交凭据后、真正发包前旧进程被围栏的窗口。
2. 使归属参与原执行者写回、故障收尾与恢复的最终条件更新。若选择独立运行记录，将其绑定原签名凭据，并在事务内锁住、复核。若改签名，给新签名可识别的版本并兼容旧签名；直接给原 result JSON 追加键会使 `valid_external_claim_result` 拒绝全部新调用。正常终态提交与释放在途记录保持一致，或以独立的保守记录继续阻止删除直至可核对；不能因内层函数已返回就宣布结果已提交。
3. 对已证实仍在途的原调用，健康的 A 与 B 都继续等，即使开始时间已超过两分钟。原请求明确退出而业务终态尚未确认时，由 A 在真正退出后持久记录退出；可在原两分钟阈值后按精确身份回收。若新调用具备完整来源，且 C1 已确认原 worker 停止或被围栏，可在两分钟内登记结果未知。每次恢复只改原调用一次，去掉在途占用后保留业务未知标识。死亡判据用已提交的停止/围栏决定，并使登记裁剪先消费或保留尚被 C3 引用的决定；缺行、暂时读失败或一次心跳过期都不足以提前判死。
4. 升级前已具备完整旧凭据、没有 worker 的执行沿用原两分钟和在途保护。停旧版本、排空活请求再升级，避免无归属的旧进程与新进程同时发外部调用。缺 UUID、MAC、原起始时间或任务/提案证据相悖时，继续保留屏障。新记录的归属损坏不能降格为旧记录而放行。单书导出排除实例内运行记录，原生恢复对已确认退出的旧代次按相同判定处置，降级在仍有活跃或归属未证状态时拒绝。
5. 删除方首先冻结新操作，对明确属于 A 的在途调用按现有等待上限观察。等待期间应结束只读/写事务以释放数据库锁。由原调用自行收尾，删除方再次在作品锁内复核。已正常收尾或明确未发、已返回未应用且没有未决证据的，继续原有删除流程。超时、归属不明、远端结果未知时返回 `project_tasks_not_stopped`，保留作品与证据。C1 对某个进程确认失联只证明本地发起者不可继续写；远端副作用不能从此推断。

### 可重复验收场景

| 强制交错 | 要观察的结果 |
| --- | --- |
| A 手动确认并已提交，阻塞本机 SDK 服务的响应正文；B 在两分钟内重复确认、启动恢复。再给该次执行注入一致的历史时钟使其越过阈值，同时保活 A | B 看到同一条 executing，重复确认 409。远端只收到一次 `tools/call`；A 收尾后原结果只提交一次。构造旧时钟必须保持 MAC 对应原起始时间，直接 SQL 改时间只能验证凭据损坏。 |
| 在提交和实际 POST 之间确认 A 失联；另一次让 POST 已到远端再使 A 失联 | 前者由原发送租约阻止迟到发送。已发场景只登记未知且保留凭据，B 不能重发。若只有已提交的 executing 而尚无可靠“从未发送”收据，恢复同样按未知。旧进程迟到返回不能覆盖已登记结果。 |
| A 收到响应但结果尚未提交，B 从正常入口删除；另测原请求在发送后断连、原 worker 刚好换代 | B 必须等待同一调用并锁内复查。已知返回的执行按原语义收尾，远端未知及无法核验的执行挡住删除，调用计数保持 1。新 worker 的其他项目或同项目其他收尾不能充当原请求退出的证明。 |
| 手动/历史自动凭据，完整旧凭据/缺时间/错误 MAC/新归属被替换；两实例同时作恢复，先停在 SELECT 再换任务或提案 | 旧完整记录保持两分钟边界，其余不改。只有同一原始身份可完成一次更新。已知未发送、明确远端业务错误、未知结果继续分别断言。自动外部调用的生产禁用行为保持。 |

SQLite 与 PostgreSQL 都以独立应用、独立会话和本机受控 HTTP 观察数据库事务与发送次数。已有可复用用例集中在 `backend/tests/test_agent_recovery_claim_identity.py:35`、`:109`、`:167`、`:195`，`test_agent_unknown_outcome.py:55`、`:139`、`:186`、`:204`，`test_agent_mcp_send_lease.py:110`、`:188`，`test_agent_mcp_skills.py:564` 至 `:611` 与 `test_recycle_bin_tasks.py:255`、`:416`、`:467`。这些是既有基线，跨实例的时序仍需新用例覆盖。
