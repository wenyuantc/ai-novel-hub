# C3 跨进程取消、管理员取消与作品删除排空

父任务为「多进程任务调度与部署演练」。C1 提供租约与接管，C2 提供领取事务与执行名额。取消和删除的设计以 0067 为基线。[技术设计](design.md) · [实施与验收清单](implement.md)

## Goal

用户在任一进程取消自己的任务、管理员取消任务或删除作品，都能得到与单进程一致的结果。作品进入回收站前须确认原工作已安全收尾。

## Background

- 本人取消运行中任务时，缺少本机执行体会触发孤立清理；分析和向导会返回待核对冲突。C1 引入了可靠的接管手续，这些入口仍要接入。
- 管理员的取消意图和审计已持久化。C1 已让 drain 跳过另一个 worker 的 running 任务。排队与待审核的清理、旧无主记录和本机的赢家记录仍存在跨进程竞态。
- 作品排空、请求侧清理与失败屏障主要依靠本机状态。C2 提供原任务名额，但名额归还早于执行协程完全退出。当前启动恢复会清除其他进程的删除意图。
- 外部工具确认可能发生在处理 HTTP 的进程。当前恢复按两分钟阈值和本机在途工作判定，无法识别另一个进程里的慢调用。

## Requirements

- **R1 取消送达执行进程**：取消运行中任务的请求落在非执行进程、且执行者存活时，请求被持久化并由执行进程执行真正的取消；请求方在现有最多 10 秒的等待窗口内返回仍有权读取的当前任务状态。延迟上限为一个轮询周期（C4 之后经内部通道即时唤醒）。
- **R2 不误判孤立**：任何进程只在「执行者不存活」时把运行中任务当孤立任务处理，并且先经 C1 的接管协议取得处理权。
- **R3 分析与向导任务可取消**：这两类任务在非执行进程受理取消时，行为与在执行进程受理一致。
- **R4 管理员取消跨进程唯一**：同一取消意图只有一个处理者产生效果；运行中任务只由执行进程取消；执行者不存活时由接管者按现有孤立规则处理。管理员受理立即返回 202，后台停止执行的等待上限为 10 秒，失败时保留屏障。
- **R5 作品删除排空跨进程成立**：删除作品时，其他进程里该作品的执行体被取消并等待其停止；存在无法证明已停止的执行体或进行中的请求侧清理时，删除失败并可重试，不继续软删除。
- **R6 收尾失败屏障跨进程可见**：阻止作品删除的收尾失败屏障在任一进程受理删除时都生效。
- **R7 删除意图不被他进程启动清空**：进程启动只解除发起进程已不存活的删除意图。
- **R8 外部调用恢复按发起进程判定**：确认原发起进程已停止或失联时可按原调用凭据标记结果未知；仍可证明在途的健康调用即使超过两分钟也可完成。对已退出的工作及有完整凭据的旧调用，沿用原有两分钟阈值。
- **R9 单进程行为保持**：单进程下取消、管理员取消、作品删除的结果、错误码与等待时间不变。

## 研究依据

四项开工前研究已按当前源码与既有测试完成，涵盖[各类任务取消的副作用与授权](research/owner-cancel.md)、[管理员竞争与清理收据](research/admin-drain.md)、[作品删除与失败屏障](research/project-drain.md)和[外部调用归属](research/external-call-ownership.md)。实际跨进程结果按下列标准验收。

## Acceptance Criteria

- [x] **AC1** 双引擎测试：任务在引擎 A 运行，通过应用 B 取消。A 的执行体收到取消，终态为已取消，章节占用只回退一次，生成记录只写一条已取消。（R1、R2）
- [x] **AC2** 同 AC1，对象为 `chapter.analyze` 与 `wizard.*`：返回结果与在 A 上取消一致，不再出现「尚未核对，不能取消」。（R3）
- [x] **AC3** 双引擎测试：管理员在应用 B 取消 A 上运行的单章任务与批量任务。只有 A 执行取消；审计只有一条成功受理；任务终态与单进程一致；B 的 drain 不执行 `on_abort`。（R4）
- [x] **AC4** 双引擎测试：管理员取消排队任务与待审核任务时，两个引擎并发 drain，只有一方完成收尾。（R4）
- [x] **AC5** 执行者失联后取消其运行中任务：接管完成后任务按孤立规则收尾，结果与现有单进程孤立任务用例一致。（R2）
- [x] **AC6** 双引擎测试：作品在 A 有运行中任务，通过 B 删除作品。即使并发名额已归还、原执行协程还在等提交回执，B 也继续等待。删除在 A 的执行体停止后才完成；完成后库内没有该作品的运行中任务，A 内存中没有该作品的执行体。（R5）
- [x] **AC7** A 上存在该作品的收尾失败屏障时，通过 B 删除被拒，错误与单进程一致。（R6）
- [x] **AC8** A 正在删除作品时 B 启动：A 的删除正常完成。A 失联后 B 启动：遗留意图被解除。（R7）
- [x] **AC9** A 有外部调用处于 executing 时，包括耗时超过两分钟的健康调用，B 上对同一会话的操作均不会把它判失败；A 失联后，B 在接管或阈值到期后把它判为失败且不重新调用。（R8）
- [x] **AC10** 现有取消、管理员取消、回收站相关测试文件通过（`test_tasks.py`、`test_admin_task_cancellation.py`、`test_admin_chapter_claim_cancellation.py`、`test_admin_uncertain_execution.py`、`test_recycle_bin_tasks.py`、`test_project_lifecycle.py`、`test_agent_recovery_claim_identity.py` 等）；改动的断言逐个列出原因。（R9）
- [x] **AC11** PostgreSQL 16 上串行通过 AC1、AC3、AC6 对应用例；SQLite 全量回归与 `ruff` 通过。

## Out of Scope

- 取消的即时唤醒（C4 提供内部通道后接入）。
- 备份运行器的中断与恢复（C5）。
- 管理员批量取消、接管他人任务等新能力。
- 已提交正文、已执行的智能体修改和外部工具效果的撤销（现有契约即不撤销）。
