# 模型配置增强：获取模型列表、思考等级、上下文与最大输出

## Goal

在「模型配置」新增/编辑弹窗中：
1. 可一键从接口拉取可用模型列表并选择，减少手输模型名出错；
2. 可设置思考等级（默认关闭）；
3. 可按 K 设置模型上下文大小与最大输出，并真正作用于生成链路。

## Requirements

### R1 获取模型列表
- 模型输入框旁增加「获取模型」按钮；点击后用表单当前的接口类型、Base URL、API Key 请求后端拉取模型列表。
- 新增配置时（尚未保存）也可用；编辑时 API Key 留空则使用已保存的 Key。
- 拉取结果作为模型输入框的下拉候选（可搜索），仍允许手动输入任意模型名。
- 三种接口类型均支持：OpenAI 兼容（`GET /models`）、Anthropic（Models API）、Gemini（models.list，仅保留支持生成内容的模型，去掉 `models/` 前缀）。
- 失败时给出可读的中文错误（鉴权失败、地址不可达、接口不支持列模型等），不影响手动输入。
- 必须遵守现有 SSRF 防护（`ALLOW_PRIVATE_AI_ENDPOINTS`）。

### R2 思考等级
- 选项：关闭 / 低 / 中 / 高；默认「关闭」。
- 「关闭」= 不向模型发送任何思考参数（对默认就会思考的模型，无法强制关闭，按模型默认行为）。
- 低/中/高按接口类型映射为对应参数（OpenAI `reasoning_effort`、Anthropic adaptive thinking + effort、Gemini 思考预算），作用于章节生成、润色、创作向导。
- 「测试」连通性时始终不开思考，保证测试快速且不因 max_tokens 过小报错。

### R3 上下文大小（K）
- 可选整数，单位 K（1K = 1000 tokens），范围 1–2000；留空 = 使用系统默认（`CONTEXT_CHAR_BUDGET`）。
- 设置后参与章节生成的上下文截断：根据 上下文大小 − 最大输出 − 预留 推算前文字符预算，替代全局默认预算。

### R4 最大输出（K）
- 可选整数，单位 K（1K = 1000 tokens），范围 1–256；留空 = 使用接口默认（Anthropic 8192，其他不传）。
- 作用于章节生成、润色、创作向导的 `max_tokens`。
- 若同时设置了上下文大小，最大输出必须小于上下文大小。

### R5 展示
- 配置列表展示思考等级、上下文、最大输出（未设置显示「默认」）。

## Acceptance Criteria

- [ ] 新增配置弹窗填好类型/Base URL/Key 后点击「获取模型」，下拉中出现该接口返回的模型；选择后可保存。
- [ ] 编辑配置时 Key 留空也能获取模型（用已存 Key）。
- [ ] 获取失败时弹出中文错误提示，模型输入框仍可手动填写。
- [ ] 开启 `ALLOW_PRIVATE_AI_ENDPOINTS=false` 时，Base URL 指向内网地址获取模型被拒绝。
- [ ] 新建配置默认思考等级为「关闭」；已有配置迁移后为「关闭」、上下文与最大输出为空。
- [ ] 思考等级/最大输出被传递到 provider 的生成调用（章节生成、润色、向导）；测试连通性不带思考。
- [ ] 设置上下文大小后，章节生成使用推算出的预算而非全局默认。
- [ ] 最大输出 ≥ 上下文大小时保存被拒（前后端均校验）。
- [ ] `uv run ruff check . && uv run pytest` 通过；前端 `npm run lint && npm run build` 通过。

## Out of Scope

- 自动从模型元数据回填上下文/最大输出（Anthropic Models API 有该字段，留作后续）。
- 展示/保存模型思考内容。
- 精确 token 计数（使用字符估算）。
