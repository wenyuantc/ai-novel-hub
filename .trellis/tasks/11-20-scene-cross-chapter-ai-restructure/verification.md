# 第 24 项验收记录

2026-11-20，在功能分支 `codex/scene-cross-chapter-ai-restructure` 的隔离 SQLite、PostgreSQL 16 和 Chrome 中执行。

## 跨章移动

- SQLite 与 PostgreSQL 的实际 Alembic 迁移均达到 `0065`。空的 PostgreSQL 迁移库完成了 `0065 → 0064 → 0065`。
- 实现前，双连接用例在 SQLite 和 PostgreSQL 上都在缺失的移动预览接口处失败。接入后，两端并发提交同一预览均只有一次成功。源章保持可编辑，移动前结构、冻结定稿和发布记录可读，独立导入 v16 后可再移动场景。
- 后端移动定向回归覆盖继承变化、显式覆盖、富文档、CRLF、生成占用、撤权以及真实职业历史冲突导致的整笔回滚。历史定向回归覆盖移动证据、备份、删除及章 ID 复用。
- 补验场景矩阵、支线交汇和标记时间线映射到目标章。SQLite 和 PostgreSQL 都验证了阅读器新章正文、提及迁移到目标章、定位到同一场景 ID，以及原章旧坐标提示失效。

## AI 建议与界面

- 真实 Chrome 使用经 Alembic 创建的 SQLite、本地 OpenAI 兼容 HTTP 假模型和两名隔离用户。1280 px 桌面分别打开两页，第一份移动预览成功提交，第二份旧确认被拒绝。源章自动补空，跳转链接定位到新章中的同一场景。
- 在 375 px 界面阻断已提交移动的响应，使用「核对移动结果」重新读取两章并定位到新章。服务端只接收一次移动写入。
- 同一账号的另一个标签页保留未保存的场景标题。场景被移出后，旧页面从「本地草稿」中查看并下载原草稿，服务端移动的是已保存稿件。
- 在 375 px 界面，核对保存稿发送预览，打开后台任务的「查看建议」，分别采纳拆分和相邻合并。采纳前内容版本保持原值，采纳后整章正文逐字符相同。检查实际两次模型请求，均只含所选场景的内容。只读协作者可读稿件，编辑动作依授权隐藏。页面运行异常为零。
- 最终前端 Vitest 通过，264 个文件、1829 个用例。前端 ESLint 和生产构建通过。
- AI 及相关提示词定向回归使用可控 FakeLLM。兼容回归中的既有关系任务 SSE 有一次负载下超时，独立重跑通过。首次组合回归中的一项协作失败来自断言读错了 FakeLLM 的记录字段，修正后独立重跑通过。
