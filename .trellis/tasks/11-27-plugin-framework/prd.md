# 插件框架：登记、启停与入口显隐

> 父任务：`11-27-admin-plugin-packages`。决定编号 D1–D15、共同需求 R1–R7 与代码证据见父任务 `prd.md`，此处不重复。

## Goal

提供一套内置功能模块的接入机制：插件用一份清单声明自己贡献的东西，管理员在后台启用 / 停用，
后端接口、后台任务与前端路由、导航都按启用状态生效。本子任务交付机制本身，不含任何真实插件。

## 依赖

无。先于 `11-27-short-drama-plugin`、`11-27-drama-canvas`、`11-27-plugin-developer-docs`；可与 `11-27-media-storage` 并行。

## Requirements

登记：

- F1 插件随代码内置，用一份清单声明：标识、名称、简介、版本，以及它贡献的后端接口、后台任务类型、前端页面与导航入口。
- F2 插件标识全站唯一；它的后台任务类型必须带插件专属前缀，与核心任务类型不冲突。重复或冲突在应用启动时即报错，而不是运行时才发现。
- F3 核心代码不出现针对具体插件的分支；新增一个插件只需要新增它自己的目录并在登记处加一行。

启停（D3、D5、D6、D7）：

- F4 管理后台新增「功能插件」页：列出所有已登记插件的名称、简介、版本、当前状态和最近变更时间。
- F5 启用 / 停用是全站开关，立即生效，记入操作审计。两位管理员同时操作时，后提交的一方得到冲突提示，不会静默覆盖。
- F6 新登记的插件默认停用。
- F7 查看列表与修改状态分别受两个后台权限控制；没有权限的账号看不到入口，直接访问接口被拒绝。

生效（R1、R3）：

- F8 插件停用时，它的所有接口一律拒绝，并返回可识别的「功能插件未启用」原因。
- F9 插件停用时，不受理它的新后台任务（新建、重试、继续都拒绝）；停用操作会取消它尚未结束的任务；已排队但尚未取消完成的任务不会被执行。
- F10 插件停用不删除、不修改它的任何数据；重新启用后数据原样可用。
- F11 插件停用时，前端不显示它的导航入口；直接访问它的页面地址会看到「未启用」提示而不是空白或报错。
- F12 管理员启停后，其他已登录用户的界面在 30 秒内（或切回页面时）跟上最新状态；服务端的拒绝不依赖前端是否已同步。
- F13 双实例部署下，在一个实例上启停，另一个实例的下一次请求即按新状态处理。

不变（R3、R7）：

- F14 没有任何插件启用时，核心功能的接口、任务、页面、导航与引入框架前一致。
- F15 现有「MCP 插件」的名称、页面、接口不变；新页面叫「功能插件」。

## Acceptance Criteria

用一个只存在于测试里的「示例插件」验证（它贡献一个接口、一种后台任务、一个作品内页面和一个导航入口）。

- [x] AC1 有查看权限的管理员能在「功能插件」页看到示例插件的名称、简介、版本和「已停用」状态；无权限账号访问列表接口得到 403，界面上没有入口。（F4、F6、F7）
- [x] AC2 示例插件未启用时：它的接口返回 403 且带「未启用」原因码；创建它的后台任务被拒绝；导航里没有它；直接打开它的页面地址显示「未启用」提示。（F6、F8、F9、F11）
- [x] AC3 有修改权限的管理员启用后：接口可用、任务可受理并能跑完、导航出现、页面可打开；操作日志里有一条启用记录。（F5、F8、F9、F11）
- [x] AC4 只有查看权限的管理员尝试启用得到 403，状态不变。（F7）
- [x] AC5 两个管理员基于同一版本先后提交状态变更，后者得到 409，状态以前者为准。（F5）
- [x] AC6 示例插件有一个运行中的任务和一个排队中的任务时停用：两个任务都以「已取消」结束，没有被执行完；插件此前写入的数据行原样存在。（F9、F10）
- [x] AC7 停用后重新启用，此前的数据仍可通过接口读到。（F10）
- [x] AC8 两个共享同一数据库的应用实例：在 A 上启用，B 的下一次接口请求即成功；在 A 上停用，B 的下一次请求即被拒绝。（F13）
- [x] AC9 已登录的普通用户不刷新页面，在管理员启用后 30 秒内导航出现示例插件入口；停用后同样消失。（F12）
- [x] AC10 两个插件使用相同标识，或某插件的任务类型与核心类型冲突时，应用启动失败并指出冲突项。（F2）
- [x] AC11 不登记任何插件时，后端与前端的现有全量测试通过，导航与路由和改动前一致。（F14）
- [x] AC12 「MCP 插件」页面、路由 `/mcp-plugins`、接口 `/api/v1/mcp-plugins` 无变化。（F15）
- [x] AC13 根目录 README 增加「功能插件」的功能说明与管理员操作说明；`.trellis/spec/` 增加后端与前端的插件框架规范并登记到索引。（R6）

## Out of Scope

- 任何真实插件（短剧在 `11-27-short-drama-plugin`）。
- 插件贡献智能体工具、作品备份规则、开放 API 接口、后台权限动作：这些接入点等第一个真实插件需要时，在该插件的子任务里连同框架一起补，
  不预先设计用不到的接入点。
- 卸载插件、清除插件数据。
- 父任务 Out of Scope 列出的各项。
