# 功能插件体系（内置模块 + 管理员启用）

> 父任务：只承载共同需求、任务地图、跨子任务验收和最终集成评审，不直接作为实现目标。

## Goal

让平台可以用「功能插件」的方式增加完整的可选功能，每个插件自带页面、入口、数据和 AI 能力，
由管理员决定本实例是否启用；核心小说功能不因此继续膨胀。第一个插件是短剧：把小说改编成短剧，
从剧本一直做到视频成片，并提供一块无限创作画布。

## 决定记录

均为用户在 2026-11-27 的规划对话中明确选定。

| 编号 | 决定 | 内容 |
| --- | --- | --- |
| D1 | 插件形态 | 带前端页面的完整功能模块（如短剧插件、角色增强插件），不是纯资源包 |
| D2 | 交付方式 | 插件代码随版本内置（后端模块 + 前端页面），不做运行时上传安装包，不在运行时加载外部代码 |
| D3 | 谁能管理 | 只有管理员可以启用 / 停用；普通作者不能 |
| D4 | 命名 | 新概念叫「功能插件」，具体插件叫「短剧插件」；现有「MCP 插件」的名称、页面、文档都不改 |
| D5 | 停用语义 | 保留数据，只关入口：页面、导航、接口、后台任务都不可用，正在运行的任务被取消；重新启用后数据全部恢复；不提供一键清除 |
| D6 | 启用粒度 | 只有全站开关；不做按角色授权，也不做按作品开启 |
| D7 | 默认状态 | 新插件默认停用，管理员手动启用后才生效 |
| D8 | 范围 | 插件框架 + 短剧插件 + `/developers` 插件开发指南，一次交付，不分期 |
| D9 | 短剧范围 | 对齐参考项目 `ai-drama-workshop` 的全流程：小说 → 剧本 → 资产 → 生图 → 分镜 → 生视频 → 成片导出 |
| D10 | 画布 | 无限创作画布：自由摆放文本、图片、视频节点，连线表示把上游内容作为下游生成的参考 |
| D11 | 画布与流水线 | 并存；画布属于某一部剧，可引用剧里的资产与分镜，也可把生成结果存回资产或分镜 |
| D12 | 与小说设定的关系 | 短剧的角色、场景、道具独立保存；提取时匹配小说同名角色和地点带入初值并记下关联；改动不回写小说 |
| D13 | 媒体存储 | 默认本地目录，部署者可改配 S3 兼容对象存储；两套都要实现并验证 |
| D14 | 视频厂商 | 第一批四家：火山引擎 Seedance、OpenAI 兼容视频接口、MiniMax、阿里云百炼 Wan |
| D15 | 开发文档 | `/developers` 写完整的插件开发指南，面向在本仓库内开发插件的开发者，以短剧插件为例 |

## 任务地图

| 顺序 | 子任务 | 交付 | 依赖 |
| --- | --- | --- | --- |
| 1 | `11-27-plugin-framework` 插件框架 | 插件清单与登记、管理员启停、后端与前端入口按启用状态生效 | 无 |
| 2 | `11-27-media-storage` 媒体文件存储（核心能力） | 图片、视频等大文件的统一存储、访问、清理与备份边界 | 无 |

| 4 | `11-27-short-drama-plugin` 短剧：剧本与分镜（文本段） | 按章节建集、改写剧本、提取资产、拆分镜、生成提示词 | 1 |
| 5 | `11-27-short-drama-media` 短剧：生图、生视频与成片导出 | 资产图、分镜视频、FFmpeg 拼接导出 | 2、3、4 |
| 6 | `11-27-drama-canvas` 短剧：无限创作画布 | 文本 / 图片 / 视频节点自由摆放、连线生成，可引用并存回剧里的素材 | 1、2、3、4、5 |

- 父子关系不等于依赖关系；上表的依赖同时写在各子任务的 `prd.md` 里。
- 子任务 1 与 2 互不依赖，可以并行。
- 子任务 2、3 是核心能力而不是插件的一部分：停用短剧后它们仍然存在，将来其他插件也会用到。
- 范围是一次交付（D8），但实现按上表顺序推进，每个子任务独立规划、独立验收、独立归档。
- 规划深度：子任务 1 现在就写完 `design.md` 与 `implement.md`；其余子任务现在只定需求与验收，
  技术设计在轮到它、其依赖已落地时再写，因为它们的设计取决于前序子任务的真实契约。

## 共同需求

- R1 所有插件相关的后端入口（接口、后台任务）都必须在服务端按持久化的启用状态判定，前端显隐只是体验，不是权限边界。
- R2 插件不得绕过框架直接改核心的路由表、导航或任务登记；核心代码里不出现针对具体插件的分支。
- R3 停用任何插件后，核心小说功能的行为与未引入插件体系前一致。
- R4 插件产生的、与作品相关的数据必须在作品备份登记表中有明确规则（导出或不导出），并随作品删除、回收站流程一并处理。
- R5 插件遵守现有的多用户约束：数据归属校验、协作者权限、AI 用量与费用记录、预算、审计。
- R6 功能增改须同步根目录 README 与 `.trellis/spec/`（项目既有质量规范）。
- R7 现有「MCP 插件」的名称、页面、接口、文档保持不变。

## Acceptance Criteria（跨子任务集成验收）

- [ ] 全新实例升级到本版本后，短剧插件默认停用：作者看不到短剧入口，短剧接口返回「未启用」，核心功能全量测试通过。
- [ ] 管理员启用短剧插件后，作者可以在一部作品里完成：按章节建集 → 生成剧本 → 提取角色 / 场景 / 道具 → 生成资产图 →
      拆分镜 → 逐镜生成视频 → 拼接导出并下载成片。
- [ ] 作者可以在该剧的画布里放置文本、图片、视频节点并连线生成，把剧里的资产拖入画布，再把画布生成的结果存回资产或分镜。
- [ ] 管理员停用短剧插件后：短剧的页面、导航、接口、后台任务均不可用，运行中的短剧任务被取消；
      小说数据与核心功能不受影响；重新启用后此前的剧、剧本、分镜、图片、视频全部仍在。
- [ ] 双实例部署下，在一个实例上启停插件，另一个实例的下一次请求即按新状态处理；两种媒体存储（本地共享卷、对象存储）下媒体在两个实例都可访问。
- [ ] 含短剧数据的作品可以导出备份并在另一实例导入；作品进回收站、恢复、彻底删除时短剧数据与媒体文件一并处理。
- [ ] `/developers` 页面的插件开发指南与实际代码一致：按指南步骤可以新增一个最小插件并在后台看到它。
- [ ] 现有「MCP 插件」页面与功能无变化。

## 已核实的现状（代码证据）

插件接入点：

- 接口路由在 `backend/app/api/v1/__init__.py` 里逐个 `include_router`，共 66 处，应用装配在 `backend/app/main.py:273`。
- 后台任务处理器靠进程内注册表登记（`backend/app/services/task_engine/registry.py:90`），各处理器模块在导入时调用 `register(...)`；
  `TASK_KINDS`（`backend/app/models/entities.py:61`）只是一份清单，不是数据库约束，仅管理端用来把未知类型显示为 `unknown`
  （`backend/app/services/admin_task_service.py:71`）。
- 智能体工具同样是写死的注册表（`backend/app/services/agent/tools/__init__.py:13`）。
- 前端在镜像构建时打成一个静态包，由后端托管；运行时没有加载外部脚本的机制（`Dockerfile:1`、`backend/app/main.py:86`）。
- 前端路由是一份静态表，页面用 `lazyPage` 按需加载；作品内页面集中在 `projects/:pid` 之下（`frontend/src/router.tsx:20`、`:119`）。
- 导航集中定义在 `frontend/src/components/StudioNavigation.tsx:65`，其中已有按 `mcpEnabled` 隐藏「MCP 插件」入口的先例（`:69`）。
- 管理页挂在 `admin/*` 路由下并用 `RequirePermission` 守卫（`frontend/src/router.tsx:65`、`frontend/src/components/RequirePermission.tsx`），
  管理导航入口在 `frontend/src/components/AppLayout.tsx:132`。

启用开关：

- 实例级开关已有成熟做法：`system_settings` 单行 + 稀疏覆盖 + 修订号 + 同事务审计，保存后跨进程通知重读
  （`.trellis/spec/backend/system-settings.md`）。它是固定七项白名单，不适合直接塞入插件状态。
- 关键入口不读进程缓存，而是在自己的事务里读持久值：任务受理处调用 `require_task_admission_open(db)`
  （`backend/app/services/task_service.py:547`、`:758`），MCP 的入口、写入、出站三处各自核对（`backend/app/services/mcp/settings_gate.py`）。
- 公开配置接口 `GET /api/v1/auth/config` 目前下发 `registration_enabled`、`mcp_enabled` 两项，`no-store`
  （`backend/app/api/v1/auth.py:27`）；前端 `PublicConfigController` 可见时每 30 秒同步、切回前台立即同步
  （`frontend/src/utils/publicConfig.ts:6`、`frontend/src/stores/auth.ts:32`）。
- 后台权限动作集中在 `backend/app/core/permissions.py:15`（38 个），超级管理员自动拥有全部（`:59`）；
  管理操作走 `require_permission(...)`（`backend/app/api/v1/admin_system_settings.py:11`）并写审计（动作清单在 `backend/app/schemas/audit.py:52`）。
- 管理端已有持久取消受理 `admin_task_service.cancel_task`（`backend/app/services/admin_task_service.py:197`）。

数据与备份：

- 数据库迁移是一条线性链，当前到 `0079`（`backend/alembic/versions/`）。内置模块的表随核心迁移一起建，停用插件时表仍然存在。
- 作品备份靠表规则注册表，任何与作品相关的新表都必须登记为导出规则或写入 `NOT_EXPORTED`，否则反射测试失败；
  当前格式 v18（`backend/app/services/project_transfer/registry.py:103`、`:199`）。
- 部署形态支持双实例（`docker-compose.multi.yml`），运行时写到单个实例磁盘上的文件不会自动出现在另一个实例。

现有的资源类扩展（供将来「插件附带资源」参考，本期不做）：

- 全局技能已存在（`owner_user_id` 为空，`backend/app/models/skills_mcp.py:26`），有 5 个 `global_skills.*` 权限动作；
  全局技能不能引用提示词组件（`backend/app/services/skill_service.py:53`）。
- 写作风格的全站层只有代码内置预设（`backend/app/services/style_service.py:316`）；提示词组件与模板覆盖只属于个人
  （`backend/app/models/prompt_components.py:12`、`backend/app/models/entities.py:1049`）。

短剧与媒体的调研依据：`11-27-short-drama-plugin/research/reference-drama-pipeline.md`、
`11-27-short-drama-plugin/research/reference-media-infra-and-gap.md`。

## Out of Scope

- 运行时上传安装包、运行时加载外部前后端代码、第三方插件分发与市场。
- 普通作者安装或启停插件；按角色授权插件；按作品开启插件。
- 一键清除某个插件的全部数据。
- 插件附带全局资源（技能、写作风格、提示词组件、模板覆盖、MCP 目录项）。
- 事件钩子（章节定稿、任务结束等触发）。
- 角色增强插件（用户举过的例子，本期只做短剧）。
- 语音、音乐模型，字幕、混音、转场（参考项目的短剧流水线不使用）。
- 参考项目的 MV、UGC 视频、工具中心、电商套图、Seedance 素材库、桌面版。
