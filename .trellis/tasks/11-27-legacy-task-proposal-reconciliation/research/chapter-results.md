# 旧章节隔离验证

## 环境与比较方法

[演练控制器](chapter_drill.py) 分别从 Git 导出旧版 `4501f18d`（0043）和新版 `ac97d4de`（0079）的后端，安装各自锁定依赖。旧库由旧应用真实 HTTP 请求造数。SQLite 使用独立临时文件，PostgreSQL 使用私有临时容器的独立库。作者、作品及模型均为虚构数据，假模型仅监听本机。相同的非空正文分别设置为草稿和已完成，说明内容本身无法判断原状态。

作者先保存正文、场景和一个手动历史版本，记录版本修订号、场景／历史摘要和状态。整章生成真实进入模型调用后，让模型停在输出前，强制终止专属旧进程，确认进程组已空、监听已关闭、流已断开，再做冷快照。每个场景从独立副本开始，先核对 0043 的持久状态再升级。排队反例在旧版仅允许一项在途执行时制作在线快照，迁移前的克隆须包含前置运行章和仍在排队的目标章。

正文比较涵盖标题、正文、字数及修订号。生成前后跨版本比较场景与历史的共有业务字段；复位前后和重启复读还比较所有场景行、历史行、原任务行和工作记录行的全部列摘要。应用正常产生的审计及运行记录不在这些“不变”断言内。

## 双库实测结果

| 旧状态与副本 | SQLite | PostgreSQL 16.15 |
| --- | --- | --- |
| 已排空的 0043 对照 | 升级后仍 done，正文基线一致，任务数 0 | 相同 |
| 真实排队章 | 克隆中核实 queued；管理员取消 202，12 秒后仍 queued，重启再等 3 秒仍 generating、取消号保留 | 相同 |
| 中断章，缺生成前状态证明 | 保持 generating；复位请求 0，重启复读相符 | 相同 |
| 原状态为 draft 的中断章 | 满足下节额外夹具证据后，作者仅提交 status 得 200；重启再等 3 秒仍 draft | 相同 |
| 原状态为 done 的中断章 | 同条件下返回 200，重启再等 3 秒仍 done | 相同 |
| 已有后继新占用 | 在独立副本按条件恢复后，新一轮生成取得新的占用键并进入假模型。维护判定停止，对该新占用复位请求 0；放行模型后新任务 succeeded | 相同 |

四个复位正例的原任务都留在 interrupted，正文修订号、正文摘要、场景行、历史版本行、原任务行和项目失败记录摘要分别与各自操作前一致；复位到独立重启复读之间没有模型调用。复位通过登录作者的真实 HTTP PATCH 完成，未验证浏览器能为未知来源的章节提供入口。检查窗口为重启后 3 秒，不能据此证明任意长时间都没有变化。

详情见 [SQLite 草稿](chapter-sqlite-draft-final.jsonl)、[PostgreSQL 草稿](chapter-postgres-draft-final.jsonl)、[SQLite 已完成与反例](chapter-sqlite-done-final.jsonl)、[PostgreSQL 已完成与反例](chapter-postgres-done-final.jsonl)。日志首项记录控制器和 C8 脚本摘要，快照项记录大小和 SHA-256。临时库与快照在完成后清理，脚本可从相同提交重新造数。

## 现场与隔离副本的界限

在专属旧进程实际被终止的情况下，新版接管仍可能留下项目级 `abort_failure / failed`。该记录内的任务 ID、任务键、执行键、工作者、操作号与证据均为空，旧任务行却保留了**接管者**的工作者键。它不能证明旧执行体身份或安全收尾。原门禁在该状态拒绝复位；项目失败标记必须原样保留，项目删除等需要通过清理屏障的操作仍可能受阻。

隔离实验能进一步验证章节字段，是因为控制器额外掌握以下现场通常缺少的事实。

- 专属库全库只有一条任务，该任务已中断且执行键、管理员取消意图为空。全库执行槽为空，同章和同串行／资源键无其他任务，章节三个占用字段均为空。
- 旧应用和假模型的连接已退出，阻塞屏障没有释放过任何模型输出；旧部署没有其他写入方。首次接管进程已完全退出，核对其 PID 对应工作者的停止时间、端口和进程组。随后启动独立维护进程复核原任务和失败记录。
- 已有生成前同一章节的独立基线；正文、修订、场景、历史仍相符。被保留的唯一工作记录恰为上述失败记录且摘要稳定。人工复位没有请求清理、取消、重试旧任务或清除该记录。

这些条件用于解释隔离结果。线上若只有中断标签、失败标记、过期心跳或相同正文，仍应停在只读核对，保留升级前快照与现库；不要用本演练脚本或作者状态接口试探线上章节。即使复位章节成功，也不能由此放开项目清理或宣告任务已收尾。

早期迭代曾因登录客户端重复进入而中止，随后发现冷库接管会留下项目级失败记录。早期另一轮没有锁住排队在线快照的时间差，出现意外模型请求，未用作双库比较。最终控制器限制旧队列并发为 1，恢复到各独立副本后再次直接比对任务行，确认造数正确后才迁移。

## 复跑

在仓库根目录分别指定数据库和生成前状态。done 轮次另含排空对照、旧在线排队、缺少基线及真实新占用的停止判定。每次启动会创建全新临时资源。

```sh
probe=.trellis/tasks/11-27-legacy-task-proposal-reconciliation/research/chapter_drill.py
backend/.venv/bin/python -B "$probe" sqlite --original-status draft
backend/.venv/bin/python -B "$probe" postgres --original-status draft
backend/.venv/bin/python -B "$probe" sqlite --original-status done
backend/.venv/bin/python -B "$probe" postgres --original-status done
```
