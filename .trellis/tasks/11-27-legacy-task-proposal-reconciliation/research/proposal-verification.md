# 旧智能体提案的双库核对

## 复现场景

从 Git 导出旧应用 4501f18（0043）和目标应用 ac97d4d（0079），分别按自己的 uv.lock 创建隔离环境。旧应用正常注册作者、建立作品与会话，在回环地址的假模型返回 create_character 工具调用后生成一条待审核提案。此时唯一任务 paused，角色表为空。造数及业务动作均通过真实 HTTP 接口，核对程序只读库。SQLite 使用独立文件；PostgreSQL 使用专属 16.15 容器及 tmpfs 数据目录。

停止旧进程后制作待审核快照。第一条路径在该快照的独立 0043 副本取消旧任务，核对操作后停服，另取“已取消”快照，再恢复到空目标升级。第二条路径将原待审核快照直接恢复到另一空目标升级，再取消任务并发送新的纯文本消息。每条路径都重启自己的新版应用，重新登录作者账号读取原会话。

## 怎么认定原提案仍完整

- 从旧库运行时读取 agent_changes 的实际列清单，逐列比对原行全部 18 列。包含提案、会话、作品、原任务的整数 ID，工具调用 ID、工具名、参数、类型、完整预览、状态、结果、效果、错误、执行和撤销时间、序号、创建和更新时间。保存初始逐字段摘要和各观察点全行摘要，原始参数及预览不进入日志。两种引擎分别与自己的 0043 基线比较。
- 0079 单列检查新增的三个字段。change_key 须为 UUID v4 且在同一迁移副本直至重启保持不变。turn_task_key 和 external_worker_key 须为空。各副本独立迁移时分配不同的 change_key，因此不能拿它跨副本关联历史。
- 单独检查角色表与任务清单。这个工具提案的预期业务效果是创建角色。即使提案状态为 proposed，也必须观察角色数、任务数量和状态、模型请求数与是否出现意外模型请求。确认和拒绝请求使用实际会话投影提供的提案标识和预览版本。
- 核对停留在原维护权限内。新版作者会话仍显示原提案；对缺失稳定轮次键的提案，公开响应隐藏 turn_task_id，数据库保留旧整数值。不能据此把旧整数复制成轮次键。

## 双库实测结果

| 真实快照与操作 | SQLite 与 PostgreSQL 的共同结果 |
| --- | --- |
| 旧版取消后正常停服，再恢复快照并升级 | 0043 取消返回 200，原任务 cancelled；实际提交单项确认、拒绝均返回 409。升级后再提交仍均返回 409。重启新版再查，原提案 proposed，18 列与最初 paused 时逐项相等，任务只有原任务，角色 0。 |
| 旧版 paused 快照直接升级，在新版取消 | 新版取消返回 200；原任务 cancelled，单项确认、拒绝均返回 409。此时只有旧版创建提案时的一次模型调用。 |
| 在上一场景明确新发同会话消息，再重启 | 新任务 202 受理后 succeeded，多一次预期模型调用；原任务仍 cancelled，原提案仍是唯一提案。重启后 18 个旧字段相等，原稳定提案键与同一副本迁移时相同，角色 0。 |

最终脚本 SHA-256 为 `1fa27255b21f98602ef7d7e5083c611bc109d4b65afc0d6a22d863cf7c7a7c82`，两次退出码均为 0。SQLite 用时 117.089 秒，PostgreSQL 用时 129.997 秒，均含清理。每库 11 次逐行核对、2 次重启后复读；临时目录已删除，PG 专属容器经查已移除。

两个库各有 2 次预期假模型请求（最初提案一次、主动新消息一次），意外请求均为 0。角色表在每个检查点均为空。原提案可以原样留存，并在维护记录注明“仍未决、本次不执行”。产品内的后续业务应以用户当前意图和新的预览为依据。

适用范围限于本地单应用实例、正常停服的两份 0043 来源快照、作者本人及一个创建角色的内建工具。两条取消路径各用独立副本；同一副本内按顺序做确认、拒绝，两次均被拒。此次从 HTTP 接口操作，旧页面按钮的观察沿用 C8 网页复核。上述检查覆盖原提案整行及对应的创建角色效果；外部插件、其他工具、同轮多提案和生产数据须分别核实其目标或外部回执。单看 proposed 无法断定外部系统是否执行过。

## 复跑

在项目根目录执行，先准备本地 Python 3.12、uv、backend/.venv，以及已缓存的 postgres:16-alpine 镜像。每条命令只使用临时数据和测试账号。

```sh
backend/.venv/bin/python .trellis/tasks/11-27-legacy-task-proposal-reconciliation/research/proposal_drill.py --shape sqlite
backend/.venv/bin/python .trellis/tasks/11-27-legacy-task-proposal-reconciliation/research/proposal_drill.py --shape postgres
```
