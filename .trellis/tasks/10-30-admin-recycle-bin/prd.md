# 作品回收站与误删恢复

## 建档状态

优先级：P0。状态：`planning`，待细化的功能需求草案。

来源：2026-10-30 管理员功能缺口盘点。用户要求将清单中的 8 项功能分别创建独立任务，本轮仅完成建档；具体产品取舍与实施方案尚未确认。

## 目标与用户价值

降低作品误删造成的数据损失，让管理员能够在约定保留期内恢复作品及其关联内容。

## 已确认现状

- `backend/app/services/project_service.py::delete_project` 当前直接删除作品；`backend/app/services/admin_service.py::delete_user` 通过外键级联永久删除关联数据。

- 项目备份和章节版本已经存在，但章节版本随项目删除，不能替代作品级误删恢复。

## 初步需求

1. 提供作品删除保留、管理员回收站、恢复、彻底删除和到期清理能力，展示作品名称、所属用户、删除时间及可恢复状态。

2. 回收站中的作品不再出现在正常书架、管理目录和开放 API 中，普通读取、编辑及新任务入口遵循删除后的访问规则。

3. 恢复时保持正文、设定、版本、封面等约定关联数据的一致性；明确运行中任务、已删除所有者和关联资源缺失的处理方式。

4. 明确删号是否保留作品及如何恢复；该策略未确认前，不将作品软删除视为已解决用户误删。

## 验收标准（草案）

- [ ] AC1：删除作品后，正常列表和直接访问均按约定隐藏/拒绝，管理员能在回收站识别目标及归属。

- [ ] AC2：在保留期内恢复后，正文、设定、版本及约定关联数据可正常使用，其他用户和作品数据不受影响。

- [ ] AC3：取消恢复或彻底删除操作不会产生相应写入；彻底删除需明确确认并清理目标关联数据。

- [ ] AC4：保留期边界、重复恢复、已清理记录及所有者已删除场景具有明确结果。

- [ ] AC5：运行中任务、删除期间访问及到期清理不会造成内容重新出现或跨用户越权。

## 范围边界

- 整个平台数据库备份和历史时间点恢复。

- 默认扩展成用户、章节、设定等全部实体的通用回收站。

## 待确认项

- 保留天数、清理时机与普通用户是否拥有恢复入口。

- 用户删除时采用保留、阻止删除还是永久清理作品，以及运行中任务的取消策略。

## 关联与先后顺序

- 与管理员操作日志协作记录删除、恢复和清理动作；与备份管理分别解决误删恢复和灾难恢复。

本任务独立规划、实施、验收和归档；以上关联不代表已经建立执行依赖。涉及产品决策的取舍，在后续规划中确认。
