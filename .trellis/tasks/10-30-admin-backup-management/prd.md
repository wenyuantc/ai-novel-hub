# 管理员备份管理

## 建档状态

优先级：P2。状态：`planning`，待细化的功能需求草案。

来源：2026-10-30 管理员功能缺口盘点。用户要求将清单中的 8 项功能分别创建独立任务，本轮仅完成建档；具体产品取舍与实施方案尚未确认。

## 目标与用户价值

让平台维护者了解最近可用备份及失败情况，降低依赖手工备份造成的数据恢复风险。

## 已确认现状

- `README.md` 的“运维与数据备份”已说明作品 JSON 备份、PostgreSQL 命令行备份及恢复；作品备份不包含账户与模型凭据等平台数据。

- 数据库恢复需要配套原始加密配置；现有后台没有定时备份、备份记录和失败提醒管理入口。

## 初步需求

1. 提供约定备份类型的计划、执行状态、开始/结束时间、结果、大小和错误摘要，能够识别最近成功备份。

2. 支持定时执行、失败提醒与约定保留清理策略，防止同一实例内重复执行导致状态混乱。

3. 展示恢复所需条件与操作指引；区分备份状态管理与下载/恢复数据库的高权限能力，不能隐式扩展普通内容管理权限。

4. 明确备份文件及加密配置的存放与保护方式，页面、日志和错误摘要不泄露数据库凭据或用户密钥。

## 验收标准（草案）

- [ ] AC1：计划按配置触发，成功和失败均有独立执行记录，重启后仍可查看约定保留的结果。

- [ ] AC2：最近成功备份和最近失败可区分，失败时通过约定渠道提醒且不误报为成功。

- [ ] AC3：并发或重复触发、过期清理、存储不可用及备份中断均有明确结果。

- [ ] AC4：在隔离环境验证选定备份可用于恢复；作品备份与整库备份的覆盖范围在界面和说明中一致。

- [ ] AC5：备份管理、文件访问和恢复权限分别符合最终确认的边界，不向普通用户或未授权管理员开放敏感备份。

## 范围边界

- 默认提供线上整库一键覆盖恢复、跨区域容灾或数据库集群。

- 替代作品回收站及替管理员在聊天中执行实际生产备份/恢复。

## 待确认项

- 首期备份类型、存储位置、执行频率、保留策略与失败通知渠道。

- 哪些管理角色可查看结果、下载备份或发起恢复，以及备份文件的加密方式。

## 关联与先后顺序

- 备份与回收站独立；与系统设置协作保存计划，与权限分级协作定义敏感备份访问边界，实施前明确是否存在硬依赖。

本任务独立规划、实施、验收和归档；以上关联不代表已经建立执行依赖。涉及产品决策的取舍，在后续规划中确认。
