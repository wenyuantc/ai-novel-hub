# 模型配置实例与两段受理复核

## 真实缺口与修复

- SQLite 真实账号配置 API 删除最高整数 ID 后重建可复用 ID。API 正常重建会重新加密密钥，但相同 ID、密文、创建与修改时间及其他字段的恢复/复制反例证明仅靠旧字段指纹无法识别不同实例。配置现在另用不可变的 `instance_key` UUIDv4 识别实例；v2 模型绑定同时核对 ID、实例键和原指纹，v1 或缺实例证据的任务不能从当前配置补签。0049 迁移、数据库约束与触发器由迁移分工负责。
- 文本和图片的新任务只读预检使用独立短会话、单条 SELECT 冻结原 actor/token、项目、原协作授权、本人优先/作者回退及模型实例；不取写锁或配置选择门禁，短会话关闭后才做 provider/DNS 检验。锁内沿 User → visibility → Project → 用户 ID 排序的配置选择门禁重新选择并比较完整绑定，变化即回滚。显式配置只能是本人配置，损坏配置不能换钥匙。
- 原任务重试采用已注册的 `RetrySource`，以单条 SELECT 同时读真实任务、授权及原配置；比较 UUID、队列时间、原输入/断点/游标、原 token、grant、实例键和指纹，不按当前默认重新选择。预检凭据绑定同一来源对象，DNS 前和锁内都不可挪用于其他任务。锁内必须先证明一次性消费凭据在同 session、协程、根事务和物理连接，并锁原 Task；随后锁定并重验原配置，凭据使用后失效。本人配置和作者回退都须使用原任务模式，不能用普通新任务模式跳过原 Task 的证明。
- 预检和模型快照是进程内私有对象，不含明文密钥，不能作为发送证明。真实发送仍须使用受控 provider 和物理发送 lease；本模块不开放协作者 AI 入口。原作者模型具体信息不得写入公共响应或日志。
- 共享向量空间升级为 `shared:v2`，把配置实例键纳入空间身份；旧 `shared:v1` 不是已证实共享空间，应关键词召回或重建。作者历史 `provider:model` 索引保留作者旧路径，不能充当共享 v2 空间。

## 验证与边界

- SQLite 先验证预检未实现的重试反例，再验证后来新增本人默认仍沿用原作者绑定；Task 输入/UUID/状态、token、grant、配置字段变化以及同 ID 同密文的新实例均失败关闭。单 SQL 和预检伪造对象、跨任务来源、一次性 proof 重复使用也有覆盖。模型预检及原绑定相关组合 75 passed；之后补充本人默认变更、本人内网提示与作者回退脱敏的定向回归 3 passed。
- 早期四项 PostgreSQL 两连接测试曾通过（55.56 秒）；此后代码与严格校验有变化。最终五项位于 `backend/tests/test_project_model_preflight_postgresql.py`，新增原任务重试等待配置写事务后拒绝变化；由主会话在隔离数据库中错峰运行，最终结果以其报告为准。
- 同 ID 的完整整库快照恢复会保留原实例键，因此不能单凭数据库内 UUID 证明回滚前后的全局时序。上线迁移/降级须排空旧服务与执行器；涉及备份恢复和历史实例防重放需运维恢复边界或外部代次，不能悄悄以当前配置重签旧任务。0049 降级依赖扫描与许可范围以迁移分工的最终报告为准。
