# E1/E2 实体 AI 接线记录

本切片覆盖 `character.generate`、`organization.generate`、`career.generate`、`relations.parse` 和
`relations.generate` 的作者任务。协作者入口继续由服务端拒绝；本记录不表示 E1/E2 已完成。

## 已实现的作者路径

- 创建任务时由服务端固定文本模型 `_project_model` 和共享检索选择 `_shared_embedding`，包括原配置
  instance UUID、来源、指纹和 vector/keyword 决策。客户端同名字段不参与绑定；重试复用并复核原选择，
  不因默认模型变化换模型。配置被编辑、删除或以相同整数 ID 和字段重建时旧绑定失败关闭。
- 五个作者入口均在释放请求只读事务后执行中央 `TaskAdmission` 模型预检；认证、项目和配置屏障在受理事务
  中重验并消费同一证明，DNS 不持业务写锁。重试通过原任务 UUID 和原绑定预检，不重新解析默认配置。
- 执行采用领取时冻结的 `TaskExecutionIdentity`；受控模型和向量请求使用同一原 actor、token、任务轮次、
  文本与共享向量选择。知识检索只使用原共享空间；历史 `provider:model` 或其他版本的向量键不能证明同一
  空间，需关键词检索并经安全索引重建后才能使用新空间。
- `EntitySourceSnapshot` 保存原执行与实际选中设定、阶段、成员、关系/类型、知识库注入设置和命中的字段摘要及集合。
  发送前、缓存预检和逐跳 HTTP 出站在同一租约内核对并持来源行锁；输出与结果在写屏障内重验，最终草稿
  使用当前锁定的同书数据重新计算。跨书关系、关系类型、角色和文档不会作为有效引用。
- 模型已发送后，新增、修改或删除同书关系允许重新计算冲突；修改导致跨书、角色对损坏或类型跨书时停止。
  任务结果与正常 done 帧采用终态事务中的同一份重算结果。

## 作者兼容与安全边界

- 历史作者任务的服务端 `ai_config_id` 只能证明旧受理选择了该整数 ID，不能证明当时配置实例、指纹、原 token
  或共享向量空间。缺少可信绑定的旧排队任务不领取；旧任务重试也不会从当前用户或默认配置补签。H4 应先排空
  旧执行体，再对历史任务采取安全取消并由用户重新发起，不能把重试当成新的模型选择。
- 发送后若仅本书关系变化且可见性代次不变，保留原作者重新计算草稿的行为。删除角色会递增可见性代次，
  因此旧流停止，不返回迟到结果。人物、世界、组织和职业的普通字段编辑即使未改变可见性代次，目前也会令
  旧来源快照失效：这些直接参与结果身份的资料没有不可复用实例 UUID，不能从当前同一整数 ID 猜测是否为旧行。
  这是当前兼容差异；中央引擎将该来源失效映射为“设定来源已变化，请重新发起”，真实 HTTP 测试已通过。
  关系和关系类型同样没有不可复用实例 UUID；此处仅把原值作为已发送的授权上下文，响应后
  的结果引用由当前同书角色对和类型重新校验，不宣称证明历史行未被全形重建。
- `get_owned_project` 和中央任务受理仍限定作者；编辑者真实 actor、原邀请/grant、本人模型优先及作者授权
  回退尚未接通，不能将现有作者 guard 当作协作者入口完成。
- 服务端实体发布和终态采用原执行 guard；公共 ASGI 帧租约已可由测试专用路由验证。**生产任务 SSE 仍走旧
  路由**，协作者 SSE 保持关闭；在运行帧、缓冲帧、终态收据和实际 ASGI send 的同一身份证明全部接通前，
  不应宣称 SSE 协作闭环。测试曾复现终态提交与缓冲帧消费之间的竞态：无权限变化时可能提前返回
  `permission_denied`；中央引擎增加原 hub 终态等待与重验后，测试专用真实 ASGI 路径的运行帧、终态帧和
  发送前 token/模型/来源失效反例 **6 passed**。生产路由切换及其真实端到端回归仍待中央完成。
