# 灵感会话与共享作品：人工应用边界

目标差异：本人独立灵感会话应用到共享作品时，现有 `apply_preview` 与 `apply` 仍使用严格作者 helper；查看者无法预览、编辑者无法人工保存。权限应落在 `inspiration_service`，先校验会话本人，再对目标作品分别检查 `content.read` / 锁后的 `content.edit`，并保留作品响应投影和授权前无 autoflush。

本切片修改 `backend/app/services/inspiration_service.py` 的人工预览与应用及相应专用测试，不改变个人会话所有权、作者旧行为或其他服务。`from_project` 会把作品内容带入持久个人会话，后续生成还涉及模型、共享向量、流帧和重邀；其完整接入需要单独绑定原协作身份并贯穿所有会话入口。本切片不提前开放该路径，避免绕过撤权和 `ai.use`。最终仍需单独完成和验证该关联会话链，不能将此人工切片视为 Gate D/E 完成。

## 验证

先以真实 HTTP 复现协作者预览被错误拒绝和授权前可能刷新待写内容；管理员应用新增真实审计反例也先失败。修复后 `tests/test_collaboration_inspiration_manual.py` 与 `tests/test_inspiration.py` 在 SQLite 共 **29 passed in 23.15s**，含本人会话、角色矩阵、管理员审计脱敏和拒绝前无 autoflush。隔离 PostgreSQL 16.15 上 `tests/test_collaboration_inspiration_manual_postgresql.py` **2 passed in 7.43s**，验证撤权或降级先提交后旧写入被父行锁内拒绝。阶段结果不覆盖关联作品的灵感 AI，也不代表 D/E 门禁完成。

## 关联作品会话的后续切片

共享作品发起的会话会持久化作品字段，因此需要将本人会话与原邀请分开保存：计划新增仅服务端使用的 `inspiration_origins`，记录原作品 ID、邀请 UUID 和不可复用的会话来源 UUID。作品彻删时来源记录不能随作品消失，否则外键置空后的旧会话会被误当成普通私人会话；删除会话时来源随之删除。查看和列出时验证本人、作品生命周期及原邀请仍 accepted；同一邀请下角色变更保留阅读，撤销后重新邀请不得使旧会话复活。管理员人工读取权限不能旁路私人会话的原协作授权。

从共享作品创建是人工读取，viewer 可创建/查看自己的会话，但生成必须单独检查 `ai.use`。关联会话应用到其他作品时需按作品 ID 稳定顺序锁定原作品和目标作品，防止交叉应用死锁。协作生成暂保持服务端失败关闭，待文本模型和共享知识检索、每次真实发送、ASGI 输出和保存的原身份链完整后再开放；不会以私人会话之名跳过 viewer 禁 AI。新表不随单书备份，存在来源行时不能降级到没有来源验证的旧代码。
