# 阶段 G：前端协作集成复核

## 范围和本轮修正

- 作品与系列响应的授权版本用于区分同账号重新邀请后的不同作用域；普通未变授权刷新保留草稿。作品、系列操作均仍以服务端逐次授权为准，客户端未获知远端变化前不声称能实时清除旧数据。
- 独立阅读器不依赖作品 store：非作者加载目录或章节后再读取当前作品能力，比较 actor 可读能力、授权轮次和相关界面能力；轮次或会话变化时拒绝旧结果并关闭当前阅读会话。作者仍沿原路径读取；只有作者上报阅读进度。
- 书架在展示、继续创作与统计前过滤缺失、矛盾或不可读的能力快照；卡片自身也不渲染无法证明读取能力的作品。`ProjectAccess` 的角色与协作标记必须一致，管理员兼查看者的人工编辑能力仍以服务端布尔值为准。
- 系列数据读取若在处理响应时发现授权版本变化，不再把该结果交给旧加载器；新作用域重新读取。系列条目删除仍按服务端 `has_uses`，而非过滤后的 `uses` 推断。
- 场景与关系保存若在授权变化后仍有编辑权，保留草稿并阻断旧回调；已发送写请求遇到网络、超时、服务器或响应解析故障时，不能推断是否提交，须读取事实、显式核对后才允许重提。写入前本地校验失败和明确的 4xx 拒绝不伪称结果未知。富文档草稿的结构与身份映射保护保持不变。

## 403/404 作品事实复查与草稿保护

- 网络层在业务请求发出前捕获 actor、会话代次、项目和授权作用域；当前作品请求收到 403（包括 `project_readonly`）或 404 时只复读作品详情，不重放业务。作品详情读取本身不触发递归；旧授权轮次的 401/403 也不能触发后来会话的全局处理。子资源缺失时仅由作品详情的明确失权结果清除作品；确认仍可读或复查网络失败时保留现有内容。
- 并发失败复用在途权威读取；读取期间又发生失败或其结果被同作用域写响应覆盖时再确认一次。草稿区共用该读取，首次复查失败不会自动重复查询；用户可手动重查。无法确认时保持提交冻结。
- 不带作品 ID 的 `/chapters/{id}` 请求只有在当前页面路径明确为 `/projects/{pid}/chapters/{id}`、作品和章节均匹配时才能安全绑定；其他页面（例如章节列表与阅读器）没有可靠归属，不猜测目标。账户、系列及管理员全局请求不被套用作品作用域。
- SSE 握手使用发起时的同一作用域；任务流仅在初始任务 `project_id` 与当前可证明作品作用域匹配时绑定，并跨重连沿用该作用域。握手 403/404 或流内 `permission_denied` 清除活动任务输出并复查作品；授权轮次变化主动中断本地订阅，不取消后台任务。纯个人和没有当前作品作用域的全局任务继续使用原语义。
- 阅读器独立于作品 store，目录/章节 403/404 会重新核验作品；仍可读或复查网络失败时仅保留原会话并显示子资源错误。章节、授权轮次或会话变化时旧核验不能影响新会话；读到其他章节时不使用旧章节缓存上报进度。
- 卡片导入的首次预览、更新预览和确认导入 403/404 保留已解析文件、预览和映射，整理标签的读取、对照及保存失败保留草稿；两者在确认权限前冻结提交，确认后仍需手动预览/对照。新授权轮次仍可编辑时保留输入并使旧回调失效，撤权、失读、账户或会话变化时清除。导入在途被打断或网络结果未知时明确提示先核对，不自动重发。

## Agent 与任务实例身份

- 单项提案使用展示时的 `change_key` 与 `view_version`；整轮提交使用展示的 `task_key` 和该动作下全部可操作提案的 ID、key、版本快照。确认弹窗打开后固定原任务、提案和审核轮次；身份缺失时禁用或拒发，403/404/409/422 只刷新事实并要求重新确认，不重放操作。服务端的 `view_version` 不包含状态，客户端也防止迟到 `proposed` 事件覆盖已执行状态。
- 通用任务的详情、输出、流、取消、重试、继续、结束、删除与拆书跳过均携带最初 `task_key` 查询参数；缺 key 的历史任务只读展示，不能操作。流初连与重连沿用相同 key，拒绝其他实例的快照，清除旧输出；新任务重试结果必须有新 key。审核候选的 `task_key/run_key/token` 必须与原任务一致，任务确认弹窗保留打开时的审核轮次。
- Agent 消息与变更只使用后端投影并持久绑定的 `turn_task_key`，不按整数 ID 推测新任务；缺原实例证明的历史关联保持只读。已执行子任务尚无可信原 UUID 证明，卡片不再用其数字 ID 查询或取消，需从任务列表操作。
- 旧 TaskOut 的章节、场景、角色与大纲数字关联尚不提供实例证明：章节编辑器、分析、角色解析及细纲展开不再据此自动恢复任务；章节任务跳转仅到章节列表，批量断点不再给当前章节标记排队。当前页面明确发起并持有原 TaskOut/key 的任务仍可订阅；对生成中的章节不推断中断或自动复位。后续需要后端提供可验证的原关联凭据才能恢复这些自动行为。
- 向导续写从当前已验证的原 TaskOut 取 ID/key 成对发送，新任务返回不同 key 后按新 key 订阅。续写来源失效或结果未知时保留部分输出、冻结旧续写入口并刷新任务列表，需用户手动核对；不得由数字 ID 补查 key。
