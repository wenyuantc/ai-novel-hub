# E1 单章与场景后台生成：阶段检查

本记录是进行中的检查，不代表 E1 或整体阶段门禁通过。编辑者入口仍关闭。

## 本轮实现与发现

- 单章任务在受理时固定作者的文本配置实例、配置指纹，以及原始向量或关键词选择；排队、重试和每次发送不按后来默认配置重新选择。作者损坏的向量配置仍按原行为受理为 202，执行前复验失败且不发送。
- 领取时的 `TaskExecutionIdentity` 与原章节 claim 沿执行链传递；文本和向量出站复验原 token、任务、模型、章节与场景快照。实际保存前在同一事务内重新持认证、可见性、项目、任务、章节及模型锁，成功日志、正文、版本和原 v2 完成收据原子保存。
- 首次建立章节发送 guard 之前核对原传输快照。此前如果同时篡改 provider 内外层凭据，guard 会把新值捕获后发送；真实 HTTP 反例现在无请求发出。
- 润色同样保留原向量选择，以便自动分析继承来源。自动分析由独立服务核成功状态、原 execution 和结果收据后派生；在来源成功后更改 token 或模型，不能派生旧身份任务。
- 普通输出事件复验原执行凭据；单章 done 使用原 claim 与完成收据核输入、断点、版本、日志和结果指纹，富文档 paused 使用提案原 claim 与私有收据校验。最终状态写入再次执行相同证明。真实 ASGI 字节交付的逐帧锁由引擎和 SSE 切片负责，不能以此记录宣称该链已完成。
- 文本与向量配置的整数 ID 被删除并重用，即使其他字段完全相同，也必须比较独立的 `instance_key`；不相等时旧任务失败且不调用模型。旧无实例证明绑定不得补签。
- 协作者失败收尾不再新增生成日志，避免身份失效后持久化 prompt、原文、作者模型或原始异常。仅在原 task UUID、入队与执行轮次、原授权、原章 claim 及输入/断点匹配时回收自己的占用；不能证明时保留占用，作者失败日志沿用既有行为。

## 已验证的局部结果

- 当前 UUID 模型配置、作者事件门禁下，`tests/test_chapter_claim_author_wiring.py`：**12 passed**；批量作者跳过已写及覆盖版本端到端：**1 passed**；富文档待审和采纳：**1 passed**。
- 作者润色成功后自动分析继承原 actor、token、文本模型和向量选择：**1 passed**；源成功后、自动分析派生前变更 token 或模型：**2 passed**。
- 新增章节专项在修正取消日志断言后统一运行：**31 passed、1 deselected**（唯一排除项为仍关闭的编辑者生成正向）；随后新增的成员移除收尾用例单独 **1 passed**。
- 本机真实 HTTP 测试覆盖模型响应头后改密 / 变更模型，阻止正文和成功日志；还覆盖文本/向量配置 ID 复用、本机模型请求前传输突变、原成功收据及伪造反例。FakeLLM 用于本地功能验证，不作为 PostgreSQL 物理锁或实际外发时序证据。
- 以真实 HTTP 建立协作并分别改密、降级、移除成员或收回作者 AI 授权，再用服务端原语构造的原任务 / claim 触发失败：**4 passed**，不新增包含私有内容的日志；Task UUID 替换、身份凭据缺失的两个单独用例也通过且保留原章占用。该测试没有开放编辑者真实受理入口，也不代表编辑者端到端已完成。
- 引擎事件门禁一度导致正文已提交后管理员再受理取消的任务停留在待核对。引擎及本切片增加严格原 operation / input / claim / 结果收据核验后，真实竞态与 admin-race 收据反例 **2 passed**，成功赢家可正常结束并释放。
- Ruff 本次涉及生产和测试文件通过；项目未配置独立 Python 类型检查器。
