## 浏览器验证

| 验收项 | 步骤与观察结果 |
| --- | --- |
| A1、A2 | 延迟第一笔富文档保存的响应，随后在页面继续输入正文和章节标题。第一笔请求仅含冻结时的正文，后续输入分别同步，Ctrl+S 可用。Chrome 的组合输入事件进行时无请求，候选字提交后才保存。通过编辑器工具栏撤销和重做，自动保存后历史仍可用，三个状态均分别同步。 |
| A3、A10 | 断网后输入正文，添加加粗、作者区块和标记，确认显示「本地已保留」。关闭页面及 Chrome，联网以同一配置目录重开，从「本地草稿」恢复。恢复后服务端正文保持原样，点击「保存恢复稿」后读取到包括加粗、区块和标记的完整文档。 |
| A4、A12 | 原页面离线继续写作，联网且基线相同时可同步。服务端提交正文或标题后故意丢弃响应，客户端保留更新的输入，手动核对后只提交未确认的新内容，修订号与实际写入次数一致。 |
| A5、A11 | 同章两个标签页从同一标题开始编辑，先到服务端的写入成功，另一笔收到 409，旧页保留本地标题并展示对比，确认保留本地后才同步。分别在两个标签页离线修改标题、关闭 Chrome 后重开，可用键盘逐份选稿，显式保存选中的标题后另一份仍可查看。恢复时来源被其他操作修改的情形由 IndexedDB 回归覆盖。 |
| A6 | 一个浏览器离线写草稿，另一个会话分别启动并完成 FakeLLM 写作、恢复旧版本。重连后编辑器显示待核对，当前输入和远端版本均保留。 |
| A7 | 被降级为查看者的协作者可查看自己已持久化的记录，页面禁用编辑和恢复。撤销访问后触发页面重新核对权限，抽屉清除草稿和下载入口。另验同源标签页换成同作品另一编辑者的 Cookie，旧请求得到身份不匹配的 409，新账号的抽屉无旧账号草稿。 |
| A8 | 隔离页面限制 Chromium 存储配额，并独立注入 IndexedDB 草稿写入失败。两种场景均显示「本地草稿保留失败」，当前文字仍在，离开保护生效，恢复联网后可手动保存。 |
| A9 | 在正文文本选区中清空场景，空白稿自动保存，并能从「版本历史」恢复清空前的完整正文。删除原章节后，从作品章节列表核对并下载原草稿，详情标记目标已失效，恢复按钮不可用。 |
| A10 | 在两个会话各自增加不同作者区块。重连后可核对远端区块，并下载完整的本地文档，界面禁止直接覆盖结构冲突。另外验证正文自动保存期间独立场景标题和摘要仍待保存，快捷键可显式提交。 |
| A12 | 模拟旧后端标题路由返回 404，正文已成功确认，标题保留待同步并提示刷新。记录到的请求中没有无条件标题 PATCH。新后端接收旧客户端缺条件的 422 由后端接口回归覆盖。 |

抽查桌面及 375px 窄屏的明暗主题。无标题场景按内容片段列示，选中后显示章序和场景号。窄屏恢复抽屉可查看详情并操作，页面无横向滚动。

## 验证边界

- 中文组合通过 Chrome DevTools 注入真实浏览器事件。操作系统原生输入法、Firefox、Safari 和手机实机尚未验证。
- 运行当前仓库的 SQLite 门禁。PostgreSQL 并发、正式环境部署与回滚尚未演练。
- 各标签页持久化以已完成的 IndexedDB 事务为准。浏览器重开复验在状态显示「本地已保留」后关闭，没有断言尚未写入磁盘的编辑或被浏览器清除的站点数据可恢复。
- 多个场景共用浏览器配置时，一次配额覆盖未触发写入错误。改用全新的配置目录单独复验配额覆盖，并独立注入 `QuotaExceededError`，两次均通过。
- 富文本应用的全选删除会触发结构保护。在实施前的 `5bc046b` 前端构建中复现了同样的提示。浏览器使用正文文本选区验收清空路径。
