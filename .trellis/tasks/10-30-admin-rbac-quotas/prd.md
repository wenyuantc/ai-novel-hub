# 管理员权限分级与用户配额

## 建档状态

优先级：P3。状态：`planning`，待细化的功能需求草案。

来源：2026-10-30 管理员功能缺口盘点。用户要求将清单中的 8 项功能分别创建独立任务，本轮仅完成建档；具体产品取舍与实施方案尚未确认。

## 目标与用户价值

让多人管理平台时按职责分配权限，并对用户资源占用设置清晰、可执行的额度。

## 已确认现状

- `backend/app/models/entities.py::User` 当前通过 `is_admin` 布尔字段区分管理员与普通用户；现有用户管理保护自己和最后一名启用管理员。

- `backend/app/core/config.py` 已提供全局及统一用户任务并发上限、每把开放 API Key 的限流，但没有按用户覆盖的资源配额。

- `GenerationLog` 的 Token 用量字段目前为预留可空字段，不能直接作为精确消耗计费依据。

## 初步需求

1. 明确超级管理员、内容管理员、审核员与普通用户的权限矩阵，将功能入口和后端动作按同一矩阵授权。

2. 支持角色分配、撤回与既有管理员迁移，保留防止平台失去最高权限管理者的保护；撤权后旧会话按最终规则失去对应能力。

3. 支持按用户设置约定资源额度，展示当前用量与上限，明确默认、继承和不限额的语义。

4. 配额检查覆盖实际资源创建/任务调度入口，考虑并发提交；现有用户数据不因额度降低被隐式删除。

## 验收标准（草案）

- [ ] AC1：权限矩阵中的每类角色可执行允许动作，直接请求被禁止接口同样被拒绝，不能仅隐藏前端入口。

- [ ] AC2：角色迁移、撤权、自操作和最后最高权限账号保护均有明确且可验证结果。

- [ ] AC3：每用户额度能够独立配置，用量显示正确，达到边界及并发提交时不会越过约定上限。

- [ ] AC4：未配置用户沿用已确认的默认行为，减少额度不自动删除现有作品或私人配置。

- [ ] AC5：角色与配额调整有记录，任何角色都不会因新角色体系自动获得他人的模型密钥或私人配置。

## 范围边界

- 积分、充值、订阅、订单、供应商费用结算及精确 Token 计费。

- 未经确认的自定义权限编辑器、组织租户体系及任意角色继承。

## 待确认项

- 首期角色集合、权限矩阵、既有管理员迁移与撤权生效方式。

- 首期配额指标和计量周期、默认额度、超额反馈，以及与全局并发上限的优先级。

## 关联与先后顺序

- 复用用户详情展示用量，与系统设置统一默认配额来源；最终矩阵需覆盖操作日志、回收站、任务处置和备份管理等新增管理员能力。
