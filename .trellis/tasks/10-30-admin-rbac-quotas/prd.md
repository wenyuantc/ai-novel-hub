## 需求

### R1：角色与多角色组合

提供下列预置角色，以及可自行创建并配置权限的自定义角色：

| 预置角色 | 默认管理能力 |
| --- | --- |
| 超级管理员 | 全部现有管理能力；角色与授权管理不能下放 |
| 内容管理员 | 全站作品人工维护、移入回收站及恢复；工坊内容管理，不含作品彻底删除或平台控制权限 |
| 审核员 | 工坊投稿审核与内容上下架，不开放其他用户的私人作品 |
| 普通用户 | 保持自己的资源与现有公开功能，无全站管理能力 |

账号可同时分配多个角色，有效管理权限为所有角色的允许权限并集，不引入显式拒绝覆盖规则。撤回一个角色不影响其他角色仍授予的权限；多角色不用于计算或叠加配额。上述为预置基线，自定义角色可扩展账号获授的管理动作，但不突破 R2/R3 的保护。

### R2：权限配置与授权范围

- 仅超级管理员能创建/修改/删除角色、配置角色权限和向账号分配/撤回角色；这些能力不进入自定义角色的可授权项。
- 自定义角色从系统提供的操作级权限目录中勾选组合，不只按菜单控制。按现有功能拆分查看与变更动作，例如作品查看/编辑/回收/恢复/彻底删除、用户查看/创建/状态调整/重置密码/删除、任务查看/取消、日志查看/清理、系统设置查看/修改、配额查看/修改、全局 Skill 维护与工坊审核/管理。最终目录与读取前置依赖在技术设计中逐项列出。
- 除仅限超级管理员的角色与授权管理外，其他现有管理能力均可显式授予自定义角色，包括高风险动作；危险动作独立配置，并保留既有确认、审计与数据完整性保护。
- 配额修改不是仅因拥有某个固定角色而自动获得的能力，超级管理员可将其授予自定义角色，但须遵守下方已确认的目标账号保护规则。
- 不开放任意自定义可执行权限或读取他人私人凭据的新能力；用户更新权限不能替代角色分配权限。

### R3：目标账号保护

- 非超级管理员的账号变更与配额修改动作仅能作用于普通账号；对任何具有管理权限的账号（不仅是超级管理员）进行状态调整、管理员重置密码、删除或配额修改，仅允许超级管理员。
- 读取安全账号信息与用户自身改密仍按对应原有能力执行，不因该目标保护一并禁止；此处保护不额外限制已获授权的作品人工管理动作。
- 保护基于真实有效管理权限，不按角色名称猜测；在实际写入边界复核，避免目标获授管理权限后，先前到达的账号管理请求仍按普通用户处理。
- 原因：现有重置密码后新密码可登录（`backend/app/services/admin_service.py:181`），若允许重置任意管理账号，便可能绕过角色管理限制，接管另一权限集合或超级管理员账号。

### R4：角色生命周期、迁移与撤权

- 内置四类角色定义不可修改或删除；需要调整权限时可复制为自定义角色，再按需分配。普通用户的个人资源能力不因后台管理角色的分配与撤回被取消。
- 自定义角色可修改，变更影响全部成员；仍分配给账号的角色不能删除，须先撤回全部分配。
- 存量 `is_admin=true` 账号迁移为超级管理员，其余账号保持普通用户；保留启用/禁用状态、密码和个人资源。显式配置的引导账号继续在启动时确保为启用超管且不覆盖密码（`backend/app/services/auth_service.py:140`）；若不希望重启后恢复此账号管理权，部署者须移除相应引导配置。
- 授予/撤回角色与编辑自定义角色权限后，后续请求按最新权限校验，实际管理写入前同样复核；不因仅改管理权限强制登出，不追溯撤销已发生的管理行为。
- 禁止对自己禁用/删除或移除自己的超管身份；任何操作不得使最后一名启用超级管理员消失。密码重置、禁用和本人改密仍沿用原会话失效规则。

### R5：两项用户配额及默认/覆盖语义

- 作品总数计入全部尚未物理删除作品，包括正常、回收站与删除中作品；达到上限后禁止新建，所有实际创建入口都不能绕过。已有作品的正常维护、软删和恢复不因占用不减而额外扣减额度。
- 后台运行任务数达到用户上限后，其他任务继续排队；降低额度不取消已运行任务，但不再启动不符合新限额的任务。两项均按当前占用计量，不做每日/月度重置。
- 系统默认作品数不限额；默认后台任务并发沿用系统设置中的每用户并发值。未配置的存量和新用户均继承默认值，不给现有账号突然增加作品上限。
- 每用户的每项配额独立支持“继承系统默认”“指定非负整数”“不限额”；用户覆盖替代该项默认值，不从多角色权限并集中计算额度。
- 显式数值 0 表示禁止新建作品或不再启动新的后台任务，不表示不限额；已有作品仍可正常访问/维护，运行中任务不被强制中止。
- “后台任务不限额”仅移除用户级并发约束，实例全局并发上限始终有效。
- 所有角色（包括超级管理员）都遵守账号的有效配额，不因角色变化自动豁免；需要增加额度时显式修改账号配额。

### R6：展示、反馈与审计

- 沿用管理用户列表/详情提供多角色分配、每项配额的配置状态、当前用量、有效上限与来源；角色/权限管理提供独立管理入口。未获相应读取或操作权限时不请求其管理数据，也不显示可执行的写控件。
- 创建作品受限时给出明确的额度不足反馈，后台任务限额导致的等待保持排队语义；降低额度不隐式删除现有作品或私人配置。
- 菜单、路由、动作按钮、异步提交与后端直接请求按同一权限规则工作；失权或账号/目标切换后撤下危险弹窗并使旧响应失效。只读管理能力不能通过原人工工作区写控件绕过。
- 角色定义、角色分配与配额调整记录真实操作者和安全摘要；原有高风险管理动作保留确认/审计。任何角色都不因此新增读取他人模型密钥、平台 API Key、私有配置、AI任务输出或代写阅读进度的能力。

## 验收标准

- [x] AC1：权限矩阵中的每类角色可执行允许动作，直接请求被禁止接口同样被拒绝，不能仅隐藏前端入口；多角色账号可执行各角色允许权限的并集，撤回角色后仅保留其他角色仍授予的权限。

- [x] AC2：角色迁移、撤权、自操作和最后最高权限账号保护均有明确且可验证结果。

- [x] AC3：每用户作品数与后台任务并发额度能够独立配置，用量显示正确。正常、回收站与删除中作品均占用作品额度，并发创建不越限；后台任务超限排队，配额降低不取消已运行任务，新调度不再超过有效上限。

- [x] AC4：未配置用户默认作品不限、任务并发继承系统设置；继承/指定数值/不限额可区分，0 不被误作不限额。所有角色含超管都受有效配额约束；全局并发上限不被用户不限额绕过，减少额度不自动删除现有作品或私人配置。

- [x] AC5：角色与配额调整有记录，任何角色都不会因新角色体系自动获得他人的模型密钥或私人配置。

- [x] AC6：能够创建自定义角色并配置操作级权限、分配给账号；只读与变更能力可区分，高风险动作须显式授权且保留确认和审计。实际接口访问和前端动作遵循所授权限，不因使用自定义角色而获得未授权能力。

- [x] AC7：非超级管理员不能创建/修改/删除角色、配置角色权限或给账号分配/撤回角色；直接请求同样拒绝，不能借普通账号更新或其他管理接口绕过该边界。

- [x] AC8：具备普通账号管理或配额修改权限的非超管，可按授权维护普通账号，但不能禁用、管理员重置密码、删除或修改任何管理账号的配额；跨角色、目标并发获授管理权限及直接请求均不能绕过。安全账号信息读取与本人自助改密不被误禁。

- [x] AC9：内置角色不可改删、可复制为自定义角色；自定义角色编辑影响全部成员，在用角色删除被拒绝，先撤回全部分配后才可删除，编辑/删除/分配并发无越权或静默覆盖。

- [x] AC10：用户列表/详情、独立角色管理、管理导航和原人工工作区的入口/读写动作正确反映权限；直接访问、刷新、同账号撤权、StrictMode、迟到响应、移动端及明暗主题可验证，无“403被误当401退出登录”或失权弹窗残留。

- [x] AC11：升级正确迁移旧管理员/普通账号并保留禁用状态、密码、既有会话和所有私人数据；引导管理员行为及最后/自身超管保护保持。迁移及应用回滚不得把自定义角色映射成全权管理员或静默丢失权限/配额。
