# C5 引擎外状态多进程设计

需求和验收口径见 [PRD](prd.md)，上游依据见[父任务设计](../11-20-multiprocess-task-scheduling-deploy-drill/design.md)和[源码调研](../11-20-multiprocess-task-scheduling-deploy-drill/research/in-process-state-outside-engine.md)。基线为当前已归档 C4 的分支，迁移头为 0068。应用实例通过同一业务数据库协调。SQLite 使用同机文件库及 C1 的配对租约侧库，PostgreSQL 可跨主机。两阶段项目导入通过数据库共享状态，无需内部通道在线。

## 整库备份

- 给备份活动行增加可空的 worker 代次和执行主机标记。排队阶段记录当时正在服务的受理者代次，领取阶段在一次条件更新里写入新代次、执行主机、开始时间并转为 `running`。键、旧状态、活动槽和预期代次均参与判定。无匹配行时直接返回。提交回执不确定时按执行键及原领取者重读，确认前不发起任何文件、网络或通知操作。受理和运行可以在不同应用。
- 启动和周期核对复用 C1 的权威失效判定。重启遗留、无代次的旧活动行按原来方式中断。带代次的排队行在受理者仍存活时可正常领取，受理者已永久围栏时按旧重启语义收尾。运行中仅在原代次已经停止或已提交永久围栏后进入恢复。未知租约保持待核实。恢复方须以原状态和归属竞争一次持久恢复权，活动槽留到收尾完成，恢复方失联时下一代可接手核对。已完成但遗留清理的记录和 `deleting`／`unknown` 副本也须先取得恢复权。终态收尾、产物身份、清理意图与通知状态写入均校验原操作身份。执行或恢复记录仍引用的 worker 不参与登记裁剪。
- 同一备份目录的运行器在触碰工作目录、保留清理或恢复产物前使用实例级文件锁，锁文件留在既有私有实例目录，避免打开不同 inode 获得两份锁。锁覆盖底层线程和 subprocess 的生命周期，活进程短暂丢租约时，后到者仍不能清理它正在操作的文件。失去执行权后请求底层停止，等待排空后释放锁。运行器停机时先结束受理及底层工作，再释放执行者登记。文件或 S3 操作期间用短事务校验归属，保留已落库的外部副作用证据。恢复只核对原定位、回收可证明属于原执行的临时目录及分片，不重放快照或 SMTP。无法证明本机可达的临时产物留待核实。
- 本地副本写入者标记采用执行主机身份，和数据库实例 UUID、worker 代次分别保存。任何主机成功打开共享目录上的原副本都可下载。只有可确认在写入主机上缺失时才条件标记 `missing`。其他主机或旧副本归属未知时，返回既有不可用错误类型，保留记录。保留清理和恢复也按同一规则判断缺失。GPG 私有目录按写入主机和执行标记回收，仍校验原 marker。多主机生产要求共享 `BACKUP_DIR` 由 C7 写入 README。
- 计划受理在数据库中对同一日期和活动槽竞争。失败方结束本事务后重读，证实当日已受理或活动槽已占用时按正常跳过处理。推进 `next_scheduled_at` 时复核原配置版本和待办时间。实际配置或数据库失败继续用固定摘要告警，手动受理保留原鉴权、审计和冲突口径。

## 灵感生成

- 对 `(session_id, step)` 使用唯一数据库占用，记录操作 UUID 和请求 worker 代次。验证会话归属和现有生成条件后，在任何模型或向量出站前领取。占用只覆盖这个步骤。活跃占用返回原 409 提示。识别永久失效后才允许换代领取，旧代次不得续写或释放新代次占用。协作灵感维持原权限及暂不可生成的结果。
- 在 SSE 响应生命周期内持有占用。在原模型发送、自动重试和成功写库的短事务中分别检查身份。正常结束、出错、取消及首帧前断开均按操作 UUID 条件释放，崩溃由永久围栏兜底。整个模型调用期间不持数据库事务。原先的请求内重试、事件名与断线不落库约定继续适用。
- 给会话的 JSON 状态加内部修订号。普通改想法、步骤、笔记和生成轮次涉及同一状态的所有更新都用原版本作条件。生成成功时在短事务中重读最新会话并追加当前轮次。若遇到并发状态变化，仅重试这次基于最新状态的写入，无需重新请求模型。转换和应用沿用现有会话归属与作品锁序，复核它们与状态修改的交叉路径。新字段通过导入默认值初始化，不进入作品备份格式和公开响应。

## 项目导入两步

- 保留双路由、文件解析器和直接上传路径。预览完成原校验后，把原始上传字节作为不透明二进制分块暂存于数据库。以有认证的加密封装及专用派生密钥保护暂存内容。每个令牌用随机值，存储摘要并绑定用户，上传内容和明文令牌不进入日志、审计或任务输出。重复解析复用现有校验器，不引入可执行序列化。
- 预览、淘汰和过期清理按同一个数据库配额行串行化，再读当前份数。上限为每用户 2 份、全站 6 份、每份 100 MiB、600 秒有效，新条目淘汰最早到期的相应旧条目。分块写入、元数据与淘汰在同一次提交生效。使用数据库时间判定过期，成功提交前不返回令牌。启动及低频维护清理过期数据。用近上限文件检查存储放大、事务占用及锁等待。
- 确认端按用户、令牌摘要和有效期解析暂存。重用普通导入的权限、配额和校验。消费令牌与新增项目及其关联行在同一提交内，失败回滚可重新确认。并发确认最多提交一次，失效或已被消费返回原 400。完成后继续按原逻辑尝试排队重建检索。确认不会取得全站的配额行，且在配额、User 屏障和记录更新之间维持现有业务锁顺序。删除用户、过期或淘汰时级联清理分块。

## 智能体会话操作

- 以会话唯一的持久操作占用替换正确性对进程内锁的依赖。短事务按会话、请求 worker 代次和随机操作键抢占；冲突时释放事务后等待，然后在实际业务事务内重新核对认证、会话归属、原邀请和轮次身份。在 SQLite 以唯一键和条件 DML 决胜，在 PostgreSQL 用相同的条件作为最终判定。等待时不持授权、作品、会话或任务行锁。以持有者及操作键条件释放，围栏已确认的失联记录才允许接管。重入调用共用外层操作，不能重复争同一个会话。
- 会话的内部 UUID 在迁移时为旧会话回填，新建时由 ORM 生成。既有外键仍使用原整数键。跨提交转载入和投影核对原 UUID，SQLite 中同编号的新会话也不能承接旧请求。
- 覆盖发送、确认、拒绝、单条及整轮撤销、删除。核对中央任务受理、改名、续跑和自动执行等能改到同一会话或提案的入口。命令内跨提交时保留占用，原授权、可见性及作品锁顺序在每个业务事务内继续有效。判断活动轮次含 `paused`，保留当前数据库索引和对 `paused` 的业务复核。
- 外部确认继续按现有契约持久提交 `executing`、原轮次、请求 worker 和调用身份，再联网。发出前核对会话操作和调用身份，写结果时再次核对。C3 的外部结果未知和启动恢复规则继续适用。确认、删除与撤销不能把存活执行者的 `executing` 当成失败或安全可删。失联可能意味着外部请求已到达，恢复只记原有未知状态，禁止自动重发。

## 周期维护与兼容

- 回收站清理中另一个实例已经完成或已领取的竞争，按受控原因跳过，真正冲突或数据库错误继续记录。仪表盘切片继续按采样时间原子 upsert。用量收尾仍只更新已过期且未完成的记录。遇到 PostgreSQL 可重试的序列化竞争或 SQLite 忙锁时，使用新事务有限重试无外部副作用的动作，保留持续失败的运维日志。
- 以 0068 为当前基线新增一个迁移，实施时核对最新迁移头。新增列以可空或默认值兼容旧行。新增长生命周期归属或占用的清理须保留尚被引用的 worker 终止证据。迁移回退要保留旧备份和项目数据，有活动占用或丢失运行效果证据时明确拒绝。项目单书导出格式维持 v16，迁移字段和暂存表不纳入导出登记。整库备份和冷恢复仍按现有流程，演练恢复后废弃旧执行代次并清理不可用的暂存。
- 启用多进程前由 C6、C7 完成排空和部署验收。升级或回退安排停机，避免旧版运行器误处理新版本的租约。C5 验收使用隔离数据库和目录，生产默认仍为一个 Uvicorn worker。
