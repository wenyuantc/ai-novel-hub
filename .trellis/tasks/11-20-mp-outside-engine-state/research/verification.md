# C5 验证记录

## 变更前对照

在 C4 收尾提交 `75e132a` 对应的代码上确认了 0068 迁移头。公开 OpenAPI 有 415 个路径。按 UTF-8、键排序和无额外空白的 JSON 计算，SHA-256 为 `648c9f60829c4f526ad4cf02ceefa95c33c269042d3bca102e4290610ebf91af`。C5 实现重新生成的公开 OpenAPI 得到同样的路径数和哈希，单书备份格式仍为 v16。

基线双应用探针发现第二个备份运行器启动会中断第一方的备份，正常计划竞争会抛出错误，异主机下载可能把本地副本标为缺失。同一导入令牌同时确认可创建两个作品。灵感响应未开始迭代时断开会遗留忙占用，两个并发新增笔记会丢失一笔。外部提案已提交执行标记、调用尚未完成时，其他实例可以提前改名。回收站同一记录由两方先读到时，会生成一条成功和一条失败审计并告警。

## 双进程 HTTP

`process_c5.py` 使用两份独立的 Uvicorn 进程、同一临时文件 SQLite、可控模型和延迟备份适配器。A 正在生成备份时启动 B，B 读到运行中状态，临时目录仍在。放行后，A 成功完成且仅一个可用副本。A 预览项目备份后，B 确认返回 201，重复确认返回 400。A 正在运行灵感生成时，B 请求同一步骤返回原 409，替身模型只接到一次生成调用，B 可读取已保存的一轮选项。

再受理一条备份，并由测试实际强停其执行进程。两次演练分别在 28.240 秒和 26.477 秒观察到存活进程标记中断且清理了工作目录。

另一次独立双进程演练在灵感请求的模型连接仍阻塞时强停执行进程。另一进程在 25.46 秒内接管同一步骤，旧请求的半截内容没有进入轮次。在健康进程互斥和失联重试两轮成功场景中，最终只有两笔完整结果。

```sh
LC_ALL=en_US.UTF-8 PYTHONPATH=. uv run --no-sync python ../.trellis/tasks/11-20-mp-outside-engine-state/research/process_c5.py
```

## 数据库专项

- 使用本机专用 PostgreSQL 16.15 容器的 `ainovel_test`，测试夹具为每个用例建立并退出时清理单独的 schema。SQLite 使用独立应用与连接池，同一文件库。
- 智能体定向验证覆盖外部调用期间的重复确认与改名、发送提交和撤销竞争、执行者结束后的接管。四个 SQLite 同编号会话替换反例在补丁后通过，覆盖发送、改名、删除及最终详情读取。
- 双库 C5 汇总首轮 55 项通过。PostgreSQL 外部确认后并发改名或重复确认时，领取落败者有时仍会提交会话行的空更新。用独立读事务对比 `xmin` 复现了无效行版本变化。改成领取失败即回滚后，两项 PostgreSQL 定向复跑通过，保留外部调用一次和原 HTTP 状态断言。
- 灵感 16 项双库专项通过。覆盖同一步骤只调用一次、并发笔记不丢失、首帧前断开、旧占用恢复、短时数据库故障后补偿清理，以及静默模型和向量请求失去租约时主动结束。
- 导入 12 项双库专项通过，验证跨端成功、单次消费、配额与淘汰、过期、分块认证、事务中取消并重试。近上限 SQLite HTTP 样本为 104,856,576 字节，产生 100 个分块，密文负载开销为 2,800 字节，未计数据库页和索引。该样本预览、并发小预览及跨端确认分别用时 0.985、0.509、1.477 秒。
- 整库 PostgreSQL 原生导出使用 PG16 测试库及 pg_dump 18.6 生成实际归档。归档目录显示两个预览表仍有结构，预览数据已排除，普通作品数据仍在。
- 迁移与周期专项覆盖 0068 往返、带占用拒绝降级、拒绝缺列 SQLite 快照、恢复时废弃原预览、worker 终止证据保留和后续裁剪，以及两应用周期维护结果一致。
