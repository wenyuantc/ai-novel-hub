# 职业等级体系（P0-3b）

> 父任务：`10-23-mumu-parity`。对应差距项：B5 职业和等级体系。这部分由用户决定从 `story-entities` 拆出，紧接其后完成（story-entities D1）。
> 依赖：已归档的 `story-entities`（角色模型、选角与上下文注入、AI 草稿预览、卡片 v1、TaskPanel 结果查看注册表）和 `task-engine`。
> 后续 `analysis-memory` 会根据章节分析，通过本任务的写入接口回写角色阶段的变化。
> 技术设计见 `design.md`，执行计划见 `implement.md`。

## Goal

作者可以为作品定义职业，以及每个职业有序的等级阶段，例如剑修分练气、筑基、金丹……；魔法师分学徒、法师、大法师……。角色可以挂上主职业、副职业，并记录当前所处的阶段。生成章节时，模型能知道本章涉及角色的境界和整套阶梯，避免写出境界错乱。

## Background（代码证据）

- 角色模型（迁移 `0007`）没有职业字段，story-entities D1 约定由本任务通过关联表挂接。
- `context_builder` 的"本章涉及角色"卡片已经包含"所属组织：…（职位）"，另有独立的【相关组织】段落（`backend/app/services/context_builder.py`）。职业可以照这个结构接入。
- 关系有统一的写入入口 `relationship_service.apply_change`，负责写历史并区分来源（`.trellis/spec/backend/story-entities.md`）。
- AI 单体生成的模式已经成熟：任务只产出草稿，前端预览确认后再保存，TaskPanel 按任务类型注册结果查看器（`task_engine/handlers/entities.py`、`frontend/src/components/entities/taskResultViewers.ts`）。
- 向导目前有世界观、角色、大纲三步（`WizardPage.tsx` 的 `STEPS`、`task_engine/handlers/wizard.py`），每一步都整体覆盖已有内容。
- 卡片格式是 `ainovel.cards` v1（`card_service.py`），不含职业。
- MuMu 的做法（`../10-23-mumu-parity/research/mumu-story-settings.md` §5）：
  - 角色表的冗余字段和关联表两套并存，阶段存成 JSON 数组。
  - 阶段只能 ±1 调整，没有历史。
  - 按名称精确匹配，AI 返回的名称稍有偏差就会静默丢失。
  - 副职业最多 2 个。

## Key Decisions

- **D1（用户确认）**：向导在"世界观"和"角色"之间新增一个"职业体系"步骤，可以跳过。这一步根据世界观生成职业和阶段阶梯。如果项目里已有职业，角色向导会给生成的角色分配主职业、副职业和当前阶段；没有职业时（包括跳过了这一步），角色向导的行为和现在一样。
- **D2（用户确认）**：
  - 阶段只记录当前处于第几阶，另加一个自由文本"状态备注"（如"半步金丹""瓶颈期"），不做百分比进度。
  - 每个角色最多 1 个主职业、3 个副职业，同一个职业不能重复挂。
  - 阶段可以跨级调整，也可以降级。每次变化都记一条历史，包括变化前后的阶段、章节和来源。

## Requirements

- **R1 职业定义**：
  - 字段：名称（项目内唯一）、类别（主修或副修，决定它能挂成主职业还是副职业）、描述、获得条件、特殊能力、体系规则。
  - 有序的阶段列表，每一阶有名称和描述，可以增删、排序，至少 1 阶。
  - 正在被角色使用的阶段不能删除，否则返回 409；调整顺序不会改变角色所处的那一阶。
- **R2 角色挂接**（D2）：
  - 角色可以挂 0 到 1 个主职业、0 到 3 个副职业，每个都记录当前阶段和状态备注。
  - 挂接关系只存在关联表里，角色表不冗余存储。
  - 删除角色、职业或项目时，相关的挂接和历史一并清理。
- **R3 阶段历史**（D2）：所有挂接变更都走唯一的写入入口：新挂、换阶、改备注、改为主或副、卸下。有变化才写历史，记录来源（manual / wizard / ai / import / analysis）、章节号和备注。历史中阶段用"第 N 阶·名称"记录，阶段被删后仍然可读。
- **R4 AI 增量生成**：
  - 一次生成 1 到 5 个新职业，可以选主修或副修，可以填要求。
  - 参考项目信息、世界观和已有职业（只给名称和阶梯摘要），不能和已有职业重名。
  - 作为后台任务运行，结果先预览，可以逐个编辑或取消勾选，确认后才保存。
  - 关闭页面后，可以从任务面板打开预览。
- **R5 职业页面**：项目导航新增"职业"页。
  - 职业列表按主修和副修分组。
  - 编辑职业时可以对阶段拖拽排序和增删。
  - 每个职业显示有哪些角色挂在上面，各自处于哪一阶。
  - 提供"AI 生成职业"。
- **R6 角色侧**：角色抽屉新增"职业" Tab，可以挂接、换阶、改备注、卸下，并查看历史。角色卡片上显示主职业和阶段。
- **R7 上下文注入**：
  - 本章涉及角色的卡片里增加"职业：剑修·筑基（2/9，瓶颈期）；副职业：丹师·一品"。
  - 新增【职业体系】段落，列出涉及角色所挂职业的完整阶段阶梯。
  - 预算不够时，这个段落的裁剪排在组织段落之前。
- **R8 向导**（D1）：
  - 新增 `wizard.careers` 步骤，可以跳过，整体覆盖语义和其他步骤一致。前端提示：覆盖会清除角色已挂的职业。
  - 角色向导在已有职业时，要求模型为每个角色输出职业和阶段，按名称匹配写入（来源记为 wizard）；匹配不上的职业会忽略并给出警告，不会静默丢失。
- **R9 卡片**：
  - 卡片格式升级到 v2：角色带上职业挂接（职业名、阶段名、备注、主或副），卡片里附带所涉职业的完整定义。
  - 导入时按名称匹配目标项目的职业，匹配不上就新建；阶段按名称匹配，匹配不上就新增到阶梯末尾。
  - 仍然能导入 v1 卡片。
- **R10 安全**：所有职业相关的接口和任务都校验项目归属，非所有者一律返回 404；跨项目的职业或阶段 id 会被拒绝。

## Acceptance Criteria

- [ ] **AC1（R1）**：创建一个 9 阶的"剑修"，删除正在被使用的阶段返回 409；调整顺序后，挂在上面的角色仍然处于原来那一阶（名称不变）。同名职业返回 409。
- [ ] **AC2（R2/D2）**：给角色挂第 2 个主职业被拒绝，挂第 4 个副职业被拒绝，重复挂同一个职业被拒绝；把主修类职业挂成副职业、或把副修类挂成主职业，都被拒绝。删除职业后，挂接和历史都被清理。
- [ ] **AC3（R3）**：把阶段从练气直接调到金丹，再降回筑基，历史按时间倒序显示两条记录，阶段名称正确；只改备注也会记一条历史；值没有变化时不写历史。
- [ ] **AC4（R4）**：AI 生成 3 个职业以任务形式运行，预览里能编辑或取消勾选，保存后只写入勾选的职业；与已有职业重名的会被标记，不能直接保存。
- [ ] **AC5（R7）**：本章涉及的角色挂着剑修·筑基，生成记录的提示词里能看到他的职业和阶段，以及剑修的完整阶梯；不涉及的职业不出现在提示词里。
- [ ] **AC6（R8/D1）**：向导走完职业步骤后，角色向导生成的角色带有职业和阶段，并写入挂接和历史（来源为 wizard）；跳过职业步骤时，角色向导的输出和写入与现在一致。
- [ ] **AC7（R9）**：从项目甲导出挂有职业的角色，导入到项目乙：没有的职业会新建，已有的同名职业会复用，阶段按名称匹配或补充；导入 v1 卡片仍然成功。
- [ ] **AC8（R10）**：其他用户访问职业、挂接、历史和生成任务一律返回 404；使用其他项目的职业 id 返回 400。
- [ ] **AC9（质量）**：后端 ruff 和 pytest、前端 lint、test、build 全部通过，没有 chunk 超过 1500 kB；原有的卡片、向导、上下文测试不会在覆盖上倒退；spec 已同步。

## Out of Scope

- 根据章节分析自动升降阶段，归 `analysis-memory`。本任务提供写入入口和 analysis 来源。
- 职业的属性加成或数值体系、阶段内的百分比进度（D2）。
