# C2 跨模块复核

2026-11-23 在分支 `codex/mp-scheduling-constraints` 核对正常 HTTP 入口、任务领取及收尾、管理员设置、插件网络操作与 0067 迁移。以下定向复验均使用项目锁定的依赖。

## 复核中修复的问题

| 场景 | 能观察到的问题 | 当前行为 |
| --- | --- | --- |
| B 创建或修改插件时等待 DNS，A 关闭 MCP | C2 初版的写入路径先取授权写锁，DNS 解析会推迟 A 提交关闭，也会占用调度需要的数据库写门。 | DNS 在数据库事务外进行。关闭能及时提交，B 恢复后收到 403。新建时没有新增行，修改时旧地址保留。实际写入时还会重新核对身份、开关、归属或数量上限。 |
| B 修改地址时等待 DNS，A 已将同一插件改到另一地址 | 原路径迟到的编辑返回 200，并覆盖 A 刚保存的连接目标。 | 重新读取原插件，核对原地址、传输方式与加密请求头。连接目标已变化时，B 收到 409，A 的设置保留。 |
| B 等待 DNS 或刷新工具结果，A 删除最新插件再以相同配置创建 | 原 SQLite 表会复用整数主键。两种操作均曾返回 200，分别把旧地址编辑、旧工具缓存写到了新插件。 | SQLite 从 0067 起使用 AUTOINCREMENT，PostgreSQL 沿用其主键序列。旧请求重查原 ID 和归属后收到 404，新插件的地址、工具和刷新时间保持创建时的值。 |

后两行对应的三个 SQLite 首轮复现用例全部失败，实际均返回 200。修复后，五个正常入口用例在 SQLite 和 PostgreSQL 16 各自全部通过。针对工具发现的第二页，又用本机真实 SDK 完成两页刷新和第二页工具试用。工具响应正文暂停时，另一端提交关闭，随后原调用正常结束。试用过程中只出现一次首工具页读取和一次工具调用。两种数据库各通过一项。SSE 握手、已发调用与取消的独立验收见 `backend/tests/test_mcp_sse_settings_boundary.py`。

## 迁移与旧数据

在 SQLite 和 PostgreSQL 16 实际往返 0066、0067。测试保留旧插件的全部列，包括请求头密文、工具、偏好、错误信息和时间，核对原会话选中的有效插件 ID，以及主键、用户/标识唯一约束、用户索引与用户删除级联外键。在 SQLite 人为中断迁移后，表结构与版本一起回滚。升级成功后两种数据库均验证了连续创建、删除和再创建的编号递增。降级时仍执行原来的执行者和占用归属检查。两种数据库各通过一项。

身份保证从停机升级时仍存在的插件以及升级后新建的插件开始。升级前已经删除的插件及其历史编号沿用原数据状态。迁移保留已有会话的选择，不对历史会话推断或改写授权。

## 其他集成路径

- **领取与展示**。引擎在授权门内按已提交状态复查全站名额、用户额度和同键队首。领取、占用和统计写入同一事务。配额、任务列表、详情与排队事件均按提交后的数据库状态计算。占用归还还核对执行 UUID、原任务和轮次，已认定停止或失联的执行者由 C1 的事务清理。[领取竞争记录](claim-concurrency.md) · [原断言迁移](assertion-migration.md)
- **恢复与关停**。检查了 SQLite 主库写锁与独立租约库、冷恢复和 0067 降级保护。系统设置在应用实例中单独初始化、轮询和回收。覆盖启动中断、迟到的设置提交回执、普通读失败及停机时的后台清理。未提交领取的确认失败会退避，其他合格任务可继续。两种数据库的定向验收覆盖这些状态。[综合验收](verification.md)
- **接口与部署**。对照主会话生成的旧版与新版 OpenAPI，415 条路径定义一致。前端 TypeScript 编译通过。SQLite 实际双进程覆盖两种并发上限、安全开关和开放接口限流收敛。[双进程记录](sqlite-http-processes.md)

本轮独立运行的后端 Ruff 和 Git 差异检查均通过。SQLite 全量运行与 PostgreSQL 专项的最终计数统一记入[综合验收](verification.md)。
