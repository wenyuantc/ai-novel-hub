## 步骤

### 1. 框架补接入点：上传体积限制

- [ ] `PluginManifest` 增加 `upload_limits`；应用装配时并入现有请求体上限规则；注册表校验路径必须在该插件前缀下。
- [ ] 测试：示例插件声明的上限生效；超限请求在解析前被拒；不登记插件时规则列表与改动前一致。

### 2. 数据模型与迁移

- [ ] 三张新表与 `drama_episodes` 的两列；迁移含降级；作品备份规则声明三表不导出、两列排除；整库备份表目录更新。
- [ ] 迁移往返与备份反射测试。

### 3. FFmpeg 封装

- [ ] `backend/app/media/ffmpeg.py`：查找、`probe_duration`、`extract_poster`、`concat`；超时与错误文案。
- [ ] Dockerfile 运行阶段安装 `ffmpeg`；`.env.example` 增加 `FFMPEG_BIN`、`FFPROBE_BIN`。
- [ ] 测试 `tests/test_media_ffmpeg.py`（需要 FFmpeg）：用程序生成的两段测试视频验证拼接后时长约等于两段之和、分辨率统一、可抽出海报帧；
      找不到可执行文件时的明确报错；超时会终止子进程。

验证：`cd backend && uv run pytest tests/test_media_ffmpeg.py -q`，并构建一次镜像确认 `ffmpeg -version` 可用。

### 4. 资产图：上传、带入、选定、删除

- [ ] `services/images.py` 与接口；从小说设定缩略图复制；每资产 10 张上限；选定互斥与自动改选。
- [ ] 测试：上传的类型与大小校验；带入后得到 `source=novel` 的图；删除选定图后的改选；删除资产后其图片的媒体对象被标记删除；查看者不可上传。

### 5. 资产图：生成

- [ ] `drama.image` 处理器：缺提示词时先生成、画幅与风格前缀、非默认造型带参考图、单目标失败不中断、结束汇总。
- [ ] 测试（假图片模型）：批量三个目标其中一个失败；第二套造型的请求里带了默认造型的图；模型不支持参考图时该目标失败并有明确原因；
      用量记录；取消后不再处理剩余目标；插件停用时受理被拒。

### 6. 参考图计算

- [ ] `services/references.py::resolve` 与 `@` 替换（纯函数为主）；`GET /shots/{id}/references`。
- [ ] 测试：顺序与去重；超过上限的丢弃清单；只引用角色时用默认造型；造型无图进缺图清单；最长名优先；`·`、`・`、`•` 等价；重复替换结果不变。

### 7. 分镜视频

- [ ] `drama.video` 处理器与受理事务（版本行 + 台账行 + 预算预检）；驱动器回调同步版本行；成功后的时长探测与海报帧。
- [ ] 选定、删除接口；版本数上限。
- [ ] 测试（假视频厂商）：五条分镜其中一条失败，其余成功且逐条状态正确；失败的单独重试产生新版本；重试整个任务不重复提交已提交的分镜；
      取消后版本行为 `cancelled`；首个成功版本自动选定、切换选定互斥；超预算被拒；查看者不可生成；删除版本后媒体对象被标记删除。

回滚点：处理器与受理逻辑单独提交。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| 前序子任务的实际接口与本设计的假设不同 | 「开始前复核」逐项核对；有出入先改设计再动手 |
| 不同模型产出的片段编码与分辨率不一，拼接失败 | 统一重编码并缩放补边；测试用两段参数不同的视频 |
| 拼接占用大量处理器与磁盘 | 全局串行；临时目录用后即清；输入总大小设上限 |
| 需要 FFmpeg 的测试在没有 FFmpeg 的环境里失败 | 测试显式标记并在缺失时跳过且给出说明；容器内的门禁必须执行这些测试 |
| 真实模型费用 | 走查用最短时长与最低分辨率；次数与费用记入验证记录 |
