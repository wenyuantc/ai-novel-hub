# 真实本地模型验收

2026 年 11 月 28 日，在独立 SQLite 数据库中，通过真实 HTTP 接口建立《铜铃归舟》、两章原文及一集短剧。原文为本次合成的渡口故事。执行环境为 Apple M1 Max，后端使用正式 OpenAI 兼容 provider，模型服务仅监听本机回环地址。

测试按剧本改写、资产提取、分镜拆解、提示词生成的顺序执行。每个请求经后台任务入口提交，订阅 SSE 至终态，再用读取接口回查业务数据。测试同时保留任务输出、各步数据快照与 SQLite 独立查询，用来区分模型返回和业务数据实际保存。

## 3B 模型与模板调整

首先使用 Qwen2.5-3B-Instruct 的 Q4_K_M 量化，权重 SHA-256 为 `626b4a6678b86442240e33df819e00132d3ba7dddfe1cdc4fbb18e0a9615c62d`。首轮改写用时 10.9 秒，生成并保存 263 字剧本。提取用时 3.4 秒，保存一名角色、一套造型、一个场景和一个道具，阿禾关联到作品中的同名角色。人工对照原文发现父亲的一句对白被移给阿禾，资产还混入模板里举例使用的「茶馆掌柜」。分镜输出在重试后仍回显输入 JSON，任务以格式错误结束，分镜表保持空。同期独立浏览器走查在另一集发起真实改写，完成并重新读取 163 字剧本。

据此将具体人名、职业、故事改为结构占位示例，把要交付的文本或 JSON 结构写到用户材料之后，并强调逐句保留说话人及结尾。在新数据库中复测同一模型，改写保存成功，耗时 7.9 秒。提取返回 JSON，但把同一角色的属性拆成多条不完整记录，校验在重试后拒绝。3B 模型在这份样本上未走完四步，且已通过结构校验的剧本仍需要人工核对对白归属。

## 7B 模型完整流程

最后使用 Qwen2.5-7B-Instruct 的 Q4_K_M 量化。GGUF 文件共 4,683,074,240 字节，SHA-256 为 `65b8fcd92af6b4fefa935c625d1ac27ea29dcb6ee14589c55a8f115ceaaa1423`。Ollama 仅本地推理，上下文 8192，温度 0.2，种子 27。先核验公开文件摘要，再在新的空数据库按同一输入从头生成。[权重文件版本](https://huggingface.co/bartowski/Qwen2.5-7B-Instruct-GGUF/blob/main/Qwen2.5-7B-Instruct-Q4_K_M.gguf)

| HTTP 发起的任务 | 至终态耗时 | SSE 及业务落库 |
| --- | ---: | --- |
| 改写剧本 | 27.4 秒，含模型首次启动 | 83 个增量事件。保存 106 字剧本，场景头为「## S01 ｜ 外景 · 渡口 ｜ 黄昏」（原文使用半角竖线）。 |
| 提取资产 | 14.1 秒 | 保存角色阿禾、两套造型、渡口场景和铜铃道具。短剧角色指向本作品中的阿禾。 |
| 拆分镜 | 29.6 秒 | 按序保存「阿禾等待」和「喊话响应」，时长分别为 12 秒、15 秒。首镜引用渡口、一套造型与铜铃。 |
| 生成提示词 | 20.7 秒 | 同一请求选择造型、场景、道具、首镜四个目标，分别保存 72、91、37、100 字提示词。另一套未选择的造型仍无提示词。 |

四个任务的状态均为 `succeeded`，SSE 终态均有 `applied=true`。单独打开 SQLite 只读连接，确认来源表有两条记录，剧本、资产、分镜和提示词已写入业务表。作品用量接口返回四种任务各一条，模型均为 `drama-qwen:7b`。模型冷启动期间，后端曾记录三次「定时刷新输出失败」，该次改写的增量和最终剧本均已读回。

**生成内容需要作者审阅。** 7B 剧本保留了父亲的原句，又重复安排阿禾说同一句话。第一次生成视频提示词得到单段文字。补充展示视频目标的多行 JSON 示例，并在用户消息末尾区分图像与视频格式后，对相同四个目标复测一次，任务 5 在 23.1 秒后成功写入。视频提示词现有 0–12 秒时间标记和结尾整体描述，仍出现重复的 0–3 秒和同段内缺少换行。场景提示词仍写入人物，与无人物空镜的要求不符。试验验证了真实生成、校验、计量和保存链路，创作内容与镜头版式不能据此判为完全达标。

最终提示词及工作流专项测试共 23 项通过，所改 Python 文件 Ruff 检查通过。验证完毕已停止自建 Ollama 和三个临时后端，确认相关回环端口均已释放，临时权重已清理。
