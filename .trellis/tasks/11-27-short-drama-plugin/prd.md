# 短剧插件：剧本与分镜（文本段）

> 父任务：`11-27-admin-plugin-packages`。决定编号 D1–D15、共同需求 R1–R7 见父任务 `prd.md`。
> 技术设计见同目录 `design.md`，实施计划见 `implement.md`。

## Goal

把小说章节改编成短剧的文字产物：按章节建集、AI 改写剧本、提取角色（含造型）/ 场景 / 道具、拆分镜、
生成图片与视频提示词，全部可编辑。作为第一个真实插件交付，同时检验插件框架的接入点。

生图、生视频、成片导出在 `11-27-short-drama-media`；无限创作画布在 `11-27-drama-canvas`。
本子任务的 `research/` 是三个短剧子任务共用的调研依据。

## 依赖

依赖 `11-27-plugin-framework`：必须通过框架登记页面、导航、接口、任务类型，不得绕过框架直接写进核心路由表或导航（R2）。
本子任务需要的新接入点（作品备份规则等）连同框架一起在这里补。

## Requirements

对齐参考项目（D9），并按 aiNovel 的实际情况调整：

- S1 作品内新增「短剧」入口。一部作品可以建多部剧，每部剧有标题、风格、画幅；剧下有多集。
- S2 建集时从本作品的章节里选择一章或连续多章作为该集的原始内容；也允许手动粘贴或修改原始内容。
  （参考项目只能粘贴，没有章节概念。）
- S3 AI 改写：把原始内容改写成格式化剧本，过程实时可见，可取消；结果可手改，也可跳过改写直接手写。
- S4 资产提取：AI 从剧本提取角色、场景、道具；角色可以有多套造型。全部可手动新增、修改、删除。
- S5 与小说设定的关联（D12）：提取时自动匹配本作品里同名的角色和地点，带入外貌、身份等初值并记下关联；
  之后在短剧里的改动不回写小说；被关联的小说设定删除后，短剧资产保留、关联解除。
- S6 分镜拆解：AI 把剧本拆成有序的分镜，每个分镜含画面描述（含台词）、景别、时长，以及引用的角色造型、场景、道具。
- S7 分镜可逐条编辑、调整顺序、新增、删除，也可整集重新拆分。（参考项目只能整体重拆，这里放宽。）
- S8 提示词：AI 为角色造型、场景、道具生成图片提示词，为每个分镜生成视频提示词；都可手改。
- S9 权限：作品作者与编辑者可写；查看者只读；AI 调用遵守现有的协作授权、用量与预算规则（R5）。
- S10 剧本与分镜表可以导出为文档。
- S11 短剧数据随作品备份导出与导入，随作品进回收站、恢复、彻底删除（R4）。
- S12 插件停用时以上入口全部不可用，数据保留（D5）。

## Acceptance Criteria

- [ ] 插件启用后，作品导航出现「短剧」；停用后消失，短剧接口被拒绝，数据仍在。
- [ ] 选择两章建一集，原始内容即为这两章正文；修改章节正文后，已建的集不受影响。
- [ ] 一键改写得到格式化剧本，过程中可看到实时输出并可取消；手改后保存，刷新仍在。
- [ ] 提取后得到角色、场景、道具列表；小说里已有的同名角色被自动关联并带入外貌描述；在短剧里改名不影响小说角色。
- [ ] 拆分镜得到有序分镜，每条含画面描述、景别、时长和引用；可单条修改、拖动排序、新增、删除；重新拆分前有确认。
- [ ] 生成的图片提示词与视频提示词可逐条查看和修改。
- [ ] 查看者能看不能改；编辑者使用作者模型需已获授权；调用记录出现在 AI 用量页。
- [ ] 导出剧本与分镜表得到可读文档。
- [ ] 含短剧数据的作品导出备份、在另一实例导入后，剧、集、剧本、资产、分镜、提示词及与小说设定的关联都还原；旧版本备份仍可导入。
- [ ] 作品彻底删除后，短剧数据不残留。

## 已核实的现状（代码证据）

参考项目（详见 `11-27-short-drama-plugin/research/reference-drama-pipeline.md`）：

- 流程以「集」为单位：建剧建集 → 原始内容（只能粘贴）→ AI 改写 → 资产（角色含多套造型、场景、道具）→ 分镜与视频 → 导出。
- 数据模型：短剧专属 16 张表（实体 7、关联 7、任务与导出 2）。没有独立的剧本表（剧本是剧集的两列）、分镜版本表、分镜参考表。
- 四个 Agent（剧本改写、资产提取、分镜拆解、提示词生成）都是一次性任务，不是流式对话；中文提示词共 165 行。
- 界面不能单条增删分镜；台词写在分镜描述文本里，没有独立字段。
- 规模：前端工作台单文件 6625 行，剧详情页 1750 行；TS 后端短剧相关约 6900 行。
- 它是单用户单机工具，技术栈不同（Go / TS + Vue），代码不能直接搬，只能按功能重新实现。

aiNovel：

- 文本模型、后台任务引擎、实时输出都已具备；章节、独立场景、角色与世界观设定、章摘要都是现成的可读来源。
- 后台任务类型清单 `TASK_KINDS`（`backend/app/models/entities.py:61`）不是数据库约束，新增类型不需要迁移。
- 已有 DOCX / Markdown / TXT 组合导出（`backend/app/services/document_export/`），可参照其授权与下载约定。
- 作品协作有查看者、编辑者两种角色（`backend/app/models/collaboration.py:29`）。
- 作品备份的表规则注册表要求所有与作品相关的新表登记（`backend/app/services/project_transfer/registry.py:103`、`:199`），当前格式 v18。

## 细节取值

默认取值（未单独征询，评审时可改）：

- 一集最多选 20 章，原始内容不超过 6 万字；一部作品最多 20 部剧，一部剧最多 200 集，一集最多 200 条分镜。
- 风格预设照搬参考项目的 9 种，写在插件代码里。
- 剧本格式照搬参考项目：场景头 `## S编号 | 内景/外景 · 地点 | 时间段`，动作为自然段，对白为「角色名：（状态）台词」。
- 导出格式为 DOCX 与 Markdown。
- 短剧的提示词本期不进入「提示词模板」页，作者不能覆盖；项目智能体本期不读取短剧数据。
