# 章节分析与回写（P0-4）

> 父任务：`10-23-mumu-parity`。对应差距项：A10 章节分析、A11 按建议重写、A7 章节摘要。
> B6 伏笔已拆到 `foreshadows`，B7 剧情记忆已并入 `knowledge-base`（见 D1）。
> 依赖（均已归档）：
> - `chapter-versions`：重写会生成版本
> - `task-engine`：分析作为任务运行
> - `story-entities`：`relationship_service.apply_change`、组织成员、角色 `current_state/life_status`
> - `career-system`：`career_service.apply_assignment`
>
> 后续 `foreshadows` 会使用本任务保留的伏笔候选，`knowledge-base` 会使用本任务产出的摘要和情节点。
> 技术设计见 `design.md`，执行计划见 `implement.md`。

## Goal

为长篇一致性补上"写完 → 分析 → 回写设定 → 下一章用上"这个闭环。每章写完后，AI 提炼摘要、情节点和钩子，识别角色、关系、组织、境界的变化，回写到设定里，并给出质量评分和改进建议。写下一章时，前情提要用的是真正的章节摘要，而不是正文前 200 字。作者可以按建议一键重写，并对比重写前后的评分。

## Background（代码证据）

- 现在的前情提要是 `context_builder._summary_line`，只是截取每章正文前 `SUMMARY_CHARS = 200` 字（`backend/app/services/context_builder.py:41,114`）。
- 回写所需的写入入口都已经有了：
  - 关系：`relationship_service.apply_change(source="analysis", chapter_no=...)`
  - 境界：`career_service.apply_assignment(source="analysis")`
  - 两者都会写历史，而且只追加，不覆盖原有语义（`.trellis/spec/backend/story-entities.md`）。
  - 组织成员和角色的 `current_state`、`life_status` 目前只能直接改字段，没有历史。
- 版本：`VERSION_SOURCES = (manual, baseline, generate, polish, rewrite, restore)`（`backend/app/models/entities.py:34`）。整章生成和润色走 `generation_service` 与 `task_engine/handlers/chapter.py`，资源键是 `chapter:{id}`。
- 任务引擎的 `resource_key` 语义是"冲突即拒绝"，没有"同键排队串行"的能力。`TaskHandler` 也没有任务成功后的回调。
- `Project` 只有 `title、genre、premise、style、status`，没有项目级开关。
- MuMu 的做法与问题（`../10-23-mumu-parity/research/mumu-creation-core.md` §7–8、`mumu-story-settings.md` §3、§7）：
  - 分析结果按章节唯一，没有历史；评分全由大模型自评。
  - 分析不进统一队列，失败会阻塞下一章。
  - 回写关系时会覆盖关系名，而且无法撤销。
  - 重写的版本功能是空的。

## Key Decisions

- **D1（用户确认）：拆分。** 本任务负责章节分析、摘要、回写设定和按建议重写。伏笔管理拆成新子任务 `foreshadows`，紧接着做；本任务从分析结果里输出伏笔候选，原样保存。向量剧情记忆并入 `knowledge-base`，统一做检索基建。
- **D2（用户确认）：分析的触发方式。**
  - AI 整章生成、润色或按建议重写成功后，自动排队分析本章，由项目级开关控制，默认开启。
  - 手动编辑不触发分析，只把这一章标记为"分析已过期"。
  - 另外提供手动分析，以及"一键分析全部未分析或已过期的章节"，按章节顺序排队。
  - 分析走后台任务，不阻塞下一章生成；分析失败只影响本章。
- **D3（用户确认）：回写设定的方式。**
  - 常规变化自动写入，可以逐条撤销：角色当前状态；已有关系的亲密度、状态、描述；境界；组织成员和职位。
  - 重大变化进入待确认清单，作者确认后才写入：角色死亡或失踪（`life_status`）、新建关系。
  - 名字对不上已有角色的变化只做提示，不写入。

## Requirements

- **R1 章节分析任务**：新增任务类型，对章节当前正文进行分析，产出以下内容：
  - 摘要（约 150–300 字）和情节点；
  - 钩子，含类型和强度；
  - 冲突与情感走向；
  - 角色、关系、组织、境界的变化；
  - 伏笔候选，只保存，不在本任务里处理；
  - 质量评分：整体、节奏、吸引力、连贯性四项，1–10 分，附评分标准说明；
  - 改进建议，含类别、优先级和建议内容。

  另外由本地规则计算客观指标（字数、段落数、平均段长、对白占比），不依赖大模型。
- **R2 分析历史与过期**：
  - 每次分析都单独保存，不覆盖旧结果。
  - 章节显示分析状态：未分析、分析中、已分析、已过期。正文和分析时不一致，就算已过期。
  - 可以查看历史各次的评分走势。
- **R3 触发与排队**（D2）：
  - 自动分析由项目开关控制。
  - 同一章已有排队中的分析时，不再重复排队。
  - 同一项目的分析串行执行，按入队顺序进行，保证回写顺序和章节先后一致；不同项目之间可以并行。
  - 提供手动分析和一键分析。
  - 分析任务出现在任务面板里，可以取消。
- **R4 回写设定**（D3）：
  - 常规变化通过现有的统一入口写入，来源记为 analysis，并带上章节号。
  - 重大变化进入待确认清单。
  - 每条变化都记录变化前和变化后的值，以及状态：已写入、待确认、已撤销、已拒绝、已跳过、失败。
  - 撤销时，只有当前值仍等于当时写入的值才恢复成原值，否则提示"已被后续修改"。
  - 如果某个字段最近一次分析回写来自更晚的章节，本次不再覆盖它，记为"已跳过"。这样重新分析较早的章节，也不会把设定改回旧状态。
- **R5 摘要接入上下文**：
  - 前情提要优先使用每章最近一次分析的摘要，没有分析时退回"正文前 200 字"。
  - 已过期的摘要照常使用，因为手动小改通常不影响摘要。
  - 其余裁剪顺序不变。
- **R6 按建议重写**：
  - 在分析结果里勾选建议，补充额外要求、需要保留的要素，以及可选的目标字数，然后整章重写。
  - 重写作为后台任务运行，结果直接覆盖正文，覆盖前自动保存旧版本，新版本的来源记为"按建议重写"。
  - 完成后按 D2 自动重新分析，界面上能对比重写前后的评分。
- **R7 界面**：
  - 章节编辑器新增"分析"面板，内容包括：评分和客观指标、摘要、情节点、钩子、建议（可勾选后重写）、回写清单（撤销、确认、拒绝）、分析历史和评分走势。
  - 章节列表显示分析状态。
  - 项目概览里放自动分析开关和一键分析入口。
- **R8 安全**：分析、回写、撤销、确认、重写都要校验项目归属，非所有者一律返回 404。

## Acceptance Criteria

- [ ] **AC1（R1/R2）**：分析一章后能看到摘要、情节点、钩子、四项评分、建议、客观指标，以及伏笔候选的原始数据。再分析一次，会新增一条历史，旧结果保留。
- [ ] **AC2（R2/D2）**：手动编辑正文后，章节变为"已过期"，并且没有自动分析；AI 整章生成成功后会自动排队分析。关闭项目开关后，生成成功也不再自动分析。
- [ ] **AC3（R3）**：一键分析 3 个未分析的章节，会按章节顺序串行执行；同一章重复触发只排队一次。分析失败不影响下一章的生成。
- [ ] **AC4（R4/D3）**：分析得出"林远重伤"、"与张三亲密度降到 20、状态变为破裂"、"林远升到金丹"、"李四加入青云门"四项变化后：
  - 这四项自动写入，各自的历史来源为 analysis，并带上章节号；
  - "苏晚死亡"和"林远与王五新结为宿敌"进入待确认清单，确认后才写入；
  - 名字对不上的变化只做提示。
- [ ] **AC5（R4）**：撤销一条已写入的关系变化，关系恢复原值，并新增一条历史。如果该值已被手动改过，撤销会被拒绝，提示"已被后续修改"。先分析第 5 章，再重新分析第 3 章，第 3 章不会覆盖第 5 章写入的状态，相关项记为"已跳过"。
- [ ] **AC6（R5）**：第 2 章有分析后，生成第 3 章时，生成记录里的提示词前情提要部分是第 2 章的摘要，而不是正文开头。
- [ ] **AC7（R6）**：勾选 2 条建议执行重写后：正文被覆盖，旧稿和新稿都出现在版本列表里，新版本来源为"按建议重写"；随后自动完成重新分析，面板能对比前后两次评分。
- [ ] **AC8（R8）**：其他用户访问分析、回写、撤销、确认、重写接口，一律返回 404。
- [ ] **AC9（质量）**：后端 ruff 和 pytest、前端 lint、test、build 全部通过，所有 chunk 小于 1500 kB；原有的生成、版本、任务、上下文测试的覆盖都不倒退；spec 已同步。

## Out of Scope

- 伏笔管理（归 `foreshadows`）、向量检索和语义记忆（归 `knowledge-base`）。
- 正文上的可视化标注（钩子、情节点的高亮定位）。
- 根据分析自动新建角色或组织。
