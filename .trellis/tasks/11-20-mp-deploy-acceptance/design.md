# C7 部署、迁移与多进程验收设计

需求与验收见 [prd.md](prd.md)，总体约束见[父任务设计](../../../11-20-multiprocess-task-scheduling-deploy-drill/design.md)。C1–C6 已收口；C8 尚未实施。预研和未验证边界见[迁移预研](research/migration-research.md)。

## 1. 交付边界

支持 PostgreSQL 16 的同一实例多 Uvicorn worker 和多应用实例，以及 SQLite 同机共享文件的多进程。默认仍为一个 worker。涉及数据库结构变化时继续先排空、停服，不允许新旧版本混跑；同版本重启被停止进程上的运行任务按原恢复规则处理，不自动重跑模型。C7 不操作线上环境。

交付物包括 Alembic 在线迁移互斥与失败回滚、可配置的镜像启动、多实例 Compose 示例、真实多进程验收脚本、当前版本的部署及排空说明、受影响规范和 TODO。C8 未完成时不宣称 `0043` 升级、恢复快照和旧代码回滚已验收，也不勾选其待办。

## 2. 在线迁移互斥及失败保护

迁移锁围绕整个在线 Alembic 调用，而不仅围绕单个版本；空库也必须取得互斥后才检查版本或建表。直接执行的在线 `upgrade`、`downgrade`、`stamp` 等沿用同一防线，离线 SQL 生成不取得锁。现有迁移的活 worker、租约侧库和数据保护必须继续生效。迁移锁不代替业务期租约，也不允许跨版本混跑。

### PostgreSQL

使用固定、项目专用的 64 位会话级 `pg_advisory_lock`，在同一实际数据库连接上等待锁、读取版本、运行迁移并完成事务，最后解锁并关闭。`NullPool` 保证连接不被放回池复用；若数据库连接池代理不能保证整个会话落在同一后端，迁移使用直连或会话池连接。并发者取到锁后重新读取版本，已为目标版本则不再执行迁移。异常先回滚再释放连接，不能启动 HTTP 服务；连接中断或提交结果不明时失败退出，重新核验实际状态。

### SQLite

仅支持同一主机、同一数据库文件和受支持的本机文件锁；主库及其租约侧库／生命周期锁须位于所有进程可访问的同一目录，遵守已有冷恢复规则。迁移专用连接在任何事务之前确认 `foreign_keys=OFF`，并显式发出 `BEGIN IMMEDIATE`，覆盖初次版本检查、全套迁移和版本更新。Alembic 在这个已有的真实事务里执行；提交前运行 `foreign_key_check`，失败则整笔回滚。应用自身的数据库连接继续按原规则开启外键。

现存历史迁移只有在外键开启时才走 `autocommit_block()`；迁移专用连接关闭外键可避开这些提交点。必须增加约束和回归，确保迁移过程中没有其他提交、自动提交块或独立连接修改结构。将来确实需要事务外迁移时先重新设计，不能宣称原子性仍成立。等待 SQLite 写锁只对真实忙锁进行可中断的重试，持续等待时有可辨识日志；非忙锁异常直接失败。不能把单次默认 5 秒忙等待当成迁移一定完成的上限。

### 失败与重试

迁移期间所有启动实例都等待或失败；任何一个实例只有自己的迁移命令成功后才启动应用。持锁者报错或被强杀后，数据库应回到完整旧结构；后继实例可以在重新取得锁后执行一次完整迁移。若失败条件持续存在，所有实例都退出且没有公开 HTTP 服务。若故障是暂时的，后继迁移完整成功后正常启动，不需要人为保留失败状态。SQLite 同时验证业务数据、版本与 schema，PostgreSQL 同样验证数据与 DDL；额外测试持锁者在提交前被杀、提交已确认后重启以及锁等待超出 5 秒。已有侧库不可见、身份不符或已有活 worker 时保持现有失败关闭行为。

## 3. 启动与连接方式

- 镜像支持 `UVICORN_WORKERS` 正整数，默认 `1`；无效值明确失败。迁移只在容器启动时运行一次，成功后用 `exec` 启动 Uvicorn，让信号正确送到服务进程。Compose 和 `.env.example` 显式传入，原有默认启动保持兼容。
- 验证 4 worker 时按「实例身份 + PID」统计，不把每进程的请求租约和调度租约误算成 8 个 worker。`/healthz` 不检查数据库；验收同时核对实际进程、有效租约及可受理的公开请求。
- 同容器多 worker 默认使用同一私有 UDS 目录。跨容器或跨主机使用 `TASK_PEER_BIND_HOST`、`TASK_PEER_ADVERTISE_HOST`、`TASK_PEER_PORT`、`TASK_PEER_NETWORKS` 配置可直达的内部 TCP。每个进程实际监听端口不同；默认 0 使用系统分配端口，网络策略须允许其他实例直达全部实际端口。通告地址不可是回环、通配或多个实例共享的负载均衡名。
- 给出两个有独立服务名和公开端口的 Compose 实例示例，同用 PostgreSQL、`JWT_SECRET`、`ENCRYPTION_KEY` 和共享 `BACKUP_DIR`；容器内监听端口不直接暴露到公网。内部协议有鉴权但不提供传输加密，跨主机使用受信私网或加密隧道。代理关闭 SSE 缓冲，读取超时覆盖长连接。共享卷必须实测两主机可见且支持备份文件所需的跨主机锁；同机容器验证不能冒充跨主机文件系统验证。
- 通道故障按 C4 既有语义：作者可跟随持久快照；协作者无法证明运行中帧来源时受控结束，允许客户端重连，不能为追求连续显示而绕过授权。

## 4. 时间与运维契约

以当前代码和实测为准记录：执行者心跳间隔 5 秒、租约 30 秒、安全余量 5 秒、调度兜底周期 5 秒、输出节流 2 秒、SSE 心跳 15 秒；本人取消在意图提交后等待终态的预算为 10 秒，数据库操作可能使请求总耗时更长。30 + 5 秒只是在数据库可访问、事件循环正常且无持续锁争用等前提下的恢复目标；时间从最后一次确认心跳和实际扫描时刻计算，崩溃后立即重启不会立即接管。持续锁、数据库故障、外部副作用待核对等情况应记录实际状态，不承诺无条件上界。设置、取消和收尾时间通过真实进程测量。

CPU 密集操作的 `CapacityLimiter(2)` 和拆书正则的两个名额按各进程、各限制器分别计算；多 worker 时总占用会随进程数增加。后台任务的全局和每用户名额仍由数据库统一约束，两者不得混为一谈。

README 写当前版本的多进程升级步骤：开启排空、处理待审核与同步请求、等待后台任务及收尾归零、手动备份并验证、停止所有实例、迁移和启动新版本、核验健康及执行者、关闭排空。停服和备份失败时停止升级并保留现场。涉及旧版协作数据的完整升级和恢复配套旧代码由 C8 另演练；C7 不提前写成已验证。

## 5. 验收矩阵

以隔离的临时 SQLite 文件、PostgreSQL 16 容器、本地受控模型和真实 HTTP/SSE 为基础；不得读取项目 `.env` 或使用现有数据库及卷。复用 C4/C5/C6 的真实进程脚手架，但逐项记录本次实际结果。三种形态分别为 SQLite 同机多进程、PostgreSQL 同实例多 worker、PostgreSQL 两个独立应用实例；每个形态的进程身份、端口和任务实际执行者必须可证明。跨主机共享卷另记录真实环境结果或明确未覆盖。

| 父任务验收 | 每种适用形态的观察点 |
| --- | --- |
| AC1 | A 运行任务、外部调用、备份和删除期间启停 B；核对 A 归属、结果和没有误标中断。 |
| AC2 | 强杀实际持有进程；测量到接管收尾，核对占用释放、可重试及重启后不重复收尾。 |
| AC3 | 并行创建多用户及同串行键任务，观察全局／用户上限、顺序、最大活动数和模型调用次数。 |
| AC4–AC5 | 从非持有进程发起本人取消、管理员取消和作品删除；观察真实执行体退出、唯一回退及删除顺序。 |
| AC6 | 跨进程作者和协作者订阅逐帧比对；撤权及降级后无后续受保护字节；只断内部通道并验证第 3 节的两种降级行为。 |
| AC7 | 从一个进程关闭注册、MCP 与调整并发设置，观察另一个进程的下一次判定和时间收敛。 |
| AC8 | 备份竞争与不误伤、同一步灵感互斥、跨进程导入预览／确认、智能体会话互斥均走真实入口。 |
| AC9 | 两端核验排空后的新建、继续、重试拒绝；原任务完成，管理状态和存活进程正确，关闭后恢复。 |
| AC10 | 空库与带数据旧库同时启动三个实例；注入故障、延长持锁、强杀持锁者并检查锁释放与失败保护。 |
| AC11 | 仅 SQLite：AC1–AC9 期间记录 HTTP、应用日志和数据库锁错误，确认无数据库忙错误以 500 返回。PostgreSQL 两列标记不适用。 |
| AC12 | 单进程后端与前端全量、lint、构建；记录通过、跳过和已知失败。 |
| AC13 | 属于 C8，C7 不将当前版本排空演练冒充旧版升级与回滚。 |

`research/verification.md` 逐项保留实际命令、进程、数据库版本、断言、故障和结果；输出不包含模型密钥、令牌或用户正文。任何缺测或失败阻止相应能力被写成已完成。

## 6. 回退与限制

开发期间只在隔离库操作；迁移失败保留日志及库，检查完整性后再决定重试。发布升级必须先有可验证的完整快照并保留匹配的旧版本；需要回退时停新服务并使用升级前快照，不能直接用旧代码连接已升级的库。SQLite 的快照恢复与租约文件重新配对沿用现有 README。脚手架只能清理自己创建、带唯一标记的临时资源，不能清理用户现有容器、库或文件。
