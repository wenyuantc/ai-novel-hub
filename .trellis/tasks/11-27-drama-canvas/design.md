# 短剧插件（无限创作画布）：技术设计

> 需求见同目录 `prd.md`（C1–C9）；决定编号见父任务 `prd.md`（D10、D11、D18、D19）。
> 建立在 `11-27-short-drama-plugin/design.md`、`11-27-short-drama-media/design.md` 及两项核心能力的设计之上。
> 参考项目没有画布（调研第 7 节），本设计没有可对照的先例。

## 1. 设计原则

1. **结构与结果分开保存。** 节点的位置、连线、文字是「人编辑的结构」，带修订号、会冲突；生成出的图片与视频是「服务端写入的结果」，
   单独存表、不参与结构的修订号。这样后台生成不会和人的拖动互相覆盖。
2. **引用节点不存内容。** 拖入的剧内素材只存「指向谁」，显示与生成时实时取源头的当前内容（D19）。
3. **生成复用已有能力。** 画布不实现自己的模型调用，文本走现有文本调用，图片与视频走核心的图片选项与外部任务驱动器。
4. **增量保存。** 画布可以很大，保存的是一批操作而不是整张图。

## 2. 结构

在 `backend/app/plugins/drama/` 内新增：

```
models.py            # 追加 4 张表
services/canvas.py   # 画布、节点、连线的读写与校验（含环检测）
services/canvas_run.py   # 汇集上游输入、发起生成、写入结果
services/canvas_refs.py  # 引用节点的解析与「存回」
handlers.py          # 追加 drama.canvas
api/canvas.py
backend/alembic/versions/0085_drama_canvas.py    # 编号以实施时的链尾为准
```

前端 `frontend/src/plugins/drama/canvas/`：页面、三种节点组件、素材侧栏、操作队列与保存逻辑。画布库用项目已有的 `@xyflow/react`
（`frontend/package.json:23`，目前只用于人物关系图）。

## 3. 数据模型

`drama_canvases`：`id`、`series_id`（CASCADE）、`name`、`viewport`（JSON：x、y、zoom）、`revision`、时间戳。每部剧最多 10 块。

`drama_canvas_nodes`：

| 列 | 说明 |
| --- | --- |
| `id` | `String(36)`，由前端生成的 UUID（新增节点不必等服务端返回） |
| `canvas_id`（CASCADE） | |
| `type` | `text` / `image` / `video` |
| `x`、`y`、`width`、`height` | 位置与尺寸 |
| `ref_type`、`ref_id` | 引用节点的来源：`look` / `scene` / `prop` / `shot`；为空即普通节点 |
| `text` | 文本节点的内容；图片 / 视频节点的生成提示词补充 |
| `settings` | JSON：画幅、时长、分辨率等生成参数 |
| `current_result_id` | 当前展示的结果（SET NULL） |

每块画布最多 300 个节点。

`drama_canvas_edges`：`canvas_id`（CASCADE）、`source_id`、`target_id`，三列复合主键；节点删除时连线随之删除。

`drama_canvas_results`：`id`、`node_id`（CASCADE）、`kind`（`text` / `image` / `video`）、`text`、`media_object_id`、`poster_object_id`、
`job_id`（→ `ai_external_jobs`，SET NULL）、`status`（`pending` / `generating` / `ready` / `failed` / `cancelled`）、`params`（JSON 快照：
实际使用的提示词与输入节点清单）、`error_message`、`source`（`generated` / `uploaded`）、时间戳。每个节点最多保留 10 个结果。

媒体对象归属与短剧其他媒体一致：`scope=project`、`plugin_id='drama'`。

## 4. 连线规则（C3）

连线表示「上游内容作为下游生成的输入」。允许的组合：

| 上游 → 下游 | 含义 |
| --- | --- |
| 文本 → 文本 | 作为待改写 / 扩写的素材 |
| 文本 → 图片、文本 → 视频 | 作为提示词 |
| 图片 → 图片、图片 → 视频 | 作为参考图 |
| 视频 → 任意 | 不允许（四家视频模型的参考视频能力不在本期范围） |

- 不允许自连、重复连线、成环。成环检测在服务端做（在同一事务内对该画布的连线做一次可达性搜索），前端同样做一次以即时反馈。
- 引用节点只能作为上游，不能作为下游（它不可被生成覆盖，D19）。
- 多个文本上游的拼接顺序：按上游节点位置从上到下、从左到右（见 `prd.md` 细节取值）。
- 图片上游数量超过所选模型的参考图上限时，生成前在界面提示将被忽略的节点，服务端按同一顺序截断。

## 5. 保存与并发（C7）

- 读取：`GET /canvases/{id}` 返回节点、连线、各节点当前结果的摘要与 `revision`；引用节点同时带上源头的当前内容。
- 写入：`POST /canvases/{id}/ops`，请求体 `{revision, ops: [...]}`，一个事务内按序执行，成功后 `revision + 1`。操作类型：
  `add_node`、`update_node`（位置、尺寸、文字、设置）、`delete_node`、`add_edge`、`delete_edge`、`set_viewport`、`set_current_result`。
- 前端把本地操作排队，防抖后成批提交；拖动只在松手时产生一次 `update_node`。
- 冲突：`revision` 过期返回 409，响应带上服务端当前画布。前端不丢本地未提交的操作：在最新状态上重放仍然有效的操作
  （目标节点还在的移动与编辑、不产生环的连线），其余的列给用户看；无法自动处理时提供「重新载入 / 保留我的版本并覆盖」。
- 结果行由生成任务写入，不改变 `revision`；前端通过任务的实时输出与一次按节点的结果查询更新显示。
- 不做多人实时协同（见 `prd.md` 范围外）。

## 6. 生成（C4）

接口 `POST /canvases/{cid}/nodes/{nid}/run`，受理时在同一事务内：

1. 读取该节点的上游节点，按第 4 节规则汇集输入；引用节点解析为源头的当前内容（文字、选定图）。
2. 上游的普通图片 / 文本节点若还没有可用结果，拒绝受理并指出是哪个节点（不做整图自动重跑，见范围外）。
3. 新增一行结果（`pending`，写入 `params` 快照）；视频另加一行 `ai_external_jobs`。
4. 创建任务 `drama.canvas`，资源键 `drama.canvas_node:{nid}`（同一节点不并发生成；不同节点可以同时进行）。

执行：

- 文本节点：以连入的文本为素材、节点自身的 `text` 为指令，调用文本模型，流式输出，成功后写入结果。
- 图片节点：提示词 = 连入文本拼接 + 节点补充文字，参考图 = 连入图片；调用图片模型（核心的 `ImageOptions`）。
- 视频节点：同上组装后经核心的外部任务驱动器生成；成功后探测时长、抽海报帧。
- 取消、失败、重启续等、用量与预算：沿用短剧媒体制作与核心能力的既有机制。

上传：图片 / 视频节点可上传文件作为一个 `source=uploaded` 的结果（体积上限经框架的 `upload_limits` 登记：图片 10MB，视频 200MB）。

## 7. 引用与存回（C5、C6、D19）

- 拖入：从素材侧栏把造型、场景、道具、分镜拖到画布，产生 `ref_type` / `ref_id` 非空的节点。造型 / 场景 / 道具成为图片节点；
  分镜成为视频节点（显示其选定视频），其视频提示词可作为文本被引用——为保持连线规则简单，分镜引用节点只能把「提示词文本」作为输出连到下游。
- 显示：引用节点带「引用」标记与来源名称，内容只读；来源被删除时显示「来源已删除」，节点保留、不能再作为输入。
- 校验：`ref_id` 必须属于同一部剧；来源删除时节点的引用列保留原值，读取时解析不到即视为已删除（不建外键，因为四类来源在不同的表）。
- 存回（`POST /canvases/{cid}/nodes/{nid}/promote`，请求体指明目标）：
  - 图片结果 → 某个造型 / 场景 / 道具的一张新资产图；
  - 视频结果 → 某条分镜的一个新视频版本。
  做法是复制媒体对象（媒体存储的 `copy`）并在目标表新增一行，之后两者各自独立；不自动设为选定，由用户在资产页或视频制作页决定。
  目标表的数量上限（每资产 10 张、每分镜 10 个版本）照常生效。

## 8. 接口汇总

前缀 `/api/v1/plugins/drama`。读需 `content.read`，改动与上传需 `content.edit`，生成需 `ai.use`。

| 接口 | 说明 |
| --- | --- |
| `GET/POST /series/{sid}/canvases`、`PATCH/DELETE /canvases/{cid}` | 画布的增改删（改名） |
| `GET /canvases/{cid}` | 整张画布 |
| `POST /canvases/{cid}/ops` | 批量操作 |
| `POST /canvases/{cid}/nodes/{nid}/run` | 生成 |
| `GET /canvases/{cid}/nodes/{nid}/results`、`DELETE /canvas-results/{id}` | 结果历史与删除 |
| `POST /canvases/{cid}/nodes/{nid}/upload` | 上传 |
| `POST /canvases/{cid}/nodes/{nid}/promote` | 存回 |

## 9. 前端

- 页面路径 `drama/:sid/canvas/:cid`（挂在 `projects/:pid/features/` 下）；从剧详情页的「画布」标签进入，那里列出该剧的画布并可新建。
- React Flow 配置：自定义三种节点组件（均用 `memo`）、只渲染视口内元素、缩放与平移、小地图、框选与多选删除、键盘删除与撤销（撤销只作用于本地尚未提交的操作）。
- 节点外观：文本节点为可编辑文本框；图片节点显示当前结果的缩略图；视频节点显示海报帧，点击后才加载播放器，避免一百个节点同时拉视频。
  节点头部有状态（生成中、失败原因）与「生成 / 取消」「历史」「存回」「上传」。
- 素材侧栏：按角色（造型）、场景、道具、分镜分组，可搜索，拖出即建引用节点。
- 性能目标（验收：一百个节点拖动与缩放不卡顿）：位置变更只更新本地状态，松手才入保存队列；节点组件不订阅整张图的状态；缩略图用媒体对象的 `thumb` 派生文件。
- 查看者：可平移、缩放、播放，所有编辑与生成控件隐藏，节点不可拖动。

## 10. 备份与删除（C9、D18）

- 作品备份规则：`drama_canvases`、`drama_canvas_nodes`、`drama_canvas_edges` 导出（节点的 `current_result_id` 排除；`ref_id` 按 `ref_type` 重映射到导入后的新 id）；
  `drama_canvas_results` 中只导出 `kind=text` 的结果，媒体结果不导出。导入后图片 / 视频节点为空，可重新生成。
- 删除节点、画布时，服务层先标记其结果的媒体对象删除；删除剧、作品时经由上层的级联与媒体存储的作品级标记处理。

## 11. 权衡记录

| 问题 | 选择 | 放弃的方案与原因 |
| --- | --- | --- |
| 保存方式 | 操作批次 + 修订号 | 整图覆盖保存：画布大时请求体大，且与后台生成更容易冲突 |
| 冲突处理 | 重放本地操作，无法处理的交给用户 | 实时协同（操作变换或 CRDT）：远超本期范围 |
| 结果与结构 | 分表，结果不参与修订号 | 结果写进节点行：每次生成完成都会让正在编辑的人遇到冲突 |
| 引用节点的实现 | 存指向，读取时解析 | 外键约束：四类来源在不同表，需要四个可空外键列，换来的只是删除时的自动置空 |
| 存回 | 复制媒体对象 | 共用同一对象：需要引用计数，删除语义复杂 |
| 上游未就绪 | 拒绝并提示 | 自动沿图向上依次生成：等于流程引擎，费用不可控 |
