# 浏览器验收记录

2026-11-27 在本机用独立 Chrome 158 测试配置、Playwright/CDP、Vite、实际 FastAPI 进程、迁移至 0081 的临时 SQLite 数据库和真实 HTTPS RustFS 验证。管理员通过登录页进入应用。

| 场景 | 操作与结果 |
| --- | --- |
| 大视频拖动播放 | ffmpeg 生成 64,154,296 字节、60 秒、960 × 540 的 H.264 MP4。用应用的 `store` 和 `store_derived` 写入视频及封面，再在临时页面挂载项目的 `MediaVideo` 组件。浏览器使用登录会话读取文件，封面返回 200。 |
| 分段传输 | 下载限速 2,100,000 字节/秒。用鼠标拖动浏览器原生进度条到 31.82 秒。Chrome 收到从第 33,161,216 字节开始的 206 响应，定位时观测到约 1.48 MB 的视频及封面响应数据，随后播放至 32.83 秒。`readyState` 为 4。 |
| 375 像素管理页 | 打开实际路由 `/admin/media-storage`，视口宽度与页面滚动宽度均为 375，表单、占用统计与卷诊断可访问。 |
| 切换存储 | 从管理页填写独立测试用 RustFS 的端点、凭据及对象前缀，测试连接返回 200。确认切换后 PATCH 返回 200，修订号从 1 升为 2，S3 成为当前使用位置，原本地位置为只读。再确认切回本地，PATCH 返回 200，修订号升为 3，S3 变为只读。 |
| 客户端异常 | 两次验收均未捕获页面 JavaScript 异常；开发服务器报告了项目现有的 React Router v7 迁移提示。 |

截图保存于本目录下的 `screenshots/`，分别记录了拖动后的视频画面、初始管理页和切回本地后的历史位置。测试页只负责挂载视频组件，媒体请求、浏览器控件、身份校验和存储均使用项目实现。
