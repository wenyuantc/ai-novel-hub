# TODO #28 协作批注

## 目标

查看者读到一句有疑问的正文时，可以选中原句提问。编辑者和作者能在同一处回复，作者改完稿后能把讨论标为已处理。入口设在章节工作台，普通阅读保持现有体验。

## 使用规则

- 作者和已经接受这本作品邀请的查看者、编辑者可查看讨论、发起批注和回复。只有作品作者可标记已处理。批注不授予修改正文的权限。仅有后台作品管理权限或仅加入系列的账号，没有本书协作批注入口。
- 一条讨论绑定一个已保存场景的一段正式正文。选区可以跨段，不能跨场景、穿过作者区块或落在区块里。提交时稿件已经变化，就保留输入的意见并请用户重新核对选区。
- 讨论显示原句摘录、留言人、时间、按时间排列的回复和处理状态。能够可靠定位时可跳回正文。定位失效时保留摘录与讨论，显示“原文位置已失效”，关闭跳转。已处理的讨论仍可查看。
- 单书 JSON 和整库备份每次都包含全部批注与回复，无需勾选。已处理的讨论和原文位置已失效的讨论也在备份范围内。恢复单书后，作品作者可查看审稿历史并继续处理意见。
- 首版聚焦发起、回复、处理和回看。手动重新绑定、重新打开讨论、编辑或删除留言、通知提醒及实时共同编辑留待后续。

## 验收条件

| 编号 | 可观察结果 |
| --- | --- |
| A1 角色 | 查看者在章节工作台选中第二段的一句后发言，编辑者刷新后能回复，作者能读到两人的意见并标记已处理。查看者仍无法保存正文，编辑者无法把讨论标为已处理。 |
| A2 定位 | 同一句在场景中出现两次，只批注第二处。再次打开应选中第二处。已知的修改发生在选区之前时，位置按实际改动平移。原句被删改或无法证明新位置时，显示失效提示并保留讨论，绝不跳到第一处。 |
| A3 边界 | 正文有中文、表情及换行时，刷新后的选区与原句一致。空选区和跨作者区块选区不能建批注。打开输入框后另一标签页改稿，提交过期选区不会生成讨论，意见草稿仍可用。 |
| A4 独立性 | 标记处理前后，正文、字数、正文版本和编辑器草稿都保持原值。位置失效和处理状态可同时呈现，作者可以处理一条原句已被删掉的意见。重复提交同一次回复只显示一次。 |
| A5 撤权 | 撤销协作后，原账号重新请求列表、回复或处理均无法取得或改变讨论。切换账号或作品后，旧页面的慢响应不会恢复旧讨论。其他仍获授权的成员能读到先前发表的意见。 |
| A6 内容隔离 | 仅在批注和回复里分别写入独有测试短语。普通阅读、TXT／Markdown／DOCX／EPUB 书稿和实际发给模型的请求均不含这两个短语，原句仍按正常规则输出。 |
| A7 使用入口 | 在桌面和窄屏分别从章节列表的“查看”进入，能完成选句、回复、跳到有效原句和查看失效提示；流程无需开启正文编辑。 |
| A8 单书恢复 | 给同一作品准备未处理、已处理、位置失效的讨论及多条回复，用默认设置导出并在另一账号下导入。逐条核对原句摘录、留言全文、历史署名、时间和回复顺序。有效批注指向新书的对应原句，失效批注仍提示失效，处理状态一致。新书作者能继续回复和处理，原协作者须获新书邀请才能参与。早于批注功能的备份仍可导入，批注列表为空。 |
| A9 整库恢复 | 用同一组样本制作整库备份，分别在隔离的 SQLite 和 PostgreSQL 环境按现有恢复流程还原。核对 A8 的讨论内容与位置，并验证还原到备份时点的成员关系及权限。 |
