# 富文本编辑、正文标记与分区块

## 目标与用户价值

落实根目录 `TODOS.md` 第 8 项：作者可在场景中直观排版正文，用全书时间线定位待修改文字，并以独立区块管理备注或备选段落，同时控制它们是否作为 AI 的背景材料。升级、改稿和备份不能丢失已有正文与作者资料。

## 已核实的背景与约束

- 当前场景以文本框编辑，选区 API 将 UTF-16 转为 Unicode 码点，先保存再 AI 预览和采纳：`frontend/src/components/scenes/SceneWritingPanel.tsx:27,72`、`frontend/src/components/chapter/RewritePanel.tsx:18,117-119`。
- `Scene.content` 为正式正文的权威，章正文是所有活动场景的 `separator_before + content` 的精确投影，并有内容 CAS、结构历史和 Unicode 拆并：`backend/app/models/scenes.py:9`、`backend/app/services/scene_service.py:59,137,153,213,494,565`、`backend/app/schemas/scene.py:150`。
- 阅读器、提及、TXT／Markdown／EPUB 导出、分析和多个 AI 背景入口消费章纯文本；当前局部 AI 会另外携带选区前后及前序场景（`backend/app/services/rewrite_service.py:110-160`），全场景／整章 AI 会原子替换场景正文（`backend/app/services/generation_service.py:441-468`）。
- 后台引擎已有待审核暂停但暂停不会自动调用资源清理或成功钩子；批量任务使用 checkpoint：`backend/app/services/task_engine/engine.py:9-14,406-411,495-505`、`backend/app/services/batch_service.py:273-292,557-634`。

| ID | 决定 | 对应需求 |
|---|---|---|
| D1 | 区块默认不是面向读者的正式正文：阅读器和常规导出不展示；完整备份保留；转换为普通正文后展示／导出。 | R3、R7 |
| D2 | 新区块默认关闭 AI 上下文，作者可逐块开关；AI 开关与阅读／导出是独立维度。 | R3、R4 |

| D4 | 标记时间线覆盖全书，按章节和场景顺序查看已保存标记并定位；跨章跳转须处理未保存草稿。 | R2 |
| D5 | 阅读器和 Markdown／EPUB 尽可能呈现支持的正文排版，TXT 为纯文字。 | R1、R7 |

| D8 | 场景／整章 AI 改稿保留全部区块及其顺序；无法可靠定位时等待作者核对并选定位置后才采纳；自动／批量任务可能暂停。 | R5、R6 |

| R6 | 自动／批量任务在需要人工确认时持久保存提案并暂停，不占用运行名额，不预先提交当前章；确认后继续原断点、不重复生成或分析，已完成的前章保持。冲突、取消、重启、重复提交和授权变化不得造成半章写入或重复采纳。 |

**实施核验补充（不修改原验收表述）：** AC9 的“恰好一次必要分析”在正常成功路径成立；若进程在记录分析领取后、外部模型请求发送前后崩溃，系统无法判断外部调用是否发生。当前选择不自动重发，并提示作者检查／手动补分析，以免重复计费。因此不能声称任意崩溃情况下外部分析严格恰好执行一次；详见 `research/verification-baseline.md`。

## 风险与边界

- 为兼容旧版，旧正文中手写的 Markdown 符号在 Markdown 导出时仍可能被外部阅读器解释为格式；编辑器及本项目阅读器仍显示原文符号。
- 兼容旧版的 Markdown 原文输出也可能包含作者原先输入的 HTML；第三方 Markdown 阅读器是否过滤这些内容取决于其自身，不能承诺其渲染安全。本项目编辑／阅读视图及 EPUB 不执行这些内容。
- “关闭区块 AI 上下文”控制系统后续自动从该区块取用的内容，不能追回已经发送的请求，也不自动删除先前生成的摘要、聊天、用户手动输入／复制文本，或其他来源中碰巧相同的文字。
- 部分整场景／批量 AI 将从自动完成变为等待作者确认；可用性及成本取决于具体模型和任务，但不能以自动完成为由静默损失资料。
- 富文本格式、标记及区块共用场景正文、历史和 AI 路径；不把一个子功能局部通过当成整项完成。统一为一个实施任务，按 `implement.md` 的顺序切片并在最后做跨切片验收，避免尚未接通的单切片对外发布。
- 技术边界、API、迁移、失败和回滚见 `design.md`；执行顺序和验证见 `implement.md`。达到验收需实际测试，不以规划或原型冒充实现完成。
