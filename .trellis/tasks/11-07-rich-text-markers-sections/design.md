# 富文本、标记与分区块：技术设计

## 1. 目标、边界与取舍

与 `prd.md` D1–D10 和 R1–R9 一一对应。既有单体、权限、场景和任务模型继续使用；不另造协作服务。按可验证的内部切片实施，但在编辑器、历史、AI、阅读和备份全链路接通前不作为完成的单项发布。

候选编辑器采用与 React 18 兼容的 **Tiptap / ProseMirror 开源核心**，使用受限 schema、自定义区块和事务映射；不使用云端、付费评论、云转换或其 AI 服务。当前 npm 元数据及官方文档见 `research/current-boundaries.md`。正式引入前固定互相兼容的版本并验证协议。由于浏览器 DOM 可能标准化换行，先用真实浏览器原型证明旧文本与坐标无损；该门禁失败时继续调整适配器／选择其他本地编辑器，不能降级为自动 trim、重排或 Markdown 解析。

不将富文本文档以 Markdown / HTML 字符串塞回 `Scene.content`：那会把控制符送入 AI、改变纯文本坐标并破坏旧原文。也不让每个出口各自临时剥除标记或区块。

## 2. 数据权威与结构

1. **正式正文**：继续由每个活动 `Scene.content` 保存原始纯文本；`Chapter.content` 仍严格等于有序场景的 `separator_before + content`，章、景字数只按正式正文计算。原始码点、空白、原始换行均不做 normalize。
2. **富格式**：场景新增版本化、严格类型的格式元数据，引用本景正式正文的码点范围。行内支持 bold／italic，块级支持 paragraph／heading／blockquote／有序和无序列表；不同块对正文换行的解释不得产生额外正文字符。为空代表整段现有纯文本，旧景可迁为默认空结构而不重新序列化正文。
3. **区块**：按所属景持久化稳定逻辑身份、正式正文码点锚点及同锚点顺序、名称、独立文本及同样的格式数据、`include_in_ai`（默认 false）和生命周期。区块是作者材料，不拼到正式正文或 `Chapter.content`。同景拖动只改锚点／顺序；转换时在选定锚点将区块文本和格式作为一次原子编辑插入正式正文，并迁移其中标记。折叠仅是视图状态，不改变作品正文和 AI 权限。零正文字符的区块两侧可能映射到相同码点；光标／选区映射还须携带左右偏向、相邻区块身份和同锚点顺序，不能仅凭整数反推。CRLF 中间不是新编辑器的可见光标落点，新结构坐标应显式拒绝而非猜测；旧纯文本场景拆分 API 原本允许按任意合法码点拆分，CRLF 跨场景仍能精确投影，不能因此收紧其兼容行为。
4. **标记**：持久化稳定身份、所属场景、正文或区块目标、颜色、活动／失效状态、有效范围或最后位置及失效时原文片段。活动标记可重叠，独立于正文排版；失效记录不得伪装成有效偏移。有效范围因编辑增长时，只要可可靠定位就继续活动，不能仅因超过摘录上限而失效；确实失效时可保存有明确截断提示的有界原文片段。专用关系表与 `(scene_id, status, position, id)` 等索引支持跨章分页；区块／标记逻辑身份及归属约束须能在快照和新作品导入中校验或重映射。
5. **版本和并发**：正文、格式、区块、标记、区块 AI 规则的一次保存必须在同一事务、同一 `content_revision` CAS 下提交并推进 revision，不能出现只更新纯文本或只更新结构。读取为一致版本；旧客户端没有格式负载时，只允许证明不会损害现存结构的写入，否则 409 并提示使用结构化接口。删除、转换、跨边界替换要作为显式操作，不以缺字段暗示删除。
6. 新建数据的所有权、范围和合理容量由服务端校验：schema 版本／节点白名单、文本区间、无效 UTF-16 分界、层级／大小、重复身份、跨景引用、非法颜色和标记状态等；不得静默截断或修正错误数据。输出不执行用户 HTML。

具体关系模型可按 `models/` 现有约定命名；核心事实只有每景正式文本、其格式结构、各区块文本和标记记录各一份。派生章文本、编辑器节点、阅读投影和时间线缓存均不能成为第二权威。

## 3. 编辑器及 API 契约

- 提供场景文档读取／原子写接口：读取返回正式文本、结构、区块、标记和内容／规划版本；提交携带 `expected_content_revision`、经校验的新文本与结构以及显式新增／删除意图。沿用 `get_manageable_project`／`get_manageable_chapter`、编辑权限、回收站屏障和标准 404／403／409／422。
- 在 `SceneDraftController` 内按 scene ID 管理完整文档草稿；保持保存、离开确认、异步响应失效与 409 本地稿保护。现有只传字符串的旧调用不得覆盖完整草稿。
- 用集中适配器在“编辑器结构位置 / JS UTF-16”与“正式正文或指定区块的 Unicode 码点坐标”间映射。记录所属目标、边界偏向及 revision；选区、区块内部、换行与场景边界不能混为同一个线性偏移。前端可复用 `utils/textOffset.ts` 的码点转换，但结构投影另有一个共享定义。服务端对坐标、非落点和文本 hash 再验证。
- 编辑时用 ProseMirror 事务映射跟踪标记／区块；标记不能可靠映射或选中范围完全消失时转失效并保存快照，不根据相同词面盲猜。区块锚点无法可靠映射时，保留区块内容并要求作者核对位置，不静默移动或删除。普通手写的明确删除区块、撤销、重做、粘贴、拖动及转换须保护其他区块、格式和标记。
- 全书时间线单独提供经鉴权、分页且按章节号／场景序／正文位置及稳定 ID 排序的查询，返回状态、片段、目标身份和必要版本；当前位置失效则只能重关联／删除，不盲跳。跨章跳转复用既有离开保护；草稿内新标记可在当前编辑上下文展示，但全书索引不伪装为已保存事实。
- 现有 Scene split/merge/reorder、旧章 PATCH、Agent replace／effects、提及 deep link、版本恢复均接入共享结构变更服务。可证明无损时迁移相应格式／区块／标记；跨界、顺序归属或历史身份无法无损确定时先预览或以明确冲突拒绝。不得为了兼容清空结构。恢复旧纯文本历史若会移除当前作者资料，必须先对照与显式确认，并记录可恢复的新版本。
- 建议新增专用 `GET/PUT .../chapters/{cid}/scenes/{sid}/document` 与 `GET .../markers`；最终路径沿现有路由风格落地。所有修改保持后台事务所有权、统一错误响应、Actor／项目／授权代次失效及可重试错误语义。

## 4. 阅读、导出、检索与 AI 投影

- **正式投影**：由正文及其格式 metadata 输出读取器视图、Markdown、EPUB；标记不渲染，区块不参与。TXT 从正式正文输出，不因排版添加 HTML／Markdown 格式控制符，但保留作者原本输入的字面符号。旧章原始文字不自动解析或迁移为富格式；旧正文中手写 Markdown 符号在 Markdown 导出中仍按旧版原样输出，外部渲染器可能将其视为 Markdown，这是已确认的兼容权衡。旧稿里本就存在的 HTML 也随旧式 Markdown 原样保留，不能宣称第三方渲染器一定过滤；本应用及 EPUB 必须安全渲染／转义。通过结构化序列化处理新增格式、XML 转义与渲染文本；不使用未净化 `dangerouslySetInnerHTML`。保持旧 EPUB 导航、权限、选章和空章契约。
- **提及与开放读取**：现有整章 hash、正文索引和定位均以正式纯文本计算；格式单独改变不应使字符 hash 虚假变化，内容 revision 仍应推进。阅读标记和提及预览需与格式共存，锚点以同一投影换算。区块不被当作已出版正文索引，转换后才进入。
- **AI 投影**：按确定的章节／场景和正文顺序，增加明确开启的区块作为作者材料；关闭区块连同名称／文本不从区块源自动注入。覆盖当前场景、前景、前章、选区前后文、分析、批量、Agent 工具及其他可出站入口；根据实际来源选择匹配材料，不能先将整个区块拼入后再靠文案请求模型忽略。
- 对关闭区块的明确选区请求，服务端先确认目标范围、版本和一次性用户意图；只从该目标附带所选区间，不能因 before／after、场景上下文或重试再附带其他关闭部分。其他原本允许的正文及设定仍依既有权限／预算发送。一次意图绑定目标、选区、操作与 revision，不能复用于新的目标或变更后的正文；日志不扩大暴露。
- 区块规则变严或相关内容变化时的出站及待采纳快照必须失效；复用／扩展项目 AI 可见版本、真实发送 lease 及现有 Agent 历史封存机制，避免尚未发送的旧快照重新带出已关闭数据。保存文档若可能收紧区块 AI 范围，须遵守现有“权限写屏障 → 可见性写锁 → 作品生命周期／内容 CAS”锁序；无锁验版或反序拿锁不能代替。系统不能识别用户手工复制的相同文字，也不追溯清除先前模型、摘要或对话中已有的派生内容；UI 应说明该边界。

## 5. AI 提案、确认和批量断点

- AI 在旧路径一次完成时不再直接覆盖有结构的场景：先形成目标章的全部场景正文候选，基于原景版本生成格式／标记／区块映射。只对可证明对应的文字／锚点自动继承，重复原文和消失锚点不能凭 diff 或位置猜测。
- 若区块位置或格式存在不确定项，持久化**完整章级提案**、源内容／规划／可见性／区块版本、标记变化、需要处理的身份及模型结果；原章一字不写。释放章节生成状态和运行槽，任务暂停并展示原文／候选、丢失格式以及每个需定位区块。交互允许选定位置、确认格式损失、放弃；单次选区改写复用当前预览。
- 作者确认在服务端重新鉴权并核验目标、revision、上下文快照、提案状态、每个区块恰好一个合法位置及格式风险确认，并保持原区块相对顺序；异步采纳、取消、清理及恢复绑定不可复用的任务 `statistics_key`、提案随机 token 与执行轮次，不能仅依赖可能复用的整数任务 ID。成功后同事务一次应用目标章全部场景、结构、版本和任务进度。409 保留只读提案／草稿供比较，不自动按新稿重放。重复确认幂等，取消不写原章。
- `chapter.generate/polish/revise` 及 `chapter.batch` 需要增加持久 checkpoint 阶段：`awaiting_review → accepted/applied → analyze/continue`。暂停前提案与 checkpoint 必须一致，释放原章抢占；崩溃发生在暂停事件前后也能恢复或明确保留提案，不重新发模型或丢提案。采纳和 batch 游标推进的重试以持久状态／任务身份防止双写；仅整章实际成功后按原规则分析一次。已完成的前章不回退。
- 既有通用 paused 任务的继续、提前结束和取消入口也必须识别提案状态：待确认时不允许普通继续绕过确认或重新发模型；提前结束／取消保留原章且明确未采纳，正确处理提案与章状态，不能伪报生成成功或依赖 paused 的 `on_abort`（引擎不会调用）。并发操作使用同一任务／提案轮次 CAS。
- 普通无结构或能完全可靠映射的结果继续沿现有无中断路径；任务列表、任务面板与详情在待确认、冲突、恢复和终止状态展示真实结果，不将等待状态显示为成功。任务临时提案不是作品正文；终止或项目彻删按生命周期清理，不混入普通作品备份。

## 6. 迁移、备份与回退

- 基于现有 Alembic head 新增迁移；增加元数据／区块／标记与持久提案存储，旧景默认空结构，不重写旧正文、字数、时间或版本。SQLite 与 PostgreSQL 均需真实 upgrade／fresh 测试。若存在新资料或无法安全保留的数据，downgrade 明确拒绝；不通过丢列完成有损降级。
- 场景快照新版本含格式、区块和标记，包括退场身份与失效片段；读旧 schema 1／更早纯文本历史时按真实数据兼容，不补造历史区块。恢复自身必须记录基线／新版本，并检查当前资料丢失和归属冲突。
- 预计项目备份 v8：在 `project_transfer.registry` 登记核心新表、格式 JSON 和所有外键／JSON ID，定义快照的可恢复身份映射；v1–v7 逐级兼容，旧格式非法夹带新结构、错景身份、丢失引用和投影不一致在 preview 拒绝。项目流式导出需检查相同 revision，不能组合多个时点。任务提案按运行态明确登记排除，不损失已保存作者材料。
- 回滚以快照和数据库备份为前提：未产生新资料时可安全降级；有新结构时先导出并保留新版本程序／数据库，不自动降级或伪造旧格式。保持现有正文、场景、AI 和任务入口的只读可见性优先于错误的自动修复。

## 7. 验证与上线风险

重点门禁是全链路实际模型 messages 的来源过滤、重复文本／Unicode 锚点、不确定映射的待确认与恢复、真实数据库 CAS／迁移、格式与纯文本投影一致、备份／历史精确恢复、移动和键盘交互及 HTML 注入防护。具体执行顺序、测试矩阵与命令见 `implement.md`。本设计的临时 Node schema 实验只证明 JSON 文本节点能保留样例，不代表浏览器编辑已无损。
