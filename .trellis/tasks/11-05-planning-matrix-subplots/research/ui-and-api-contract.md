# 研究：矩阵工作台与批量操作契约

- 问题：如何把已确认的章级规划、全类型设定关联及 AI 规划内容展示组织为可实施的界面和接口。
- 范围：现有 UI／API 模式及方案建议。
- 日期：2026-11-05。

## 已确认范围

已有章节＋未建章细纲；建章后承接；POV／支线参与生成和重写；手动关联覆盖角色、全部世界观、组织、人物关系和职业。用户已确认章节分布＋作者维护明确交汇；最终身份／参与数／AI 契约以 design.md 为准。

## 界面建议

1. 增加作品内“规划”入口，独立懒加载 `/projects/:id/planning`，含矩阵与支线交织视图。沿用 `StudioNavigation.tsx:41` 的创作区和 `router.tsx` 的 lazyPage 模式。
2. 矩阵以章节／未建章细纲为行、选择的设定或支线为列；固定行标题，POV 与标签作为可维护的元数据。大纲／分卷用于分组，不制造一纲一章的假设；未建章显示“大纲名 · 细纲 N”，不伪造实际章号。
3. 提供分卷、已建章／未建章、标签、条目类型及名称过滤；行分页、列窗口／选择器均显示总数，不静默丢弃超出窗口的数据。先用项目已有 AntD、原生表格和 SVG，不引入新的图谱库。
4. 格子分别展示手动关联、POV、正文确定提及与歧义。自动提及来源只覆盖现有角色／地点／物品；组织／职业等显示“无自动追踪”，不能显示为“未出场”。无正文与零提及也要分开。
5. 格子可打开说明与操作浮层：查看设定、查看提及、添加／移除手动关联。复用既有设定编辑页的深链或只读详情，组织与职业不能强转成 MentionEntity。
6. 勾选行后出现批量工具条，明确选择作用字段与操作；确认前显示目标数和变更摘要。分页／切换作品／权限变化时清理不再有效的选择，不能对不可见旧选择悄悄执行。
7. 支线独立维护名称、作者概览、颜色及按单元排列的推进文本；作者概览明确标为不自动进入 AI。节点标为“本章推进目标”，不以“有正文”自动认定为已兑现。
8. 支线轨道图提供可键盘访问的等价表格；颜色之外有名称和文本状态。375px 下内容容器自身横滚或切卡片，不能造成页面级横向溢出；支持明暗主题。
9. “AI 规划内容”抽屉展示实际采用的 POV、目标章节点、关联类型和预算提示；未建章明确说明只预览规划指令，建章后才能按真实章号解析有效设定和生成正文。
10. 删除源后仍存在的规划进入“待重新关联”列表，可查看内容并明确重新关联；节点／事件可单独维护，空单元隐藏，首版不硬删除可能被快照引用的 unit 身份。不能悄悄附到相同章号的新章节。

## 批量写入建议

- POV 是单个可空的角色 ID；设置／清空。修改 POV 不隐式改写手动角色集合，AI 使用时对二者去重。
- 标签和实体引用使用 `add | remove | replace | clear` 四种明确操作；省略某字段表示保持不变。`clear` 不接受非空值，`replace` 可用空数组清空，但 UI 统一显示清空含义。
- 全部目标及所有引用先校验，再在同一项目写屏障／事务中应用；任意版本冲突返回 409，整批不写入。人工编辑路由沿现有拥有者／管理员能力，不扩大 AI 代执行权限。
- 手动角色复用已有章出场或未建章细纲的角色列表。新增世界观／组织／职业／关系引用独立存储；关系明确使用 timeline_id，不能使用无类型混合整数数组。MatrixColumn 独立区分设定列和支线列。
- 最终方案采用项目 planning_revision 防止旧界面覆盖新数据、binding_epoch 校验快照中的作者绑定意图；错误沿现有 `{detail, code?, ...}`，不采用通用技能示例中的另一套响应包。
- 首版批量目标上限 100 个，每次操作的实体／标签集合有边界；超限明确 422，不分批提交后声称原子成功。网络超时后先重读状态，不自动盲重放创建或版本冲突请求。

## 验证建议

批量 payload 构建与全部操作组合；两个目标中一个版本过期时无部分写入；跨类型同 ID；关联或源删除后的旧请求；计划建章衔接；自动／手动来源不混淆；授权撤回／旧响应不再刷新旧作品；浏览器验证矩阵交互、图表键盘与窄屏。
