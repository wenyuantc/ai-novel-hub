## 目标与用户价值

让管理员进入后台后快速了解平台规模、待办事项和运行情况，并通过趋势图与历史分析了解平台变化。

## 已确认现状

- `frontend/src/router.tsx` 已有用户管理、作品管理、操作日志和回收站路由，没有管理员汇总首页或全站任务监控路由。

- 用户/作品统计、持久化任务和工坊待审核数据已有基础，分别见 `admin_service.py`、`admin_project_service.py`、`task_service.py` 和 `workshop_service.py`。

- `admin_project_service.list_projects` 通过 `project_lifecycle.active_conditions()` 排除已回收和正在删除的作品；用户管理的作品数仍包含回收站作品，首页不能直接假定两个现有统计口径相同。

- 用户模型保留禁用账号，章节模型保存 `word_count`，工坊投稿存在 `pending` 审核状态；这些字段可作为聚合来源。

- 当前没有平台每日统计记录。`TimestampMixin` 只记录创建与最近更新时间；章节字数会更新，作品彻删会级联删除章节和关联任务，因而不能将现存数据按创建日期分组冒充准确的历史平台总量（`backend/app/models/base.py`、`backend/app/models/entities.py`、`backend/app/services/recycle_bin_service.py`）。

- 现有任务记录可被删除、清理，并按每用户最多 200 条已结束记录裁剪（`backend/app/services/task_service.py` 的 `MAX_FINISHED_PER_USER`）。直接按任务表汇总只能代表仍保留的记录，不能称为完整的历史失败总数。

## 功能要求与统计口径

### R1：全站总览

汇总用户数、作品数、章节数、总字数、工坊待审核数及任务数量，清楚标注统计口径：

- 用户统计覆盖所有仍存在的账号，包含管理员及禁用账号。
- 作品、章节及正文总字数包含回收站中的作品及其章节，不沿用正常作品列表排除回收站的口径；当前总量不包含已经彻底删除的数据。
- 章节按当前章节记录计数；字数沿用服务端 `word_count`，不叠加历史版本或生成日志中的正文。回收、恢复不改变总量，彻删后才减少对应当前总量。
- 工坊待审核数按全站 `pending` 投稿统计，与后台任务的 `paused`（待审核）数量明确区分。

### R2：入口与权限

管理员首页与个人作品概览保持独立，仅管理员可以进入及读取全站数据。统计和待办提供已有管理入口：用户、作品、回收站、操作日志及工坊审核。作品总数包含回收站，跳转时明确正常作品管理与回收站的边界；章节和字数不虚构独立的全站管理页。全站任务监控仍是独立任务，本次不新增未交付模块的失效链接。

### R3：可靠的加载与异常状态

处理零数据、加载中、部分统计失败、重试及各区块的数据更新时间；请求失败不展示为真实的零。刷新失败时可保留上次成功值，但必须标明过期和失败，不能使整页不可用。

### R4：趋势与历史分析

首版完整交付趋势图与历史分析，不缩减为轻量总览。支持近 7 / 30 / 90 天，默认近 30 天，按北京时间（Asia/Shanghai）划分统计日；展示用户、作品、章节及正文总量趋势与净变化，以及任务每日新增和成功、失败、取消、中断的结果数量。规模的净变化允许为负，不能命名为新增用户数、新增作品数或写作产出。新建与结束任务可发生在不同日期，两者不要求日内相等。

规模历史点代表当日最后一次成功采样，展示实际采样时间；当日数据为未结束的统计日，不伪称准确的午夜终值。提供可阅读的数据表，不能只能通过颜色或鼠标悬浮读取图表。

### R5：历史起点与缺口

从功能上线起记录每日统计，上线前及采集缺失的日期显示“无记录”，不补成零，不用现存数据倒推历史总量。接受初期历史曲线较短，并提供可理解的提示。缺失日期不连成实线；没有有效比较基准时净变化显示不可计算，不虚构增幅。后续彻删不修改已记录的历史点。

### R6：完整任务统计与异常提醒

采用用户选定的推荐方案：从功能上线起独立保存任务累计与结果统计；清理任务、自动裁剪、彻删作品或删除用户，不丢失已经记录的统计。展示当前排队、运行、待审核数量，以及开始跟踪以来的新建总数和各结束结果数量。提供最近 24 小时失败、被中断的任务数。

同一任务暂停、继续不重复新增计数；重试创建的新任务按新任务计。上线前已存在的任务只作为明确标注的初始化存量，不冒充上线后的新建量或历史结果；其上线后真正发生的结束结果可以记录。尚未结束即被业务级联移除的任务保留移除标识，不伪造成功或失败结果。

### R7：刷新与适配

支持手动刷新和每 60 秒自动刷新；自动刷新可关闭，页面不可见时暂停。离开页面或权限失效后停止后台轮询及旧响应回写。桌面、移动端、明暗主题均可使用，遵循现有后台页面风格。

## 验收标准

- [x] AC1：使用多个用户和不同状态作品/任务核对，各项统计与源数据及约定统计范围一致。

- [x] AC2：空平台显示有效的零数据状态；部分接口失败可以识别并重试。

- [x] AC3：未登录与普通用户无法读取全站管理统计。

- [x] AC4：卡片跳转到正确的管理入口；尚未交付的管理模块不产生失效链接。

- [x] AC5：桌面、移动端及明暗主题下，统计、待办和异常提示均可阅读和操作。

- [x] AC6：趋势图与历史分析展示的日期、指标和统计口径一致；无历史记录或存在采集缺口时明确提示，不把缺失展示为零或真实历史值。

- [x] AC7：回收或恢复作品不改变包含回收站的作品数、章节数及总字数；彻底删除才减少对应的当前总量，已经记录的历史快照不受后续彻删影响。

- [x] AC8：任务清理、自动裁剪、作品彻删及用户删除后，上线以来已经记录的任务累计及结果统计保持不变；暂停后继续同一任务不重复增加任务总数，重试产生的新任务按新任务统计。

- [x] AC9：近 7 / 30 / 90 天查询包含正确的北京时间日期边界，默认 30 天；净变化的比较日期明确，零、负数、缺失和不足两个历史点均正确处理。

- [x] AC10：任务每日新建及结束结果与真实事件对账，跨日结束归入结束日；最近 24 小时失败/中断统计在任务清理后仍准确，初始化存量不冒充新增。

- [x] AC11：手动刷新、60 秒自动刷新、关闭开关、隐藏页面暂停、重新可见后恢复、切换时间范围及卸载行为正确；慢旧请求不能覆盖新范围或重新出现的账号页面。

- [x] AC12：任务与统计同成同败，事务回滚、并发取消/结束、重启恢复和重复回调不漏记或重复计数；图表缺失日期不跨缺口连线，屏幕阅读器和移动端可通过数据表获取数据。

本地验收依据：后端1211项、前端542项、lint/类型/等价构建及隔离真实浏览器记录均通过。PostgreSQL实例未实跑，标准前端build受既有目录权限限制；这些未执行/受限项不能当作通过，详见 `research/check-report.md`。
