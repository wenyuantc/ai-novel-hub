# 管理员用户详情

## 建档状态

优先级：P2。状态：`planning`，待细化的功能需求草案。

来源：2026-10-30 管理员功能缺口盘点。用户要求将清单中的 8 项功能分别创建独立任务，本轮仅完成建档；具体产品取舍与实施方案尚未确认。

## 目标与用户价值

让管理员从一个用户入口了解账号使用情况和资源占用，并快速维护其作品。

## 已确认现状

- `frontend/src/pages/AdminUsersPage.tsx` 当前展示用户名、角色、启停状态、项目数及注册时间，已有创建、改密、角色和删号操作。

- `backend/app/models/entities.py::User` 当前未保存最近登录时间；`admin_project_service.py` 已支持按 `owner_user_id` 查询作品。

## 初步需求

1. 从用户列表进入详情，展示账号基本信息、最近成功登录时间和约定的资源统计。

2. 展示所属作品并支持进入管理工作区，复用现有按用户筛选和分页能力。

3. 复用已有账号管理动作与自操作/最后管理员保护；最近登录无历史数据时明确显示暂无记录，不伪造历史。

4. 详情只提供管理所需的元数据，不读取用户的模型密钥、平台访问密钥或私人配置内容。

## 验收标准（草案）

- [ ] AC1：最近成功登录时间在真实登录后更新，失败登录不覆盖该时间；历史无记录有明确展示。

- [ ] AC2：作品数、章节数、字数及约定资源用量与源数据一致，零资源账号正常展示。

- [ ] AC3：用户详情中的作品均属于目标用户；从详情打开作品管理后仍显示正确归属。

- [ ] AC4：从详情执行账号操作继续遵守现有管理员保护和会话失效规则。

- [ ] AC5：未登录、普通用户和不存在的用户目标按约定拒绝，加载失败可重试且不暴露私人凭据。

## 范围边界

- 登录设备/IP 轨迹、完整用户行为监控和模拟登录用户。

- 本任务中新增角色体系或资源额度控制。
