# 笔名署名、分组与筛选

## 目标

承接父任务 R13.1 / D13.2，使作者用一个笔名为作品署名，并按笔名整理书库。

父任务：`../11-16-pen-names-templates-thumbnails/prd.md`。2026-11-16 用户已确认每部作品选择一个笔名、协作者只读该作品笔名且不能浏览作者其他笔名；其余具体行为随整体方案最终评审。

## 现状

作品列表同时展示本人作品与已接受邀请的协作作品：`backend/app/services/project_service.py:421`。书架使用账号用户名展示作者：`frontend/src/components/shelf/LibraryBookCard.tsx:26`、`:31`。因此，笔名的个人管理权限与作品署名读取需要分别处理，不能把普通内容编辑权当作笔名管理权。

## 需求

- PN1：作者可新建、改名和删除本人笔名。同一作者不能保存相同的规范化笔名，不同作者可使用相同名称。
- PN2：每部作品至多关联一个本人笔名。旧作品和主动清除关联的作品显示账号名，不强制迁移旧作品。
- PN3：书架和作品概览展示当前笔名；协作管理、审计仍使用真实账号身份，不把笔名当登录身份。
- PN4：作者可按全部、未设置及具体笔名筛选，结合原有搜索、状态与排序。仅本人笔名进入管理和筛选目录；全部视图仍能看到已授权协作作品。
- PN5：协作者能看见获授权作品上的笔名，但不能修改笔名／关联或枚举作者笔名库。管理员内容权限也不开放他人的私库。
- PN6：删除笔名解除本人全部相关作品（含回收站）的关联，保留作品。笔名改名及时反映于仍有关联的作品。
- PN7：旧建书入口保持可用；普通新建和作品概览可选笔名，其余入口默认未设置，可随后选择。模板建书的笔名由创建者当次选择。
- PN8：单书备份只保存该作品当前笔名文本；恢复时在导入者自己的库里复用同名笔名或创建新笔名，不引入来源库 ID。旧备份无笔名则保持未设置。
- PN9：EPUB 现有作者字段默认取作品笔名，没有时取原账号名；显式导出 author 优先。站内和开放 API 下载一致。

## 验收标准

| 编号 | 场景与结果 |
| --- | --- |
| PN-AC1 | 建立两个笔名、分别分配作品，作者和协作者看到正确署名；不能给作品同时绑定两个笔名。 |
| PN-AC2 | 笔名筛选与搜索／状态／排序组合有效；清除筛选恢复全部可见作品，账号切换不复用旧用户笔名状态。 |
| PN-AC3 | 作者可维护自己的库；协作者和管理员代管路径对他人笔名库／关联写入均拒绝，不能枚举其他笔名。 |
| PN-AC4 | 删除笔名不删除作品，回收站恢复后没有悬空关联；重命名、关联、删除的并发结果符合最终版本。 |
| PN-AC5 | 当前备份恢复只带当前署名，不带其他笔名；同名复用、无同名创建、旧备份恢复正确且不留半成品。 |
| PN-AC6 | 站内和开放 EPUB 默认笔名署名正确，显式作者覆盖正确；真实账户信息不被改写。 |
| PN-AC7 | SQLite / PostgreSQL 迁移和同作者约束有效，HTTP 权限与实际桌面／375px 页面验收通过。 |

## 依赖与边界

本任务首先实施，不依赖缩略图／模板。向后续任务提供本人笔名选择与署名投影契约。

不增加多作者笔名、笔名公共主页、公开笔名目录，不开放他人笔名管理，也不新增 DOCX 署名版式。模板不会自动绑定来源笔名。
