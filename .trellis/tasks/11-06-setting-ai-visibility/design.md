# 技术设计：设定 AI 可见策略

本设计实现 [PRD 的 R1–R6](prd.md)。在现有 FastAPI／SQLAlchemy、React／Ant Design 架构内增加一套策略数据、一个 AI 专用投影和一个发送屏障。不引入新的权限体系、搜索服务或通用图引擎。

## 1. 边界与数据流

```text
人工设置 / 共享字段目录
  → 权限、归属、校验、版本 CAS → 配置、关联、当前代次（同一事务）
      ├─ 现有人工 API → 原档案、字段、时间线、卡片和备份
      ├─ 人工提及 → 匹配配置、当前词典 → 原文跨度／热力图
      └─ AI 场景 → 受信任的纳入原因 → 有资格的条目 → 时点解析 + AI 白名单投影
                  → 预算裁剪 / 模板 / 工具 / 向量请求 → 带代次的实际发送
```

- 统一服务（拟 `services/setting_ai_visibility.py`，必要时拆纯选择器与发送门禁）负责稳定 `EntityRef`、配置读写、选择原因与 AI 投影。复用 `setting_catalog_service`、既有时间线 resolver、字段投影和 AntD 控件；不在每个 prompt 或 UI 页面各写一份策略。
- 业务路由不直接读写 ORM；人工读走 `get_manageable_project`；写要求 `projects.edit`、项目活跃、项目锁与版本校验。模型侧继续严格 owner，管理员人工读写权限不授予他人作品的私有聊天、模型资源或生成权限。
- 禁止把 ORM、人工完整 DTO、未投影的嵌套对象直接序列化给模型；不做最终提示词字符串替换。只读 AI 预览共用投影和预算，人工排除原因可单独显示，但不得混入模型文本、工具错误或向量查询。

## 2. 持久化、接口和冲突

### 数据

- 预计 Alembic `0037` 基于 `0036`。四类实体新增 `ai_mode`（`always | detected | manual_only | never` 或内部兼容 NULL）、`mention_enabled`（内部 NULL 表示按旧范围或新建默认）、`mention_case_sensitive`（默认 true）、`mention_exclusions`、`ai_hidden_builtin_fields`。新建默认 `detected`、启用追踪、无排除；升级前的行留 `ai_mode=NULL`，先迁存量再设新建默认，不能用带默认的 ADD COLUMN 意外填满旧行。
- `always_in_context` 保留给历史数据与旧接口；NULL 走旧常驻／定位、旧名单和每个消费者原有选择逻辑。新策略一旦显式设置优先于旧 flag；作者只编辑追踪或字段时不强行改条目档位。验证老备份、老卡片导入用真实 SQL NULL 而非因 ORM server default 省略值；覆盖手工、向导、实体任务、拆书等所有新建路径。
- `setting_field_definitions.ai_hidden` 适用于全部绑定；`setting_text_fields.ai_hidden` 仅限 `definition_id IS NULL` 的旧字段。两者默认 false，按当前配置过滤，不回溯权限。旧字段改绑若会把隐藏值变成可见，拒绝；作者先显式调整目标定义或旧字段，不能静默扩大共享配置。
- 有向关联表 `setting_ai_links`：`project_id, source_handle_id, target_handle_id`，端点复用稳定的 `SettingReferenceHandle` 真实类型 FK；项目内方向唯一、自关联禁止。提取小型 get-or-create handle helper，复用归属及锁，不让 GET 建句柄。链接不把目标变成字段历史依赖；删档案沿用现有句柄清理和引用保护，链接随端点级联清除。恢复时整图校验端点与项目一致；不能把只被 AI 关联使用的句柄误清理。参照 `setting_field_service.py:1108–1163`。
- `projects.ai_visibility_revision` 是配置 CAS 及 AI 快照代次；`ai_history_epoch` 标记可能收紧的边界。真实配置变化才递增 revision；已可见数据改为隐藏、条目档位降级、删除可用链接、关闭追踪／收紧匹配、取消旧常驻等可能降低纳入资格的变化递增 epoch；不能证明只是放宽的组合改动保守视为收紧。只放宽、等值 PATCH 不封存历史；等值不产生假版本。编辑普通原值不是改策略。共享／旧字段修改同时遵循原字段／时间线版本，epoch 与内容设置一笔提交。

### 人工接口与错误

| 路径（`/api/v1/projects/{pid}` 下） | 契约 |
|---|---|
| `GET /setting-entries/{kind}/{id}/ai-settings` | 当前档位（包括只读兼容状态）、有效追踪配置、内建可隐藏字段及当前掩码、有向目标列表、`ai_visibility_revision`。 |
| `PATCH /setting-entries/{kind}/{id}/ai-settings` | `expected_ai_visibility_revision` + 选填档位、追踪项、内建掩码或替换目标列表；整笔校验。省略不变；空数组清空；不接受 null 回到兼容态。 |
| 现有共享字段定义 GET／POST／PATCH | 增加 `ai_hidden`，省略不影响旧客户端；沿用 `expected_fields_revision`，真正变更在同一配置事务更新 AI 代次。 |
| `PATCH /setting-entries/{kind}/{id}/legacy-fields/{fid}/ai-visibility` | 只允许该条目的旧字段；提交 `ai_hidden`、期望时间线版本与 AI 版本；不覆盖未保存字段正文。 |

- 布尔／枚举／版本和 ID 严格校验；掩码只接受当前 kind 白名单。排除词为去首尾空白的字面短语，拒绝空项，至多 20 项、每项 80 码点；以当前匹配模式稳定去重。每源至多 32 个不同关联目标，复用四类型候选分页；全部端点逐个归属校验后才写。重复、自关联或越界 422，其他作品／不存在目标 404；批量失败全回滚。
- 过期 CAS 或多块预览期间配置变化返回 409（`stale_revision` 附作用域和当前版本）；保留草稿、支持重新读取对照，不能自动换版本重提。禁用的显式 AI 任务目标返回可操作的业务错误（如 `setting_not_available`），不要给模型回传该对象身份或值；模型工具不能借错误辨认禁用对象。
- 最小审计记录动作、目标、变动字段名／版本，不额外记录作者专用文本或排除词原值；应用现有人工审计规则。

## 3. 匹配与单跳选择

1. 批量加载当前身份、配置、目标章和版本。非章节入口沿用自己的时点（当前），不为原来不消费字段的功能额外加全文。作品、时间线、字段目录和 AI 配置的前后版本校验贯穿普通块、规划块和查询；使用新的标量快照，拒绝 ORM 旧身份混搭。
2. 字面候选由 `mentions.matcher` 统一处理：保留现有大小写敏感默认、ASCII 词边、最早位置／同起点长词优先。忽略大小写按 Unicode 字面折叠并保持可逆的原始码点边界，不把折叠字符串位置返回给前端。一个排除短语只屏蔽落在其完整命中区间内、属于该条目的候选；先剔除失效候选再定歧义和非重叠跨度，长词全部被排除时仍尝试同起点合法短词。禁跟踪不参与竞争。匹配不做全书外扩、正则或全文重写。
3. 新规则只将唯一归属的字面命中作为自动原因；歧义在人工侧可查看候选。AI 当前场景输入限定为本章梗概／计划与上章尾、当前章正文或选区、当前大纲／向导输入、作者当前聊天或操作指令等与现有任务对应的输入，不扫描已组装的设定、历史工具 JSON 或全部资料寻找二次触发。未配置角色保留旧 AI 选角（含短词与歧义规则）和旧入口的默认注入；作者显式调整匹配后才使用新匹配。保持四来源的权限、全文统计和源码偏移。
4. 先将允许的常驻、作者明确引用与字面命中合并为直接候选（原行为回退也明确标记原因）；拒绝 `never`。只从这些直接候选计算一次显式出边和现有目标章有效的成员／任职关系；从关联加入的目标不进入展开队列，循环不需要递归求解。普通角色关系只渲染合格的两端，普通引用字段只在目标也有发送资格时显示轻量值，不纳入档案；对未配置旧条目组合保留原允许的轻量显示，但目标明确拒绝时优先拒绝。
5. 先过滤再去重、排序、预算和派生检索；保留已有显式规划优先级。只被选为 legacy「其他角色名单」的条目不是直接入选来源；显式新档位不能通过旧名单或主角兜底。升级 matcher 版本，词典指纹覆盖条目身份、名称、别名、追踪、大小写、排除词；缓存保留过滤后的归属身份，不仅保留词面。AI 条目档位不影响人工命中。保持有界缓存和分批／线程卸载，无逐条 SQL 或每条目一次全文扫描。

## 4. AI 投影与入口矩阵

### 内建内容白名单

| 条目 | 可隐藏的内建项（独立开关；阶段为一组） |
|---|---|
| 角色 | 定位、年龄、性别、简介、外貌、性格、背景、当前处境、生死状态、旧关系备注 |
| 世界观（六类） | 档案正文 |
| 组织 | 类型描述、宗旨、所在地、势力值、简介 |
| 职业 | 描述、获得条件、能力、规则、职业阶段资料 |

- 名称、别名、稳定身份及类型是实体级数据，不是字段开关。职业类别（主／副）、世界观分类是类型信息。成员／任职／人物关系是单独事实，不作为本期可编辑字段键；任一端无资格时相关结构化行不得发送，隐藏阶段也不得通过角色职业摘要发出阶段名／值。隐藏角色定位等内建字段时不要输出“空值默认状态”替代真实字段，也不要在旧名单、筛选或工具结果中重复该值。
- 先按原时点读取，再输出专用标量 DTO；隐藏字段整项不输出（名称、选项、基础值、当前值、事件、引用目标、派生状态）。自由文本中由作者自行写入的重复文字不做字符串消除。约束落在结构化数据身份及来源，非敏感词过滤。
- Agent 工具按同一已确定的当前回合资格过滤查询、搜索、分页、嵌套成员／关系、定义与选项、时间线基线和事件；查 ID 不升级为人工指定。拒绝借写入、预览错误、确认回执、合成缺回执绕行；成功回执改用允许字段或最小结果。旧已执行效果仍由人工查看／按现有规则撤销。模型不能修改本期策略或建立作者专属链接。
- Agent 仅对当前作者输入计算新规则的资格，不把当前浏览路由自动算手动选中；复用存在的显式选择入口，不新增聊天附件编辑器或隐式全档案提示词块。Agent 现有工具读取按资格投影、先过滤再分页和裁剪，保留未配置会话的旧提示词行为。

| 入口组 | 主接入点及旁路 |
|---|---|
| 写作 | `generation_service`、`context_builder`、`planning_context_service`、`rewrite_service`：普通／锁定块、POV、cast、世界观、仅名单、关系、组织／职业、伏笔、预览、续写与批量。仅正文润色不额外加载设定。 |
| 分析与非章节生成 | `analysis_service`、`entity_ai_service`、`outline_ai_service`、`wizard_service`：正文命中、组织名单、角色／上级／职业、关系两端与旧备注、显式任务主对象、续跑。要求模型读取已隐藏主对象或唯一输入字段时，在发送前明确拒绝，不静默按空档生成。 |
| 项目智能体 | `agent/{context,runner,service,tools}` 及 handler：输入、列表／详情、结构化分析和伏笔、工具回执、摘要、自动执行／提案确认／重试。作者 API 和模型 DTO 不共享完整序列化。 |
| 检索／其他 | `retrieval_service`、`foreshadow_service` 及其调用点：先过滤检索用结构化名称再构造 query／embedding；发送门禁也覆盖这些请求。索引作者上传的原文、独立试写、测试模型等没有设定来源的不新增权限变化。 |

完整路径和边界证据见 [AI 出口调研](research/ai-paths.md)，实现时逐项补实测，不以该表代替真实请求验证。

## 5. 代次、重建与真实发送

- 受控负载带 `{project_id, ai_visibility_revision, ai_history_epoch}`，在数据构建时捕获。系统不得给旧 payload 重新盖最新戳。当前 epoch 下，排队首轮及仅有作者原始输入的任务可重新构建；续写／展开等携带旧派生材料不能安全重建则在下一次网络请求前停止。已提交的章节／副作用保持原结果；任务用明确提示及现有失败／部分成果语义释放资源，不假报完成。
- `AgentConversation` 记录使用的 epoch。旧 epoch 且已有历史的会话禁止发送新轮、摘要、继续与重试；原会话、摘要、提案及工具记录保留可读，前端提示新开会话。没有可靠字段来源，不尝试从文本猜哪些旧结果可用；既有待执行提案也不得靠旧回合确认后继续发请求。合法空会话可在首轮采用当前 epoch；历史的完成副作用不得重复执行。
- 采用 [发送边界调研](research/dispatch-boundary.md) 的受控 HTTPX 请求／响应钩子：每个真实发送尝试在网络前用独立事务获取项目发送门禁并重读版本和生命周期；响应头返回或失败即释放，不锁完整流。PG 用独立命名空间的项目级事务共享／独占 advisory lock，SQLite 用可测试的物理 no-op 写事务，不靠内存锁。配置保存取得同一独占门禁、检查版本并提交，才向作者报告成功；有界等待冲突显示“本次未保存，可重试”并保留草稿。业务写事务不持有到模型网络调用。
- 逻辑作业队列检查、组装后版本检查和真正传输检查各有职责，不能互替。收紧先提交则旧戳不通过；发送先取得门禁则保存不会在旧负载发送窗口尚未关闭时成功。服务端不承诺远端的收包顺序或撤回已发请求。传输异常、重试、重定向、模型 fallback 与取消均不得绕过；不改变已有 SSRF 策略。收到旧戳冲突后不得把同一载荷包装成网络错误自动重试。
- 服务端重启和多 worker 使用持久代次；在旧版本部署混跑时无法保证禁送，因此需排空／停旧 AI 执行器再升级。新增“执行锁冲突”和“会话需新开”的交互保持作者草稿及历史可查。

## 6. UI、格式兼容和回退

- 四类详情复用「AI 与提及」区：四档简短解释，显式标明沿用旧规则、关联箭头方向、追踪关闭提示、内建勾选和保存状态。共享字段在字段配置页显示定义级作用范围，旧字段与内建项在各条目设置。单独保存，权限变化或跨项目切换作废旧请求，不覆盖外层表单草稿；作者仍能编辑隐藏内容。
- 扩展 `MentionEntity` kind/category、类型标签、候选预览与四详情深链；未追踪条目可查看明确的无匹配状态，热力图不把关闭项计为出场。组织／职业按现有名称匹配，使用已支持的别名数据，不引入新的别名编辑模型。
- 完整项目备份预计 v6／`APP_SCHEMA=0037`：登记新增列与链接表，导入规范化验证并重映射句柄及两端；源项目 CAS／epoch 不复制，新作品重新开始。旧 v1–v5 用无策略默认，拒绝旧版本冒充携带新保护数据而静默丢失。作者导出的文件仍含原值，UI 文档需提示不宜当作公开分享文件。
- 卡片 v6 仍只打包现有角色／组织／职业范围及字段快照。保留包内条目配置、实际携带内容的字段可见规则和源在包内的链接；世界观等包外目标使用现有显式 `external_references` 映射，不自动导入世界观档案。保留 v6 中兼容角色的旧常驻信息，旧卡片按其原有推断导入。跳过／复用既有实体不覆盖设置；共享字段定义复用要求可见策略相容，不能使隐藏内容可见。预览与确认比对配置版本，未解析目标不执行。
- 效果快照采用显式版本兼容：新格式（预计 effects v5）保护策略列与关联完整性；旧效果缺新字段时只有可证明不会覆盖作者限制才允许恢复，否则 409，全笔回滚。AI 代次不写进可逆业务快照，撤销不能倒退代次。分类／字段引用与级联仍按旧合同。
- 回退不得启动会忽略新策略的旧应用。未写入新配置的隔离库可测试可逆迁移；存在新策略、链接或非兼容历史时拒绝有损 downgrade。出现问题先停 AI 出站，保留数据与限制，回滚应用须仍支持新模式或走经确认的隔离恢复。
