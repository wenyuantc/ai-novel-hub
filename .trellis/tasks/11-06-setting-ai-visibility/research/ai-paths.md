# 调研：结构化设定进入模型请求的路径与隔离边界

- 问题：除普通章节上下文外，哪里会读取、派生、重放设定？仅章节注入与统一禁送各需要什么？
- 范围：仓库静态走查；包含文本模型、向量查询、项目智能体原生工具和重放。只记录证据与产品选择，不作需求决定。
- 日期：2026-11-06

## 结论

1. 只改 `cast_service.select_cast` 或 `format_entry_fields` 都无法兑现全产品“永不加入”。前者不控制其他角色名单、规划锁定段、关系边和非章节 AI；后者不控制 Agent JSON、内建属性和关联目标摘要。
2. 四档纳入策略决定某入口何时拿条目；硬禁送和字段隐藏决定即使入口主动取也拿不到什么。主动工具、明确任务选择、从正文复制的字面名称不是同一数据来源，不宜用最终提示词全文字符串替换混在一起处理。
3. 可验收的建议承诺是“本应用控制的 AI 出口不再从受保护的结构化设定读出隐藏数据”。若连修改前已经形成的模型输入副本也不得再送，另须定义旧 Agent 回放、运行中续轮和续跑的失效策略。已发送给供应商的数据不能撤回；自由文本、旧派生结果和独立外部服务不能承诺语义净化。

## 范围选择及代价

- **仅章节写作注入**：覆盖普通/规划段、名单和关联投影、生成/重写/选区改写、对应续写/批量/预览；明确章节分析是否纳入。若大纲、向导、Agent 等仍能读取，界面必须写清“仅不进入章节写作提示词”，不能承诺“AI 不可见”。改动相对集中，作者需自行区分其他入口。
- **新读取的结构化设定统一禁送（建议）**：同项目的模型输入采用一致的“入口用途 × 纳入原因 × 条目策略 × 字段规则”投影；包含 Agent 显式读写、非章节功能、自动拼出的二级关联与向量查询。直接引用和自动关联可提升纳入优先级但不能解禁。只过滤 AI 视图，不改人工档案、不删除关系／成员／任职，不引入任意递归抓取。
- **设置保存后也不再发任何旧结构化副本**：需另外界定作业、会话、多轮模型请求边界与收紧触发点。现有 planning_revision 与 fields_revision 前后检验并不包含新策略（`planning_context_service.py:488–537`、`context_builder.py:735–741`），且不能撤回已发请求。对同一任务后续续轮/工具重放要有代次失效和保守停止，或明确“已经运行的本轮可能沿用快照”；不承诺按远端接收时刻做隔离。

## 历史副本与排除边界

- `services/generation_log_service.py:19–56` 保存实际 messages，:88–106 是人工权限读取而非当前提示词来源；不建议回写旧审计记录。
- `services/wizard_service.py:141–162,306–315` 续跑重建新提示词但会重发旧任务部分输出；大纲展开多轮把旧轮的 key events 放进下一轮（`outline_ai_service.py:429–443,544–551`）。如果首版允许复用既有材料，说明“不撤回既往、不修改聊天与正文”，区分“不再从设定读取”与“不再重放”，不能混称立即抹除。
- 正文、作者指令、写作风格、外部知识文档、历史分析/记忆、已生成的答复可能复制或推断出该信息。类型化引用可过滤，任意自由文本不扫删。MCP 独立外部服务、用户持密钥调用其他 API 不是本应用 AI 投影；不要因此暗改人工权限或开放 API。
- 拆书模型输入来自导入原文及阶段发现（`services/book_import/reverse.py:393–417,702–725,793`）；列出现有角色/组织/职业/世界观的已查代码用于写入去重（:841–922），未见把现有档案发送给拆书模型。不应误改写入去重逻辑。

## 验收证据

- 用记录型 provider 检查实际出站 messages，分设角色名、仅名单名、字段标签和字段值哨兵：生成、章重写、选区、续写、批量+分析、向导、大纲、实体生成/关系解析、Agent 读及写回执。向量配置另断言 embed 请求。正文故意写入同名文本仍保留，不用一次全局 substring 判断来源。
- 禁送条目分别被手动出场、POV、关系两端、组织成员、职业、reference、伏笔关联命中，不能漏出；验证预览与发送投影一致，编辑/统计/卡片备份保留原值，裁剪只作用于合格候选。
- 若承诺收紧后历史隔离，用存量 Agent 读/写 tool 结果、摘要、确认后续跑、缺回执分支验证正常与摘要调用均不重发，工具配对正确，不重复执行副作用。
