# 连载与存稿工作台

## 目标

作者在作品内安排每日更新，知道手上的定稿够发几天，并能回答“某章当时在哪个平台发了哪一稿”。需求来源见 [待办第 18 项](../../../TODOS.md#18-连载与存稿工作台)。

## 现有能力

章节的生成状态包含草稿、生成中和完成。普通编辑历史可以合并、裁剪和删除，章节编辑器已有正文差异视图。这些能力决定了工作台要单独保存作者确认的定稿。[章节状态](../../../backend/app/schemas/chapter.py#L11) · [历史保留](../../../backend/app/services/version_service.py#L8) · [版本删除](../../../backend/app/services/chapter_version_service.py#L129) · [正文对比](../../../frontend/src/components/chapter/VersionDrawer.tsx#L143)

## 首版需求

| 编号 | 作者可见的行为 |
| --- | --- |
| R1 编辑和定稿 | 章节可标为待修订、待校对。确认定稿时冻结已保存的读者可见正文与章标题。旧章节和新生成的正文均需人工确认才进入定稿。 |
| R2 改稿 | A 定稿后继续写 B，仍可按 A 发布，该章继续计入未发存稿。预览中提示草稿有修改。作者将 B 重新定稿后，下一次登记默认选 B。已发出的 A 始终可查。 |
| R3 排期 | 一部作品共用一个每日章数目标和一张日历。可为一章安排、调整、取消一个计划日期，查看当天计划、待发章和实际首发章数。允许无排期时手动登记发布。 |
| R4 存稿 | 可发布存稿为“有有效定稿且从未登记发布”的不同章节数。相同章节在任一平台首次发布后只退出一次。按当前日更目标显示能完整支撑的天数与余章。未设目标时只显示存稿数。 |
| R5 发布留档 | 每次手动登记平台、实际发布时间和选定的定稿，预览明确显示将留档的正文。同章多平台补发、同平台发修订版分别留档。重复提交同次登记只产生一条记录。 |
| R6 核对和导出 | 可按平台和时间找到发布记录、读到该次原文，与当前已保存草稿核对正文差异，并把选中的历史发布稿重新导出。章节编辑或普通版本清理后仍能读取已发布稿。 |

## 验收场景

| 编号 | 操作与预期 |
| --- | --- |
| A1 · R1、R2 | 旧章显示生成完成，存稿为 0。确认定稿 A 后存稿为 1。保存新草稿 B 后仍为 1，登记预览准确展示 A 并提示有改动。显式重新定稿后预览变为 B。 |
| A2 · R3、R4 | 日更 2 章、10 章定稿未发，显示 5 天。移动或清除一章排期后仍为 5 天。未设置目标时显示“未设置日更目标”。 |
| A3 · R3、R4、R5 | 一章先发起点再发番茄，10 章存稿只降至 9 章，显示 4 天余 1 章。两个平台分别保留时间和原文，跨两天登记也只完成一个首发章。 |
| A4 · R2、R5、R6 | 起点已发 A。草稿 B 重新定稿后在番茄发 B。检查起点记录可读、可导出 A，与当前草稿对比可以看到 A 到 B 的变化。清理普通版本后仍成立。 |
| A5 · R3、R5 | 计划周二发、实际周三发，两个日期可区分。重试同一次登记得到同一条记录。同时登记两个不同平台会产生两条记录，库存与日历均按一章计算。 |
| A6 · R1–R6 | 只读协作者能按作品权限查看，无权改定稿、排期或登记发布。导出沿用单独的作品导出权限。旧备份导入后从无排期、无定稿开始，新备份能恢复两平台的历史正文。 |

## 首版边界

作者自行到外部平台发布，回到工作台登记。各平台独立排期、自动投递及外部平台回执留待后续。迁移和测试安排见 [实施计划](./implement.md)。
