## 权威顺序

用户已确认的范围／兼容策略优先；经最终审核的 PRD、design、implement 是实现合同。前序研究保留探索时的备选与问题，不表示这些问题仍未解决。

## 用户确认

- 建立本任务并进入规划。
- 章节级回溯、最小文本自定义字段；独立场景／完整字段系统留给TODOS第7／4项。
- M1：现档案保留为待校准基础，新增变化完整记录；不自动迁移旧历史。

## 核对处置

| 来源 | 发现 | 已落实到design的处理 |
| --- | --- | --- |
| timeline-1 | 旧分析可在人工A→C→A校准后覆盖基线 | legacy_compat_allowed不可逆关闭；旧创建撤销检查整个主体、统一写入口。 |
| timeline-2 | 已卸下职业被改kind会破坏旧区间上限 | 职业定义更新也枚举历史主体、全受影响区间校验与原子回滚。 |
| timeline-3 | 相同值提前return跳过自动组替代 | 替代独立原语先定位旧组、排除其求值、验证后原子替代；有旧组即使同值也记录新来源。 |
| timeline-4 | 关系身份可能换到第三人 | identity端点集合必须等于固定人物对，校验覆盖所有读写／导入。 |
| timeline-5 | source不能表达人工确认／编辑保护 | 独立automatic/confirmed/manual保护事实，保留provenance。 |
| integration-1 | 旧effects不带新事实表，恢复会分叉 | 新effects带版本；旧版涉及时间线主体／章锚时安全409，无关纯正文撤销保留。 |
| integration-2 | 仅历史引用的全局关系类型可能不导出 | v2备份收集完整类型引用闭包，核心引用缺失拒绝而非置空。 |
| integration-3 | 隐藏关系的直读／复建遗漏 | 明确current/record查询；普通／开放API、卡片、AI缺失关系生成、载体复建、备份与effects分别核对。 |
| integration-4 | source FK与分析导出策略表述不准确 | source_change_id SET NULL；分析／回写仍核心导出，未新增导出开关；源丢失独立维护。 |

以上均已进入实施步骤和测试要求。只是规划问题已收敛，代码尚未实现，测试尚未运行。

## 关键规格

- 章初／章末双边界，分析章末生效；人工记录可选择。
- 真实章节ID和计划章号分开；删除后的孤儿不按同号重建复活。
- 统一只读求值与同事务最新投影；当前表不是独立事实来源。
- 组织成员为角色状态必要联动，组织树／势力体系不时间化。
- 基础编辑／剧情变化显式区分，旧接口歧义返回可操作409。
- 全部实现须在最终规划摘要获用户后续明确批准并运行task.py start之后。

## Caveats

旧基线待校准期间不能保证变更记录之前的历史准确；此限制已获用户接受。新规则和全部验收仍待实现及实际验证。
