## 技术设计与回退

- 第三方登录回调先按平台和用户 ID 查绑定。已绑定者按原账号状态登录；未绑定者复用本地注册写入前对有效注册开关的检查（`backend/app/services/auth_service.py:66`），在同一事务创建普通用户并写入唯一身份绑定。关闭注册先于建号生效时整笔拒绝；并发首次登录发生唯一键冲突时整笔回滚，重新读取已提交的绑定。用两家平台分别验收开放、关闭、授权中途关闭和并发回调。
- 两家分别登记回调地址，逐次校验 state，由后端换取令牌并读取本次授权的用户 ID。GitHub 使用 PKCE S256，只需公开身份信息。Linux DO 的 Wiki 给出授权码流程和不可变的用户 ID，PKCE 能力与用户信息端点留到真实应用联调核实。账号绑定只使用平台与稳定 ID。[Linux DO Connect](https://wiki.linux.do/Community/LinuxDoConnect) · [GitHub OAuth 授权流程](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps)
- TOTP 种子加密保存，恢复码明文仅在发放时展示。验证尝试次数限制、已使用的时间步和恢复码消费均需跨 worker 生效。敏感值排除在日志和审计记录之外。设计中列出启用或重置后已有会话的失效规则。[TOTP 规范](https://www.rfc-editor.org/rfc/rfc6238.html)
- 部署者通过只读清单登记预装程序。作者端仅能选择登记项，API 拒绝自定义启动命令、参数、工作目录和环境。用实际子进程验证退出和进程树回收。多实例使用一致的插件清单与版本，节点缺失时返回部署错误。
- 回退新登录入口前先确认受影响用户还有可用登录方式；已启用的第二步继续生效。本机托管可独立关闭，按现有部署流程排空已发出的调用并保留其执行记录。表结构升级与恢复在数据库副本演练。
