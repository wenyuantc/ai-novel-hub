# TODO #32 登录方式与本机 MCP 插件

多人部署时，作者可以用第三方身份进入自己的书架，为账号开启第二道验证，并在作品智能体中使用装在服务端的 MCP 工具。来源见 [TODO #32](../../../TODOS.md#32-登录方式与本机-mcp-插件)。

## 子任务与完成条件

| 子任务 | 可独立演示的结果 |
| --- | --- |
| [第三方登录与两步验证](../11-26-oauth-two-step-login/prd.md) | 开放注册时，首次用 Linux DO 或 GitHub 登录可直接建号。关闭注册时，只有已绑定的第三方身份能回到原书架。所有用户（包括管理员）均可自愿启用验证器动态码，并在启用时收到一次性恢复码。密码及两家第三方入口遵循同一规则。 |
| [托管本机 stdio MCP 插件](../11-26-managed-stdio-mcp/prd.md) | 部署者在服务器预装并登记后，作者从列表自行启用。作者界面及 API 均禁止自定义启动命令。作者可试用工具，并在自己的智能体会话确认一次真实调用；结束后可查证进程回收。 |

## 联合验收

- [x] 升级原有部署后，已有用户可用原密码访问原作品，已保存的 Streamable HTTP 和 SSE 插件仍可调用。
- [x] 演练普通用户经超级管理员核实后重置两步验证，以及唯一超级管理员由部署者在服务器本机恢复。核对两次操作的审计来源、目标账号和最终状态。
- [x] 用两名作者和一名作品协作者验证。更换登录方式后，用户 ID、书架、角色和私人插件归属一致；协作者的智能体会话继续受原有 MCP 限制。
- [ ] 分别关闭第三方入口、本机托管，验证两项能力可以独立配置和回退。全站 MCP 开关同时约束远程和本机插件。
- [ ] 在 SQLite 单进程、PostgreSQL 多进程环境分别记录结果。Linux DO 真实回调、GitHub 真实回调与真实 stdio 子进程各有独立证据。

## 交付范围

首版聚焦 Linux DO、GitHub、验证器动态码与恢复码，以及服务器预装插件。通用 OIDC、短信／邮件验证码、桌面桥接和在线安装均在本次范围之外。两项能力可独立交付，父任务负责联合验收。功能已实施，两库与双进程联合验证见[验收记录](research/integration.md)。第三方平台的真实授权仍待测试应用凭据。[总体设计](design.md) · [实施计划](implement.md)
