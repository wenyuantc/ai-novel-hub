# TODO #32 总体设计

## 两个子任务的边界

| 子任务 | 维护的数据与配置 | 复用的现有边界 |
| --- | --- | --- |
| [第三方登录与两步验证](../11-26-oauth-two-step-login/design.md) | 由部署者配置 Linux DO、GitHub 的凭据与回调，本库保存外部身份绑定、两步验证配置、挑战及恢复审计 | 原用户 ID、注册开关、Cookie 会话、角色与管理审计 |
| [托管本机插件](../11-26-managed-stdio-mcp/design.md) | 部署清单登记预装插件，个人记录保存作者选用的目录项、工具缓存和偏好 | 原插件所有者、MCP 总开关、智能体提案、确认和执行记录 |

两个子任务以当前登录的本地用户 ID 衔接。作者改用第三方登录后，书架和私人插件列表仍属于原账号。目录只说明本部署提供哪些插件，每位作者独立选择和使用；目录登记不会自动授予任何作品、其他用户插件或协作者会话权限。

## 发布与回退

登录和 stdio 均可单独交付。迁移按仓库当前单 head 规则合并，在升级前的 SQLite、PostgreSQL 副本上验证两个子任务共存。整库备份用于恢复库内身份、选择及偏好，部署者另行保存凭据、加密密钥、目录与插件程序。恢复时核验原用户可以登录、未授权的节点不能启动本机插件。

使用两家平台的真实测试应用验证 OAuth 回调；使用实际子进程验证 stdio 的启动、物理写入和回收。回退 OAuth 时先确认受影响作者仍有可用的登录方式，并保持已启用的第二步有效。停止本机托管时先排空已发送的调用和进程，再核对远程插件仍可用。[联合验收](prd.md) · [实施顺序](implement.md)
