# 实施计划

## 1. 两级词表与读写权限（A1）

- [ ] 核对开发分支当前 Alembic 单一 head 与备份格式，再添加全站、个人词条及词表修订。旧实例从两份空词表起步，旧作品和发布历史可照常打开。降级前检查是否已有会丢失的词条。
- [ ] 提供管理员维护全站词表、作者维护本人词表的接口和界面，复用现有权限目录、账号隔离及管理操作审计。验证新增、修改、删除、重复与并发修改。单书迁移使用目标作者词表，整库恢复保留两级词表。
- [ ] 从作品归属解析个人词表。用作者、编辑协作者、普通查看者、另一作者和管理账号验证权限矩阵；不得通过检查接口读取其他作品或列举未命中的私人词条。

## 2. 定稿和发布共用检查（A2、A3）

- [ ] 从读者投影或所选定稿取章名与正文。以字面词条生成带上下文和码点位置的命中；覆盖同词跨表、同词多次出现、不同词重叠、跨富文本样式、换段及表情。
- [ ] 在既有定稿、手动登记接口共用服务端复核；响应能区别「需要确认」「稿件或词表已变」与既有版本冲突。验证无命中兼容旧请求、取消零写入、网络重试取回原收据、两人同时改词和定稿的两种先后顺序。
- [ ] 接入章节连载抽屉的定稿和登记页。逐项从清单跳转到对应稿件，作者可返回修稿或确认继续。检查切换稿次、账号、作品、慢响应和窄屏；已有历史定稿从原稿定位。

## 3. 逐平台评估与人工投稿（A4、A5）

- [ ] 使用[平台调研](research/platforms.md)核对起点、番茄、晋江，记录来源日期、作者写权限、接入资格、可导入格式、成功状态和核实方式。新材料可改变某个平台的判断。
- [ ] 增加尚未登记即可导出所选定稿 TXT 的入口，沿用冻结正文、渲染和两次授权检查。用包含中文、表情及分段的样稿回读文件，验证从导出到人工登记的完整路径。
- [ ] 逐家给出结论。能验证专用导入格式时增加样稿验收；只有人工途径时，交付通用导出和手动登记。登记前后分别核对存稿及跨平台首发。可在本阶段单独验收前两项 TODO。

## 4. 已验证平台的自动发布（A6，取决于第 3 步）

- [ ] 对每个确认具备写权限的平台，实现作者授权、远端作品绑定及单章发送。先落库所选稿次和发送意图，再向平台提交。发送前再次核对授权、稿件与检查确认。
- [ ] 实现平台的受理、审核、实际发布与失败状态转换。回执可核验时幂等写回，超时使用原意图查证，需人工核实时提供与原意图关联的登记入口。确认恢复、重复点击及并发回执不会产生第二次发送或第二条成功记录。
- [ ] 用官方测试环境或获准使用的测试作品留存脱敏回执，检验作品、稿次、平台和实际发布时间。仅有模拟适配器时只记录测试结果。全无可接入平台时，本步骤继续待办，并在 TODO 保留其依赖条件。

## 5. 验证与交付

| 检查 | 执行方式 |
| --- | --- |
| 后端定向回归 | 在 `backend/` 执行 `uv run pytest tests/test_serialization_*.py tests/test_book_search.py`，并加入本次新增的词表、定位、权限及适配器测试。 |
| 数据与并发 | SQLite 和独立 PostgreSQL 测试库均验证升级、词表并发、重复登记及备份恢复。PostgreSQL 配置按后端质量规范，使用 `uv run pytest -n 0` 运行对应模块。 |
| 前端及浏览器 | 在 `frontend/` 运行 `npm run lint`、`npm run build`、`npm test`。桌面与窄屏分别验证两级词表、命中定位、明确确认、换稿失效、定稿 TXT 下载及双平台历史。 |
| 全量回归 | 在 `backend/` 执行 `uv run ruff check .` 及 `uv run pytest -n 4 --dist loadfile --durations=20`（默认 SQLite）。真实平台验收单独记录。 |
| 文档与回退 | 同步 README、连载及权限规范。若适配器停用，验证人工登记、原稿下载和存稿统计仍可用；存在历史回执或待核实发送时保留相关数据。按实际验收结果逐项更新 TODO。 |
