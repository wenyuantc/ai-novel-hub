# 管理员系统设置

## 建档状态

优先级：P2。状态：`planning`，待细化的功能需求草案。

来源：2026-10-30 管理员功能缺口盘点。用户要求将清单中的 8 项功能分别创建独立任务，本轮仅完成建档；具体产品取舍与实施方案尚未确认。

## 目标与用户价值

让管理员通过后台管理选定的运行设置，并清楚了解哪些配置已经生效。

## 已确认现状

- `backend/app/core/config.py::Settings` 当前从环境变量/.env 加载配置，并由 `get_settings` 缓存。

- 注册、全局/用户任务并发、自动分析、MCP 和开放 API 限流均已有部署级配置；当前缺少后台写入与生效管理入口。

## 初步需求

1. 提供允许配置的白名单及表单，覆盖约定的注册开关、并发和 MCP 等设置，展示当前有效值与来源。

2. 明确环境变量与后台配置的优先级、持久化方式、即时生效或重启生效的区分；应用各处读取相同的有效设置。

3. 进行类型、范围及跨配置约束校验，保存失败保持旧值；不在后台回显或修改数据库、JWT、加密密钥等部署凭据。

## 验收标准（草案）

- [ ] AC1：约定设置可读取、校验和保存；非法值被拒绝且原有效配置保持不变。

- [ ] AC2：注册开关变化同步影响注册接口和登录页，不能出现页面与后端行为相反。

- [ ] AC3：并发、MCP 等设置按各自生效规则影响真实业务，页面明确提示需重启的配置。

- [ ] AC4：服务重启后配置来源与优先级保持一致，旧的纯环境变量部署仍可运行。

- [ ] AC5：未登录和普通用户不能读取管理配置或进行修改，页面和响应不暴露部署凭据。

## 范围边界

- 网页内编辑任意环境变量、在线更换 JWT/加密密钥或管理数据库连接凭据。

- 运维部署编排及自动重启服务器。

## 待确认项

- 首期设置白名单、配置覆盖优先级与各项生效时机。

- 并发限制降低时已有任务的处理方式，及恢复部署默认值的交互。

## 关联与先后顺序

- 与操作日志记录设置变更；全站任务监控与用户配额必须沿用同一有效配置解释。
