# 故事内时间线

## 目标

作者能回答“这件事在书里什么时候发生、读者在哪一章看到”，也能在核对情节矛盾时看到日期依据。比如第一章写归来，第三章回忆出发，作者可以从两个顺序查看同一段旅程。[TODO #30](../../../TODOS.md#30-故事内时间线)

## 现有基础

章节和活动场景已有稳定编号，场景可跨章移动。现有设定演变以章初、章末及场景位置决定当前设定。一致性检查逐章提取带引句的事实，再按章序跨章比对；事实中的 `time_hint` 来自模型。代码入口见[技术设计](design.md)。

## 首版需求

| 编号 | 作者可以做什么 |
| --- | --- |
| R1 | 每本书设置一套固定历法，给纪年和月份命名，设置月份的顺序及每月天数。日期精确到日。修改历法时能看到对已有标注的影响，非法日期不能保存。 |
| R2 | 在章节填写默认日期，在场景单独指定日期。未单独指定的场景显示“沿用本章”；清除场景日期后恢复继承。章、景都没填时显示“未标时间”。跨章移动只改变继承所得的日期。 |
| R3 | 在作品内切换“故事顺序”和“章节顺序”，每项可见日期、来源和章景位置，可直接打开对应稿件。同日各项保留章景顺序以便查找；未标项在故事顺序下单列。 |
| R4 | 跨章一致性检查把可明确归属的登记日期和原文事实一道比对。检查保留原文引句、日期和来源供核对。倒叙、同日并列、证据无法定位或日期缺失，本身均不构成时间矛盾。 |
| R5 | 使用作品现有阅读、编辑和 AI 权限。旧书可逐章补录。单书备份恢复后继续使用同一历法、章景日期和继承关系。 |

R1 的固定历法、R2 的章节默认与场景覆盖均已由用户确认。

## 验收条件

| 对应需求 | 可观察的结果 |
| --- | --- |
| R1 | 设置“星历”，雾月 20 天、雪月 15 天。星历三年雾月二十可保存，雾月二十一被拒，雪月一日排在雾月二十之后。缩短雾月使旧日期越界时能定位受影响的记录，修改失败后原数据完整。 |
| R2 | 第一章默认雾月初十，回忆场景单独标初三，另一场显示“沿用本章·初十”。移动到默认十二的第二章后，单独标的仍是初三，沿用的变成十二；清除覆盖后显示十二。 |
| R3 | 第三章“出发”在初三，第一章“归来”在初十。故事顺序先出发再归来，章节顺序相反。切换后均可跳到原场景。同日两场不声称有先后，未标时间的旧章仍能找到。 |
| R4 | 第一章初十明确写唯一一把佩剑被彻底熔毁，第三章初三写持剑出门。按故事日期，这段倒叙可以成立。只把持剑日期改为十二，重新检查时应能提示潜在矛盾，列两处原文和日期。仅出现“他记得当年持剑出门”时应结合回忆语义，不能把场景日期直接认作当年的日期。 |
| R4、R5 | 在检查进行中更改相关日期，旧结果不能作为基于新日期的结论保存。既有问题能提示需要复查。无日期的旧书仍可使用原有文本检查。 |
| R2、R5 | 查看者可浏览，编辑者在授权范围内修改，发起 AI 检查沿用现有授权。新格式单书备份导入新书后，跨章场景、继承来源及顺序正确；旧格式导入后日期为空。 |

## 范围边界

首版以一书一历、单一纪年、固定月份天数和单日标注为限。闰月、跨纪年换算、日期区间、小时精度和从正文自动填日期留待后续。本期在现有跨章一致性检查内使用日期；设定随章节演变、读者阅读顺序及连载发布日期继续各用原有语义。
