# C6 停止受理新任务的排空开关

本任务落实父任务「多进程任务调度与部署演练」的 D3 和 R8，需求位于 `.trellis/tasks/11-20-multiprocess-task-scheduling-deploy-drill/prd.md`。C1 的执行者登记与 C2 的共享系统设置已完成。C3 至 C5 提供了跨进程取消、流转发和备份受理的现行基线。

## 目标

管理员在停服升级前暂停全站后台任务受理，等待已有工作结束，并从系统设置页确认剩余任务及存活进程。

## 背景

- 现有系统设置有六项，并发上限最低为 1。系统设置读取异常已有故障保护。任务仍可在设置正常时持续入队。见 `backend/app/schemas/system_settings.py:8-28`、`backend/app/core/authorization_runtime.py:25-26` 和 `backend/app/services/task_engine/engine.py`。
- 任务受理统一入口是 `task_service.py:506,693,726` 的新建、重试和继续。部分任务经 `task_engine/admission.py:102` 做模型预检。智能体提案处理后可经 `agent/service.py:1367` 继续轮次。章节任务回调经 `analysis_service.py:945` 派生分析。
- 管理任务页提供当前筛选的七种状态计数，系统设置页在 `frontend/src/pages/AdminSystemSettingsPage.tsx`。见 `.trellis/spec/backend/admin-task-monitoring.md`。
- 升级前需要先排空旧执行体，再做迁移。旧版本遗留的排队任务可能无法在新版本继续。见父任务 `research/deployment-migration-rollback-background.md` 第 1 节和第 3.2 节。

## 需求

| 编号 | 行为 |
| --- | --- |
| R1 | 新增「停止受理新任务」，代码默认关闭。具有系统设置修改权限的管理员可以保存变更，沿用现有设置审计。 |
| R2 | 开启后，新建、重试或继续后台任务的请求统一返回维护提示和固定错误码。拒绝的请求不生成任务行、抢占资源或调用模型。与新任务绑定的业务变更随受理一起回滚。 |
| R3 | 任一进程提交开关后，其他进程的下一次受理按新值判断。关闭后恢复正常受理。 |
| R4 | 已排队或运行中的任务继续执行，后续工作可以凭原执行的有效凭据完成派生。已有流订阅继续工作。 |
| R5 | 待审核任务继续计入剩余量，排空期间禁止续跑。原先可提前结束或取消的任务继续支持这些操作。只保存内容或提案决定的操作可以完成，随后自动入队的工作等开放后再由用户发起。 |
| R6 | 系统设置页显示当前开关状态、全站排队、运行和待审核数量，以及仍在收尾的执行、活动备份与存活进程。使用共享持久数据，避免父任务进入终态与派生任务入队之间出现误导性归零。 |
| R7 | 普通用户看到明确的中文维护提示。编辑、批量、智能体输入在请求被拒时保留。 |
| R8 | 开放 API 的受理契约与站内一致。当前 `/api/open/v1` 路由只读，排空期间读接口照常响应。以后新增后台任务入口时复用统一受理检查。 |
| R9 | 排空期间暂停受理新的计划备份。已受理的备份继续，管理员仍可手动备份。配置和计划到期记录保留，开关关闭后按原计划算法恢复。 |
| R10 | 兼容旧设置与旧数据库。停用开关时现有受理与业务流程照常。迁移遇到旧版无法读取的覆盖或审计记录时拒绝降级。 |

## 验收

- [x] **AC1 · R2、R3** 开启后分别向两个应用提交单章、批量、智能体轮次、知识库索引。每个应用均返回维护错误，数据库中没有新增任务、章节占用或索引副作用，假模型收到零次新调用。覆盖依附任务入队的拆书导入及知识库上传、重建索引。
- [x] **AC2 · R2、R5** 重试、直接继续、拆书跳过并续跑、富文档批量采纳并续跑均被拒，旧状态、提案或断点保留。智能体会启动任务的提案保持待确认。可以提前结束支持该操作的任务、取消或保存无需继续执行的决定。关闭排空后可手动继续已处理完提案的轮次。
- [x] **AC3 · R4** 开启时已有 3 个排队任务、1 个运行任务，全部继续执行。原单章成功后自动分析被受理并完成。覆盖有效执行凭据触发的索引与拆书分析，拒绝过期或伪造的来源。既有流仍收到进度与终态。
- [x] **AC4 · R3** 应用 A 保存开关，B 的下一次请求在收到任何重载通知前即被拒。关闭后 B 下一次受理成功。控制两种并发先后，验证先持有受理事务的任务可排空，先提交开关时请求无业务副作用。
- [x] **AC5 · R1、R6** 两个应用读取的全站计数与库内一致，并随工作结束归零。暂停父任务回调时仍显示收尾中。存活列表与真实进程及租约一致。读写权限和审计可核对。
- [x] **AC6 · R7** 浏览器验证章节编辑、批量和智能体对话的维护提示、输入保留，以及管理页状态刷新。前端 lint、build、test 通过。
- [x] **AC7 · R8** 核对开放 API 路由与公开契约，排空开启后使用有效 API Key 读取小说或章节仍成功。后台受理错误结构由站内真实端点验证。
- [x] **AC8 · R9** 已到期的计划在排空时不生成新备份行。手动备份及开启前已受理的备份可以完成。关闭后两个应用按原有规则只受理一次到期计划。
- [x] **AC9 · R10** SQLite 与 PostgreSQL 16 的迁移往返通过，已有非排空设置保留。存在排空覆盖或审计时降级会被拒。默认关闭场景的受理和设置回归、SQLite 全量与 Ruff 通过。

## 范围

C6 交付后台任务受理开关及其管理状态。只读维护模式、维护公告、定时开启、管理员批量取消和旧版遗留任务清理都在当前范围之外。请求内同步 AI 调用（如流式局部改写）仍按原接口运行，停服前的处理方式记录在 README。部署形态和完整升级回滚演练由 C7、C8 验收。
