## 目标与用户价值

管理员能从用户列表进入单个账号详情，了解账号状态、最近成功登录和基础资源数量，并进入该用户的作品管理；管理过程中保留真实管理员身份和既有安全边界。

## 背景与现状

- `frontend/src/pages/AdminUsersPage.tsx` 已有账号列表、新建、重置密码、启停、角色变更及删号；列表作品数包含全部未物理删除作品，并提供按用户筛选的正常作品/回收站入口。
- `backend/app/models/entities.py::User` 未保存最近登录时间。注册和密码登录成功后会签发 Cookie；改密也会续签 Cookie，因此“签发 Cookie”不等于本任务定义的登录。
- `backend/app/services/admin_project_service.py::list_projects` 已有按 owner 筛选、分页及章节/字数聚合，正常作品能进入现有工作区；回收站有独立管理入口。
- 作品在“正常→删除中→回收站→物理清理”间变化；删除中暂时不属于正常目录或回收站，过期待清理仍属于回收站。详见 `research/current-contracts.md` 的源码证据。
- 登录与会话/迁移风险及复用点见 `research/auth-contracts.md`；项目尚无可靠的完整 Token/费用数据。

## 功能需求

### R1：账号详情与入口

- 用户列表中的用户名及明确的“详情”入口可打开独立用户详情页；支持直接访问、刷新和返回用户列表，不新增全局导航分组。
- 展示用户 ID、用户名、管理员/普通用户角色、启用状态、注册时间和最近登录时间；当前账号保留“我”标识。
- 加载中不展示上一个目标账号的信息或危险动作；不存在的目标有明确提示，加载失败可重试。

### R2：最近成功登录

2026-11-01 用户确认：成功的账号密码登录及注册后的自动登录均更新最近登录时间；密码错误、不存在账号、禁用账号、日常访问和改密续签不更新。

- 管理员创建账号及启动时 bootstrap 不是登录，不产生登录记录。
- 存量账号无历史记录时显示“暂无记录”，不根据注册/更新时间回填。
- 记录持久化成功后才能返回登录/注册成功；并发登录不能使时间倒退，不能绕过同时发生的密码重置、禁用和会话撤销。
- 时间沿用现有 UTC 存储、前端本地时间展示约定。

### R3：基础资源统计

2026-11-01 用户选择基础统计：仅作品数、章节数、正文总字数，分别展示“正常作品”与“回收站”。

- 统计覆盖目标用户的全部相关作品，不是当前列表页的小计。
- 正常和回收站使用各自现有目录的真实生命周期口径；回收站包含已经到期但尚未物理清理的数据。
- 删除中数据不伪装为回收站：存在时单独提示同维度的暂存数量；账号全部作品数包含正常、回收站与删除中，用于解释总量及删号限制。
- 章节数包含空正文章节；正文总字数只计算当前章节正文的服务端字数，不叠加历史版本、大纲、设定、日志等内容。
- 零资源显示 0；空作品计 1 个作品、0 个章节、0 字；物理清理的数据不再计入。

### R4：所属作品与管理路径

- 详情内展示固定归属于目标用户的正常作品分页列表，包含名称、状态、章节数、字数和更新时间，并可进入现有作品工作区。
- 提供按目标用户筛选的“全部正常作品”及“回收站”入口。回收站作品不能通过详情链接到正常编辑区。
- 进入工作区后继续显示真实作品归属，不切换登录账号；不因详情入口开放他人的 AI、私有配置、密钥、任务输出或阅读进度。

### R5：复用账号操作

- 列表与详情复用重置密码、启用/禁用、授予/撤销管理员及删除账号的交互与校验；新建账号仍在用户列表。
- 保留自身操作限制、最后一名启用管理员保护、同事务审计及 token_version 会话失效规则。
- 名下有任何作品（含删除中、回收站、到期待清理）时禁止删号；零作品仍须严格输入用户名确认，服务器保留最终校验及待收尾取消请求保护。
- 操作成功后刷新当前账号信息与统计；详情删号成功后回用户列表；失败保留明确反馈且允许安全重试，不自动重发危险操作。
- 切换目标、离开页面、退出/切换管理员身份后，旧响应和确认框不得操作或污染新目标；提交时防止重复点击。

### R6：访问控制和最小披露

- 详情仅对当前启用中的管理员开放，服务端每次请求校验；未登录 401、普通用户 403、不存在目标 404。
- 仅提供账号管理元数据与本任务约定的计数；不返回密码哈希、会话版本、模型凭据、平台 Key、私有配置、正文或生成内容。
- 读取详情不产生账号管理审计写入，也不触发模型请求或后台任务。

## 验收标准

- [x] AC1（R2）：注册自动登录/成功密码登录持久更新最近登录；错误、禁用、普通访问、改密续签、管理员创建/bootstrap 均不更新；历史 null 显示“暂无记录”。
- [x] AC2（R3）：多账号、多作品、多章节、空作品及零资源场景的正常/回收站统计准确，不混入别人的数据、不按章节重复计作品、不累计历史正文版本。
- [x] AC3（R3）：软删后只转入回收站统计，恢复后转回正常，彻删后消失；到期待清理仍计入回收站；删除中单独提示且全部作品数不漏算。
- [x] AC4（R1/R4）：从列表、直接 URL 和刷新均可打开正确详情；分页始终绑定目标用户；正常作品可进入管理工作区且归属正确，回收站入口带正确 owner 筛选。
- [x] AC5（R5）：列表/详情账号操作使用既有 API 并保持保护、审计和会话失效；删号成功返回列表，有作品或待收尾任务时仍拒绝。
- [x] AC6（R1/R5）：加载、空态、404、失败重试清晰；快速切换账号/退出/离页、延迟读取/操作、StrictMode 重挂载及双击不会复活旧数据、确认框或危险操作。
- [x] AC7（R2/R6）：权限和错误状态正确、响应只含明确白名单；登录并发禁用/改密时不接受过时凭据、不签发未经核验的新会话版本，时间不倒退，落库失败不报成功。
- [x] AC8（R1/R4/R5）：桌面与 375px 明暗主题均可用，危险确认与表单能键盘操作；管理他人作品不产生越权的私有资源、AI/任务输出或阅读进度请求。
- [x] AC9（R2）：从当前迁移版本升级后存量登录时间保持 null，用户/作品/子行及外键完整；回退只移除新增字段，不误删关联业务数据。

## 范围外

- 磁盘占用、Token、费用；知识库文档等其他资源用量。
- 独立最近活跃时间、登录 IP/设备轨迹、完整行为监控、模拟登录用户。
- 新角色体系、资源额度或配额控制；这些仍归 `admin-rbac-quotas`。
- 新增账号操作 API、用户私人配置查看权限、重做作品工作区或全局管理 UI。
- 历史登录数据推算、统计历史曲线、自动轮询或新的缓存/统计后台任务。
