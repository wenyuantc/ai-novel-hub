# 执行者租约验证记录

## 环境

后端使用项目锁定的 Python 3.12 环境。SQLite 用例每次新建临时数据库。PostgreSQL 16.15 使用绑定本机回环地址的独立容器、专用 `ainovel_test` 数据库，以及逐用例随机 schema。

```sh
docker run --detach --rm --name ainovel-c1-lease-01a20602 \
  --publish 127.0.0.1::5432 --env POSTGRES_DB=ainovel_test \
  --env POSTGRES_PASSWORD=c1_local_test postgres:16-alpine
docker port ainovel-c1-lease-01a20602 5432/tcp
```

以下命令从 `backend/` 运行。PostgreSQL 串行验证时设置 `AINOVEL_POSTGRES_TEST_URL` 到该次映射端口。

## AC13 慢响应、强杀及原生快照恢复

- 用户确认独立文件前的真实 SDK 对照复现了故障。SQLite 单文件版约 25 秒误中断健康任务，PostgreSQL 同一请求成功。原始记录见 `sqlite-slow-provider.md`。单文件版全量在布局变更时中止，当时只有 2,110 项通过。
- 最终文件布局下，`test_task_worker_slow_headers.py` 通过，运行 34.61 秒。服务器收完整请求后等至少 32 秒才返回头，两个应用前后两个 16 秒窗口的权威心跳均推进。双方保持原身份，只发出一次模型请求，最终正文完整。
- 真实双进程使用默认心跳、租期和轮询参数。B 持主库写锁 64.99 秒，前 35.11 秒两者各续约 7 次。强杀 A 后 29.87 秒侧库先确认失联，主库仍记录 A 为原执行者。放锁后 0.08 秒，B 完成自己的任务并仅收尾 A 一次。详见 `sqlite-contention.md`。
- `test_task_worker_sqlite_registration.py` 六项含两个真实子进程强制退出，以及两库各自提交前后丢失确认的故障。与单章、向导接管十项合跑，16 项通过。两库之间退出时，登记不完整的身份无法领取任务。
- `test_task_worker_sqlite_recovery.py` 验证主库时间戳陈旧时的存活识别、停止／围栏传播中断后的重入、旧执行体迟到写、主库持锁时双方仍续约，以及频繁唤醒与连续派发失败后的按期扫描。
- `test_backup_sqlite_restore.py`、`test_backup_adapters.py` 和作品备份完整往返合计 39 项通过。实际用 CLI 恢复 0065 与 0066 原生快照，在原配置路径执行迁移并打开新的配对。原任务正文、执行键和收据保留，旧进程身份失效。跨主机冷恢复要求管理员先确认源主机全部停止。

**SQLite 租约文件损坏对照。** `tests/test_backup_sqlite_restore.py::test_new_copy_rotates_lease_authority_and_recovers_saved_task` 以完整文件与损坏文件分别运行，2 项通过（4.24 秒）。先从有运行中任务的 0066 主库生成原生快照。损坏组在执行者已登记、后台写入停止时原位覆盖租约文件 16 字节头部。原执行者续约从成功转为失败，另一应用启动抛出配对错误，没有新执行者登记或任务状态变更。两次尝试后，损坏文件的 SHA-256 未变。旧执行者停机释放生命周期锁后，使用独立保留的主库快照在原路径冷恢复。快照 SHA-256 保持一致，新租约代次、执行者身份均已改变，恢复前持久的旧执行者被围栏；普通恢复将任务及统计各自置为中断并清空执行键。

### 验收边界

任务已成功提交、派生回调的完成情况却无法证明时，旧执行者失联仍可能留下原执行标记。C1 的周期接管处理 running 任务；系统保留成功行的标记，避免重复触发自动分析等副作用。这个排空情形留给 C3 核对。整站多进程启动、并发上限、跨进程取消和实时订阅按父计划分别验收。

最后提交边界另有三组真实章节用例。SQLite 驱动接收 COMMIT 前本地已知失租时，原事务的终态和统计整体回滚，接管者凭已提交的业务收据收尾。仅远端作出失联决定、原事务已持有主库写锁并通过核验时，或驱动已接收 COMMIT 时，原写按主库顺序先于接管。三组均只调用模型一次，正文和统计一致。旧执行者启动的后续事务始终需重新核验，其中包括终态后的历史裁剪。

独立检查见 `integration-review.md`。最终实现上，串行运行 PostgreSQL 16 租约模块、两库 0066 迁移与现有迁移模块，共 43 项通过，用时 125.80 秒。完成测试后已停止此次临时 PostgreSQL 容器。
