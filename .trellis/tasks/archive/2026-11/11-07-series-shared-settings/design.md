# 系列作品与跨书共享设定 · 技术设计

状态：作者已审阅。产品契约见 [PRD](prd.md)，证据见 [现状](research/current-implementation.md)、[归属依赖](research/transition-dependencies.md) 与 [投影写边界](research/projection-write-boundaries.md)。

## 1. 一份系列基础 + 显式采用后的单书投影

**权威写入仅在系列库。** 系列的同一条档案只有一个可写源。作者「在本书使用」时，为该书建立同类型的本书 ID 和绑定；提升旧条目时沿用其本书 ID，不删除重建。现有章节、规划、字段引用、关系和时间线继续只认识同项目的 `(kind, id)`。未采用的系列条目只由系列库列出，不进入作品目录、提及、选择器、AI 或单书备份。

复用现有 `Character`／`WorldSetting` 作为本书投影，而不是创建另一套选择、章节演变和引用系统。系列写事务同步刷新已绑定的投影；没有第二个可独立修改共享字段的入口，不靠任务异步补齐，也不按名称同步。角色列表上的简介和世界观正文列原本就是「本书当前有效值」，不能用它们反向更新系列。

替代方案：

| 方案 | 取舍 |
| --- | --- |
| 分组加手动复制 | 两个权威副本会分叉，不满足修改一次跨书生效。 |
| 把既有角色／世界观行直接移到系列所有 | 可以只存一行，但要把同项目过滤、角色对唯一键、单书写回、级联及撤销一起改成多归属；还需要分离行上的书内当前值。 |
| 权威档案 + 逐书投影（采用） | 不改变章节或关系的身份。代价是系列更新写成本随**采用该条目的书数**增长，且必须封住所有投影写旁路。首版限定显式采用、同步事务；不为全部成员和全部条目预分配。读路径批量取归属，不能逐条查询。 |

## 2. 持久边界与字段归属

迁移拟接在 `0037` 后（`0038`，实施前核对当前 head）。不重建 `projects`／角色／世界观父表，不迁移或合并已有内容；仅新增表与必要的非部分唯一索引。建议表边界如下，名称按现有 SQLAlchemy 约定：

| 记录 | 数据与不变量 |
| --- | --- |
| `series` | 稳定 ID、owner、名称、单调 `revision`、时间戳。非空 owner；owner 的作品移除前仍沿用现有删号保护，无书时删号可级联其私有系列。名称去首尾空白，不以名称做身份。 |
| `series_books` | 一书至多一系列（`project_id` 主键）。`(project_id, owner_id)` 和 `(series_id, owner_id)` 对应父表的非部分唯一键；服务也在锁内校验同 owner 和生命周期。回收站保留成员记录，彻删书级联移除。 |
| `series_entries` | 稳定 ID、`series_id`、`kind = character/world`、严格按类型验证的基础档案与条目 AI 规则。载荷使用明确字段白名单，不含项目、章节、字段/关系引用 ID；不接受任意字典透传。全系列不靠名称唯一化。 |
| `series_entry_uses` | `(project_id, series_entry_id)` 唯一。复合 FK 同时校验对应成员关系和系列条目归属／kind；角色与世界观两列恰一，分别用 `(project_id, local_id)` FK 指向对应实体，一个本书 ID 只绑定一条系列设定。普通本书删除不能连带删绑定；绑定未清理前禁止删系列条目。整书彻删由成员 FK 级联用途，绑定到本书实体的 FK 使用延迟 NO ACTION，使同事务项目级联可完成；两种数据库都验证。 |

本书类型 ID 与系列 ID 分别传输，不能把未采用条目的 ID 塞进旧 `EntityRef`，也不能按同名猜测。SQLite 新身份按项目现有约定启用不复用主键；数据库和服务同时守住跨作者／跨书边界。规划阶段用 SQLite 内存约束原型验证了错 owner／错系列／错书实体、直接删除绑定实体被拒，以及彻删 A 后系列和 B 仍在；真实迁移和 PostgreSQL 并发尚未验证。

| 字段 | 系列基础 | 作品保留 |
| --- | --- | --- |
| 角色 | `name, aliases, profile, appearance, personality, background, gender` | `age, current_state, life_status, role_type, sort, always_in_context, relations_text, setting_tags`，关系/组织/职业/出场/伏笔、自定义字段、章初和章末事件。新采用时用既有角色默认值，不从其他书复制。 |
| 世界观 | `title, aliases, category, content`（基础说明） | 本书排序、标签、自定义字段和所有事件。改世界观类别前复用 `assert_entry_type_change_allowed` 对所有已绑定书验证；任一本不兼容则整笔拒绝。 |
| AI | `ai_mode, mention_enabled, mention_case_sensitive, mention_exclusions, ai_hidden_builtin_fields` 用现有规则归一化 | 一跳关联和自定义／旧字段可见性仍在本书维护；隐藏的共享内建字段也不能从本书事件值绕过。 |

角色简介等与世界观说明同时是时间线字段：系列投影只刷新 `SettingTimeline.baseline` 的相应键，再按该书现有事件重算实体当前列。手动记录本书事件可在该书改变这些字段，不会反写系列。修改本书起始年龄／状态等只作用于该书。书内基础编辑不能以 PATCH／分析／撤销改变系列拥有的基础键。

提升时从已确认的 `baseline` 取共享时间线字段，静态字段取现有条目；缺基线或 `legacy_unverified` 时引导先初始化／校准，不从当前值猜历史。旧 `ai_mode=null` 需要显式选择首个系列档位及追踪（默认建议「检测到才加入」），保留原隐藏字段，不把旧兼容兜底默默推广给其他书。系列版本和来源的编辑快照必须匹配预览；不改变源书的出场、历史或引用身份。

## 3. 状态转移与可恢复依赖

| 动作 | 同一事务内的结果 |
| --- | --- |
| 加入 | 校验活跃且同 owner；成员可浏览共享库，不自动建立采用记录。重复加入相同系列不重复写入，不能隐式换系列。 |
| 新建／采用 | 在系列库新建独立档案；采用时创建对应本书实体、已确认的本书基础和绑定，重复采用返回同一 ID。不接管同名本书实体。 |
| 提升 | 验证源条目为目标系列成员书专属条目且预览未过期；创建权威档案和绑定，沿用源书实体 ID、时间线及本书状态。 |
| 编辑共享 | 校验 revision、类型与隐私规则；应用到所有绑定书（含仍可恢复的成员）。任一投影/校验失败则资料、绑定及版本全回滚。无变更不递增。 |
| 取消采用／退出 | 不带走系列数据。只可删除该书未被引用且没有需保留的书内数据的投影；退出对该书所有绑定逐项检查后一次提交。 |
| 移回某书 | 目标为同系列活跃成员书。目标已有绑定则保留其 ID、基础和本书状态，仅解除共享；否则新建一条目标书专属条目。清理其他书可安全移除的投影；只要有一处失效或丢数据，整笔拒绝。最后删系列档案，而不是留两份权威副本。 |
| 删除条目／空系列 | 删除条目复用全部受影响书的预检；删除系列仅允许无条目且无活跃或可恢复成员。软删书不改变绑定，恢复仍有效；彻删只影响该书。 |

用同一个依赖预检给出预览、冲突摘要和最终写入校验。**需要保留**：当前和可恢复的结构化引用，包括章节出场、细纲与脱离规划中的 JSON ID、POV、世界观、可恢复大纲快照、关系／任职／成员／伏笔、字段句柄的实际引用、AI 关联，以及已写的本书时间线事件、字段和有内容的本书基础差异。只有默认空基线、排序及无使用的基础句柄不当作依赖；停用或孤儿事件如仍保存作者数据不能略过。**不永久阻断**：纯文本提及和热力图重算，旧 AI 输入、待确认分析和撤销在执行时重验，不把历史草稿当永久绑定。实现前对照 [依赖调查](research/transition-dependencies.md) 把 FK 与非 FK 入口都纳入受控测试。

不变量：引用写入若先持父锁提交，随后移除方必须看到并阻挡该依赖；移除先提交时，引用写入方在父锁内查不到该本书 ID，必须拒绝。共享保存要么全部绑定书的基础与版本同事务更新，要么全部维持旧值；禁止先确认成功再逐书补写。

## 4. 并发、写入隔离与实际 AI 出站

- 系列事务先校验 actor，取得系列行写屏障并核对 `expected_revision`；按 `project_id` 排序取得受影响作品的 AI 写门禁，再按同序取得父作品锁。锁内重查成员、绑定、生命周期、来源版本和依赖；不得先查询后脱离事务提交。单书新增／恢复引用也必须在已有父作品锁内校验并写入；不持作品锁再反向获取系列锁。PG 使用现有出站 advisory 门禁；SQLite 用物理 no-op UPDATE 屏障和现有忙冲突语义。内部覆盖可恢复书的锁必须允许已授权的非活跃记录，但不放宽普通 API/出站查询；并发彻删导致目标失效时重新读取或整笔冲突，不半更新。
- 所有实际投影变化同事务更新受影响书的 AI 可见版本；潜在收紧（含移除、改名／别名或新增候选导致匹配竞争、隐藏或追踪变化）递增历史代次。纯共享文本改动防旧投影重发，但不承诺清除已保存聊天和历史产物。绑定增删或规划目录变化同步更新既有规划读版本，时间线基础改动推进对应 timeline revision；不把共享编辑当成改了本书字段目录。多查询一致读在有跨代风险时复核对应版本。
- 已有 AI 消费者继续只读取当前作品资料。绑定角色和地点按现有候选、显式选择、单向一跳与字段过滤进入上下文；不扩大正文、前情、笔记、聊天、知识库或检索范围。验证模型**真实 HTTP 发送**、重试／续跑与 Agent 历史封存：原构建戳跨策略或归属变化不得换戳发送，已发请求不承诺撤回。
- 建立一个投影写保护 helper，用本书实体与请求字段识别受保护元数据/基础；不能把投影整行设为只读。旧角色／世界观 CRUD、基础 PATCH、AI 设置、向导覆盖、卡片、拆书、Agent 修改与效果撤销在各入口持锁使用它或专用的批量变体。角色／世界观向导**覆盖模式**遇绑定，在受理及落库均拒绝该种覆盖；其它无关向导功能不受影响。项目内合法关系、事件、标签、字段和本书 AI 关联仍可维护。撤销若会删除／恢复绑定实体或改写共享字段则冲突；只撤销本书事件时在当前范围重验并按当前基础重算。不能仅凭历史会话封存推断人工撤销不可用。
- 卡片导入、拆书或按名字的自动入库不能用同名绑定作为隐式合并或跨书写入对象。卡片冲突时保留本书副本选择或显式改名，不能默认复用绑定作为导入关系端点；显式选用的本书引用以及正常单书写作分析不受影响。单书备份、按书读取与 Agent 快照沿用本书 ID，不新开系列级 Agent 工具。

## 5. 内部 API 与界面契约

新增内部 `/api/v1/series` 路由，沿用鉴权、错误结构、分页和 service 事务约定。系列拥有者写入，**所有服务同时查 actor、目标成员及资源范围**。私有／不存在的系列或条目均 404；不把「拥有另一本书」或 `projects.edit` 当作系列权限。

| 方法和路径（相对于 `/api/v1`） | 用途 |
| --- | --- |
| `GET/POST /series`，`GET/PATCH/DELETE /series/{sid}` | 自己的系列概览、创建、成员摘要、改名、删除空系列。 |
| `POST /series/{sid}/books`，`DELETE /series/{sid}/books/{pid}` | 加入和退出。加入参数为 `project_id`；已有他系成员需先安全退出。 |
| `GET/POST /series/{sid}/entries`，`GET/PATCH/DELETE /series/{sid}/entries/{eid}` | 分页、类型／名称过滤、新建、读写共享基础、删除。以 `kind` 区分响应和输入。 |
| `POST /series/{sid}/entries/promote` | 书内 `project_id + EntityRef`、来源版本、旧 AI 显式档位（需要时）；返回系列条目和原书引用。 |
| `POST /series/{sid}/entries/{eid}/uses`，`DELETE /series/{sid}/entries/{eid}/uses/{pid}` | 采用／取消；采用返回书内 `EntityRef` 和新版本。 |
| `POST /series/{sid}/entries/{eid}/move-to-book` | 以 `project_id` 指定收回目标。 |
| `GET /series/{sid}/impact` | 按操作和目标返回只读预检（影响成员数、依赖类别及有限示例、来源快照戳）；写入不能信任前端预检结果。 |

修改用 `expected_revision`（DELETE 用查询参数）；冲突示例：`409 stale_revision` / `scope=series`、`series_setting_in_use`（按本账号作品与引用类别列有界摘要）、`series_setting_managed`（误走书内基础写）、`series_baseline_unverified`。重复同一无变更动作不制造新的条目。读取保持 `ProjectOut` 和角色／世界观本书 ID；在作者会话返回轻量系列摘要与条目归属。单书管理员最多看到该书已采用投影，不获得系列链接、其他书摘要或写权；授权 API Key 继续只读取该书的本地资料与显式采用的投影，不在开放接口暴露系列 IDs／入口。

前端沿用书库、作品概览、`CharactersPanel`／`WorldPanel`、AntD 与已有草稿／冲突处理。系列页显示成员和可分页共享库；作品设定的「全部／本书／系列」区分可浏览与已采用，不把同一绑定显示为两行。点击「在本书使用」时说明将进入本书选择器、按现有规则供 AI 使用，并沿用本书读权限；编辑界面把「系列基础」和「本书演变」分开。旧读请求离页/换书/换身份失效；保存冲突保留草稿并显式刷新对照，不静默重试；成功后精确刷新已受影响资源，不能覆盖其他未保存表单。成员作品仍在原书库搜索、统计和阅读入口中。

## 6. 传输、发布和回滚

- 单书备份保留 `ainovel.project` v6 形状：显式采用的投影、对应基线／事件和本书引用按原注册表导出为书内快照，其他系列条目、成员和绑定不进入文件。登记相关表的 `NOT_EXPORTED`、同步 exporter 的 `APP_SCHEMA`，复用 FK／JSON 重映射。备份提示「恢复为独立作品」；不能写出只有系列裸 ID 的依赖，不能导入伪造的关联字段。系列变化期间利用受影响书版本复核，不闭合跨代混合文件。
- 已选角色卡片导出仍是静态快照，不夹带系列身份；合法旧备份／卡片继续导入。不改变 EPUB／Markdown 等正文导出；实例整库备份自然保留新表，单独验证恢复能重建相同系列关系。
- 空库与有真实存量的 `0037` 都验证升级，无系列时路径和数据不变。首次上线前排空旧执行器并原子切换运行版本；旧代码不认识投影写保护，不能与新写路径混跑。无系列数据时才允许 schema downgrade；有数据拒绝有损降级，优先前向修复，必要时停写并按经过验证的整库备份恢复匹配的版本。
