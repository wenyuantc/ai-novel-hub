# 系列作品与跨书共享设定

> 作者已审阅并授权实施，采用「共享基础档案，各书独立演变」。

## 目标

让创作同一世界的多本书的作者维护一份系列设定，不再靠导入复制后逐本修正。作者能辨认一条设定是作品专属还是系列共享，并主动调整归属。

## 背景与约束

- 来源：`TODOS.md:72–80`。系列分组、跨书共用、查看与调整归属是一条可端到端验收的主流程。跨账号协作授权属于第 11 项，不并入本任务。
- 作品、条目、章节引用、设定演变和写作上下文当前都以作品为边界。卡片导入只是创建本地条目或处理同名冲突，不建立同步关系。事实及代码定位见 [现状调查](research/current-implementation.md) 和 [归属调整依赖研究](research/transition-dependencies.md)。
- [Novelcrafter Series Codex](https://www.novelcrafter.com/help/docs/codex/series-codex) 可作交互参考：同系列书可查看同一共享库，按全部／系列／本书切换，可直接新建共享条目或改变归属。本文档不据此推断其引用、权限或剧情历史行为。

## 首版范围

| ID | 场景 | 行为 |
| --- | --- | --- |
| R1 | 管理系列 | 在书库创建、重命名系列，管理已有作品的加入和退出。仅同一作者自己的正常作品可加入，每部作品最多归属一个系列，也可独立。仅无条目且无成员（含仍可恢复的成员书）的空系列可删除。 |
| R2 | 浏览与维护共享库 | 支持角色、地点及其他五类世界观。在系列库直接创建或编辑一次；成员书刷新或重新打开可见新内容。角色／世界观页面显示归属并可按全部／本书／系列筛选；编辑共享基础时说明影响全系列。同名旧条目不自动合并。 |
| R3 | 调整归属 | 成员书可提升本书条目为共享，保留原书结构化引用和数据。已有旧历史且基础值未校准时先明确确认基础，不把剧情末态提升为共同事实。将共享条目收回指定成员书、删除共享条目、取消本书使用或退出系列之前，检查会失效的已保存资料和结构化引用（含可恢复的细纲快照及回收站作品）；有依赖则提示涉及作品与用途并阻止操作。不静默断链、复制或覆盖。字面提及不阻挡；旧待执行输入及撤销在使用时重验。 |
| R4 | 在书中使用 | 仅浏览系列库不会把条目加入本书。作者点「在本书使用」后才可用于章节出场、规划（角色／POV／世界观）、提及和既有写作上下文；原书提升时自动保留本书使用。仍遵守四档 AI 可见策略和字段隐藏，手选不绕过，AI 不改共享基础。 |
| R5 | 共享基础、独立演变 | 名称、别名、角色简介等基础档案、世界观基础说明和条目级 AI 规则共用。出场、关系、自定义字段、角色在本书的年龄／状态及各书的章初／章末变化留在本书。两书可分别写同一角色的剧情变化；修改共享基础以新基础重算各书有效资料，不转移任一书的事件，也不重写正文或历史记录。 |
| R6 | 数据与访问安全 | 系列库及操作仅作者可访问。对共享条目，单书既有权限只覆盖作者明确加入该书的条目，不能借单书管理员或 API Key 读取系列库或其他书。单书备份只带本书明确采用的共享条目快照，不带系列归属或其他书资料；恢复为独立作品。回收、恢复和彻删单本书不破坏其他成员书及共享库。 |

## 不在首版

- 组织和职业条目本身的共享、关系图及组织成员或职业任职的跨书同步、系列级自定义字段目录／分类规则。原书已有的数据和功能不能因本任务被删除。
- 跨账号共享或协作、同名设定自动去重合并、实时推送刷新。
- 跨书剧情时间轴、选取或自动继承前作结局、按卷切换共享基础版本、读取其他书的正文／笔记／聊天／知识库、整系列导入导出、外部 API 的系列访问。

## 验收标准

- [x] AC1 / R1–R2：作者创建系列并加入 A、B。A 提升「林青」，在系列库新增地点「白塔」。B 刷新后能在系列筛选看到两条；改一次白塔说明，A、B 都读到新值；非成员作品 C 的入口及其他账号均不能读取。B 的同名本书角色仍存在。
- [x] AC2 / R3：A 提升前的选角、细纲和已有剧情历史仍可打开；若 B 引用了该条目（包括只存在于可恢复快照的引用），收回到 A 或移出 B 被拦住且数据不变。解除 B 的依赖后收回到 A，A 保留原引用，B 不再读到系列条目。仅有正文同名文字时不阻挡。
- [x] AC3 / R4：B 没有选用共享条目时，章节选择器和 AI 候选不出现该条目；选用后可指定出场、保存规划、定位本书提及。设为「永不加入」或隐藏字段后，手选和基于旧策略的待发送请求都不能将相应资料发送给模型。
- [x] AC4 / R5：A、B 给同一个共享角色分别记录本书章末状态。A 的事件不出现在 B 的章初或章末；更新共同简介后各书看到新简介及各自有效状态，已有事件没有转移或丢失。
- [x] AC5 / R6：回收再恢复 A 后原绑定仍有效，最终彻删 A 不影响 B；恢复 B 的单书备份可打开 B 的角色、地点和历史引用，不创建系列关系，也不导出只在 A 采用或从未采用的条目。仅对 B 获授权的外部 API Key 无法获取系列库、A 或未在 B 采用的条目。
