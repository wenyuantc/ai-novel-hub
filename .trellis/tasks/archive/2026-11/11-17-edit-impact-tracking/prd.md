# 修改影响追踪

## 目标
父任务 `11-17-consistency-check-impact-tracking` 的子任务 2，承接其 R4 及 R5、R6 的相关部分：作者修改早期章节后，能看到该章派生内容已过期，并可手动评估对后续章节的影响，逐项确认复核。

## 依赖与顺序
依赖子任务 1 `11-17-consistency-check-issues` 落地的事实台账表结构、单章抽取函数与问题清单页。2026-11-17 子任务 1 的实现与验证完成（尚未提交归档）后，按用户「全部任务都要完成」的指示接续写出 design.md 与 implement.md 并实施；两者的改动在同一工作区叠加。

## 背景
证据见父任务 research/code-inventory.md。父任务决策 D2 已定两级判定。相关现状：
- 章级摘要即最新分析的摘要，过期判定已存在于导出路径（backend/app/services/document_export/story.py:153–179）。
- 剧情记忆已有只读的 `source_stale`（backend/app/services/memory_service.py:309），仅在记忆页面显示。
- 设定演变保存了 `source_content_hash`（backend/app/models/progressions.py:124），目前没有任何比对。
- 没有统一的「正文已变更」事件；过期均可由指纹在读取时判定。

## 需求
| ID | 行为 |
|---|---|
| T1 | 第一级（免费、即时）：章节正文保存后，在该章编辑页与一致性页面可见其派生内容已过期的清单：章摘要、来自该章的剧情记忆、由该章分析写入的设定变化。不调用模型，只按指纹判定，不误报未受影响的条目。 |
| T2 | 第一级清单的每一项可跳转到对应的摘要、记忆或设定变化位置，由作者自行更新（如重新分析）或确认无需更新。 |
| T3 | 第二级（手动）：作者对已改动的章节点击「评估影响」，重新抽取该章事实台账并与改动前的台账比较（最多两次模型调用：重抽一次；新旧事实字面不同时再由模型判定一次是否为实质变化，避免措辞差异造成误报），得到新增、消失、改变的事实。 |
| T4 | 仅当事实确有变化时，列出后续章节中引用了这些事实主体的章节及其相关原文证据，作为「可能受影响」清单；事实无变化时明确告知「未发现剧情事实变化」。 |
| T5 | 受影响清单逐项可标记「已复核」或「无需处理」，可跳转到对应章节位置；被列出的章节正文之后发生变化时，该项提示已变更。 |
| T6 | 该章没有改动前的台账时，只显示第一级，并提示先运行一次一致性检查。 |
| T7 | 权限：查看者可查看；确认复核需编辑能力；评估影响需 AI 能力并沿用模型授权规则；撤权后进行中的评估失效关闭。 |
| T8 | 新增的影响记录与确认状态纳入作品备份或登记不导出理由；与子任务 1 的备份格式兼容。 |
| T9 | 评估影响不改动正文、摘要、剧情记忆、设定，也不改变子任务 1 中问题的状态；两处对同一章节的提示口径一致。 |

## 验收标准
- [ ] AC1 / T1,T2：修改并保存第 5 章后，其摘要、来自第 5 章的剧情记忆、由第 5 章分析写入的设定变化显示已过期并可跳转；其他章节的派生内容不受影响。重新分析第 5 章后对应提示消失。
- [ ] AC2 / T3,T4：将第 5 章改为「佩剑已毁」并评估影响后，第 12 章出现在受影响清单中并展示相关原文；只改错别字时评估结果为未发现剧情事实变化，不列出后续章节。
- [ ] AC3 / T5：受影响项可确认并保持；被列章节再次修改后该项提示已变更。
- [ ] AC4 / T6：未做过检查的章节只显示第一级与引导提示。
- [ ] AC5 / T7：查看者、编辑者、非协作者与撤权路径符合既有契约。
- [ ] AC6 / T8,T9：备份往返后影响记录与确认状态保持；评估前后子任务 1 的问题状态不变。
- [ ] AC7：后端与前端完整门禁通过；README、规范与 TODOS.md 第 14 项第四条同步。

## 口径
- 受影响章节只依据后续章节已有的最新事实台账判断；尚未抽取或已过期的后续章节无法判断，须在结果中列出并引导运行检查，不静默忽略。
- 每章只保留最近一次评估；重新评估时未变化的受影响项保留原确认状态。
- 第一级中由旧分析写入、作者确认无需更新的设定变化可标记为已确认，不再提示。

## 不在本任务
保存即按共享人物列出后续章节；保存后自动 AI 评估；自动更新摘要、记忆或设定；一致性检查本身（子任务 1）。
