# 外部执行期间的用户与作品删除

## 发现与保护范围

外部确认在提交 `AgentChange.status=executing` 和 claim 后才调用 MCP；该请求可能持续跨越任务取消。若只查看任务是否处于终态，作品或触发用户删除会级联删除会话、提案，或将 `turn_task_id` 置空，丢失可证明外部操作未结束的记录。已有真实 HTTP 反例中，带未决提案的用户和作品删除均返回 204。新增反例也证明，外键已置空但持久 `turn_task_key` 仍关联任务时，原前检会错误允许用户和跨作品关联的作品删除。

`has_unsettled_external_change` 在锁内检查：未识别的非终态、任意残留 claim/task key 或 `_external_outcome_unknown` 标记（包括 JSON null），以及终态外部结果缺失、非对象或缺少与状态对应的字符串 `error`／`text`。MCP 正常生成失败结果 `error` 或成功结果 `text`；空对象、缺字段及 JSON null 无法证明正常收尾。关联通过提案自身作品、会话的作品与用户、任务整数 ID、持久 `turn_task_key`、结果中的任务 UUID，以及任务章节所属作品判断；只要有任一关联就保留未决证据。明确无 claim 的正常完成记录和正常 proposed 记录不拦截，完全无关联用户和作品不因他人执行受到影响。SQLite 与 PostgreSQL 分别使用其 JSON 操作实现相同含义；未验证的数据库类型失败关闭。

用户删除在现有认证 gate 与 actor/目标 User 写屏障中检查该用户的任务执行标识及未决外部提案，匿名返回 `user_has_pending_tasks` 并使用原失败审计；有自有作品仍先走既有规则。作品删除先取得认证/User、再取得 project 锁，未决提案且本进程没有项目工作时直接匿名返回 `project_tasks_not_stopped`。若本进程恰有工作，仅在原权限复核后写入删除意图、释放锁并等待，不取消任何任务。等待结束后重新按认证/User → project 顺序锁内查询所有未决提案；只要任一提案仍未决就清除意图并 409。因而本地 `project_work` 仅是等待线索，绝非证明某条 claim 由本进程执行或已经停止的依据。等待期间请求取消、超时或权限／意图变化均不能留下删除意图。所有未决证据消失后才继续既有任务排空与项目删除。

回收站物理清理和到期清理在项目锁内调用同一检查，并检查任务 `execution_key`。任务直接作品 ID 缺失时，仍按其章节所属作品查占用，避免物理清理章节时将唯一关联置空。正常任务、历史终态和管理取消流程继续走原有排空规则。管理员手动失败继续记录失败审计；到期清理逐项失败并保留数据。

## 证据

- 新增 SQLite HTTP 用例覆盖用户会话、任务 ID、结果任务 UUID、持久 turn UUID，跨作品错绑及仅章节关联，执行中/未知状态、缺损结果和 JSON null、无关用户/作品、正常历史、回收站清理及系统过期。外部未决且存在无关本地工作时，专项分别验证始终未决、等待中持久状态完成、请求取消和等待超时；在持久事实解除前，无关 queued 任务保持原样。第一次完整专项（不含真实 MCP 一项）30 passed；随后新增的缺损终态结果在旧前检上四项红灯，修复后的复测待错峰执行。
- 完成任务身份并行改造后，真实 FastAPI 请求与 `FakeMcpConnector` 本地替身验证两项通过：作者与管理员删除都等待外部确认，远端只调用一次、确认 409、删除 204、任务取消且未泄露调用结果；该测试不访问真实外网。多个本地工作时，在任一工作结束后重查持久事实，无需等其他工作自然结束；专项 5 passed。
- PostgreSQL 16.15，本机专用 `collab_test` 隔离库、随机 schema：最初四项双连接测试 **4 passed in 18.40s**，覆盖 claim 先提交时两种删除阻塞后均 409、删除意图先提交阻止新 claim、删号先提交使后续旧身份失效。随后增加持久 turn UUID、无关本地工作与跨连接事实重查、缺损终态结果，合计实跑 **9 passed in 33.63s**。用例模拟未来协作 Agent 遵循同一锁协议，并非协作 Agent HTTP 的完整验收；外部结果未知的后续接线完成后仍须复验。

## 边界和后续

- 本协议依赖外部执行只有在执行体结束且持久完成结果已安全提交后才移除 claim。不得以过期时间或仅凭本进程没有 work 推断另一进程的执行体已停止；`recover_external` 和执行确认收尾须遵守同一事实，相关修复由并行的外部执行／engine 工作负责。
- MCP 超时或连接错误只证明本地连接结束，无法证明远端业务没有继续执行。原实现可将这类结果写成普通 `failed` 并清除 claim，删除检查无法再区分已结束失败与远端结果未知。并行工作正实施持久 `_external_outcome_unknown` 与 claim 保留，本前检将该标记及缺损情况视作未决；尚须验证所有未知结果路径、旧数据处理及明确的人工处置策略，不能声称已经证明远端停止。
- 没有任何仍存会话、任务 ID、任务 UUID 能关联某用户的纯孤儿数据，无法反推其触发用户；此类数据也不会通过删除该用户的会话或任务级联删除。作品维度仍依据提案或其他可见外键保护。人为破坏跨作品外键的并发写入若不遵循相关作品的共同锁协议，本次快照检查不证明其可串行化；生产写路径及历史修复工具必须遵循共同屏障。
- 终态任务与 `on_abort`、`_on_success` 的持久执行代次和章节／索引 claim 清理仍依赖 0045 协议与跨进程验证；本切片不能单独证明所有账号删除与后台派生执行竞态已闭合。
