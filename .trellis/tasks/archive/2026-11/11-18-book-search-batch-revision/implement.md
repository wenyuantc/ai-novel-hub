# 实施与验证

## 实施顺序

1. **正文检索与定位。** 对照 `scene_service.project_scenes`、阅读页、提及锚点和一致性证据跳转。实现字面匹配、范围校验、分页和来源标识。用同段重复用词、补充平面字符、空章、未知词、过期页和场景分隔符验证。
2. **替换预览。** 复用富文档范围映射。以一章多场景、同场景多命中、不同长度替换、编辑时的格式边界和标记为样例，校验单项与组合预览。预览不产生写入。
3. **批次事务和撤销。** 新增迁移、批次模型和作品级服务。核对人工编辑的写屏障、版本记录合并规则与审计提交点，先全量预检，再统一写入。验证第二章写入失败时整批回滚、相同请求重试、两个编辑者并发、只改章名或改后改回、目标章删除或重建、撤权和生成中章节。
4. **工作区页面。** 接入菜单、阅读页、权限和作品刷新机制，覆盖跨页勾选、预览失效、提交后的记录和冲突章清单。模拟旧自动保存与批改的两种先后顺序，确认有冲突的草稿可恢复。禁止过期响应覆盖新作品或新预览。
5. **备份与回归。** 接入 `project_transfer` 注册表、格式升级与导入引用重映射。覆盖含历史、未选择历史、旧格式、冲突批次和损坏快照。迁移在隔离库验证，保留非空降级保护。按 PRD 在浏览器走通查找、跳转、排除引文、确认、成功撤销与冲突撤销。

## 验证命令与观察点

以下命令用于实现阶段。先跑受影响用例，再跑仓库完整检查。新增批改用例应覆盖真实数据库事务，失败注入后重新查询所有受影响章节和批次行，不能只断言 HTTP 状态。

| 工作目录 | 命令 | 验证范围 |
| --- | --- | --- |
| `backend/` | `uv run --frozen pytest -k 'book_search or batch_revision or chapter_title_save or rich_document or project_transfer'` | 新功能与交叉路径，新增测试模块采用前两类名称 |
| `backend/` | `uv run --frozen ruff check .` | 后端静态检查 |
| `backend/` | `uv run --frozen pytest -n 4 --dist loadfile --durations=20` | 项目既有 SQLite 回归 |
| `frontend/` | `npm test`、`npm run lint`、`npm run build` | 页面逻辑、类型和构建 |

浏览器验收使用同一作品两个编辑会话。一次选中第 2、5 章，排除引文后确认；一轮无后续编辑，一轮在第 5 章另写一句，再分别从批次历史撤销。核验两章正文、版本、标记及历史状态。另用只读协作者验证搜索定位和写操作权限。

## 失败处理

若实现发现单章保存会自行提交，改用其事务内写入部分；若现有映射无法保证保留富文档，预览须指出具体命中及原因。验证替换、撤销、备份导入和重试能各自保持原子性后，再更新功能待办的完成状态。
