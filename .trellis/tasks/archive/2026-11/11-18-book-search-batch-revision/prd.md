# 全书搜索与批量修订

## 目标

作者统一人名、地名或术语时，可以一次找齐当前作品正文中的用例，逐处判断是否替换，并在需要时撤销这次修订。需求来源见 [TODOS.md 第 16 项](../../../../../TODOS.md#16-全书搜索与批量修订)。

## 现有能力与边界

- 已有提及定位通过文本范围和内容指纹跳转，旧位置失效时会提示作者。单章已有版本预览和恢复。见 [提及定位](../../../../../frontend/src/utils/mentions.ts) 和 [章节版本服务](../../../../../backend/app/services/chapter_version_service.py)。
- 本项操作对象为当前作品的章节正文。场景正文构成章节可读文本，作者区块有独立内容。人物改名指替换正文中选定的用例，角色卡、知识库、摘要和笔记均在本项范围之外。见 [场景富文档契约](../../../../spec/backend/rich-documents.md)。

## 需求

1. 按输入的原文搜索全书或指定起止章节，范围含两端。每个命中都能看到所属章节和上下文，并跳到对应段落。同一段落内的多处命中可以区分。
2. 输入替换文本后，按章节展示每处命中的原文和改文。作者可逐处勾选，确认后仅替换选中的用例。
3. 一次确认生成一条批次记录。预览后选中的章节发生变化时，整批停止并提示重新核对。撤销也以整批为单位，只要任一受影响章节在修订后又被编辑或删除，就保留整批现状，列出冲突章节。此撤销规则已于 2026-11-18 确认。
4. 搜索与写入遵循作品现有的阅读、编辑权限。替换或撤销时须保护正文格式、作者区块、标记和已有的自动保存冲突处理。命中若横跨场景或无法安全保留文档结构，预览应标明原因，作者可跳过该处继续选择。

## 验收场景

- [x] 第 2、5、9 章均含「青石镇」。搜索全书能看到三章的命中。限定第 2 至 5 章后只看到第 2、5 章。从第 5 章的第二处命中跳转，能定位该处原文。
- [x] 将「青石镇」改为「青石城」。在预览中取消一处刻意保留旧称的引文，再确认替换。引文保留旧称，勾选的用例改为新称。
- [x] 重新打开作品后能找到该次修订记录。各章没有后续修改时，撤销一次即可恢复本批改动，保留原有正文格式、标记与区块。
- [x] 修订后在第 5 章另写一句话，再尝试撤销。界面指出第 5 章冲突，新写的句子和其余章节的改名均保留，批次仍显示为已应用。若只有未参与该批的第 9 章发生编辑，撤销成功，第 9 章保留新稿。
- [x] 编辑者甲预览后，乙先保存一个选中章节。甲确认时看到冲突，其他选中的章节也没有被替换。调换顺序，乙的旧自动保存收到版本冲突，草稿仍可核对。
- [x] 只读协作者可搜索和定位；有编辑权限的用户可以提交和撤销。修订处于富文本或标记附近时，预览能说明对该处的影响，无法安全处理的命中仍可定位。
