# 全书搜索与批量修订设计

## 搜索和定位

在作品工作区增加「全书搜索」入口。以已保存的章节正文为搜索对象，输入框接受非空字面文本，按原样匹配，区分大小写，从左向右返回互不重叠的命中。首版聚焦准确找词，正则、模糊匹配和联动修改设定资料不在范围内。

后端按章号、章内位置稳定排序，使用现有 `Chapter.content` 投影搜索，分批读取和分页输出，不把全书正文发给浏览器。查询携带作品、搜索词、起止章节，续页校验范围内章序、身份和修订的快照，过期后提示重查。无命中、范围反转、首尾章节已删除和旧结果失效应有可区分的反馈。

每个命中包括章标识、章号、章版本、原文指纹、Unicode 码点半开区间和前后文。保留空白和换行。定位复用 `frontend/src/utils/mentions.ts` 与阅读页已有锚点，增加搜索来源和失效提示。任意正文词均可定位，包括提及词典中不存在的词。旧位置只提示重新搜索。

## 预览和应用

在作品 API 下分设搜索、预览、应用、批次历史和撤销操作。查询、历史按现有 `content.read` 鉴权。提交和撤销使用 `content.edit`，在写入时重验当前账号与作品权限。浏览器保留跨页选择，展示每章的勾选数和原文／改文，换作品、关键词、范围或替换词时使旧预览失效。没有有效改动时不能产生批次。

预览的每一项绑定原作品、章、场景、章版本、命中区间、搜索词和替换文本。应用只接收这些条件和明确选择的命中。在服务端重新验证归属、范围、选文、位置及文档限制，不接受客户端提供的最终正文。删除重建后不能凭相同章号或复用的主键更新新章。只处理勾选的命中，写入范围限定为包含这些命中的章节。

通过 `scene_service.project_scenes` 的章景范围，把章内命中映射到活动场景。跨景、场景分隔符、CRLF 中间或无法证明格式与区块锚点可保留的命中，可预览和定位，标明不可批改的原因。同一场景按码点从后往前替换，复用 `rich_document_mapping.map_explicit_replacement` 的格式与标记规则。对会成为失效状态的标记，在预览中提示。按最终勾选组合核验映射，结果与预览不一致时整批要求重查，不能静默丢掉格式或跳过已选项。

沿用人工编辑的权限、发送屏障、单章生成和在跑批量任务范围保护。按稳定顺序取得目标章节，先预检全部目标，再用现有富文档写入、章投影、版本与审计的事务内函数处理，每章只推进一次内容版本。批次记录与正文在同一事务提交。避免循环调用会自行提交的单章保存接口。投影和指纹更新后，沿用既有的摘要、记忆和设定过期提示。

## 批次记录、撤销和重试

批次头保存作品、稳定批次标识、操作时间、状态、改动章数和命中数。明细独立保存实际改动的场景、原富文档、应用后的章修订号以及核验身份所需的信息。即使普通章节版本被合并或裁剪，仍可核对该批次。保留历史章号和章名，目标章被删除时仍能指出冲突。恢复仅覆盖本批涉及的正文与富文档字段，保留独立的规划数据和作品其他资料。

撤销时在同一写事务中核验整批状态、每个受影响章的身份、修订号及场景归属。返回全部可识别的冲突章，整批保留原状态。后续编辑即使改回相同文本，版本已变也算冲突；未参与的章不会阻塞。条件全部满足才恢复各章、推进新版本并将批次记为已撤销。禁止将章节版本号倒退到旧值，以免放行旧自动保存。

应用请求用稳定请求标识绑定账号、作品和载荷摘要。回执丢失后，重试同一请求只返回原批次；重复撤销已撤销的批次返回其现状，均须先鉴权。异常或事务失败时全部回滚，不留下孤立批次。只读页面只返回展示所需的修订信息，原富文档快照留在服务端。

## 兼容与恢复

新增批次数据采用增量迁移，已有作品无须重建章节或搜索索引。作品备份沿用「章节版本」选项携带批次历史和撤销数据。导入时映射作品内章、景与快照引用，已删除目标保留为失效，不能按名称或编号重新绑定。旧备份以空批次历史导入。实现时验证可撤销和已有冲突两类备份往返；数据库降级有批次数据时遵循现有非空保护。
