所有本地厂商响应均由模拟服务提供。本次未使用真实服务商的付费额度。

| 场景 | 验证结果 |
| --- | --- |
| 图片 | 实际 SDK 向本地模拟服务发送参考图与画幅，验证协作者发起、作品作者承担一张费用、媒体可读、超预算与撤权后拒绝。图片专项 15 项通过。旧版 OpenAI 图片模型遇到不可表示的比例会给出提示。 |
| 任务恢复 | 真 Chrome 保持页面打开，强制结束等待中的后端进程并启动新进程。同一厂商编号收到 1 次提交、2 次查询，产生 1 条用量，原页面自动播放。 |
| 取消 | 从页面取消等待中的任务后，任务及台账均为 cancelled，无结果文件或费用，执行槽位为零。成片和费用已保存时，迟到的取消会被拒绝。 |
| 下载与授权 | 下载限制、私有地址、重定向、密钥仅用于配置地址，以及执行期间撤权均有专项回归。提交结果未知时保留错误提示，不自动重发。 |
| 计费 | 单价支持每秒、币种与分时档位。验证个人与作品用量、拒绝超预算、无定价只计量、同一任务重复进入不重复计费。 |
| 预算迁移与并发 | SQLite 与 PostgreSQL 16.15 均从 0072 的旧费用开始，核对 0073 的历史累计为 79、尚无提醒，再升到当前结构并发结算。重复结算保持幂等，账号与作品各产生一条到额提醒，回到 0073 后继续降级触发预算数据保护。 |
| 迁移与备份 | SQLite、PostgreSQL 16.15 验证 0081→0082→0081、旧资料和视频/音频降级保护。SQLite 原生恢复及 PostgreSQL pg_dump/pg_restore 恢复了同一任务号和历史用量。单书导出、导入均排除厂商任务。SQLite 空库从 base 到 0082 再回到 base 的原有全链测试通过。0082 重建表时保留 0062、0063 的四个列级 CHECK，避免回退删除历史价格列时因表级检查仍引用旧列而失败。 |
