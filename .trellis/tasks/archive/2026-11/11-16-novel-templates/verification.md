已在隔离 SQLite 实例准备来源测试作品：含正文及角色、地点、组织、职业图片；角色由系列采用；另有上级／下级组织、含角色引用的章纲与细纲、地点的计划章变化（当前值为「计划后的测试地点状态」）。此准备不代表模板接口或验收通过。

实施代理阶段证据：最小真实 HTTP 已覆盖本人预览、保存、模板管理、空正文建书及删除模板后同意图重放；SQLite 故障注入覆盖配额、结果回收／恢复／彻删及全应用后失败无半本书或收据。快照首批 8 项覆盖配置、依赖、同名身份、四类字段、计划值与图片上限；应用层 SQLite 9 项、真实 PostgreSQL 5 项通过，覆盖四类字段回读、图片末尾故障回滚、计划值和风格并发。上述为阶段定向测试，尚不能代替各验收项及独立复核。

真实浏览器阶段验收：单书编辑协作者的来源作品概览没有“保存为小说模板”入口。作者从带正文的测试书选中下级组织和章纲后，预览明确列出缺少上级组织及细纲角色，确认按钮不可用；明确补选后再加入地点和职业，预览显示 1 角色、1 世界观、2 组织、1 职业、1 章纲、1 细纲、4 图片并成功保存。新建时选择该模板及不同于来源的笔名“山间”，新书概览显示 0 章、0 字和未加入系列；地点列表显示图片及计划后的当前值，角色列表显示图片，大纲页显示 1 条章纲及未建章细纲。此阶段发现的依赖原因内部 ref 已修正，重验见下。

同一真实服务以 API 补核对：来源与新书的地点图片 bytes 相同但资源版本不同；新书地点 baseline 状态为 confirmed、值为计划后的当前内容，progressions 为 0，新书 chapters 为 0，章纲和细纲各 1 条。

375px 真实浏览器：作者打开保存弹窗、预览配置及配套定义清单，滚动到底可见全部操作按钮；成功保存纯配置模板，再从手机宽度新建对话框选择该模板、填写书名并创建，新书概览显示 0 章、0 字。测试结束后已恢复浏览器默认尺寸。

真实 HTTP 权限补核对：有来源作品编辑权的测试协作者读取作者的模板详情及预览作者作品模板，均得到 404。

独立前端复核后及最终缩略图尺寸提示修改后均重新运行：`npm run lint`、`npm run build`（含 TypeScript）通过，最终 `npm test` 为 236 个文件、1644 项通过；模板定向 6 文件、19 项通过，覆盖断网后重开沿用原 key、旧请求与新意图竞争、身份失效及扩展字符长度。模板冲突、断网重试和账号切换的真实浏览器验证与上述组件／单元测试分别记录。

重启临时后端加载本轮快照代码后，真实浏览器重新选择下级组织与章纲：依赖原因显示「组织『测试下属组织』的上级组织」和具体章纲名称，不再暴露内部 ref；展开配套定义可见字段「模板测试境界」及「初阶、进阶」选项。补选并重新预览后，通过独立测试会话修改来源作品，再点击保存，界面显示「源作品已变化，请更新预览」，保留当前选择和输入并禁用直接保存。

真实浏览器断网重试：填写模板及书名后停止隔离测试后端，提交得到 502，界面保留模板名称、版本和书名并提供「使用同一请求重试」；关闭再打开弹窗后该状态仍在。恢复后端并重试进入新书概览，显示 0 章／0 字；只读核对临时 SQLite，目标书仅 1 本且关联 1 条创建收据。此场景模拟提交前后端不可用；提交已成功但确认丢失另由服务的故障注入测试覆盖。

真实浏览器在模板库修改名称和说明，版本由 1 升至 2；从来源作品以仅配置内容替换后版本升至 3，列表的设定和图片计数变为 0。只读检查隔离测试数据库，已用旧模板创建的新书仍保留 4 个图片绑定，证明替换模板未改变既有作品。

真实浏览器从作者切换为协作者账号后，私人模板库显示空状态；「从作品保存」的来源下拉仅列出协作者自己拥有的测试书，不包含可编辑的作者作品。直接接口越权 404 另有 HTTP 和自动测试证据。

另在隔离测试库引导独立管理员账号：真实浏览器可人工查看作者作品，但署名只显示当前作品的「海上」，没有署名选择器及「保存为小说模板」入口；管理员自己的模板库为空。该管理员直接读取作者模板及修改作品署名均返回 404，自身笔名库为空。

在隔离 HTTP 实例中对先前模板创建的新书执行后续使用：确认起初章节为空，修改其地点名称，按细纲建出 1 章并核对角色出场引用；导出 v11 单书备份，检查三张模板／收据表不在备份中，随后预览并恢复。恢复作品保留修改后的地点、缩略图、1 章及本人所选笔名「山间」。测试脚本最初把 `pen_name` 误当字符串断言；按实际响应对象的 `name` 字段只读重核后通过。

整库恢复组合验收使用临时数据库：SQLite 通过产品的在线快照适配器生成文件，再复制到独立恢复库；逐行核对笔名、作品关联、设定图资源和绑定、模板、模板图片及创建收据，`quick_check` 与外键检查通过。恢复库启动服务后，模板图片可读；删除原模板后按原意图重放仍返回原作品。PostgreSQL 16 另从空库真实迁移到 0057，经 HTTP 创建笔名、设定图、带图模板与带收据的新书；使用产品的 `pg_dump` 适配器和 `pg_restore` 恢复到另一个隔离库，恢复后模板图片可读，删除模板再用原意图重放仍返回原作品及笔名。上述两套均只操作本任务合成数据。

独立服务复核新增协作者、管理员对作者模板私库的 HTTP 隔离，以及提交成功但确认丢失后同 key 找回原书；还验证模板删除且额度降为 0 后成功重放。损坏 JSON、深层 JSON、非法 UTF-8 均转为受控错误并不产生作品；0057 在 SQLite 的模板、图片、仅收据及 PostgreSQL 的模板、仅收据存在时拒绝降级。服务复核在快照代码稳定后需重跑最终组合。

独立应用复核修正了部分大纲卷号：来源第 2／5 卷、每卷多章、同名卷标题分别在 SQLite 和真实 PostgreSQL 完成 HTTP 预览→保存→建书，新书卷号、章纲排序和细纲序号连续，仍为 0 章／0 字；直接应用回归 SQLite 11 项、PostgreSQL 1 项通过。

真实 PostgreSQL 回收站清理回归覆盖目标主体／章节／场景／分析来源的跨作品外键检查，以及双方先后持锁两种顺序。先写一方未提交时，purge 实际等待；其提交后 purge 检出并拒绝错误跨书引用，目标作品仍在回收站且他书值不变（空／非空目录共 2 项）。反向顺序的 8 组竞争及同书、双作品并发清理亦通过。清理不全库反查绕过服务写入的无 FK JSON／替代链损坏，也未做大库压力测试。

快照独立复核后的 SQLite 组合 105 项通过，真实 PostgreSQL 16 快照整文件 9 项通过、无跳过；覆盖章首／场景／章末排序、多条时间线与既有 resolver 对照、4500 条无效或被覆盖历史只向 Python 返回最终有效事件、非法空追加、细纲 JSON 与图片的读取前大小校验及正常中文内容。应用侧内存受当前值和输出上限约束，数据库仍需扫描和排序所选时间线历史元数据。

最终后端完整套件收集 7429 项，按文件分组使用独立源码和 PostgreSQL 16 数据库；一组初次出现 10 秒任务流超时后，以相同源码和库低负载整组重跑通过。最终六组结果合计 **7410 passed、19 xfailed、0 skipped**，各进程退出 0；Ruff 通过。19 项 xfail 为已有 API Key／用户会话身份及自动 MCP 发送边界，不能计作通过；首次超时原因未被单独证明，详见父任务 `verification.md`。
