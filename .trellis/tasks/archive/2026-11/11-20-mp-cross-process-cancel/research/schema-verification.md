# C3 迁移、备份与单书传输验证

基线为 0067。0068 增加本人取消时间、删除与外部调用的执行者身份，以及保存原轮次的工作记录。工作记录独立于任务和作品外键，原任务裁剪后仍可核对。单书备份保持 v16，导出的 `app_schema` 为 0068。

## 数据库迁移

- 升级前校验旧服务已停止。保留可与原任务 UUID、执行 UUID、用户、轮次、串行键和已停止 worker 对上的旧槽，由 C1/C2 恢复。旧槽的整数任务 ID 与实际任务不匹配时拒绝升级，原版本、原槽及旧删除意图均保留。确认离线后只解除旧删除意图，保留原作品和外部调用凭据。
- SQLite 在真实写事务内原位加列，PostgreSQL 先锁住相关表。测试在建表及添加索引后注入失败，确认新列随版本回滚。升级后核对模型与真实表的列、类型、可空性、主键及索引；SQLite 还核对已删除作品留下的自增高水位和子表外键。
- 在途执行者、执行槽、工作记录、执行中的任务或管理取消意图、删除意图以及外部未决收据会阻止降级。归属列为空的历史 executing 调用也要先核对。测试分别验证未知结果继续阻挡、已核对的外部错误允许降级。
- 0066 至 0068 的迁移、SQLite 冷恢复和 0045 冻结结构用例合计 25 项通过，覆盖本机临时 SQLite 和 PostgreSQL 16。完善未决外部收据降级条件后，0068 的 SQLite 用例独立复验通过。最终跨方言门禁计数以任务总验收为准。

## 恢复与导入

- 快照会检查数据库版本与执行字段、工作表列是否一致。分别移除工作表、证据列、三个归属字段或改错版本时，恢复在安装新配对前拒绝，目标无残留副本。
- 关停调度后，仍受理 HTTP 的应用继续持有独立请求租约。旧版快照恢复用例先检验此时的离线锁会拒绝操作，随后正常停止请求租约并恢复快照。已证实终止的执行槽可释放，原失败证据在冷恢复后可读取。
- 完整单书往返中注入源实例的工作 UUID 和删除 worker，导入后的作品保持独立，实例数据库也没有新增该工作记录。全实体往返及登记表反射检查共 3 项通过。20 个版本断言所在用例在 SQLite 环境有 21 项通过，另两个 PostgreSQL 参数已在专用测试库逐项通过。

复验入口为 `backend/tests/test_task_worker_migration.py`、`test_backup_sqlite_restore.py`、`test_kb_index_identity_migration.py`、`test_project_transfer.py` 和 `test_serialization_transfer.py`。SQLite 配对文件、内存数据库和竞争写入的补充检查见 `test_c3_schema_boundaries.py`。
