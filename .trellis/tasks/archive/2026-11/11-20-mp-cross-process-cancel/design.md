# C3 跨进程取消与作品删除设计

本设计以含 C1 与 C2 的本地提交 `d2908f0`、数据库版本 0067 为基线。C3 的数据库版本为 0068。需求和验收编号见[需求文档](prd.md)，测试顺序见[实施清单](implement.md)，运行结果见[验收记录](research/verification.md)。

## 本人取消一项运行中的任务

接到请求的进程沿用现有的本人、原协作授权、作品状态与审核身份检查。在这一笔受保护的事务里，以任务 UUID、入队轮次、执行 UUID 和当前状态为条件登记取消时间。重复受理使用同一意图。取消绑定业务轮次，移交处理权时仍有效，继续、重试或复用整数 ID 时不能继承。提交回执不明先按原身份重读。在原轮次的终态或待核对结果提交时一并处理意图，重新入队前以原身份清除残留。

| 数据库里的事实 | 谁处理，如何返回 |
| --- | --- |
| 原执行者仍健康 | 接收端提交后唤醒本地调度器。执行端按周期扫描，用原 UUID 与入队时间调用现有的取消逻辑，保留领取、最终提交和 SQLite 游标的保护。本机可立即走相同路径。 |
| 取消与成功、暂停或管理员意图相遇 | 已提交的业务结果和完整收据决定终态。管理员意图一旦先被观察到，本人请求加入同一轮处理。后来获准的管理员意图也复用已在途的清理。后台扫描、本人、管理员和删除请求均不能启动第二次业务回退。 |
| 原执行者已停止或失联 | 沿用 C1 的判活和 `prepare_orphan_scan`、`adopt`。成功接管后，在同一轮次内复查意图与业务收据，再选择取消或既有恢复结果。对 SQLite 必须先把侧库的不可逆决定同步至主库。 |
| 已标记待核对或凭据缺失 | 进入既有的待核对、冲突或仅限完整收据的修复路径。对已有 `recovered_at` 的行不重复接管。分析、向导和批量任务仍保留其专用结果判定。 |

本人 API 在释放数据库锁后最多等待现有的 10 秒，本机唤醒和对端读取共用一次截止时间；到时返回有权读取的当前任务状态。返回前复核原用户、授权和轮次。管理员 POST 保留 202、原操作 ID 与审计语义。后台领取、心跳和下次扫描不能因某个取消等待 10 秒而被堵住。具体 handler 的副作用及管理员竞争见[本人取消](research/owner-cancel.md)和[管理员取消](research/admin-drain.md)。

## 管理员取消与请求侧清理

复用已有管理员操作 ID、章节收据和业务终态。对排队、待审核和接管清理，在首次可能产生副作用前，用事务条件更新或唯一约束取得该原轮次唯一的清理权。管理员 drain、本人取消、恢复和执行器最终收尾都要遵守相同的所有权规则。另一个处理者观察结果或等待。管理员的受理审计与意图同事务，重复请求沿用已有操作。在线接到取消并能证明旧单章占用时，原有结果为 cancelled；启动恢复接手先前已受理的 running 意图时，原有结果可以是 interrupted。认领时冻结处理原因，断线和再次接管均沿用。

清理可能跨越多次提交。主库的 `task_work_records` 登记清理操作 UUID、作品、原任务、轮次、负责的 worker 和状态。需要重试时保留可核验的原始资源身份，只保存核对所需的字段或摘要，日志不写正文或凭据。资源变更与相应回执同事务写入。跨事务的步骤逐项核对原收据。处理者崩溃或提交回执丢失时，接管者先核对本轮已经完成的步骤。未知的外部效果或无法证明的业务回退继续阻止删除。

- `_cleanup_work` 仍可唤醒本机等待者。会修改资源的 HTTP 或后台清理在首次变更对外可见前，以同一会话登记在途操作。嵌套调用共享同一操作身份，外层结束并确认结果后才归还。等待远端状态的只读请求不得登记成它自己在等的工作。
- `_failed_cleanups` 按原任务、轮次及资源凭据记录可重试的失败；`_unproven_abort_failures` 表示证据不足，须留下独立的作品屏障。两者共同提供原 `_abort_failures` 的作品级结论。只有核对到原结果，或对原资源完成可证明的重试，才能解除对应屏障。
- `recovering` 根据 C1 已持久确认的接管身份推导。原持有者仍有写权时，可按完整身份重试 `winners` 中已有的成功或暂停候选。原持有者丢失后，接管者根据可重读的业务收据裁决；证据不足则保留原有的不确定状态。`completed` 依据该管理员操作、原轮次及完成事实复核，重新排队后的同一任务不能借用上一轮结果。

HTTP 可能在调度器关闭时仍接收请求。为跨事务写入的请求提供应用级执行者身份，复用 C1 的租约、围栏和 SQLite 配对机制，生命周期覆盖 HTTP。调度器停止或换代不能把活请求登记为已结束。应用退出时先停止接收新工作、等待已登记请求并确认结果，再关闭相应租约。持有作品行或 SQLite 写锁时沿用当前事务登记工作，不能另开一个等待同一把锁的写会话。

停调度时，受理本人取消或作品删除的请求 worker 也可发起 C1 接管。每次只核对请求指定的任务 UUID、入队时间与执行 UUID。旧无主任务直接参加原子认领；有原 worker 时先在对应数据库核实其已停止或失联。成功认领后使用原有恢复流程重新核对已保存的正文、审核断点和未决失败。请求断连及回执丢失后，后备处理继续核对原轮次。管理员同时受理时，等本人接管退出后交接原操作。

## 作品删除

1. 在已有鉴权和作品锁内冻结删除意图，保存删除 token 及请求发起 worker。若已有无法核对的外部调用，沿用现有提前拒绝契约。可定位到实际在途调用时先等待并重查，避免先取消其他任务才发现作品不能删除。
2. 为该作品的可取消任务复用同轮意图。等待原执行体、已提交终态后仍在进行的回调、请求侧清理和外部调用结束。等待期间释放业务锁，被删除请求创建的短期清理也须按各自身份归还；删除动作自身的 token 不计为待排空工作。
3. C2 的名额在原执行协程返回前归还，归还事务也可能已提交但回执迟到。复用 C2 的领取事务，为作品任务在 C3 的在途工作表中同时登记原执行 UUID、worker、任务轮次与作品 ID。任务行可以先被裁剪。由原协程的完成回调在确认协程已退出、从本机执行体索引摘除后，用原身份异步写退出确认；确认写入失败时重试，删除方继续等待。这样沿用 C2 的名额计数，又能查到名额归还之后仍在退出的工作。预选尚未提交时由队列及领取门与删除冻结互斥，失去领取的候选不得启动处理器。对停止或被围栏的执行者走 C1 恢复并复核所有业务收据及未决请求。
4. 在最终软删除事务里重新鉴权、锁定同一作品并核对原 token、发起人和执行者租约。重新查询开放任务、管理员意图、业务收据、执行名额、在途清理、清理失败和未决外部调用。新工作登记使用同一作品锁与删除状态检查，封住最后检查与提交之间的窗口。全部排空后再写删除状态和原审计。永久删除及定时清理沿用相同相关屏障。
5. 超时或无法证明安全收尾时保留作品，按现有接口报告冲突。请求释放自己的删除意图时核对 token 和 owner。启动及定时恢复只清除已可靠确认停止的发起人留下的原意图，历史无 owner 的情况在停旧服务升级时单独处理。删除请求中断不会自动完成删除。

更详细的证据和时序见[作品排空](research/project-drain.md)。

## 智能体外部调用

手动确认绑定实际处理 HTTP 请求的 worker，自动执行绑定原任务执行者。在独立运行字段或记录中同事务保存原调用 claim、发起 worker 与 `executing` 状态，保留已有凭据 JSON 的严格字段及签名检查。实际发送、结果保存和恢复均核对该调用、发起者与既有任务、会话、授权、快照等凭据。手动调用也须在真正发出工具请求前验证原处理者仍可写。结果要等外层事务提交才能对其他进程宣告完成。

| 观察结果 | 恢复行为 |
| --- | --- |
| 有证据表明原调用仍在途，发起者健康 | 允许原调用完成，包括已经超过两分钟的慢调用。其他进程的会话访问和启动扫描不得把它标成失败。 |
| 原处理者已被可靠确认停止或失联 | 核对原 claim 后可以提前标为现有“结果未知”。迟到响应不能覆盖新状态，接管者不再次发送。 |
| 能证明原工作已经退出，或属于升级前可核对的旧调用 | 继续按既有两分钟阈值与完整凭据核对，再决定是否标未知。旧的空归属不当作新调用的失联证明。 |
| 登记损坏、身份不匹配或结果未知 | 保留既有删除与后续执行保护，重读或访问会话均不触发重新调用。 |

失联围栏能阻止旧处理者继续写数据库，无法撤回第三方已收到的操作。端到端测试分别观察原处理者退出、数据库结果和服务端实际收到的调用数。[外部调用归属](research/external-call-ownership.md)

## 数据迁移与兼容

迁移 0068 承接 0067。新增或补充运行时字段仅存于实例数据库。现有对外接口保持结构，作品文件仍为 v16，导出记录新的 `app_schema`。变更租约清理逻辑，凡仍被删除意图、清理工作或外部执行引用的执行者，须保留可核实的终止事实。SQLite 冷恢复继续使用 C1 的配对证明，恢复后先处理原租约与残留业务收据。

升级前停止旧写入，核对旧名额和删除、外部调用的在途状态。对残留名额，只用可验证为同一轮次的记录确认作品；无法区分全站任务和丢失作品归属时，迁移在变更前提示先用旧版本恢复并排空。降级前同样排空新意图及在途操作，对仍有未确认屏障的数据库拒绝降级，保留版本和数据。[执行与回滚清单](implement.md)
