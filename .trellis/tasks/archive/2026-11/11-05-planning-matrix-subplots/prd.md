## 目标

落实 `TODOS.md` 第 3 项：让作者在统一工作台安排章节和未建章细纲的视角、设定与支线，识别推进空档和明确交汇，并让已保存的本章规划实际参与 AI 生成与重写。

2026-11-05，用户同意创建 Trellis 任务并进入规划，随后确认以下选择：

## 背景与已有能力

- 当前已有大纲、细纲、章节与出场角色。未建章细纲有稳定身份，但没有真实章号；一条大纲可以展开多条细纲。证据：`backend/app/models/entities.py:479`、`:504`，`backend/app/services/plan_service.py:73`；详见 `research/codebase-foundations.md`。
- 章手动出场角色已经参与 AI 选角，细纲建章会带入角色。矩阵需沿用该事实来源。证据：`backend/app/services/cast_service.py:121`、`:147`，`backend/app/services/plan_service.py:262`。
- 正文提及仅是角色／地点／物品的字面证据，伏笔是埋设／回收模型；两者均不等同于作者的支线推进计划。证据：`backend/app/services/mentions/summary.py:73`，`backend/app/models/entities.py:711`。
- 单章与整章重写、局部改写存在不同入口；旧自定义模板也必须覆盖。证据：`backend/app/services/generation_service.py:275`、`:299`，`backend/app/services/rewrite_service.py:110`；详见 `research/ai-integration-design.md`。

## 需求

| 编号 | 可观察行为 |
| --- | --- |
| R1 | 提供规划矩阵，以章节／细纲与设定／支线交叉展示，支持分卷、来源、标签、条目类型及名称筛选，能跳转到原章节、细纲和设定详情。正文提及、手动关联、POV、推进节点及交汇各有明确标识。 |
| R2 | 独立维护支线名称、作者概览、颜色及每个章节／细纲的推进文本。交织视图展示同位置推进、内部空档和末次推进后的间隔，支持阈值提醒；已建章和未建章分别计数，不把空档自动诊断为剧情错误。 |
| R3 | 单项或批量调整 POV、项目标签和手动设定关联。明确区分设置／清空、追加／移除／替换；替换某类设定不影响其他类型。提交前展示目标和变化，冲突或任一非法引用时整批不生效。 |
| R4 | 规划跟随源位置变化，删除源后仍可找回、重新关联。兼容作品备份、旧备份、大纲快照及既有智能体操作的撤销。只读用户可查看；写入遵守作品权限；规划编辑不直接修改正文。 |
| R5 | AI 生成、整章重写及局部改写使用本章 POV、节点、交汇和手动关联参考。批量与自动续写保持对应行为；局部操作只处理选区／光标，规划仅提供章节背景。新增投影排除后续章、其他未建章与失联规划，作者概览不自动进入 AI。 |
| R6 | 未建章细纲可完整规划；建章后数据保留且不重复展示。复用已有章时若双方规划冲突，先提示作者解决，不静默覆盖；大纲作为分组，不伪装成正文章。 |
| R7 | 手动关联覆盖独立故事档案类型：角色、全部世界观分类、组织、人物关系、职业。关联资料进入同章 AI 参考，但不据此赋予角色职业、组织身份或关系变化。角色／世界观／人物关系及成员、职业阶段沿用既有按章回溯；组织基础档案和职业体系仍是当前静态资料。 |
| R8 | 作者在一个章节／细纲上创建明确交汇事件，维护标题、说明和至少两条参与支线，支持编辑、移动、删除。事件可独立于普通节点存在，矩阵与交织图将其区别于“同章推进”，本章 AI 只包含该事件一次。 |

## 交互与兼容约束

- POV 是可空的视角角色，不擅自设置第一／第三人称。本次明确临时写作指令优先于章节 POV，章节 POV 优先于通用风格视角。
- 支线推进和交汇都表示作者计划，不因章节有正文就判定已经发生。事件最少两条参与支线；被事件引用的支线须先处理该引用才能删除。
- 矩阵区分未写章节、零提及、歧义和不支持自动追踪的类型。D3 不扩大现有正文自动匹配范围。
- 已建章与未建章分别展示真实位置；不会借用显示顺序给未建章捏造正式章号。其 AI 预览只描述规划指令，建章后才按真实位置解析有效设定。
- 仅标签调整、无新增规划时保持原有 AI 提示词行为；旧保存模板能获得新规划。超长规划有明确截断提示，不静默丢掉全部约束。
- 多窗口并发修改需明确提示冲突、保留本地待提交内容，不能静默覆盖；计划从源删除后重新建立同号／同名对象也不得自动错挂。
- 桌面和 375px 窄屏可用，支持明暗主题与键盘操作，图表提供等价文本信息；两维大列表有明确分页／窗口与总数。

## 验收标准

| 编号 | 场景与预期 | 覆盖 |
| --- | --- | --- |
| AC1 | 含真实章和未建章细纲的作品打开矩阵，行身份、分组、来源标识正确；可过滤并进入原内容，建章前后同一规划只显示一次。 | R1、R6 |
| AC2 | 同一个格子存在手动关联和正文命中时分别显示；歧义、未写和无自动追踪类型不会被当成确定出场。 | R1、R7 |
| AC3 | 多章批量设置 POV、追加／移除／替换／清空标签和各类型关联，刷新仍保持；替换角色不删除组织或职业。 | R3、R7 |
| AC4 | 两个目标中一个已经被他处修改、已删后同 ID 重建或含跨作品引用，提交整批失败，另一个目标不受影响。 | R3、R4 |
| AC5 | 同一支线在第 2、6 章推进，视图显示中间实际存在章节的间隔；分页或条目筛选不改变间隔；计划细纲单独统计，未安排支线不伪造断档。 | R2 |
| AC6 | 未建章细纲保存 POV、标签、全部设定类型、节点和交汇后建章，内容与关联保留；双方已有冲突规划时没有任何章被部分创建。 | R4、R6、R8 |
| AC7 | 删除源、重展开、改挂大纲后规划保留或明确进入待关联；新建同号章不认领旧数据，作者可明确重新关联。 | R4、R6 |
| AC8 | 恢复新／旧大纲快照不误挂复用 ID，不覆盖之后修改的规划内容；智能体撤销遇到作者后续改动时提示冲突。 | R4 |
| AC9 | 作品备份恢复保留所有规划、全类型引用、交汇参与集合及待关联内容；旧备份仍可导入，非法引用整笔拒绝。 | R4、R7、R8 |
| AC10 | 真实生成与整章／局部重写请求包含第 5 章 POV、节点、交汇和相应设定；新规划投影中不含第 20 章记录、其他未建章或作者结局概览。 | R5、R7、R8 |
| AC11 | 批量逐章使用对应规划，自动续写沿用首轮规划；旧覆盖模板缺少新变量仍能获得规划；仅标签／无规划时旧消息保持兼容。 | R5 |
| AC12 | 单独关联组织、人物关系或职业，默认提示词可看到相关参考，不新增授职／成员／关系事实；可回溯状态按章，静态档案边界准确。 | R5、R7 |
| AC13 | 两条支线仅有普通节点时显示同章推进；添加明确交汇后出现事件标记，删除事件不删除普通节点。没有普通节点的交汇也能显示、计入分布并只注入 AI 一次。 | R2、R8 |
| AC14 | 交汇的参与数不足、重复或跨作品时不写入；移动事件后原位置和新位置的分布同步；删除被引用支线先提示处理交汇。 | R4、R8 |
| AC15 | 只读管理、权限撤回、旧异步响应、窄屏、主题与键盘操作均符合既有作品工作台行为；失败可见且可重试。 | R1、R3、R4 |

## 范围外与能力限制

- 独立场景正文、场景排序和富文本编辑；AI 自动识别／创建支线；全书一致性检查。
- 不扩展组织简介、职业规则等基础档案的历史版本系统；关系、成员和职业挂接不是新建第二套事实源。
- 不自动判断节点已兑现、自动发现真实交汇，或保证模型必定遵循每条创作目标；验收以实际输入消息及编辑范围为准。
- 排除后续记录只针对新增规划数据；不承诺扫描自由文本中的全部剧透，也不改变现有整卷大纲输入策略。
- 本次新增内容纳入作品备份；独立 `ainovel.outline` 导出仍保持原有大纲格式，避免把作品范围的支线／设定引用偷渡成另一种导出协议。
