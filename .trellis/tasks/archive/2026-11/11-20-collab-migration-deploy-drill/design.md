# C8 协作迁移演练设计

## 1. 范围与版本边界

以 `4501f18`（迁移 `0043`）为旧版，在隔离 SQLite 和 PostgreSQL 16 中验证升级到包含 C1–C7 的当前分支提交、失败保护和从快照回滚。执行开始时固定新版提交和实际 Alembic head；不以当时尚未包含 C1–C7 的 `main` 代替。记录提交、依赖锁、数据库及工具版本。`0044–0054` 与后续迁移一次执行至新版 head，中间 schema 仅供隔离迁移检查，不对外部署。

此任务交付可重复的演练脚本、证据、README 和待办状态；不修改产品代码或迁移。发现缺陷时保留证据并保持对应验收项未完成，另记待处理问题，不能靠改应用、伪造数据或降低验收标准掩盖。

## 2. 隔离与测试数据

- 用 `git archive` 分别导出固定旧版和新版提交到专属临时目录，分别依据各自 `uv.lock` 准备 Python 3.12 环境；工作目录不能包含产品 `.env`。子进程采用白名单环境变量、随机测试密钥及独立备份目录，应用和可编排的假模型只监听本机。避免输出密码、密钥、token、请求正文和模型正文。
- SQLite 使用临时主库；PostgreSQL 使用随机名称的专属容器、随机凭据及临时数据库，端口只绑定本机。`pg_dump`／`pg_restore` 使用专属容器内的工具。绝不对既有容器、库、卷或用户文件执行清理。退出时只回收本次创建的进程、容器与临时目录；失败诊断只输出脱敏摘要。网络、锁和资源归属确认失败时直接停止。
- 先通过旧版真实应用 API、任务引擎和本地假模型生成多用户、多作品、模型凭据、章节、生成日志、智能体会话与提案、知识库文档以及各类任务。通过受控假模型屏障产生真实运行中、同串行键排队及生成中章节，通过旧版支持的功能产生待审核、已完成和已中断任务。实际请求、任务 ID、状态和计数形成清单；不直接插库伪造业务任务。若某状态无法由旧版实现，记录原因并保持 AC1 未完成。
- 多种破坏性场景从上述独立快照克隆，避免用户取消、管理员取消、继续及重发互相改变前提。需要验证真正遗留的 `running` 时，在假模型阻塞后终止专属旧进程，核对它已退出并捕获其持久状态；优雅停止与异常退出分开记录。两类数据库分别运行。

## 3. 正常升级与回滚

1. 固定两个版本及部署配置，检查目标数据库类型、库名、旧迁移版本、资源归属、依赖及原加密密钥；虚构测试数据不能使用真实凭据。
2. 针对旧版没有全站排空开关的事实，以受控维护模式禁止新的业务入口，同时保留排空所需的操作通道。等待在途同步流及外呼，逐项完成／取消排队、运行和待审核任务及活动备份；核对系统全局任务清单、用户侧状态、章节生成状态和实际在途调用。中断或有疑问的项目逐项记录，不能仅看一次 HTTP 健康检查认定排空。
3. 仍在旧版时生成并在隔离目标验证一次快照；停止全部旧进程后，再创建并验证最终一致快照，记录版本、清单和校验和。SQLite 使用在线 backup 或停服后的完整数据库快照；PG 使用 `pg_dump` 自定义格式，并恢复到独立空库。仅以停服后的快照作为升级与回滚基准。
4. 确认旧进程已退出，再用新版迁移到固定 head 并启动新版。核对旧作者作品、章节、生成日志归属、0047 提案及 0049 模型配置实例身份的回填；通过真实 API 发起任务、产生新生成记录并验证协作邀请。记录应用及假模型双方观察。
5. 回滚演练先限制访问、停止全部新版进程，另行备份新版库并验证，保留用于后续人工核对；从升级前最终快照恢复。PG 在另一全新空库恢复，不覆盖现存库；SQLite 先完整保留现有主库、WAL/SHM 及新版租约侧库／锁文件，再按 C7 的冷恢复约束处理配对，不能将新版侧库误接给旧主库。确认恢复库为 `0043`，启动对应旧代码和原加密密钥，真实验证登录、作品读取、模型凭据解密和一次任务；同时确认升级后新增数据不在旧快照中。

回滚会丢失快照之后在运行库中产生的数据。保留新版库备份不等于能自动合并或安全导回这些数据；运维文档必须说明回滚前的取舍与核对。旧库和新版库不能由新旧服务同时写入，不能通过清表或 Alembic 降级替代恢复快照。

## 4. 未排空、降级和错误回退

| 场景 | 实验与观察 |
| --- | --- |
| 旧排队、运行中、待审核、生成中章节及旧索引 | 使用真实旧版数据及相互独立的库副本，先保证旧进程已退出，再升级、启动新版；记录旧任务／章节最终状态、假模型调用数，以及同串行键新任务能否执行。 |
| 用户取消、管理员取消、继续／结束、重试与重新发起 | 每个操作使用独立副本，核对 API 实际响应、持久状态、执行体与章节占用；继续后的结果、无 claim 章节的管理员收尾两项尤其不能沿用推断。 |
| 新数据降级保护 | 新版产生生成记录与协作邀请后停服，对专属副本执行从 head 到 `0043` 的降级。对比前后版本、全量 schema、各表行数和稳定的数据摘要；记录实际先触发的保护。 |
| 未产生新数据 | 独立构造由旧应用产生的正常终态、提案、未结束任务及生成中章节等基线，直接迁移后不启动新版应用；各自在隔离副本上测试并记录首个拒绝及可降级条件。若前一保护掩盖后续保护，单独做对应迁移边界实验并标注实验的构造方式，不能声称整链已验证。 |
| 旧代码连新库 | 仅用含虚构协作及生成记录的新库克隆，先停止新版；记录旧应用能否启动、读取或失败的真实表现，及旧日志读取边界。绝不把某次启动成功写成兼容承诺。无论结果如何，README 禁止旧代码直接连接已升级库。 |
| 并发启动迁移 | 从相同 `0043` 旧库副本同时启动两个包含 C7 迁移保护的新版本实例，记录等待、迁移、退出码、版本和启动情况；至少在两种数据库分别验证，失败时不得声称通过。 |

新版本最终路径和日志隐私以实际操作结果为准。短暂 HTTP 成功不代表旧版有协作隔离；不能使用真实用户数据做此实验。

## 5. README、复核与证据

- 在现有多实例运维、数据库备份和 SQLite 恢复章节之间建立清晰链接，补充 `0043` 旧版没有排空开关时的可操作流程。给出单实例／双实例适用范围、停止受理、在途任务确认、停服、快照与隔离恢复验证、升级及回滚的具体命令或明确引用现有已验证命令，并写明失败时保持停机的条件。原版实际不支持的操作不能写成可用。
- 涉及恢复时明确版本／镜像和 `ENCRYPTION_KEY` 对应、PG 新空库、SQLite 主库与侧文件、验证完再开放流量，以及快照后的数据不会自动带回。同步修正与实测不一致的规范，按事实更新 `TODOS.md` 11、25 项，不把未通过项勾选。
- 验收证据与脚本保存在本任务 `research/`。每个结果记录提交、命令、数据库与工具版本、时间、状态、实际结果及局限；日志做白名单脱敏。每个结论要有具体场景对应，不能把空库烟测或 C7 同版本恢复当成 C8 的证据。
- 由未参与演练的独立执行者／全新会话只依据最终 README，在独立虚构环境重做一次升级和回滚；只提供中立的环境信息，不提供内部脚本步骤。未完成该独立验证时，AC8 保持未完成。
