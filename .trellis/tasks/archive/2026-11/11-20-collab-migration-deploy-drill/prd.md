# C8 协作迁移部署、排空与回滚演练及操作步骤

> 父任务：`.trellis/tasks/11-20-multiprocess-task-scheduling-deploy-drill`（决策 D5–D7）；历史调研来源快照见本任务 `research/legacy-background-2026-11-20.md`。
> 依赖：C7 已完成本地验收。本任务不改产品代码；演练以包含 C1–C7 的版本为新版。

## Goal

把第 11 项（作品级协作者邀请）唯一未完成的交付门禁补上：在隔离环境里实际走一遍协作相关迁移的部署、旧任务排空与回滚，确认设计中的每条要求在真实数据上成立，并把可照做的操作步骤写进 README。

## Background

- 出处是归档任务的门禁 H4：「按设计验证旧任务排空、数据库迁移、服务部署和回滚」（`.trellis/tasks/archive/2026-11/11-09-novel-collaborators/implement.md:96`）。设计要求（同目录 `design.md:84-89`）：有数据时拒绝有损降级；不允许新旧版本混跑，先排空旧任务与流，再升级数据库与服务，最后开启入口；回滚时须先停用访问，不能通过只撤前端入口或清表声称已安全回滚。
- 协作迁移 0044–0054 作为一个兼容单元一次上线，前一版是提交 `4501f18`（head `0043`）。2026-11-25 当前分支包含 C1–C7，head 为 `0070`；本地 `main` 不含这些改动。演练时固定并记录实际新版提交与迁移 head。
- 原调研覆盖 0044–0065：已有智能体提案（0047）、`interrupted`／`paused` 任务（0049、0051）或 `generating` 章节（0046）等也可能使降级被拒；生成记录身份（0052、0048）、协作邀请与审计（0044）是新版数据的降级保护示例。0066–0070 还有执行者、任务占用和排空相关保护。整条链的实际结果待演练验证。
- 旧版本创建的任务缺少 `_task_actor_token_version` 等字段。原调研认为排队任务可能保持排队、不调用模型并占住串行键（原锚点 `backend/app/services/task_engine/engine.py:1275-1284`），本人可取消但不可重试，旧知识库索引有专门清理路径；运行中任务在停止旧服务或新服务恢复时会被处理。待审核旧任务继续后是否停滞、管理员取消无 claim 的旧章节任务能否收尾只有推断；C1–C7 之后上述结论均以实测为准。
- 原调研未发现设计提到的「旧服务日志隔离兼容补丁」，因此不能以「新库 + 旧代码」作为回退方式。
- 历史调研中的 README 锚点为 `README.md:215,552,814,878-909`；C7 已补充当前版本的排空、备份与恢复步骤，但 `0043` 旧版没有 C6 排空开关，不能直接套用。旧版完整操作仍待演练并写明。
- 原调研发现旧的 PostgreSQL 迁移测试曾在提交 `b329323` 移除；C7 后已新增 PostgreSQL 迁移专项，但仍没有「带真实旧数据从 `0043` 一次升到 head 再回退」的端到端验证。

## Requirements

- **R1 演练环境**：全部在本地隔离环境进行，不读产品 `.env`、不碰现有数据库与数据卷；PostgreSQL 16 容器与 SQLite 文件各一套；旧版本代码取自 `4501f18`，新版本为演练时包含 C1–C7 的当前分支提交。记录两端提交、迁移 head 和依赖环境。
- **R2 旧数据**：用旧版本应用真实产生数据，至少包含多个用户与作品、已完成的生成记录、智能体会话与提案、知识库文档、各状态的任务（排队、运行中、待审核、已中断、已完成），以及一个生成中的章节。
- **R3 升级路径演练**：按「升级前检查 → 停止受理并排空 → 备份并在隔离库验证备份可恢复 → 停旧服务 → 迁移 → 只启动新版本 → 升级后验证」完整执行；停旧服务后再次生成并验证作为回滚依据的最终快照，避免备份后仍有写入。记录每一步的命令、脱敏输出与耗时。
- **R4 未排空的后果演练**：另做一遍不排空直接升级，记录各类遗留任务在新版本下的实际表现与人工处置路径，核实背景中两处只有推断的情形。
- **R5 降级保护验证**：在升级后产生新数据的库上执行降级，确认被拒且数据与版本号不变；在未产生新数据的库上确认哪些存量情形仍会拒绝。
- **R6 回滚路径演练**：按「停新服务 → 备份当前库 → 恢复升级前快照 → 启动旧版本代码 → 验证」完整执行，确认旧版本能正常登录、读取作品、解密模型凭据并运行任务。
- **R7 禁止路径写明**：确认并写明不存在「新库 + 旧代码」的回退方式，回滚只能恢复快照。
- **R8 并发迁移观察**：记录两个实例同时执行启动迁移的实际表现，验证 C7 迁移并发保护在 `0043` 旧库上的行为。
- **R9 操作步骤入 README**：在 README「运维与数据备份」一带新增升级、排空、回滚的操作步骤，写到可以照做的程度：前置检查项、每步命令、如何确认已排空、失败时的处置、回滚的判断条件。同步修正 README 与规范中与演练结果不符的表述。
- **R10 演练脚本归档**：演练使用的脚本与记录存于本子任务目录，使演练可以重复。
- **R11 待办更新**：`TODOS.md` 第 11 项的「尚未完成」与第 25 项第二个待办按演练结果更新。
