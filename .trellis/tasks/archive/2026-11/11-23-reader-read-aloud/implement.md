# 阅读页朗读实施计划

按下列顺序实施。每一步的结果都可以单独验证，声音与高亮同步后再做实机听验。

### 1. 让普通章节能在本机读出来

- [x] 在阅读页接入本机中文声音筛选与播放控制。用户点击后从第一段起逐句播放，提供暂停、继续、停止和调速。接入既有阅读设置，加载老设置时验证默认语速。
- [x] 在 `frontend/src/utils/reader.ts` 附近建立纯文本段落范围，沿用现有普通阅读排版。用两段同文、中间空行、含 emoji 的长段验证，只有正在发声的段落被标亮。
- [x] 用可控制开始、结束、错误事件的语音替身测试状态转换。覆盖先空后有的声音列表、只有在线中文或本机外语、语音接口不存在、播放中出错、连续点击和暂停后改速。没有合格声音时 `speak` 调用次数须为零。

### 2. 让富文本、提及与搜索共用段落位置

- [x] 将同一段落坐标接入 `RichReaderContent`、阅读页的 `MentionPreview` 渲染入口和 `SearchHitContent`，覆盖普通、提及和搜索三种视图的纯文本及富文本。切换提及显示时应保持播放位置。
- [x] 在现有渲染测试中加入粗体列表、标题、引用、跨行搜索、仅换行命中以及前面有表情符号的重复段落。断言读到第二处时只标亮第二处，同时搜索位置、实体点击和列表语义正确。

### 3. 处理离页、失权与设备差异

- [x] 将语音取消与 `ReaderView`、`ReaderSession` 生命周期及正文指纹关联。测试停止后立刻重播、暂停后切章、旧章结束事件迟到、登出、阅读器发现撤权和同章内容更新。旧回调不得重新发声或标记新章。
- [x] 回归作者与只读协作者。两者都可本机听稿；只读账号全程不产生进度写入。检查工具栏键盘操作、窄屏按钮、浅色／护眼／深色下的高亮和搜索命中。
- [ ] 用安装本机中文声音的设备听完一章，听辨调速、暂停、继续和章末停止。在无本机中文声音的环境核对安装提示。记录操作系统、浏览器、声音和实际听到的结果；仅有模拟回调的环境单独记录。

### 4. 回归与交付

- [x] 对照 [验收表](prd.md) 逐项记录结果，区分自动化检查与实际听验。在根目录 README 的阅读说明中补充入口、本机中文声音安装提示和语速生效时机，按项目约定更新阅读器规范。
- [ ] 全部验收完成后更新 TODO #31 的状态。如果真实设备上的语音有兼容问题，记录具体设备与现象，保留普通阅读入口和失败提示，不用在线声音替代。

### 2026-11-25 验证记录

| 场景 | 方法与结果 |
| --- | --- |
| 开播、两段同文、章末停止 | macOS 15.1、Chrome 158.0.8127.37，使用本机「婷婷」（zh-CN）。打开虚构章节后无语音请求，点击后收到原生发声事件，高亮从第一处移到第二处，章末清除。主动停止后再次播放从章首开始。 |
| 暂停、继续、调速 | 本机 Chrome 在原生暂停后返回 interrupted。暂停时保留高亮，改为 2 倍后保持安静；继续时以新速度重读当前短句并读完。单测另外覆盖支持原位继续的引擎及播放中下一句应用新语速。 |
| 提及、搜索与排版 | 自动化覆盖纯文本、富文本、同文重复、空块、列表、引用、实体按钮和跨行命中。浏览器验证浅色、护眼、暗色三种背景下，同段的搜索标记和朗读轮廓共存。 |
| 切章、授权与退出 | 自动化覆盖快照替换、会话失效、撤权确认和迟到的语音回调。浏览器用虚构只读协作者操作，全程未提交阅读进度。 |
| 空章、语音不可用 | 空章入口禁用。自动化覆盖浏览器缺少接口、仅在线中文和仅本机外语。浏览器中模拟移除全部声音后出现安装提示，未提交新的朗读请求。 |
| 键盘与小屏 | 实测 375px 视口控件均在屏内。Tab、Enter 和空格可完成开始、暂停、继续和停止。 |

### 角色配音与情绪复验（2026-11-25）

- 同段旁白和对白独立选声。自动识别明确的前置或后置说话提示，处理嵌套、跨段引号及无归属对白。读者可为旁白与角色分配本机中文声线，修改台词角色和情绪，并试听修改后的原句。
- 同一设备的 Chrome 使用「婷婷」与「Eddy（中文，中国大陆）」完成两个角色的七条话语。已验证悲伤的原生语速、音高与音量参数，以及 375px 视口上的配音抽屉。
- 在限制为一种中文声音的浏览器中，平静读法下张三、李四和王五分别以 0.91、0.88、1.06 的音高开始朗读；张三再次开口仍是 0.91。只有一种音色的设备使用音高辅助区分角色。
- 修改角色、情绪后刷新，原版本保留纠正。正文指纹改变后采用新解析，同书已选声音仍在；换账号后读取各自的设置。只读账号在这些操作中未产生写请求。以上为真实浏览器和语音引擎事件，情绪感染力需人工听辨。
- 最终前端全量回归为 274 个测试文件、1915 项通过；ESLint、TypeScript 与生产构建均通过。

### 已配置模型的 AI 自动配音验收（2026-11-25）

- 阅读页「配音」面板复用已有的文本模型选择。只有点击「分析本章并配音」才请求分析。只读角色可继续本机朗读。获准使用作者模型的编辑者可以使用授权配置并看到费用提示。
- 服务端校验作品权限、章节指纹及码点范围，发送当前章已保存正文、台词位置和声音候选名称／语言。模型用编号选声；设备 URI 不发给模型。验证完整返回后再映射回本机声音。超过输入预算时提示更换模型。
- API 集成测试使用应用临时数据库及测试模型，覆盖模型选择、计费归属、访问控制、坏结果以及模型调用期间改稿。Chrome 验收使用虚构正文和预设模型响应，验证整章七条话语按顺序真实发声，人工纠正覆盖 AI，刷新不重新计费，失败仍可沿用上次结果。未向真实模型服务发送稿件，模型判断准确度待用实际配置及样章评估。
- 最终回归通过前端全套 1929 项测试、ESLint、TypeScript 和生产构建，以及后端阅读器、配音及用量入口 26 项测试。
