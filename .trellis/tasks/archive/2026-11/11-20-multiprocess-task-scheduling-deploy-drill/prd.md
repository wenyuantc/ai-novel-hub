# 多进程任务调度与部署演练

> 父任务。来源：`TODOS.md` 第 25 项。本任务只承载需求全集、子任务映射、跨子任务验收和最终集成评审，自身没有实现工作；实现在 8 个子任务中完成。技术设计见 `design.md`，执行顺序见 `implement.md`。

## Goal

让应用在多个 Uvicorn worker 或多个应用实例共享同一数据库时仍然正确：任务不被重复调度，调度约束按全站生效，任何进程的启动、重启或崩溃都不会误伤其他存活进程的任务，任一进程受理的取消、订阅、监控和删除都得到与单进程一致的结果。同时补上第 11 项（作品级协作者邀请）遗留的「部署、旧任务排空和回滚未演练」，产出可照做的操作步骤。

用户价值：部署者可以按文档扩容或同版本滚动重启，不再受「只能单进程」限制；升级时可以先停止受理、等任务跑完再停服；协作相关版本的升级与回滚有经过演练的路径。

## Background

调研证据见 `research/task-engine-single-process-inventory.md`（引擎内 36 项）、`research/in-process-state-outside-engine.md`（引擎外 47 项）、`research/deployment-migration-rollback-background.md`。

### 多进程下已经成立的部分

- 同一任务不会被两个进程领取：`authorization_state` 全局门行锁、原排队行 `FOR UPDATE`、条件 UPDATE 的 `rowcount == 1`（`backend/app/services/task_engine/engine.py:1285-1297`）。
- `resource_key` 互斥（部分唯一索引）、章节占用、知识库文档占用都在数据库层。
- 角色、权限、登录态、作品配额每请求读库，没有进程缓存。
- 继续、重试、提前结束、智能体提案确认都是改库加唤醒；调度器每 5 秒轮询，跨进程最迟约 5 秒被看到（`engine.py:633-652`）。

### 部署、排空与回滚的现状

- 遗留项就是协作任务唯一未勾的门禁 H4（`.trellis/tasks/archive/2026-11/11-09-novel-collaborators/implement.md:96`）。其设计要求停机升级：先排空旧任务，再升级数据库与服务，最后开启入口；禁止新旧版本混跑；回滚靠恢复升级前整库备份加配套旧代码（同目录 `design.md:84-89`）。
- 迁移 head 为 `0065`。0044–0065 的降级都是「有新数据就拒绝，空才真删」；新版本写过任一生成记录或协作邀请就降不回 `0043`。
- 协作迁移的前一版是提交 `4501f18`（head `0043`）。它创建的排队任务缺少新身份字段，在新代码下不执行也不失败，停在队列并占住串行键（`engine.py:1275-1284`）；只有 0045 前的知识库文档索引任务会被自动清理为失败。
- 没有维护模式或全局停准入开关；并发上限最小为 1；管理端只能逐个取消任务；整库备份走应用自身，停机后只能手工 `pg_dump`。
- README 只有原则性表述（`README.md:215,552,814`），没有排空、升级、回滚的操作步骤。
- 设计提到的「旧服务日志隔离兼容补丁」从未实现，「新库 + 旧代码」的回退方式不存在。

### 测试现状

- 没有任何测试让两个引擎共享一个库；约 30 个用例直接断言「库里 running 且本进程无执行体即遗留」（清单见引擎调研第 10 节）。
- CI 只跑 SQLite；现存 3 个 PostgreSQL 测试文件靠 `AINOVEL_POSTGRES_TEST_URL` 手动启用（`README.md:942`）。

## Decisions

用户于 2026-11-20 确认：

- **D1 部署形态**：PostgreSQL 与 SQLite 都支持多进程。PostgreSQL 支持同机多 worker 与多实例；SQLite 支持同机多进程共享同一数据库文件。不引入 Redis 等新组件。
- **D2 跨进程实时流**：订阅落到非执行进程时经内部通道转发到执行进程，体验与单进程一致，协作者逐帧授权核验仍由执行进程完成，不增加数据库写入。同机用本机套接字；多实例需要实例间内网互通并做内部鉴权。通道不可达时退回按库内值刷新，并保证任务结束时正常收尾。
- **D3 排空开关**：新增系统设置。开启后所有进程拒绝新建、继续、重试任务并给出明确提示，已排队和运行中的任务照常跑完；管理端显示剩余活动任务数，归零后再停服升级。

沿用现有约定、随规划一并确认：

- **D4 失联任务不自动重跑**：执行进程崩溃或失联后，其运行中任务在租约到期后由存活进程按现有恢复规则收尾（记为中断、按收据完成或保留待核对），由用户重试。延续 README「运行中的模型调用不能跨进程恢复」。
- **D5 升级仍需停机**：涉及数据库结构变化的升级不允许新旧版本混跑；本任务支持的是同版本的多进程常态运行与滚动重启。被重启进程上的任务按现有语义记为中断。
- **D6 演练形式**：在本地隔离环境进行（PostgreSQL 16 容器与 SQLite 各一遍），基线为 `4501f18`（`0043`）到当前 head，回滚实际启动旧版本代码验证；演练脚本随任务目录归档，操作步骤写入 README「运维与数据备份」一带。
- **D7 旧版本遗留排队任务不自动清理、不补签**：延续协作设计的裁决，操作步骤要求升级前清零，演练验证未清零时的现象与人工处置路径。
- **D8 多主机备份目录**：要求多主机部署共享 `BACKUP_DIR`；不共享时给出明确错误，不再把副本误标为缺失。
- **D9 PostgreSQL 测试**：新增的 PostgreSQL 用例沿用环境变量手动启用的方式，不恢复 CI 中的 PostgreSQL。

## Requirements

- **R1 不重复调度**：同一任务任意时刻至多一个执行体；`serial_key` 同键串行且按入队顺序；全局与每用户并发上限按所有进程合计生效。
- **R2 不误标中断**：进程启动、重启和运行期间只处理「执行者已确认不在」的任务；存活进程的任务、外部调用、备份和删除意图不受影响。
- **R3 失联收尾**：执行进程失联后，其运行中任务在有界时间内由存活进程收尾并释放占用；失联进程得知失去租约后停止执行与写入。
- **R4 任一进程受理的操作都正确**：本人取消、管理员取消、作品删除排空、继续、重试、提前结束、智能体提案确认的结果与单进程一致。
- **R5 实时流与活动任务读取**：订阅在任一进程都得到与执行进程一致的帧序列；协作者撤权或降级后没有后续帧到达客户端；内部通道不可达时流退回库内值并以正确终止帧结束；`/output`、任务列表、管理监控、配额页的活动值在任一进程一致，允许不超过输出节流间隔的滞后。
- **R6 系统设置跨进程生效**：注册开关与 MCP 总开关在其他进程的下一次判定即生效；并发上限、自动分析开关、限流阈值在有界时间内收敛。
- **R7 引擎外状态**：备份只执行一次且启动不误伤；灵感同一步骤不并发生成；项目导入的预览与确认可落在不同进程；智能体会话操作在两种数据库上都跨进程串行；删除意图不被其他进程的启动清空。
- **R8 排空开关**：见 D3。
- **R9 部署与迁移**：多实例同时启动时迁移只执行一次；提供多 worker 与多实例的受支持启动方式与配置说明；README 与规范去掉「单进程」限制并写明新的前提。
- **R10 SQLite 多进程**：同机多进程共享数据库文件时 R1–R8 同样成立；写入争用表现为有界等待，不向用户暴露数据库忙错误。
- **R11 兼容与渐进交付**：每个子任务合入后单进程部署行为不回退、现有测试语义保留；多进程支持在最终验收通过后才在 README 宣称。
- **R12 演练与操作步骤**：完成协作迁移的部署、旧任务排空与回滚演练，README 有可照做的升级、排空、回滚步骤。

## Acceptance Criteria

以下勾选基于 C7、C8 在隔离环境留下的验收记录；实际运行范围与未覆盖情形见 `research/parent-closeout-review.md`。AC12 的跳过项与 xfailed 不视为通过。

跨子任务验收，在 C7 的真实多进程环境中逐条验证；PostgreSQL 16（同机多 worker 与两个实例）和 SQLite（同机多进程）各一遍。

- [x] **AC1** 进程 A 运行任务期间启动或重启进程 B：A 的任务继续并正常结束，状态从未变为中断；A 进行中的外部调用、备份和作品删除不受影响。（R2）
- [x] **AC2** 强杀执行进程：其运行中任务在「租约期限 + 一个调度周期」内被存活进程收尾，章节占用与串行键释放，之后可重试；被强杀进程重启后不重复收尾。（R3、D4）
- [x] **AC3** N 个进程下，同时运行的任务数不超过全局上限，每用户不超过其限额；同 `serial_key` 的任务不并行且按入队顺序执行。（R1）
- [x] **AC4** 从非执行进程取消运行中任务（本人与管理员各一次）：执行体被真正取消，终态为已取消，资源只回退一次。（R4）
- [x] **AC5** 删除作品时若其他进程有该作品的执行体：删除等待其停止后才继续，完成后没有仍在运行的执行体。（R4）
- [x] **AC6** 订阅落在非执行进程：作者与协作者都收到快照、增量、结构化事件和终止帧；运行中撤权或降级后没有后续帧到达客户端；断开内部通道后，流退回库内值并以正确终止帧结束。（R5）
- [x] **AC7** 在一个进程关闭注册或 MCP 后，其他进程的下一次注册、插件刷新、试用调用即被拒；并发上限等在 10 秒内收敛。（R6）
- [x] **AC8** 多进程下一次备份只执行一次且启动不误伤；同一灵感步骤并发生成只有一个成功；项目导入的预览与确认落在不同进程可以完成；同一智能体会话的并发操作不产生重复执行。（R7）
- [x] **AC9** 排空开关开启后，任一进程拒绝新建、继续、重试并提示原因；已有任务跑完；管理端显示剩余活动任务数与存活进程。（R8）
- [x] **AC10** 多个实例同时启动：迁移只执行一次，全部实例启动成功。（R9）
- [x] **AC11** SQLite 同机多进程下 AC1–AC9 成立，过程中没有数据库忙错误以 500 返回给用户。（R10）
- [x] **AC12** 单进程回归：后端与前端全量测试、lint、构建通过；每个子任务合入时单进程行为不回退。（R11）
- [x] **AC13** 演练：`0043` 旧版本到当前 head 在 PostgreSQL 16 与 SQLite 各完整走一遍升级前检查、排空、备份、迁移、验证，以及恢复快照并启动旧版本的回滚；README 有对应操作步骤；`TODOS.md` 第 11 项遗留与第 25 项更新。（R12）

## Out of Scope

- 失联任务的自动故障转移或自动重跑；运行中模型调用的跨进程续传。
- 新旧版本混跑与涉及结构变更的零停机升级。
- Redis、消息队列等新组件；SQLite 跨主机共享。
- 多主机不共享 `BACKUP_DIR` 时的跨实例备份下载。
- 旧版本遗留排队任务的自动清理或补签；「旧服务日志隔离兼容补丁」（明确放弃，回滚只走快照恢复）。
- 对真实线上实例的操作。
