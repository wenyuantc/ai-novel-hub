# 标签与设定自动分类：技术设计

状态：2026-11-05 完整设计已获用户批准；字段完整门禁已于2026-11-06通过，本子任务开始实施。前置合同以 `11-05-typed-setting-fields/design.md` 为准，字段定义、选项、EntityRef、时间线和求值器不在本任务另造。

## 1. 数据与身份

采用当前条目标签＋保存分类规则＋按需计算成员，不保存易失效的成员表。

| 修改 | 数据与约束 |
| --- | --- |
| 四类实体 `setting_tags` | JSON 字符串数组，默认 []；独立于项目题材标签、别名和规划标签。规范化去首尾空白、去空、去重，大小写按原样精确匹配；每条目最多 50 个、每标签 50 个码点。 |
| `SettingCategory` | project_id、稳定 id、name、applicable_types、match_mode=all/any、sort。适用类型沿用字段目录枚举；名称作品内唯一。 |
| `SettingCategoryRule` | category_id、sort、kind=tag/dropdown；tag 规则保存规范字符串，dropdown 规则保存 definition_id 与 option_id 的真实 FK。CHECK 保证恰有一类载荷；不保存自由表达式树。 |
| `Project.categories_revision` | 标签／分类目录 CAS，和 fields_revision、timeline revision、planning revision 分开；任何标签或分类规则写入递增。 |

标签采用条目内字符串这一最小方案；不建第二套标签身份／重命名管理系统。标签建议从现有条目去重读取，作者也能先配置尚未使用的标签规则。编辑条目的标签就是改变该条目成员条件，不承诺全作品自动重命名。

分类删除级联删自己的规则；规则对定义／选项为 NO ACTION，单独删除被规则引用的配置须 409；整作品删除仍同语句级联。字符串标签为 json_plain，适用类型为 json_plain，真正 ID 用 FK 登记，不能把含 ID 的规则载荷标成普通 JSON。

C1真实PG验证发现多条项目级联分支的约束检查顺序需要延迟：仅规则→定义／选项两条FK声明`DEFERRABLE INITIALLY DEFERRED`，仍保留`NO ACTION`，模型与0036一致；服务层仍提前409。单删保护用真实COMMIT或`SET CONSTRAINTS ALL IMMEDIATE`验证，不能只证明flush阶段暂未报错；整作品删除及最终无孤儿同时验证。0035已冻结外键不修改。

四实体SQLite自动ID也必须不复用：标签草稿以(kind,id)寻址，删最高ID后复用会让远端旧请求在目录版本未变时误写新条目。0036未交付阶段与四ORM表同时启用AUTOINCREMENT；SQLite用显式recreate="always"一次完成tags＋AUTO，迁移级先关外键、前后检查并恢复原连接开关；PG仍原ADD列。保留全部父子旧行、时间戳、原文及其他表序列高水位；空态反向重建精确回0035，非空先拒降级。16条真实HTTP覆盖两建库路径／四实体／删最高及删空，旧GET／PATCH404且新tags／revision不变。只保证0036起自动分配不复用，不追溯找回旧删除最高ID或禁止手写PK。前端成功删除forget／有效404清草稿是补充，不能替代后端身份保证。

## 2. 规则语义

每个分类至少 1 条、最多 20 条非嵌套条件，适用类型至少 1 个。条件只有：

1. `tag`：条目当前 setting_tags 包含该规范标签。
2. `dropdown`：条目在目标位置的对应定义值等于指定稳定 option_id。

先按分类适用类型过滤，再对完整条件执行 any／all；不适用字段、未填值、显式清空均为 false，不把缺字段当成空选项匹配。条件必须属于本作品，option 必须属于该 dropdown 定义，定义至少与分类适用类型有交集；错误条件在保存时拒绝，不能在求值时忽略。

一个条目可命中多类。停用选项或字段不删除已有规则，历史值仍可匹配；编辑旧规则可保留原停用身份，新建条件只能选择当前可用选项。

默认当前：使用字段子任务 position=None 的全部有效值。历史模式：支持已有章 ID 或计划章号，二者互斥，并选择 start/end。规则和标签按当前保存版本，只有下拉值按所选位置回溯；界面固定提示“下拉字段按所选章节计算，标签按当前整理信息”。显示名也使用当前名称。

## 3. 查询与批量求值

目录和候选查询复用字段子任务的领域中立查询服务；不能从前端按行调用 effective，也不能照搬规划目录“先加载全部对象再切片”的规模假定。

- 对四类表按适用类型和名称筛选，以 `(kind顺序, sort, id)` 稳定顺序分批读取候选；世界观以当前固定 category 细分。
- 每批只加载规则所需的字段定义／实例和相关事件，通过共享 `resolve_entry_fields` 在同一位置求值；候选批量目标 200 行，实际按数据库参数上限调整。
- 在完整规则求值后累计 total，只保留当前请求页的匹配行和说明，保持内存有界。不能先各类型取第一页、先分页再筛分类，或只对本页统计总数。
- 列表返回分类、categories_revision、fields_revision、position、items/total/page/page_size。每行有 EntityRef、类型、当前名称、标签和服务端产生的匹配理由。
- 不建立持久成员缓存或新增检索系统；在一个只读一致数据库快照中完成全部候选批次、字段／规则／标签读取，no_autoflush，无绑定／时间线／标签创建副作用。不能用默认逐查询快照混合前后两次编辑；字段／分类版本与该快照绑定，前端查询代次仍独立守卫迟到响应。实现时用数据库支持的一致只读事务，并用并发屏障用例证明完整结果的一致性。

一致快照使用SessionmakerDep的独立session，在任何SQL前配置：PostgreSQL为REPEATABLE READ；当前SQLite legacy驱动显式BEGIN。在该session内重新检查归属与生命周期，不修改已由认证查询启动的请求事务，也不改变全局engine策略。官方依据和验证边界见父任务 `research/consistent-read-contract.md`。

## 4. API 与写边界

前缀 `/api/v1/projects/{pid}`：

| 路由族 | 功能 |
| --- | --- |
| `/setting-categories`、`/{category_id}` | GET 列表／详情，POST 创建，PATCH 修改／排序，DELETE 分类。写入 expected_categories_revision。 |
| `/setting-categories/{category_id}/entries` | GET 完整规则匹配的分页条目；type、q 和章节位置筛选。 |
| `/setting-categories/preview` | POST 未保存规则的只读计数／样本预览，复用同一求值函数，不持久化；路由显式登记为读取权限。 |
| `/setting-entries/{kind}/{id}/tags` | GET 当前标签和版本，PATCH 整体替换标签数组，带 expected_categories_revision。 |
| `/setting-entry-tags` | GET 有界标签建议，按 q 搜索当前条目标签；不是可写的全局标签库。 |

类别 PATCH 省略字段不变；显式 tags=[] 清空，tags=null 拒绝，规则空数组拒绝，名称去空后不得为空。配置和标签在项目 active 写屏障及一个事务内修改；底层 helper 只 flush。

在用选项／定义的删除和更新检查扩展到分类规则：即使零绑定／零事件，规则已引用的 dropdown 也不能改类型；缩小适用类型若使任何现存规则失去交集则409。改名／排序／停用保留既有规则身份，合法范围调整仍允许；统一图校验覆盖人工修改、导入和 effects。实体正常删除不需要因当前标签而受阻。世界观换类仍沿用前置字段保护，不为分类改变原始类型。

目录／规则版本冲突为 409 stale_revision 并附 scope；跨作品条目、字段、选项不可见为404／校验错误；人工只读 403；其他409按具体 code 处理，不自动刷新版本覆盖。授权路由、管理员人工审计和项目刷新资源均显式注册。

## 5. UI 和状态

- 新懒加载 `setting-categories` 页：分类列表、结果列表、规则编辑。规则表单提供名称、多类型、ANY／ALL，以及标签／下拉选项条件行，不出现表达式或数据库 ID。
- 四类现有详情各自加入“整理标签”，用独立保存区和 tags 多选，不与别名、剧情变化或外层资料表单混存。配置字段值的工作由前置子任务完成。
- 结果展示类型、名称、标签、匹配原因和“查看”，按当前／已有章／计划章及章初末筛选。切筛选回第一页；空结果、加载失败、错误重试分别显示。
- 复用字段子任务抽取的四类型详情 URL helper。历史链接携带有效位置和只读预览意图，`id` 之外的参数经验证；不把历史值灌入基础编辑草稿。
- 名称／元数据／规则／值在独立 draft 中管理。身份 key 包含真实 actor、project、category／entry、位置与请求代次；换账户或失读撤下数据，失写禁写，冲突保留草稿并提供最新对照。
- 服务端成功后广播设置目录／分类及实体资源失效。字段变化时分类重新查询，不能使用旧 base_value 比较。草稿不会被广播 reload 覆盖。
- 只读可看规则、值和分类；所有写按钮、弹窗确认和提交函数均按 canEditNow 复查。桌面用表格、375px用卡片，支持键盘、主题和可见焦点，不引入新图谱／表单依赖。

## 6. 持久化、卡片和撤销

- Alembic `0036` 依赖 `0035`，实施前核对；为四表补空 setting_tags，新建类别／规则表及 categories_revision。既有项目标签绝不填入条目。
- project v5／APP_SCHEMA0036，接受 v1–v5。合法v1–v4经已有逐级升级后，对缺失或规范空数组补setting_tags=[]与两张空分类表；夹带非空标签／类别／规则明确拒绝，非法形状或null不能当空吞掉，不静默丢资料。保留字段阶段旧版未来类型化资料的严格闸门。v5自身必须包含两张分类核心表，不能用旧版补空掩盖损坏；规则依赖的定义／选项先导入。RULES、反射、enum／JSON处理、预览和 remap 一起更新。两revision属于被排除的运行代次，源值不继承，新项目从默认起点开始。
- cards v5 保存包内条目的 setting_tags；不包含作品分类规则或成员快照。v1–v4卡片缺失或规范空数组默认为空，夹带非空新标签或非法形状明确拒绝；旧同名实体跳过及职业复用不覆盖标签，引用仍遵循v4显式映射，不新增world容器。
- effects 格式升v4；快照和依赖保护覆盖类别／规则／标签，后续规则引用的定义／选项不能被撤销删除或改成不适用。fields_revision/categories_revision同时从PROJECT_RULE导出列和effects独立项目快照／恢复值中排除，新作品使用默认起点；恢复从当前数据库高水位递增受影响目录，不从before旧值起算。整轮失败不递增，恢复后重验图；旧效果仍按前置任务整轮版本预检。
- 软删／恢复保留标签和规则；彻删测试覆盖新外键。开放 API 保持现有白名单，不因内部schema追加标签而泄露新数据。
- 有非空条目标签或类别时，降级明确拒绝有损操作；空态降级可验证，应用回退需与备份／schema配套。
