# C2 调度与设置验收记录

2026-11-23 在项目锁定的 Python 3.12.10 环境验证，功能提交为 `c593a20`。SQLite 3.47.1 使用临时文件，PostgreSQL 16.15 使用只绑定本机的独立容器、专用 `ainovel_test` 及每个用例各自的 schema。双应用测试使用独立连接池和设置对象，另以真实 uvicorn 进程复核对外行为。

| 验收项 | 实际观察与复验位置 |
| --- | --- |
| AC1 全站上限 | 两个引擎各自预选不同任务，交换争最后一个名额的胜者，六项各执行一次，全站峰值 2。PostgreSQL 的第三条连接用 `pg_blocking_pids` 观察到实际锁等待。 |
| AC2 用户上限 | 双引擎、三项任务，用户上限 1 时峰值为 1。限额降到 0 时已有任务可完成，后项保持排队，调高后继续。真实进程再以全站 6、用户 2 验证用户硬顶。 |
| AC3 同键串行 | 同项目章节分析按入队顺序进入和完成，每个作品的模型并发峰值为 1。PostgreSQL 实际锁住较小 ID，后项仍等待。 |
| AC4 队首受阻 | 令队首用户满额或仅在 A 本地退避。B 的后项无法越队，另一个串行键仍可前进。两方言使用相同验收场景。 |
| AC5 待核对与回收 | 待核对任务对两个应用可见，配额为 0，同键任务可正常运行。占用只随原执行归还或已确认的停止、围栏回收，后续轮次的占用不受迟到归还影响。 |
| AC6 回调与兼容 | 人为阻塞成功回调及最终发布，两端仍读到占用。分别隔离全局、用户和同键三项约束。9 项生命周期测试分别在两种数据库通过，包括归还失败、回执丢失、取消、异常及关停。原断言的替换原因见[逐项清单](assertion-migration.md)。 |
| AC7 即时关闭 | A 关闭注册和 MCP 后 B 首次请求均为 403，无新账号或认证 Cookie，MCP 监听端收到 0 条 TCP 连接。注册与关闭的两个提交顺序、九个插件入口、逐项导入和 SDK 的发包边界另有定向回归。 |
| AC8 普通设置与错误恢复 | 已在 SQLite 与 PostgreSQL 验证空闲副本刷新、默认值恢复、同分钟限流、章节成功后的自动分析和启动失败清理。真实进程下调高每分钟限流后，B 首次允许额外请求分别在 3.643 秒和 4.431 秒，同一分钟下一次请求仍返回 429。 |
| AC9 配额与排队位次 | 真实双进程两端在稳定时读到同样的 2 个名额，收尾后均为 0。另四个排队任务在两端位次均为 0、1、2、3。通过受控停点比对列表、详情和排队帧，并验证另一用户的任务仍不可读。 |
| AC10 方言与全量回归 | 专门覆盖 AC1–AC5 的调度模块在 SQLite 及 PostgreSQL 各 9 项通过。完整回归结果见下方。 |

## 对照、迁移和接口

- 在改动前的 `a16eb2a`，同套调度测试有 8 项失败，C1 已有的待核对用例通过。旧版真实进程在上限 2 时允许 4 个模型请求并行。修复后，两次独立演练均由每个进程实际执行 3 项任务，每项只调用一次模型。[双进程命令与观测记录](sqlite-http-processes.md)
- 在两种数据库实际往返 0066 与 0067。旧任务保留，未确认归属和活跃执行者会阻止降级，拒绝后原版本及占用仍可核对。SQLite 原生快照冷恢复曾实际持有占用的任务，确认旧执行者后归还。作品 JSON 维持 v16，导出的 `app_schema` 为 0067。
- 从改动前后的应用生成排序后的完整 OpenAPI 文档逐字节比对，415 条路径的定义一致。前端 TypeScript 编译通过。

## 回归命令

在 `backend/` 下运行 SQLite 全量，PostgreSQL 组使用同一套依赖并配置本机专用连接。

```sh
env -u AINOVEL_POSTGRES_TEST_URL LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8 uv run pytest -n 4 --dist loadfile --durations=20
uv run ruff check .
uv run pytest -n 0 -q tests/test_task_scheduling_constraints.py tests/test_task_slot_lifecycle.py tests/test_task_worker_slot_reclamation.py
uv run pytest -n 0 -q tests/test_system_settings_cross_process.py tests/test_system_settings_publication_races.py tests/test_mcp_cross_process.py tests/test_mcp_sse_settings_boundary.py
```

首轮 SQLite 全量发现 5 项任务流快照用例失败。按固定顺序执行租约测试和快照测试即可复现。租约测试临时替换了注册表中共享处理器的方法，恢复时留下了实例属性，遮住后续测试设置在类上的停点。修复测试清理后，在同一进程依次执行租约、任务快照、提前订阅与智能体任务流四个完整模块，123 项通过（288.42 秒）。进度、身份隔离及授权的原有断言和等待时限均保留。

配置 PostgreSQL 16.15 后串行运行调度、占用回收、系统设置、MCP 和迁移，并补跑 SQLite 全量按条件跳过的 28 项。共 77 项通过，0 跳过，耗时 365.71 秒（含迁移用例的 SQLite 对照）。按 pytest 实际收集的模块及参数标识逐一比对（含由 PostgreSQL 模块导入的租约用例），全部 28 项均在此轮执行并通过。独立运行 C1 的 PostgreSQL 租约回归另有 14 项通过。

最终 SQLite 全量共 7,203 项，7,156 项通过，0 项失败，28 项因需要 PostgreSQL 跳过，19 项为项目已有的预期失败。用时 39.3 分钟。后端 Ruff、独立迁移脚本和双进程演练脚本的 Ruff 均通过。
