# 管理员全站任务监控

优先级：P1。状态：`completed`。用户于 2026-10-31 在最终方案摘要后回复“开始”，已批准实施；实现与验收已完成，已获提交/收尾/合并推送授权。

来源：2026-10-30 管理员功能缺口盘点中独立建档的任务。2026-10-31 用户要求启动已有 `admin-task-monitoring`，随后依次确认下列四项推荐方案；不重复建档，也不把需求选择当作实施批准。

## 目标与用户价值

让管理员集中查看全站任务、定位排队与失败情况，并在不读取他人模型凭据、提示词或生成正文的前提下人工取消任务，及时处理异常占用。

## 背景与已确认事实

- 普通任务查询与处置仍严格按所属用户校验：`backend/app/services/task_service.py::list_tasks`（292）、`get_owned_task`（256）。他人的任务与不存在统一 404；本任务新增独立管理员入口，不放宽普通 owner helper。
- 当前任务引擎 `backend/app/services/task_engine/engine.py` 仅支持单进程部署，已有全局/用户并发限制和串行资源规则。`backend/app/models/entities.py:77` 区分排队/运行、待审核与四种结束状态；待审核不占执行并发，不等于成功结束。
- `task_service.py::_cancel_loaded_task`（331）可共享已加载任务的取消能力，但授权由调用者负责。`_cancel_loaded_impl`（337）包含独立提交，运行中收尾又在引擎独立会话中完成；不能仅在外层补一条审计就宣称处置与审计原子。
- 管理员首页与独立统计已经交付，见 `.trellis/spec/backend/admin-dashboard.md`。Task 是现存明细；独立统计不含用户、作品、正文和原始错误，不能据此重建已删除任务。
- `task_service.py::MAX_FINISHED_PER_USER`、`clear_finished`（439）、`prune_finished`（458）规定常规已结束任务每用户最多 200 条且可主动清理；回收站历史不参加普通裁剪。作品彻删也会移除任务。
- 取消、查询与异步收尾必须保留 `statistics_key` 的执行身份隔离。整数 ID 可被 SQLite 复用，旧请求不能作用于新任务。
- `backend/app/ai/providers/base.py::describe_error`（91）截取异常原文；`task_engine/engine.py::_run`（295）/ `_consume`（351）会保存业务错误或事件 detail，故原始 Task.error 不是管理员安全摘要。
- 安全边界不限于 error：`task_engine/handlers/agent.py:58` 的 Task.title 含指令前 20 字，`services/agent/runner.py:96` 的 stage 含私有插件名称。任务标题/阶段也必须采用安全展示，不借元数据接口泄露输入片段。
- 同一 Task 可以暂停后重新排队，created_at 不随之改变，updated_at 又会受其他写操作影响；本轮排队/运行时长应有可信起点，旧记录无法确定时不得伪造。

## 需求与已确认取舍

下列四项取舍均由用户于 2026-10-31 选择推荐方案 A；其余需求承接原任务草案。

### R1 全站安全明细与组合定位

提供独立管理员列表和安全元数据详情，展示任务编号、所属用户、作品、类型、状态、安全阶段、进度、本轮排队/运行时间、创建/开始/结束时间和必要错误摘要。覆盖仍存在的任务，作品处于回收站或删除协调中时须明确标识。

支持按用户、作品、任务类型、状态、创建时间组合筛选及分页，提供失败/中断定位和排队/运行时长排序。计数明确属于当前筛选下的现存明细，不冒充首页历史累计；前方排队记录数不作准确开始顺序或等待时间承诺。

### R2 人工取消与审计

所有当前管理员均可取消任意用户的 `queued`、`running`、`paused` 任务，不要求任务满足系统异常条件。必须二次确认、填写非空取消原因并记录真实管理员身份的操作审计。不能伪装成任务所有者；本人任务从管理入口处置也记录管理审计。

界面与审计区分“取消请求已受理”和“任务已取消”。受理后按现有引擎的安全规则收尾并释放占用；正在结束或原子保存已获胜时返回实际结果，不声称撤销已提交内容。耗时收尾要明确取消中，不因等待超时虚构取消成功。取消原因仅作管理操作说明，不要求或自动附带任务原文。

### R3 仅保留现存任务明细

不新增独立长期明细归档，不改变现有正常任务历史保留/清理策略。明细被主动清理、自动裁剪或作品彻删移除后，不再提供查询；独立任务累计及管理员取消审计不会随 Task 级联丢失，仍受各自既有生命周期/显式审计清理规则约束。安全收尾尚未完成的记录不能被提前删除而失去恢复依据。

### R4 保守诊断与权限隔离

管理员仅查看安全错误类别和固定说明，无法可靠分类时统一显示“执行失败”；不提供原始报错或脱敏后的详细报错。未知阶段安全回退，不能透传指令片段或私有插件名称。

读取与取消不新建所有者的模型调用，也不授予重试、继续、成功提前结束、接管、读取生成正文/完整提示词/断点或私有配置的权限。普通用户原有权限不变。

### R5 轻量实时监控

默认每 5 秒自动刷新，可关闭；页面隐藏时暂停、恢复可见后更新，也提供手动刷新。采用失败/中断筛选和时长排序辅助定位，不以统一时长判定卡住、不增加阈值告警、不自动取消。

请求失败须明确数据过期及上次更新时间；切换筛选、分页、目标、账号、降权或卸载后，旧响应不能复活数据/弹窗。移动端和浅暗主题沿用现有管理界面，不引入独立视觉体系。

### R6 管理入口衔接

同步管理员导航、账户菜单和面包屑；从管理员首页可进入现存任务及对应状态列表，任务安全详情支持可定位入口。链接明确现存任务和累计统计的口径差异，不把个人任务面板/输出接口变成管理入口。

## 验收标准

- [x] **AC1（R1、R4）**：管理员能定位至少两个用户的任务；未登录/普通用户/已降权管理员不能调用管理接口，普通用户任务接口仍只读写本人任务。
- [x] **AC2（R1）**：组合筛选、分页、稳定排序、筛选内状态计数与实际现存队列一致；回收站/删除中作品有明确标识。重新排队的本轮时长不从最初创建时刻计算，旧起点缺失显示未记录。
- [x] **AC3（R2）**：管理员对三个未结束状态填写原因并二次确认后才受理；真实 actor、目标身份、原因和受理事实可追溯。审计受理写入失败不放行取消副作用；受理成功不被文案伪称实际已取消。
- [x] **AC4（R2、R3）**：并发完成、保存已提交、待审核竞争、重复取消、目标移除及已结束取消都有明确反馈；不破坏任务/章节状态，不重复累计终态，不让旧请求影响复用整数 ID 的新任务；中途断开或重启不会丢失已受理的收尾意图。
- [x] **AC5（R4）**：监控/取消不触发新的所有者模型调用，不提供他人任务的重试、继续、提前成功结束、接管、输出读取等越权入口。
- [x] **AC6（R3、R6）**：清理/裁剪/彻删任务后列表与详情不返回旧明细；累计统计和取消审计不随之级联删除；页面与首页链接明确两种口径，且不改变正常历史保留策略。
- [x] **AC7（R4）**：原始错误、任务标题或阶段含密钥、调用地址、正文、指令片段或私有插件名时，管理员 API、页面和自动生成的取消审计摘要均不透传；错误只显示有限类别/固定说明，无法可靠识别则为“执行失败”。
- [x] **AC8（R5、R6）**：5 秒轮询、手动刷新、开关、隐藏/恢复、失败过期提示均正常；筛选/目标/账号/权限变化及卸载后旧响应无效，取消不重复提交，桌面/375px与浅暗主题下操作可用。

## 不在本期范围

- 跨账户使用模型密钥、读取生成内容、原始提示词/断点/私有资源，或重试、继续、成功提前结束、接管所有者任务。
- 独立长期明细归档、恢复已清理任务或改变正常的任务保留策略。
- 原始/脱敏详细报错、统一超时卡住判定、阈值告警、自动取消。
- 多实例调度、跨进程续跑模型任务、替换现有任务引擎。
- 新的管理员角色分级、配额及外部监控基础设施。

## 依赖、兼容与已知限制

复用已交付的管理员身份、操作审计、作品生命周期及首页；管理员角色分级不作为硬前置。本任务独立规划、实施、验收和归档，无需新增父/子任务。

运行任务取消需等待既有执行体安全收尾，已提交正文、已执行的智能体修改或外部工具效果不会因取消被自动撤销。后台请求受理意图的恢复不等于跨进程续跑生成任务；重启后实际终态仍遵守原引擎的中断规则。
