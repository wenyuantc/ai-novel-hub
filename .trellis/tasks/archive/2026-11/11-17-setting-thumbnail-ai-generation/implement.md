# 实施与验证计划

## 前置条件

- 已完成需求收敛、研究及上下文清单，用户已批准最新完整方案，任务已启动并实施。
- 保留第 13 项工作区全部既有改动。新功能基于已有缩略图、作品协作、系列协作和封面生图实现，不重置或覆盖其他人的改动。原 `commit-plan.md` 已过时，最终按实际变更重新整理。

## 顺序与依赖

1. **合同与最小测试**：落实 `design.md` 的作品／系列提示词、生成、确认请求和响应 schema；先添加覆盖当前条目显式选择、`never` / `manual_only`、字段隐藏、未保存草稿、模型来源和预览不写库的行为测试。限定真实 actor，准备不泄露配置的防篡改来源及预览证明。
2. **后端作品链路**：复用已有可见字段投影、作品图片模型决议及图片 codec；在作者和协作者各自路径绑定原主体、邀请、可见性、实体来源及模型指纹，确保真实物理发送、响应及 AI 确认的重新鉴权和 CAS。测试伪造凭据、跨作品／主体、撤权重邀、项目回收／条目转系列、模型改变以及当前图片版本冲突。
3. **后端系列链路**：在步骤 1 的共用合同和图片能力基础上独立实现系列本体的可见投影、本人模型选择和受控发送；证明真实系列授权变更与发送、回包和确认的数据库锁顺序，保留系列 revision 和缩略图版本检查。测试无任何采用书的系列条目、系列 editor 与单书 editor 差异、纯管理员、模型缺失及撤权重邀。
4. **前端集成**：基于前两条已确定的 API 合同，扩展四类项目 `ProjectThumbnailEditor` 和系列 `SeriesEntryEditor` 的图片操作区。实现可编辑提示词、模型选择及费用来源、生成预览、明确确认、取消及冲突反馈；保护 actor／作用域／请求代次、未保存文本草稿和图片元数据。系列控件不得依赖项目路由或回退作者模型。布局和无障碍须适配桌面、375px 和键盘交互。
5. **联调与更新**：运行受影响行为、并发和回归测试；更新根 README、缩略图与 AI 可见性／系列等受影响规范、`TODOS.md` 和本任务验证记录，以实测行为为准。必要时更新父任务验证及提交清单；未请求提交时不提交、不推送。

步骤 2、3 的共用认证和 Provider 边界须统一，避免对相同共享文件并行写入；前端只在步骤 1 的 schema 确定后对接。每个可验证阶段运行相应测试，最后由 Trellis 检查子代理复核跨层权限、测试及规范。
