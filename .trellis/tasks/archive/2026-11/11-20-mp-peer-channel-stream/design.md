# C4 技术设计

基线为本地提交 `aabd3c3`、数据库版本 0068。A 表示执行任务的进程，B 表示接收浏览器订阅的进程。本文描述待实现行为。[需求和验收](prd.md)

## 1. 一个浏览器订阅如何找到执行者

B 通过现有 `/tasks/{task_id}/stream` 完成身份校验，冻结最初的 `_StreamBinding`，包括账号创建时间和令牌版本、作品及其删除轮次、任务键和入队时间、任务与成员各自的邀请轮次、是否需要活动编辑权限。重连沿用客户端原任务键。每次路由先读可见的同轮任务和 C1 执行者登记，持锁事务结束后才连接对端。路由结果如下。

| 观察到的状态 | 订阅行为 |
| --- | --- |
| 本机正在执行同一轮 | 使用原本地订阅和发送管线。仅有同 ID 的 hub 不构成归属证明。 |
| 已领到 A | B 向库中登记的 A 建立一次内部订阅。A 再查自己的活租约及该轮执行键，独立核验原读者绑定，只从自身 hub 提供数据。B 按当前账号、作品可见性与原任务轮次检查作者帧，协作者帧按第 3 节复核。内部请求不能向第三个进程转发。 |
| 仍排队 | 给出同一行的排队快照、队位变化，持续观察领取。进入已确认的本地执行时衔接原订阅，其他进程领取时衔接该进程。保留本机原先“注册并取快照”的同步临界区。 |
| 已暂停或已终结 | 按原授权调用现有持久回放，发送完整投影快照和唯一的 `paused`、`done` 或 `error`。直接订阅已经终结的任务不查内部通道。 |
| 租约未知、对端断开或版本不兼容 | B 进入第 4 节的降级。订阅只观察 C1/C3 的恢复结果。它没有接管执行、改写状态或释放名额的权限。 |

**排队与领取之间的衔接。** 已经看到 queued 的订阅必须能收到 A 领取后即刻产生的章节和工具事件。A 从领取首次发布前开始，用该轮 hub 保存短期、有序、有界的原始事件及其原来源，含领取、reset 和结束边界。B 以原排队轮次声明“自领取起订阅”，A 在同一无等待临界区内取缺失前缀、确定游标、接入实时队列。已经 running 才订阅则取当前快照，加后续增量。短任务在 B 发现领取前就结束时，先按原轮次查短期保留的结束缓冲区，再走持久回放。已记录 A 的只找 A；未知 A 的按原轮次向存活端点做有界查找。仅持有缓冲区并能证明本轮的原执行者可回复。从库中重新得到 running 行或当前文本，无法补出已错过的结构化事件。超出保留时间或容量、出现游标缺口时显式转降级，丢弃不连续的后缀。保留期内强引用原 hub 及其来源、后继和终态证据，保证弱引用登记在正常交接时仍有效。全局和单轮预算计入被保活的文本、结果、断点和来源对象，释放订阅或到期后清理。排队观察和短期留存不得改变本地订阅的公开帧序列。

## 2. 对端发现、内部协议与生命周期

- 在每个应用的 lifespan 内用 Python 的 asyncio streams 启动一个独立监听。本机默认使用同一操作系统账号下的短路径私有运行目录（0700）、每次启动唯一的 UDS 文件（0600）。跨实例使用显式配置的私网监听及可从其他实例直达的通告主机；每个服务进程独占一个实际端口，可绑定端口 0 后登记实际值。地址必须能直达原进程，通用负载均衡地址不能承担该职责。私网应具备传输机密性或由部署层提供加密隧道。正式部署参数和放行多 worker 归 C7。
- 先 bind，再随该代 `WorkerLease.register` 写入现有的 `task_workers.peer_url`。同进程的 HTTP 请求租约和调度租约共用一个监听，分别登记自己的 worker key。调度器停用或换代后，HTTP 仍可转发并重载设置。接收方逐请求核对目标是否是本机当前相应代次以及发送方是否有效。按 `Task.worker_key` 选执行者。广播按监听地址去重，保留有效目标身份；排除本机两个身份。SQLite 使用配对侧库的活性事实，PostgreSQL 使用 C1 数据库时钟和围栏；数据库查询不因连通性失败写入 stopped 或 fenced。
- 协议只接受固定版本的订阅、排队交接查询和唤醒操作。请求签名从部署 `JWT_SECRET` 按用途派生，覆盖版本、操作、源与目标 worker key、时间戳、随机 nonce、会话标识及完整规范化负载。接收方先校验形状、长度、签名、目标、时间窗和一次性 nonce，再查任务。nonce 表按有效时间回收，未过期且已满时拒绝新请求。响应由独立用途密钥认证，绑定本次请求、订阅原绑定摘要、任务及执行轮次、方向、递增帧号、事件类型、数据与授权描述的摘要。拒绝乱序、重放、缺号、截断和未知版本；空闲心跳和结束也必须属于本连接。握手、完整逻辑帧、确认和关闭各用绝对截止时间，零碎字节不延长预算。只有完整认证的心跳才能证明通道仍在响应；B 另按绝对周期短查任务授权、同轮归属和实际状态，只有心跳也能在库中已暂停或已结束时收尾。时间偏差过大走降级。两端只使用配置允许的私网端点或私有目录里的 UDS。
- 每条连接只服务一个订阅，复用 A 原管线的快照、增量合并和结构事件。对端按逻辑帧顺序原样交给 B；控制元数据不进公开 SSE。用长度前缀和受限传输块承载大快照，完整校验后才能写浏览器，保留原 Unicode 和正文。超过传输块的合法帧可跨多个块；超过整个订阅的资源预算则在公开发出任何部分前显式降级。协议单块、并发订阅数、缓冲总字节、握手和每次 I/O 都有上限。实施时记录所选上限、溢出降级、超大合法快照和慢读者实测；不能把 asyncio 默认 64 KiB 行长当成产品正文上限。日志只留固定错误类别、计数、时延，不记录正文、签名、凭据或整包异常。
- 在对外路由、OpenAPI 和浏览器请求里均不注册内部操作。bind 失败只撤销该端的通道登记，保留数据库兜底。应用退出先拒绝新对端连接、取消并等待监听任务、订阅和后台发送，按 C3 顺序归还登记；在每一个部分启动失败的退出路径执行相同清理。仅在私有目录中验证设备号、inode 和属主后删除本实例的套接字。强杀没有机会执行 finally，重启必须使用新文件；安全回收确认死亡的旧代遗留，保留其他进程的文件。

## 3. 两次真实发送分别证明什么

1. A 从本执行 hub 取得原来源。受控帧走现有领取、排队、发布、后继或终态验证，在原帧发送事务中完成投影、内容校验及实际限时内部写出。A 签发本帧的精确数据和只读核验所需的固定身份。A 内部的弱表、对象引用和 `SendGuard` 留在 A。消息携带有版本、逐类型白名单的只读字段，禁止传送运行时对象、SQL、用户令牌、模型凭据和通用可执行检查。
2. B 完整收帧并验证签名后，在实际浏览器 ASGI `send` 的同一协程里使用自己的 `_TaskFrameGuardedResponse` 取得 `_task_frame_lease`。沿用认证、可见性、作品、双方模型配置和任务的原锁序，核对账号、成员版本和角色、作者模型授权、项目活跃状态、原任务绑定。按 A 验证时选定的**具体来源**，共享既有只读条件，核对本帧在当前库里仍可发送。保留事件及载荷摘要、同根事务和同物理连接的 send 前后检查。签名证明数据来自可信执行者；B 仍要判断原读者此刻能否收到这段具体内容。
3. 可携带的条件与本地来源一一对应。排队、领取仅能证明原规则允许的空正文、排位/领取等帧；已终结的持久投影由 B 重算。发布类包含已核验的执行、可见性 revision/epoch/删除时间、模型选择和原来源所需的核验字段。单章、分析、批量、向导、实体、一致性、智能体等以现有 `stream_kind_open` 开放范围逐项覆盖。批量后继、向导保存后换戳、智能体会话及提案、富文档待审核及“成功但未发布”的收据，按原有专门规则在 B 复核；原始凭据摘要可供比对，不能拿最新数据库行反推原来源。签名、动态前提或轮次有一项无法证明，就结束受控发送。见[逐帧授权研究](research/frame-authorization.md)。
4. A 与 B 依次取得与释放各自的租约。A 可以在本机有界写出时持锁，不能等 B 取得锁、完成浏览器写入或回 ACK。B 在完整收取本帧后才开事务，持锁期间只访问本地库并限时写浏览器，不再调用 A。默认 SQLite 的 SHARED、SQLite WAL 的写屏障和 PostgreSQL 的共享锁都要验证。断开后取消读写、关闭异步生成器并退订。已尝试发送一帧后的错误按原响应器中止，不在同一响应重试不确定的字节。

每个订阅仅允许一个已写出、待确认的逻辑帧。A 完成第 n 帧的内部写入并释放事务，再在锁外等 B 的确认或同帧重核请求。B 收全，用自己的锁写给客户端，释放事务后才确认，A 收到确认才取第 n+1 帧。这样即便两条相邻帧都大于套接字缓冲区，慢客户端也不会与 A 的下一次 WAL 写屏障互等。确认丢失时关闭上游，禁止因此重发已经写过的浏览器帧。B 尚未开始公开写、仅遇到批量或向导的合法后继窗口时，可在释放租约后请 A 用同一序号、原载荷摘要和原对象重新证明该帧，沿用一次截止时间；非法身份直接拒绝。ACK、重核和相应控制记录也绑定本连接并认证。在 PostgreSQL 上共享锁定正在复核的原成员行，核对权限切换与账号/作品/任务锁序一致。

两端以最初的认证和实际库中作品/成员关系确定作者或协作者分支；握手声明不能选用较宽松的管线。作者与个人任务沿用原读者身份、当前作品可见性与投影，不套用协作者种类白名单，覆盖作者自己的知识库/拆书流。权限变化或任务轮次变化时不得通过降级重新绑定。判据是撤权提交之后，B 不会再把新的受保护字节交给客户端连接。已在提交前交给网络的字节无法撤回。测试卡住 B 的实际写入，分别验证撤权先提交与发送先进入锁两种顺序，同时观察最末端 HTTP 客户端。固定无内容的拒绝通知和心跳沿用现有语义。

## 4. 通道故障和活动读取

- 作者降级跟随原 `task_key + queued_at`，用短事务重验原读者和作品，按现有公开投影定期读取数据库，仅在正文、进度或阶段改变时发覆盖式快照。切换时用最新可见的持久快照整体替换展示，即使暂时变短也以库为准。文本长度、前缀和阶段名都不能辨认 reset，快照与旧增量不能拼接。按同轮结束时转现有持久快照和唯一终止事件。详情消失、会话失效、数据库持续故障走原受控错误或有界断线；不把未知结果伪造为中断。接管认定 interrupted 才发送中断，已确认的成功、取消、待审核或未发布结果按原状态回放。
- 协作者的 queued 快照以及 paused/终态可以在本地按同一锁定行重算。运行中仅有 `Task.output_text` 缺少发布来源，即使有权查看详情也不能用它补发。先复查是否已经可以持久回放，仍在运行且缺来源时发送一次固定 `permission_denied` 并结束；合法客户端按现有规则复核详情、限次重订阅。知识库索引、拆书等继续服从现有类型限制。前端仍消费原有事件名、快照覆盖和结束状态。
- `task_service.to_out/get_output` 与管理监控共用严格的本地实时值选择：运行行与本机有效调度代次、任务/入队/执行键、当前执行登记和未关闭 hub 都要一致；其他情况取库内投影。管理查询只增加核对归属所需列，继续用安全阶段白名单。排队读使用库内队位。配额的已用名额已经从 `TaskExecutionSlot` 计数，在两端对照验证。
- `TaskEngine.flush_interval` 当前为 2 秒，源码按下一条事件检查时间。加入尾沿写回：同一执行由单个串行写入者合并脏标记，到期时即使没有下一次模型输出也写回。冻结同一版本的输出/进度/阶段及对应执行凭据，沿用原 `_flush` 授权、CAS 和事务确认；写入失败或写入期间再有改动不能误清标记。reset、换代、取消和终态优先，禁止旧定时器覆盖新状态。健康数据库下最后一个增量或仅进度变化最迟在一个节流窗口触发并完成可观测刷新，计时测试记录实际落库及 HTTP 可见时间；数据库阻塞或提交不明归原恢复路径。一次窗口内合并更新，转发每个事件不产生额外流水。

仅有 C3 请求侧 worker 接管收尾时，即使它是任务当前持有人，也不能当作原执行源。对于已结束的短任务，保留的原来源只用于绑定同一仍有效端点、同一入队轮次、原执行及已验证终态；即使终态清除了行上的 worker/执行键，也须由原终态凭据关联，旧进程死亡则按库回放。活动读取中的“结果待核对”须用原任务、入队和执行键匹配已有的持久证据（如 `recovered_at` 或经 C3 的 `owner_cancellation._unproven_execution` 按完整任务身份匹配并复核含义的持久收据）。如果仅存于 A 的 `_uncertain_executions`，在库恢复可写后对同轮追加可被另一端区分的持久标记，再核对 A/B 的详情和不产生业务副作用。标记不能把普通清理失败解释成未知结果，不能解锁任务或启动重试。数据库不能核实期间继续现有不确定处理。[读取与恢复依据](research/reads-wake-fallback.md)

## 5. 唤醒、降级时限与回退

业务意图以数据库提交为准。创建/继续后提示调度器，原轮取消提示持有者（本人和管理员均覆盖），成员变更提示相关订阅、正在运行和待审核的协作任务，设置提交提示各应用实例单独重读已提交 revision。唤醒仅携带核对所需标识。出站发送在事务释放后有界并发、可合并；接收端只执行本地唤醒与重读。心跳、重载、重复消息和本地产生的 `notify()` 不再对外广播。通道不可用时，沿用 C2/C3 的数据库领取、取消和设置读取防线。为静默的运行中协作任务和挂起订阅补齐定期复核，按各自的绝对轮询截止时间推进，其他唤醒不能饿死定时检查。HTTP 持有的订阅由应用级定时器复核，即使调度已停仍要执行。每轮批量预筛需要复查的 running、paused 和原订阅，复用原授权/收尾路径，不向每个执行体争写锁。验收区分“已开始处理并观察到状态变化”和“等待真实执行体退出后最终完成”。

实现与核对分别使用的主要源文件和锁序证据见[监听与生命周期研究](research/transport-lifecycle.md)。沿用 0068 的可空地址列；兼容未登记地址的实例和旧数据。回退时关闭监听、停止广播、撤掉本代地址，再按当前发布流程以单 worker 重启；既有任务与业务收据继续按原方式读取。前端公开接口、导出格式和持久化事件类型保持既有契约。C5–C8 和正式多实例放量由各自任务承担。
