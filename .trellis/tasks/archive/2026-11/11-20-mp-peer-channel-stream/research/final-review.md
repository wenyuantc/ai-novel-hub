# C4 实现独立复核

复核基线为 `aabd3c3`。沿公开任务路由检查了读者身份的取得、任务与作者或成员的绑定、两端发送及锁的先后、任务轮次切换、监听退出、读取进度、设置提醒和前端重连。数据库验收和整套回归的命令及计数见[总验收记录](verification.md)。

## 代码与部署入口

- 执行端在真实帧来源的发送事务内发布，确认发生在退出事务之后。接入端在另一事务中校验本部署的订阅对象、原读者及其帧前提，并持锁到公开写入结束。订阅已确认或关闭后，传输对象会撤销原帧的登记。SQLite 默认日志、WAL 与 PostgreSQL 使用各自的原有锁路径。详细时序见[授权设计](frame-authorization.md)。
- 应用在 lifespan 绑定实际地址，分别登记在 HTTP 与调度 worker。停用调度不会把同端 HTTP worker 变成原执行者。强杀进程留下的 socket 有单独的文件归属核对、双代围栏及存活端实测。[传输复核](transport-implementation-review.md)
- 文档中的 `TASK_PEER_NETWORKS` 说明已与代码对齐，它用于检查监听地址、通告地址和出站目的地址。本地后端可从 `backend/.env` 读取各项设置，默认 Compose 仅转发其 `app.environment` 显式映射的值。生产启动仍使用一个 Uvicorn worker。
- 前端从首个快照开始计算连接稳定时长。第二个及后续快照只更新展示，断线重试次数仍由原逻辑决定。[前端实测](frontend-verification.md)

## 本次复核发现的路径

- 作者删除作品时，转发端最初将原有的已脱敏取消或“任务不存在”改为权限错误。复核要求按原账号创建时间和令牌版本、作品和任务轮次匹配持久取消，确保仍在删除中的原作者收到相应结果；协作者继续经过原授权门禁。
- 排队任务若在发现领取前已经结束，未知执行端的交接查找需要同时约束目标数和总等待时间。短期原帧已经过期后，可以直接回放同轮持久结果。
- 持久阶段字段最多保留 100 个字符，原本从本机 hub 取阶段的详情和列表会返回更多字符。复核同时检查空阶段和管理端的安全阶段投影。
- 公开投影会清理私人引用的内部凭据。在接入端对已经投影的正文再执行同一次过滤，可能让有效引用消失。两端现在比较来源端基于原件得到的公开值及本地可见引用的摘要。原件中仅用于证明关联的内部字段留在来源进程。
- 原发送代码在检查 8 MiB 上限前已经编码整个对象。现在对输入按结构、JSON 转义和 UTF-8 长度分段计数，超限直接结束该订阅。复核用 510 组嵌套及 Unicode 样本对照标准编码，逐个检查实际边界可发送以及少一字节时拒绝。
- 演练脚本在仓库根及 backend 目录外检查时，Ruff 对测试帮助模块的分类会随工作目录改变。脚本现为测试帮助模块显式分组，两个目录下的检查均通过。

## 独立检查命令

在仓库根运行 `backend/.venv/bin/ruff check backend`、`backend/.venv/bin/ruff check --config backend/pyproject.toml .trellis/tasks/archive/2026-11/11-20-mp-peer-channel-stream/research/process_stream.py` 和 `git diff --check`，均通过。在 `frontend` 运行 `./node_modules/.bin/tsc -b --pretty false`，退出码为 0。后端没有单独配置静态类型检查器。

独立通过两个实际 HTTP 端口比较作者和协作者收到的正文。模型输出包含一条有权查看的相关任务效果，来源中附有内部身份证据。两端收到相同的公开 JSON，均保留该效果并移除证据。两项通过，耗时 5.78 秒。针对编码边界和整包分配的两项协议用例另行通过，耗时 0.08 秒。

核对最终 JUnit 及 pytest 汇总，SQLite 的 C4 串行组 110 项通过，PostgreSQL 16 配置的串行组 121 项通过。两组均含上述协议用例、作者删除作品时的令牌正反对照，以及实时私人引用与阶段读取的回归。SQLite 全套的其他分组和最终各门禁计数见[总验收记录](verification.md)。
