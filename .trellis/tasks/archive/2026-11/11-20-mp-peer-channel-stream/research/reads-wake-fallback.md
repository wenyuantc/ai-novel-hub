### 两秒不是现有写入保证

`backend/app/services/task_engine/engine.py:261` 定义两秒，`_consume:1974,2057` 在收到下一条 runner 事件后才检查脏值；`hub.py:108,122,140` 的文本、reset 和进度都会变脏。因此在一个 delta 后让模型停顿十秒，普通 B 读接口可能十秒都读不到更新。只过滤残留 hub 不能满足 R6。

计划把既有输出快照写改为按截止时间合并脏变更，保留原持久行、正常运行时每个节流窗口至多一次合并写，转发订阅数量和帧数不增加数据库事件写入。在无后续事件时也能交付尾部脏变更。每轮独立，只有一个刷写任务，顺序处理变化、reset、取消及终态。`engine.py:2065` 的 `_flush` 在根事务核验 handler、执行归属、原输入和断点；批量 `handlers/batch.py:221` 验证当前 attempt / verified_text，runner 可在两次产出之间推进 cursor。定时器不得拿旧文本配新 job 或跨执行轮次写回。需要串行化有效快照和 handler 状态检查，作废已过期的待写项；关闭、取消、重新领取以及收据未知都须排空计时器。在旧 `_flush` 的入口即清 dirty，遇到存储错误可能清零或抛错，新的定时路径也必须保留身份失败处理与新脏值，不能吞错或用旧进度覆终态。

AC5 用正常可写数据库测试一条 delta 后静默超过节流间隔，断言文字、合法阶段和进度在下一次 HTTP 读取一致。另测大量增量、同一窗口无变化、批量 reset 和终态与迟到刷写竞态，核对写次数及最终行。DB 不可用、等待真正业务锁期间无法承诺严格的墙钟新鲜度。已有 `backend/tests/test_batch_stream_progress.py:32`、`test_chapter_stream_performance.py:241` 可防止绕开批量检查和变相逐片段落库。

## 降级和轮次

1. 订阅最初绑定 UUID、用户和令牌版本、作品、queued_at 与成员原授权。每次轮询用新短会话重读；复用 `backend/app/services/task_engine/engine.py:3536` 的绑定判断、可见性以及第 3637 行开始的作品投影和最终核对。已删除、撤权、改密或旧轮只以已有受控形式结束。`resume_task` 原地保留整数 ID 与 UUID，却会更新 queued_at（`task_service.py:702,742`）；旧订阅不可默默追入下一轮。retry 则新建任务。
2. 排队时还没有执行者，保留合法首帧、真实数据库队列位置。领取事务提交后重新定位到取得任务的 worker，然后在该 worker 的 hub 上取得快照并同步登记订阅（`task_engine/hub.py:86`）。已经在 B 等待的订阅需要专门的交接证明：单靠 B 按秒重查后重新挂 hub，无法补回在此期间已经发出的 chapter_start、tool_start、proposal 等瞬态事件。实施设计需提供可测试的连续交接，例如对等端在执行前接收已有订阅并确认就绪，或在对应轮次为交接提供有界、保留来源的序列，按可验证游标恢复；可用性失败按 R5 降级，禁止用旧事件制造“完整”序列。正常单进程、已在 A 正常订阅的事件序列沿用现有管线。
3. 作者在执行进程不可达或转发中断时，用数据库已发布文本、阶段和进度发覆盖式 snapshot，实时监听器与 DB 值不可混合拼接。切换只在同一轮内，已发正文可能快于最后一份数据库快照。识别得出的旧快照可等它追平；批量 reset 或游标已换时允许权威快照替换，不能把字符串长度当作先后依据。双端测试既包含静默中断又包含合法清空。缺失的瞬态工具/章节事件无法从任务行重建。
4. 每次轮询先分类，再分别处理活动、暂停和终态。paused 是本次流结束但可继续的状态（`models/entities.py:87`）。已结束或暂停沿用 `stream_evidence.persisted_replay_events:293` 和投影，通过已有语义发 snapshot 后恰好一个 done / paused / error，保留成功但未发布的受限收据。已强杀的进程由原租约和 C3 收据接管流程判断后果，`engine.py:676,752` 可判成已完成、暂停、中断、取消或待核对。AC4 的 interrupted 演练使用没有已提交完成收据且可证明中断的样例；另测真实成功和不确定记录。对于有持久证据的“结果待核对”沿用第 1876 行固定错误并关闭本次输出流，任务行保留原状态，禁止伪造中断。网络不可达本身也不能证明任务已经中断。
5. 协作者的运行中文本虽已刷库，也缺少原活跃帧的发布证据；`stream_evidence.py:399` 的已结束回放只接受终态/paused。不能证明的运行中降级走既有的受控错误，最后写出前重新核验授权；完全具备持久回放证明时才发给协作者。队列快照走已有独立受控证明，不能类推为任意运行中文本。前端 `frontend/src/api/tasks.ts:358,392,429,485,509` 只有首次 permission_denied 会复查详情并重订阅一次，403/404 或第二次拒绝即结束。网络故障另有最多八次退避；稳定连接才会重置计数。前端 `frontend/src/hooks/useTaskStream.ts:81` 的 snapshot 替换、delta 追加、reset 清空都应在浏览器或现有客户端夹具实际验证。

## 跨进程唤醒和失联上界

| 待观察状态 | 发送点与接收动作 | 通道不可达时 |
| --- | --- | --- |
| 新建、重试、继续 | 正常受理或外层事务确认后触发本机调度，并向可执行 peer 发送队列变化提示；接收端只调用现有本机唤醒。普通入口见 `task_service.py:652,669,737`，智能体外层事务有 `agent/tools/tasks.py:166,518` 的 DeferredEngine。成功前的 savepoint、审批预览不能广播。 | `engine.py:921` 每五秒按绝对期限扫描。AC6 让 B 仅受理、A 有空闲槽，观察 A 的真实领取；队列受并发限额或串行键限制时按已有调度语义处理。 |
| 本人与管理员取消 | 本人原意图提交后 `owner_cancellation.py:111,149`；管理员在审计提交后 `admin_task_service.py:253`。接收端查自己的执行键和主库的原请求，再调用原 C3 扫描和收尾；禁止由消息直接取消。 | 定时调度已运行本人及管理员扫描；接管或实际外部收尾用独立期限。原 C3 的取消接口等待预算仍为十秒，一秒检查的是执行端接到信号/开始处理，不能将已取得结果的执行强行判作 cancelled。 |
| 成员变更 | `collaboration_service.py:115,146,154,175` 会在提交后、或连接已释放但结果未知时只发复查信号。接收端以项目和目标成员唤醒本地订阅，检查本地 running 及相应 paused 行，全部复用 `engine.py:3443,3469`。包括仅受理 HTTP 而仍持有订阅的进程。 | 目前全量 paused 复核默认十五秒，运行体无通知仅在下个受控发送/写检查点拒绝，订阅心跳十五秒。要通过“一个调度轮询周期”，需独立于新 token 到来的有界复查：每个调度周期检查本地实际活动且受成员授权约束的执行体和订阅，并让 paused 筛查在同一周期受理。利用批量预筛/既有锁内终核，避免为每个轮询都争写锁；接收 HTTP 的服务不能只依赖已经停止的 scheduler 触发订阅检查。没有授权则任何后续内容帧都须立即受控拒绝，和主动发现失效的时限分开测试。 |
| 系统设置保存 | `system_settings_service.py:67,90,110,218` 在产生有效持久版本后发布；同一发布函数也被初次 load、定时 reload 和故障恢复使用。仅在已确认本地写入（或仅要求重新读库的失联提示）安排一次对等刷新；接收端唤醒**独立**管理器，在锁内读主库当前版本并刷新本机消费者。 | 现有管理器独立轮询，默认与调度周期相同，调度器停止依然工作。接收端不得将收到的配置值直接盖本地，也不能在每次 `_publish` 后再向所有人广播。验证 A 在无业务流量时更新设置、旧消息迟到不回滚、短暂断线后回到库中版本。 |

每种通知是可丢、可重复的提示。用有界任务及合并键（例如队列、设置、项目成员）避免阻塞业务请求；收包端只触发本地动作，不从心跳、轮询或内部消息再扩散。成员键太多时退到一次有界全量复核，保证不会静默丢掉某个撤权信号的最终效果。数据库未成功提交或业务回滚时，“被唤醒”本身不能改变持久状态。

AC6 在正常可达的本机双应用中，从**可核实的业务提交**计单调时钟，一秒内观察执行侧的领取、真实取消信号、成员复核和已发布设置；再断通道，变更安排在刚结束的一轮轮询之后，无网络时最迟下一轮开始实际处理。以显式测试屏障记录入队/领取、复查、状态写入或设置发布，另给数据库事务/排队结束明确独立的等待预算，避免用固定 sleep 制造通过。监控两程请求数和日志，重复、延迟、回环、超时均不改变最终事实。覆盖现有 `test_system_settings_cross_process.py`、`test_system_settings_publication_races.py`、`test_c3_owner_cancellation.py`、`test_c3_admin_cancellation.py`，并加真正无模型输出的协作撤权样例。
