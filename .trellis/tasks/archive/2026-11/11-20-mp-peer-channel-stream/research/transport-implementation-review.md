# C4 内部传输与资源回收复核

2026-11-24。范围为监听和两份 worker 登记、内部订阅与提醒、帧确认、异常停机和套接字归属。

## 代码与回归

| 场景 | 实际观察 |
| --- | --- |
| 两份租约和代次 | 每个应用的 lifespan 先绑定监听。调度和 HTTP worker 各登记自己的 UUID 和同一实际地址。停止调度后旧调度目标失效，HTTP worker 仍能接收提醒。随后启动的调度 worker 使用新 UUID。 |
| 回滚与清理 | 关闭监听使新接入立即失败，关闭已接入的 writer 和正在使用的出站连接，等原握手截止后回收握手中的连接，再撤下本监听当前两份登记的地址。任务归属、执行键及业务结果沿用原有逻辑。正常关闭只移除记录的原 socket。 |
| 接入容量 | 把容量降到一条，保持一份已认证订阅。额外出站调用失败，额外 TCP 接入读到 EOF。客户端断开后，来源端阻塞的订阅协程退出，连接名额可重新使用。 |
| 连续大帧及确认 | 两个独立应用各自监听真实 TCP，公开端口使用生产 SSE 路由。SQLite WAL、协作者、私有发送缓冲设为 8192 字节时，两条各约 192 KiB 的正文增量均超过实际内核发送缓冲。阻塞第一条公开 ASGI 写出期间，来源端只发送了第一条。放行后两条内容完整、顺序相同，响应以单个 done 收尾。 |
| 断线和字节上限 | 缩短帧级期限后，接收端读到一条快照但未确认，来源订阅在有界期限内退出；超过编码字节上限的快照只导致本次连接关闭。分四段间隔约 70 毫秒送入头和签名时，250 毫秒绝对截止仍会结束读操作。 |
| 唤醒及回退 | 在线和断开两组分别验证领任务、用户及管理员取消、成员变更和设置刷新。双应用的运行和调度状态各自独立。 |

评审发现并由传输代码负责人修复了两个退出边界。接入协程还没执行的瞬间，取消它无法运行内部清理，因此监听现在从接入时同步持有 writer，关闭时主动释放。写入套接字归属文件遇到中断时，可以留下半份记录，现在通过创建时取得的设备号和 inode 核对、删除半写记录。对应回归分别观察真实 socketpair 的 EOF，以及旧文件被替换后新文件内容仍在。维护者一并串行化监听启停，在退出时等待握手完成清理。

公开路由也通过真实 HTTP 访问，OpenAPI 可读，内部订阅路径返回 404。完整公开契约以及多进程任务数据由[总验收记录](verification.md)与[双进程记录](process-verification.md)另行对照。

## 强杀后的实际文件回收

在一次性 SQLite 库中用 `research/process_stream.py` 的 `environment` 启动两个独立 Uvicorn。分别从数据库核对两份活动登记的 PID 和 UDS 地址，并从文件系统记录 socket 和归属文件各自的 inode。给本次启动的进程 17802 发送 SIGKILL 后，每 200 毫秒检查数据库和两组文件。

- 30.16 秒时，数据库确认被杀进程的 HTTP、调度两份登记都已围栏。
- 60.05 秒时，存活进程的定时清理已移除旧 socket 和旧归属文件。期间持续检查进程 18100 的两份文件，其 inode 始终相同。
- 此时进程 18100 的两份登记仍活动，公开 `/healthz` 返回 200。正常关闭它后，它自己的 socket 和归属文件也均已移除。
