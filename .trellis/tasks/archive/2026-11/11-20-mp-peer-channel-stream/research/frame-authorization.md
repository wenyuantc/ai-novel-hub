# C4 研究：跨进程订阅的逐帧授权

日期为 2026-11-24。范围为当前仓库的任务 SSE、公用投影、授权写入口和回归用例。研究问题是如何让执行进程 A 证明来源，让接入进程 B 在写给原读者时仍能阻止失权内容。以下双进程行为属于待实现、待验收的设计。

## 当前证据

- 公共入口冻结 `_StreamBinding`，其中包含原账号与令牌版本、Task 数字 ID 和 UUID、作品与作者、上次删除时间、入队时间、任务邀请轮次、读者邀请轮次、是否要求活动编辑权。成员包含同时具有管理员角色的协作者。作者与协作者在此分流。见 `backend/app/api/v1/tasks.py:62`、`backend/app/services/task_engine/stream_lease.py:144`。
- 来源属于 A 本机。领取、发布、帧、终态收据均通过对象身份及弱登记表验证，发布时还绑定原执行及确切 hub。合法帧的摘要覆盖事件名和投影后的数据。见 `backend/app/services/task_engine/stream_evidence.py:128`、`:161`、`:257`、`:279`、`:718`。guarded 队列在发布时复制数据并绑定来源，快照与注册同步完成，队列上限 1000 项。见 `backend/app/services/task_engine/hub.py:13`、`:86`。
- 任务协作者最后的生产发送入口为 `_TaskFrameGuardedResponse._send_frame`，在当前协程登记同一物理根事务，锁内先核来源和载荷，在 `await send` 前后核验事务身份和载荷完整性。失去授权可发送固定空任务错误。已进入实际发送时中断或超时即关闭，不能再发送可能重复的帧。见 `backend/app/services/task_engine/stream_lease.py:102`、`:349`、`:401`、`:445`。对端慢读与网络缓冲不能证明客户端已经渲染字节，仓库的可验证边界是服务端实际 ASGI 发送和撤权提交的先后顺序。
- 基础锁顺序为原账号、作品可见性门禁及作品行、按用户 ID 排序的模型配置选择门禁、原 Task 行；随后核成员 invitation/revision、活动 editor 和当前作者模型授权。PostgreSQL 的账号、作品及任务用共享行锁，项目策略与配置选择还使用事务级 advisory 锁。正规成员写入口取作品写门禁。SQLite 回滚日志下真实 BEGIN 加读页取得 SHARED 锁，让写事务的提交等到本帧完成；WAL 下走现有写屏障。见 `backend/app/services/task_engine/stream_lease.py:196`、`backend/app/services/authorization_service.py:260`、`backend/app/services/ai_dispatch.py:338`、`backend/app/services/ai_config_service.py:44`、`backend/app/services/collaboration_service.py:205`。当前成员查询本身没有显式共享行锁；双进程路径若允许直接 SQL 更新成员字段与实际发送竞态，应在读者这一步共享锁定该成员行，并在 PG 测试证明该写入的提交顺序。
- 除成员状态外，活动帧还需核可见性戳、场景与章节占用、任务原执行、当前模型与共享向量绑定、实体或向导续写来源、智能体会话与提案身份。终态另核逐字相同的 Task 视图、原输入和收据。见 `backend/app/services/collaboration_ai_guard.py:739`、`:799`、`backend/app/services/task_engine/stream_evidence.py:227`、`:344`、`:799`。单纯用“B 的订阅仍可见”无法覆盖 A 验完后才发生的模型轮换、可见性收紧或提案变更。

## 两跳如何复核同一帧

1. B 在公共入口取得原绑定，在受鉴权的内部订阅中绑定 A、B 的 worker 实例、本次随机订阅标识、原绑定摘要、任务与执行轮次。A 在库内验证它确实是该执行者，按原读者投影并选择既有受控来源。A 的原生核验只在本地登记真实的领用、发布、后继或终态证据；远端传入的字段不能登记为这些对象。
2. 在 A 原验证通过的具体分支，生成**只读、按分支区分的帧前提**。协议版本、发送及接收 worker、订阅、严格递增序号、原绑定摘要、任务与原执行身份、事件名、准确的载荷摘要及前提一起认证。用于 UI 的只传原公开数据。前提使用固定字段、受限长度和枚举，绑定不许省略的部分由事件、任务类型和分支决定。只传身份、代次、模型配置实例和指纹、规范化摘要及分支所需的有限选择字段。私钥、模型密钥、provider、数据库会话、可执行对象及完整内部任务输入均留在本进程。现有模型身份字段可见 `backend/app/services/project_ai_config.py:53`；原执行可比较字段见 `backend/app/services/task_engine/execution_identity.py:55`、`:128`。
3. B 的专用发送入口只接受已验签、与待发订阅和序号匹配的这种帧，再持本地原绑定的真实发送租约，将选定的只读前提与当前库中事实逐项比较，完成校验后持锁到公共 ASGI send 返回。同一组类型化读校验供 A、B 共用；A 额外执行弱表登记、hub、同执行及后继来源判定。B 从本地可信库行读取原始输入、配置等数据，用固化键和规范化摘要核对后调用现有只读查询。帧描述无权描述 SQL、决定跳过何种检查、构造 SendGuard、执行外部调用或授予写权限。未知版本、形状、缺字段、错类型、来源与当前状态不相容均关闭。

| A 已证明的分支 | B 对当前库的复核 |
| --- | --- |
| 排队、刚领取的空正文帧 | 复用原受限事件形状、原队列及入队轮次和锁内投影比较。排队转领取时只允许现有的空正文过渡。领取帧携原执行和领取事实。见 `stream_evidence.py:589`、`:649`、`:678`。 |
| 活动执行发布 | 核本执行 worker、执行键、UUID、入队时间、步骤与输入/断点身份，以及 A 选定的可见性、模型配置实例/指纹、共享向量选择、章节占用、场景与实体或续写来源。智能体按事件重查原会话、邀请与 epoch，对 proposal/executed 再核 change_key 和所属 Task。字段覆盖以 `SendGuard.require_task_read` 每个适用的读检查为清单，测试逐项改变。 |
| 批量与智能体同执行后继、向导自身保存 | A 依据原帧和同 hub 已登记的后继选取具体有效来源，携原、后继执行身份、原帧投影戳、选定收据摘要及适用状态。B 核持锁行精确匹配选定的后继步骤/输入/断点，执行与原轮次相同，并执行选定来源的当下模型、读者、会话等读检查。向导另核原未决与完成收据、构建戳/保存事务读到的新戳、当前仍是该新戳，续写使用原构建 epoch；只对原验证器准许的向导种类启用。见 `stream_evidence.py:446`、`:814` 及 `collaboration_ai_guard.py:541`。 |
| 正常执行终态与持久回放 | 前者核原执行、A 的已登记终态、原执行允许的输入转换和当前 Task 视图摘要，沿用终态读校验。已结束或 paused 的库内回放直接在 B 按锁定行重新生成投影并核原订阅身份，富文档审核仍联查有效提案。执行键或 worker 清空是合法终态，必须用原轮次与终态视图证明承接关系。两者共用当前成员/账号复核。见 `stream_evidence.py:257`、`:365`、`:399`、`:841`。 |

4. 两跳顺序持锁。A 在该帧有界的内部写入时完成核验，写入后立即归还本地租约；B 等到完整且已认证的帧，单独取本地租约。A 不能在锁内等 B 的 ACK 或浏览器。B 不能持数据库锁等 A 的下一帧、后继或收据。否则 WAL 下双方会争同一写锁。即使业务不依赖 WAL，代码也不应把这当成两端握手的前提。
5. 正常的批量步骤推进、向导保存或从运行转终态，可能发生在 A 签发与 B 复核之间。若此时**仅**原执行合法推进且原帧的来源需要重新确认，B 先退出整个租约，再以同订阅、同序号、同载荷摘要向 A 要求重核同一帧；A 限量保留这一个待确认原帧及其来源，在原超时预算内用原验证器解析已发布后继或终态后重新认证。此交互的等待全部在锁外，重复确认不会重复公开发送。任何授权、可见性或身份明确失效均直接拒绝；禁止用任一端重读的最新行给旧正文补发证明。重核超时通过既有断流/拒绝路径结束。未改变的帧应一次通过，合法推进的受控帧也须有成功用例。

## 降级与背压

- 协作者正在运行时，`Task.output_text` 没有活动来源。持久回放验证器只接收 finished/paused，排队行快照另有专门分支。A 不可达且任务仍运行时，B 输出已有固定 `permission_denied` 并关闭。若任务已结束或 paused，可在 B 以原绑定调用完整回放。收据受限成功保持 `done`、`unpublished: true`、`result: null`，已取消或中断用库中终态映射。前端已有先核同一任务详情、最多一次授权错误重连的语义。见 `stream_evidence.py:293`、`:399`、`:752`、`frontend/src/api/tasks.ts:392`、`:503`。
- 作者运行中降级采用相同读者、任务 UUID 和入队轮次做周期性可见性与投影复查，快照替换旧文本，检测 finished/paused 后用公共持久回放映射及时结束。作者正常与协作者特例保持现有知识库与拆书开放范围。
- A 复用 hub 的有界队列并限制待确认帧和连接数，B 限制读取与解析缓冲。传输按既有帧的合法大小处理大快照，可分块并在完整、验签后发布。A 的内部写、B 的外部写各有时限，持锁期间只等待自己这一跳的写。断开、超时、积压溢出时释放订阅与连接。B 已开始写同一帧时发生异常，直接断开，避免补发半帧。见 `stream_lease.py:401`、`:434`、`hub.py:95`。

## 可执行验收

- A 已输出带唯一标记的正文，B 在持本地租约前静止。用公开入口撤权/改为查看者/关闭作者模型授权/改密/停用/撤权后重邀，等事务提交再放行。通过实际 TCP 收集 B 完整的 SSE，确认零标记正文且仅有既有拒绝；加入静默变更以排除靠通知碰巧通过。反向用屏障暂停 B 的真实 ASGI send，验证正式撤权提交要等这帧完成，随后帧均被拒。SQLite 文件与 PostgreSQL 16 各自使用独立连接；再以 SQLite WAL 验证双跳能成功且取消慢连接可释放锁。
- 在同一位置单独改变作品可见性、轮换模型实例或配置指纹、变更智能体提案、丢弃富文档审核，证明即使读者仍是 editor，旧内容也不会发出。对照用例保留原授权、保持原内容，逐帧收到正文与结构化事件。在 A 核验到 B 写之间推动合法批量后继、向导自身保存与正常收尾，逐帧核无重复或漏发；切换到新执行或由第三人收紧可见性则拒绝。
- 在 B 提交输入前切断 A→B，运行中协作者的库内非空正文绝不出现。完成后验证 paused、成功、未发布收据、取消、中断与既有回放一致。作者断线后应看到可见的最后快照及恰好一个正确终止事件。构造重复序号、串订阅、错读者或错执行的测试数据，B 不向公共客户端传出内容。
- 现有基线见 `backend/tests/test_task_sse_frame_guard.py:149`、`:235`、`:277`，`backend/tests/test_collaboration_stream_running_e5c1.py:377`，`backend/tests/test_collaboration_stream_agent.py:316`，`backend/tests/test_collaboration_stream_replay_e5b.py:136`、`:244`。规范见 `.trellis/spec/backend/error-handling.md`「后台任务与 SSE 契约」、`.trellis/spec/backend/database-guidelines.md` 和 `.trellis/spec/frontend/hook-guidelines.md`。

本篇为源码研究，未运行双进程测试。实现验收还需核对所有开放种类的本地/远端读谓词对等、前提限额适配合法快照，以及真实两种数据库的锁序和超时。
