# 技术设计

## 数据与生命周期

作品导航新增「连载与存稿」。沿用章节编辑器保存草稿、场景聚合和生成状态的入口。工作台管理下表的数据，只有作者明确操作时才写入。

| 数据 | 归属与约束 |
| --- | --- |
| 连载目标 | 每个作品至多一条，每日目标为正整章或空。首次访问按空目标读取，无需写库。 |
| 章节编辑与排期 | 一个作品内的现存章至多一条工作台条目，保存编辑状态、可空计划日期、并发修订号。无条目的章节显示待修订。条目有自有主键，并保存作品归属。 |
| 定稿 | 在条目下按次创建不可变版本，保存序号、确认时间、章号、标题、原始正文、读者可见的排版与内容指纹。条目为“定稿”时，最新确认版本即当前待发版本。登记发布、普通保存或清理普通版本都不能修改定稿。 |
| 发布记录 | 每次一条，绑定具体定稿并保存渠道、实际发布时间、登记时间及操作重试依据。相同定稿可以被多个平台记录复用，后续重新定稿不会改变旧记录。 |

只在定稿条目上统计未发存稿。主动将编辑状态从定稿退回待校对或待修订时，提示此次操作会撤下待发稿。普通保存草稿不触发状态变更。有过发布记录的章持续显示“已发布”，并可同时显示“草稿有修改”。后续确认修订版只改变下次默认稿件。

工作台条目使用可空的章节引用。删章时保留已发布条目和所引用的定稿，历史列表沿用原章号和标题，标明源章节已删除，此时仍可读原稿和导出。移除无发布历史的孤立条目及排期，存稿和待发列表只连现存章。旧章号或整数 ID 被重新使用时不会承接原记录。作品进入回收站后服从既有可见性，永久删除作品时随之删除连载数据。按仓内章节删除关联检查验证普通删除、批量重建和协作路径。

历史记录按工作台条目 ID 识别同一章。源章删除后依然能按章汇总历史首发，详情隐藏依赖当前草稿的对比操作。

## 定稿、比对与登记

1. 确认定稿前展示将要冻结的已保存章号、章标题和正文。空白正文或生成中尚未稳定的草稿不能定稿。来自章节编辑器的入口先处理未保存／冲突状态，不把仅在浏览器里的修改写进发布历史。
2. 在同一写事务里复核作品权限、章身份、草稿基线与条目修订号。从章节及权威场景取一致的阅读投影。复用现有阅读／导出投影，保留标题、原文换行和排版，排除作者笔记、私有标记与规划。过期预览返回 409 并提示刷新。
3. “草稿有修改”按读者实际可见的标题、章号、正文和排版比较。修订号用于判断并发冲突。仅修改作者备注时不应提示正文变了。列表不逐章加载全部正文。需要完整核对时在章节详情计算。文本差异复用已有 TextDiff，纯排版变化单列提示。
4. 发布表单默认最近一次有效定稿，明确显示稿次、章名及预览，可为已发布过的稿次补录其他平台。提交指定定稿 ID、预览时的条目修订号、非空渠道、带时区的实际时间和稳定请求 ID。实际发布时间可补录过去。未来日期走排期。确认后在同一事务写入记录。
5. 按作品、操作者和请求 ID 识别重试，附请求内容指纹。重放前仍核验访问权限。同参数返回原记录，异参数报 409。并发的两个渠道各保留其记录。发布记录追加不占用草稿修订号，也不相互覆盖。同时重定稿与发布必须有明确先后或返回冲突。预览了 A 的操作绝不能悄悄发布 B。

确认新定稿要核验当前草稿。登记已经冻结的 A 只依赖该定稿、工作台条目与实际权限。后台正在生成草稿 B 时，A 仍可登记发布。读写并发由数据库事务和条件写入保证，覆盖 SQLite 与 PostgreSQL。

## 日历与存稿口径

- 库存用“现存章且有有效定稿且无发布记录”查询得出。日更目标为正时，用整数商和余数展示支撑天数和余章。目标未设则显示引导设置，库存为零时显示零。
- 首版按北京时间归日，日历与登记表单都标出时区。计划日存日期，实际发布时间存 UTC，查询按业务日换算半开区间。例如北京时间零点之后的记录归入新一天。
- 按月列出计划章数和实际首发章数，选中某天可查看章节。实际首发取每章所有平台记录中最早的实际发布时间，再按天汇总。事后补登更早的时间会迁移该章首发所属日。计划日仍可对照实际首发日。日更目标表示当前节奏，用于首页库存折算。日历过往实际数量取真实记录。
- 响应只带摘要、状态与计数，正文按所选条目／记录请求。列表按作品过滤、排序稳定、分批或分页。为计划日期、定稿归属与首发时间查询建立相应索引。月界和跨页列表不得改变全作品的统计结果。

## 接口与界面

使用作品下的 `/api/v1/projects/{pid}/serialization` 路由组。所有资源 ID 都在该作品内解析。实施时让前后端字段统一，保留以下操作契约。

| 操作 | 输入和输出 |
| --- | --- |
| 概览、月历、章节列表 | 月份、日期或筛选与分页。返回日更目标、全书库存、按天的计划和首发数，以及章节摘要。 |
| 设目标、调编辑状态、改期 | 按作品或章提交目标／状态／计划日及预期修订号。支持清除目标、取消排期。 |
| 确认定稿、登记预览 | 使用章 ID、草稿版本和条目基线校验。确认成功返回冻结的版本标识。登记预览提供所选稿次以及草稿差异提示。 |
| 登记／查看发布 | 登记返回稳定记录标识。历史可按平台查看、按实际时间排序。详情返回对应稿次原文。比较接口或同一详情所需数据必须保证章、作品与记录匹配。 |
| 导出记录 | 以发布记录 ID 取不可变投影，复用 TXT、Markdown、DOCX 渲染与下载权限复核，文件名含章名与可辨识的发布记录信息。 |

前端在作品页提供日更目标、库存与完整天数、月历、待发章节。在章详情提供定稿、预览和登记入口，历史记录可读、可比、可下载。窄屏用当天清单保留同样的操作。切换作品、章节或账号时取消旧请求，防止旧正文、旧权限或旧下载结果显示在新页面。现有 `content.read` 用于浏览，`content.edit` 用于状态、排期与手动登记，下载单独要求 `export`。管理员人工编辑沿用现有审计。

## 迁移、备份与回退

- 创建独立连载表。升级旧库后目标为空，章节均无人工定稿与发布历史。迁移编号从实际 Alembic 头顺延。
- 更新单书导入导出版本、注册表和重映射，恢复作品、条目、定稿和发布记录之间的归属。导入旧备份时初始化为空。校验跨作品引用、缺失定稿、孤立历史条目及恶意混入的作者材料。源实例的操作者重试标识不作为新实例的写凭据。
- 优先通过回退应用版本并保留新增表来回退功能。仅空连载表允许直接降级。已有历史时提示先备份，避免回滚抹掉发布原稿。
- 来源依据见 [共用排期](research/shared-schedule.md) 和 [定稿依据](research/editorial-baseline.md)。
