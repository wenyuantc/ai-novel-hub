# 协作批注技术设计

## 现有接入点

| 位置 | 设计依据 |
| --- | --- |
| `backend/app/services/project_access.py` | `access_for` 分开计算作品成员身份和后台管理能力。`resolve_access(for_update=True)` 在写锁内重读当前成员。批注动作据此检查作者或已接受的本书成员。 |
| `frontend/src/components/scenes/SceneWritingPanel.tsx` | 章节工作台已有可选择文字的只读富文本编辑器，以及文档无法展示时的只读文本框。批注操作单独判断权限。 |
| `frontend/src/components/scenes/richTextExtensions.ts` | `editorCodePointSelection` 校验正文作用域并拒绝穿过作者区块；反向定位已有 `selectEditorCodePoints`。 |
| `.trellis/spec/backend/scenes.md`、`.trellis/spec/backend/rich-documents.md` | `Scene.content` 是正式正文，章节正文是有序拼接的投影。正文位置采用 Unicode 码点，场景有稳定身份和退场、移动规则。 |
| `backend/app/services/project_transfer/registry.py` | 单书备份逐表登记。讨论和留言登记为必含的作品资料，协作授权沿用 `NOT_EXPORTED` 规则。 |

## 写入与读取

拟新增讨论和留言两张表。讨论保存本书、来源章景、原始选区、有限长度的原句摘录、选区指纹、用于核对的版本、当前位置状态和处理状态。首条意见和回复均为纯文本留言，发表时由服务端生成展示署名，账号引用可空。成员撤权保留原有意见，账号删除后按匿名署名展示及导出。回复有稳定顺序，即使两条的时间相同也能还原先后。作品彻删清理批注。

以作品和章节为列表范围，提供新建讨论、读取回复、追加回复和作者标记处理操作。每次请求都核对作品、章节、场景和讨论归属。写操作在同一事务内复核授权及所需版本。创建讨论与首条留言共同提交，作者处理采用幂等更新；发言使用客户端操作标识，在目标和发言人范围内防止网络重试产生重复留言。用户提交的空白或超长留言应在落库前拒绝。列表和长讨论按需分页。

## 原句定位

1. 在发起批注时冻结场景身份、已保存的章节内容版本、本景半开区间 `[start, end)` 及选中文字指纹。服务端对当前正式正文重算并生成摘录，拒绝越界和 CRLF 中间的端点。作者或编辑者有未保存改动时，先完成现有保存流程，再复核同一选区；查看者只需读已保存版本。
2. 将位置有效性与讨论处理状态分开。正文保存时，有可信的局部替换范围且不触及原句，可保持或平移锚点，再校验原句指纹。整景覆盖、AI 改写或历史恢复若缺少可靠映射，对受影响场景保守标记失效。相同词面和旧偏移不足以证明位置。其他场景的独立改动不使本景批注批量失效。
3. 在写入事务里同步处理受影响批注，覆盖人工保存、批量修订、AI、拆并、跨章移动和历史恢复；读取时核实当前归属与版本证据，无法确认时只返回失效状态。完整场景移章后按稳定身份随景查询；拆并或退场无法证明连续性时从来源章讨论列表回看。真实删章沿既有归属校验清理相应讨论，登记新增外键。
4. 编辑页只在当前显示稿与已验证的选区一致时跳转；用户正在改未保存稿时提示先核对稿件。正文编辑器使用现有正反向码点工具；文本框回退需验证浏览器换行规范化、UTF-16 和服务端原文的往返，不能可靠映射时仍可查看讨论。侧栏或窄屏抽屉中展示回复，关注点切换后保留刚选定的范围。

## 内容隔离与迁移

讨论由独立接口读取。普通阅读、正文历史、发布稿、可读文件渲染、全文检索和 AI 上下文继续从原有正文及其允许的资料取数。工作台只发送正文选区给已有写作助手，批注面板的选区、摘录和回复不能混入。换号、撤权或切换作品时清除旧讨论与输入框，丢弃早先异步请求的结果。

### 单书 JSON

- 两表以核心组（`TableRule.option=None`）登记，纳入备份大小估算、预览和默认导出。即使关闭章节历史等可选资料，也要带上所有讨论及完整回复。基于实施时的实际格式版本递增 `ainovel.project` 版本，同步更新 `APP_SCHEMA`。旧格式正常升级为空批注，旧格式夹带非空批注表时按版本校验拒绝。
- 导出保存讨论所属章景、原句摘录与定位证据、处理状态，以及每条留言的内容、显示署名、时间和顺序。复用作品导出的快照一致性检查，并覆盖独立于正文版本的回复、处理操作。一次成功导出须可还原到同一个时点。
- 导入在同一事务中重映射作品、章、景、讨论与回复。预览和实际导入使用相同校验，缺失父讨论或章景归属矛盾时报错。对有效位置，在导入的正文上复核范围与指纹，将定位版本绑定到新书；原本失效的批注保留原摘录和失效标记。移动过的场景沿既有移动记录确认归属。
- 跨账号导入保留备份中的展示署名，源库账号 ID 不作为目标库用户引用。同名账号、导入者都不会替代原留言人的署名。单书备份不携带成员授权，副本按新书的作者和邀请关系授权。

### 整库恢复与版本回退

SQLite 使用现有原生快照，PostgreSQL 使用现有 `pg_dump` 流程。两者随库保存讨论、留言、账号及成员关系，恢复后按备份时点的账号和权限继续审阅。用隔离目标分别验证两个数据库的恢复结果。

新增迁移从实施时实际的 Alembic head 接续，旧作品初始没有批注。回退应用时保留数据，降级迁移遇到已有讨论时拒绝有损删除。
