# 协作批注浏览器验收

2026-11-25 使用隔离的 SQLite 库、迁移 0073 → 0074、真实 FastAPI、Vite 和 Google Chrome 158.0.8127.37。作者、编辑者、查看者各自使用独立的浏览器会话。作者建立测试书后按用户名发出邀请，两个协作者分别接受。测试未连接外部服务。

| 场景 | 观察到的结果 |
| --- | --- |
| 桌面 1280×900、窄屏 375×812 | 查看者分别从章节列表的「查看」和「更多操作 → 查看」进入只读工作台。用鼠标拖选第二段里第二次出现的「石桥映月。」发批注。点击「跳到原文」后，浏览器实际选中了带有 🌙 的第二段里的同句。 |
| 回复与处理 | 编辑者刷新工作台后能看到查看者的署名与意见，能发表回复，页面上没有处理按钮。作者能读到完整讨论并标为已处理。建讨论和回复返回 201，处理返回 200。三次操作前后的正文字段、字数和章节内容版本一致。 |
| 原句失效 | 删除第二处原句且保留第一处后，刷新能看到「已处理」「原文位置已失效」、旧摘录和原有回复，跳转按钮消失。窄屏讨论抽屉实测宽 375px，桌面为 480px。 |
| 原句平移 | 作者在真实富文本编辑器的段首键入「此前，」并保存。浏览器发出的单条替换步骤为 `{start: 0, end: 0, insert: "此前，"}`。原句范围由 `[11, 16)` 平移到 `[14, 19)`，查看者刷新后仍跳到第二段里的同句。 |
| 过期选区 | 查看者打开批注输入框后，作者会话修改了该场景的正文。旧选区提交返回 409，列表为 0 条。查看者点击「重新选择原文」后再次选中第二处同句，无需重写意见即可提交，返回 201。 |
| 撤权 | 撤回查看者权限后，使用其原登录会话请求列表、发回复、标记处理，均返回 404。刷新后查看者页面不再显示批注。作者仍能读到该查看者曾发表的意见。 |
| 跨作品慢响应 | 在桌面浏览器拦住旧书两个已从服务器取回的批注列表响应，经应用侧栏和书架进入另一部空书的章节批注，再放行两个旧响应。新书继续显示「本章暂无批注」，旧书意见未出现。 |
