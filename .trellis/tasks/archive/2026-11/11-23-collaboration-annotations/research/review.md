# 跨层审查

核对了成员身份和写锁、选区创建及操作重试、富编辑器输入步骤、定位失效、单书导入导出、备份快照以及工作台异步结果的身份隔离。

- 普通 HTTP 部署的浏览器可能缺少 Web Crypto 摘要接口。批注现可提交完整原句，服务端在写锁内核对版本、场景、范围和选中文字，随后生成相同的 SHA-256。两种提交方式共享幂等记录。原句不另存进留言，也不会进入模型。
- 富编辑器提供的替换步骤在服务端验证总插入量，客户端和服务端均对可选证据设上限。缺少证据的旧请求沿既有保存流程处理。
- 单书预览对留言、历史署名及摘录检查可存储字符，拒绝 NUL 和孤立代理项，避免预览成功后在 SQLite 或 PostgreSQL 落库时出错。含失效位置的摘录同样受检。

审查时后端全库 Ruff、前端 ESLint 和 TypeScript 通过。HTTP 与原批注接口专项 4 项通过，前端选区取证专项 2 项通过，单书备份专项 3 项通过。全量回归、整库恢复和浏览器现场验收分别记录。

复核删号流程时确认，发言和删除账号都先锁定目标用户，存在性查询与匿名化更新、删除用户同属一个事务。用户没有留言时跳过空更新；有留言时保留正文，清除重试标识，署名改为「已注销用户」。跨账号导入的历史署名没有本地作者 ID，不受此次删除影响。
