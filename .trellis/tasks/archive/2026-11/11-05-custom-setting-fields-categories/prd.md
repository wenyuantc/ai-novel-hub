# 自定义设定字段与分类

## 目标

完成 `TODOS.md` 第 4 项：作者可以按设定类型配置复用字段，记录字段随章节变化，并通过标签或下拉字段规则自动组织设定。回写早期章节时使用当时有效的字段值，避免把后期阵营或关联资料提前带入 AI 上下文。

## 背景与已确认决定

- 2026-11-05：用户要求开始第 4 项，并同意创建任务进入规划。
- 用户明确选择“采用自动归类，按标签或下拉字段配置分类规则”。
- 用户对新增单行、下拉、引用字段的按章回溯要求回复“都要支持”；四类字段全部支持，静态三字段建议已被否决。
- 2026-11-05：最终摘要提交后，用户回复“开始”，批准按该完整方案实施两个顺序子任务。

## 已核实事实

- 第 1 项只交付角色和世界观的条目级最小文本字段；完整类型配置、下拉、引用及分类明确留给本任务。依据：`.trellis/tasks/archive/2026-11/11-03-setting-progressions/prd.md`。
- 现有字段通过稳定 ID 与剧情变化关联，改名不能改变历史绑定；有效变化仍引用字段时不能静默删除。依据：`backend/app/services/setting_progression_service.py:1098`、`:1143`。
- 世界观子类型固定，条目没有统一标签，角色已有定位筛选；作品标签不能替代条目标签。依据：`backend/app/schemas/story.py:7`、`:32`、`:63`、`frontend/src/utils/characterList.ts:10`。
- 现有 `career` 时间线表示角色职业挂接，`membership` 表示角色组织成员；它们不是职业和组织条目本身。依据：`backend/app/models/progressions.py`、`.trellis/spec/backend/setting-progressions.md`。
- 原多行文本字段已被章节上下文、角色卡、项目备份和智能体效果消费；兼容必须覆盖这些链路。依据：`.trellis/spec/backend/setting-progressions.md`、`.trellis/spec/backend/project-transfer.md`。
- 更多源码证据和官方参考见 `research/`；参考产品不支持的字段回溯不能作为缩减用户已确认范围的理由。

## 需求与可观察行为

| 编号 | 要求 |
| --- | --- |
| R1 | 支持多行文本、单行文本、单选下拉及单个设定条目引用，具备对应编辑和展示控件；引用可选择本作品允许类型的条目。 |
| R2 | 在作品内配置可复用字段及其适用类型，覆盖角色、世界观六个子类型、组织和职业定义；同类型条目可使用相同配置。旧条目级字段保留，不能仅因同名自动合并。 |
| R3 | 分类按标签或下拉字段规则自动收纳条目；支持多条件的“任一满足”或“全部满足”，同条目可出现在多个分类。删除分类保留条目。 |
| R4 | 保留旧字段及既有剧情变化；字段、下拉选项和引用目标改名后仍保持身份和历史关联。修改配置或删除资料不能静默清空已用值及历史。 |
| R5 | 四类字段均能设置起始值，并在已有或计划章节的章初／章末记录变化，查看当时有效值。多行文本支持追加／替换；单行、下拉和引用支持替换与显式清空。 |
| R6 | 生成、整章重写、局部改写、分析及规划显式参考使用统一的目标章节字段值；引用仅展示当时有效的目标身份，不递归加入被引用档案或自动改变选角。 |
| R7 | 完整作品备份保留字段配置、值、选项、历史、标签和分类规则并正确重映射引用；兼容旧备份与旧角色卡。新卡片明确快照与引用范围，不能按同名猜测引用或静默丢资料。 |
| R8 | 沿用项目权限、只读查看和并发版本保护；冲突不部分写入、不丢草稿；切换作品、条目、章节或权限后不显示迟到响应。 |

分类默认查看当前资料，可切换指定章节的章初／章末；下拉条件使用同一时点的有效值。条目标签和分类规则是整理元数据，本期不记录它们自身的章节变化，界面须说明这一边界。

## 跨子任务验收标准

- [x] AC1（R1、R2）：为角色配置单行“称号”、下拉“阵营”和引用“驻地”后，同类条目能填值；组织、职业及每种世界观子类型也能使用其适用字段，错误类型不能写入。
- [x] AC2（R4、R5）：原多行文本及事件原样保留，字段改名或显式关联复用配置后仍按原章节生效；不按同名擅自合并。
- [x] AC3（R1、R5、R6）：第 20 章章末修改四类字段后，第 5／20 章章初仍为旧值，第 21 章为新值；实际生成、重写及分析请求与只读预览一致。其他字段不被清空。
- [x] AC4（R3、R5）：配置“标签＝青云宗”或“阵营＝青云宗”分类后自动收纳匹配条目；下拉在第 20 章改变时，早期与后期视图成员正确不同，标签条件明确按当前整理标签计算。
- [x] AC5（R3）：任一／全部条件可分别验证，同条目可命中多类；删除分类后条目、字段值和历史保留。
- [x] AC6（R4、R7）：改名或停用选项保留历史；被字段历史引用的条目不能被旧删除、向导覆盖或智能体路径悄悄删除；完整删除作品仍能正常级联。
- [x] AC7（R7）：完整备份导入新作品后，四类起始值、章节事件、引用、规则和标签保持语义，ID 与源作品隔离；旧备份／旧卡片继续导入，新卡片缺失引用目标时明确报告处理。
- [x] AC8（R8）：跨作品／跨用户访问被拒绝；只读作者与管理员按现有权限工作；两个页面竞争保存时只有有效版本成功，失败方保留草稿；快速切换不串数据。
- [x] AC9（R5、R6）：插章、改号、删章、撤销及智能体恢复仍遵循现有章锚与事务规则，不以同号新章复活孤立事件，不覆盖作者后续修改。

## 风险与交付约束

- 类型化值会改变现有文本假定，需保留旧入口适配并统一所有消费方。
- 下拉选项、引用目标及旧字段可能只在历史中使用，删除检查不能只看当前值。
- 实现采用 Trellis 子代理；模型／迁移／公共类型与共享服务顺序修改，避免并行编辑冲突。
- 进入顺序实施：父任务负责协调，先启动字段子任务，分类保持等待前置门禁。工作区原有 `pelican-cycling.html` 与本任务无关。
