# 站内通知浏览器验收

2026-11-25 使用本机 Chrome 158，通过独立浏览器上下文登录作者和编辑者。桌面视口 1280 × 900，手机视口 375 × 812，另有无关账号验证查询隔离。前端使用 Vite，后端运行 FastAPI 和真实任务引擎，SQLite 从空库执行 Alembic 到 0073。使用本地 OpenAI 兼容流式模型替身，计费通过应用实际入账。所有场景通过业务 API 建立业务事实，无直接插入收件表。

| 场景 | 实际操作和观察 |
| --- | --- |
| A1 邀请 | 手机端收到作品与系列两条协作邀请，逐条打开后分别只显示「灯塔与海图」和「海图系列」的对应邀请。点接受并再次确认后，作品邀请从列表消失，系列邀请仍保留。作者收件箱为空。 |
| A2 任务 | 模型替身返回 400，编辑者收到一条失败通知。主动重试后新任务成功，手机仍能打开原失败任务的独立详情并看见原失败原因。 |
| A3 检查 | 编辑者重试成功产生零问题检查 #2，作者和编辑者各收一条检查通知。后续 #3 生成一条有两章证据的问题，作者仍能从旧通知打开 #2 的零问题概要。作者已读不改变编辑者未读数；关闭作者检查提醒后只有编辑者收到下一次结果；重新打开后作者亲自发起只收一条。 |
| A4 预算 | 作者授权编辑者使用作者模型；成功调用返回 100 输入、10 输出 tokens，真实计量为 CNY 1.1。账号及作品预算各为 CNY 1.0，直接跨过 80% 和 100%，作者只收到每个作用域各一条已达额度通知。分别点开跳到对应作用域的 CNY 预算卡，可见实际花费与额度；编辑者没有预算通知。 |
| A5 已读及偏好 | 手机逐条标读，未读从 2 降到 1。抽屉中的四项开关各自关闭再开启，保存后状态正确。第三人收件箱持续为空。 |
| A6 撤权 | 编辑者保持收件箱打开，由作者撤权。点击原检查条目出现失效提示，仅剩不相关的系列邀请，未读归零；原通知打开接口返回 404。作者重新邀请、编辑者重新接受后，原通知和携原通知 UUID 的原检查深链仍返回 404。 |
| A7 工作台 | 桌面和手机通过工作台铃铛打开同一收件入口。Chrome 模拟收件列表网络中断，抽屉提供「重新加载」；恢复网络并点击后重新出现真实条目。 |

Chrome 通过 CDP 设置视口、点击界面并读取可见文案。桌面检查和预算、手机邀请和失败任务的截图保存在本目录。同一目录的截图来自独立测试账号。上述结果覆盖这些具体操作。预算逐笔阈值、月界、数据库并发、回滚、历史清理、账号切换期间的迟到响应等由对应专项测试覆盖，不计入本次浏览器实测。
