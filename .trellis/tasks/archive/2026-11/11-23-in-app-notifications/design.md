# 站内通知设计

## 收件箱与读权限

每个接收人一条收件记录。建议保存通知 UUID、接收人、四类之一、稳定事件键、来源和目标引用、创建时间、已读时间。按「接收人＋事件键」唯一，按接收人和倒序时间／ID 建索引。两位接收人独立保存已读状态。通知使用固定文案，按当前权限解析可显示的名称和目标，收件表不复制正文、检查证据、原始错误、模型输出或任意跳转 URL。

个人偏好按「用户＋类型」保存，缺省为开启。同一事务检查投递资格、偏好和唯一键；重复写入保留已有的已读状态。关闭期间的事件即使后来重试也不能补发，预算档位在提醒关闭时照常推进。若需延期处理，业务事务应保存当时可投递的接收人及事件键，消费时再次核对资格。账号删除级联清理个人收件和偏好；单书导出与导入排除个人收件数据。

列表、未读数、标记已读及打开目标共用可见条件。先限定当前接收人、来源身份、目标权限和生命周期，再计数与分页。作品或系列协作通知保存接收时的邀请轮次，撤权后重新加入也无法唤回旧轮次。待处理邀请是例外入口，凭同一邀请 UUID、待处理状态和接收人本人显示；接受、拒绝、撤回或目标失效后退出收件箱。直接打开业务页面仍走原有鉴权。个人账号预算提醒仅引用本人预算，避免泄露已失去权限的作品信息。

## 事件从哪里来

| 来源与现有入口 | 提议接入方式 | 对应位置 |
| --- | --- | --- |
| 作品／系列邀请，`backend/app/services/collaboration_service.py` 的 `invite`、`list_invitations` | 在生成邀请 UUID 的业务事务写收件行，重邀有新 UUID。投递失败回滚时不留下孤立邀请提醒。原协作变更唤醒机制专供任务流复验，继续沿用。 | 书架 `/projects` 的 `Invitations` 组件增加精确定位，打开邀请不自动接受。 |
| 本人后台任务，`backend/app/services/task_statistics_service.py` 的 `record_state_change` 与 `task_service.py` 的 `finish_paused_task`、`retry_task` | 在条件更新成功的终态事务派发，盘点正常收尾、失败、手工完成、恢复和收据补偿。以稳定任务 UUID 去重，接口断线、进程重启和重复收尾使用同一身份，显式重试使用新 UUID。读取复用 `task_visible_to_actor` 和原详情投影。 | 在个人 `TaskPanel` 增加按 ID＋任务 UUID 打开指定任务的入口，可解析到当前页之外的任务。能力受限、历史已清理或数字 ID 被复用时关闭失效目标。 |
| 账号／作品预算，`backend/app/services/ai_usage_storage.py` 的 `finish_call` 与 `ai_usage_query.py` 的 `budget_progress`、`update_budget` | 从真实入账触发，复用后者已有的币种、承担人、阈值比较和月界计算。按下节策略持久化跨档事实。 | 账号 `/settings/ai-usage`，作品 `/projects/:pid/ai-usage`，定位本币种预算卡。 |
| 一致性检查，`backend/app/services/consistency/check.py`、`consistency/query.py` 和 `task_engine/handlers/consistency.py` | 运行概要落库和任务终态分开提交。在确认任务成功且找到同次成功的 `ConsistencyRun` 时生成结果通知，接收集合取发起人与当前作者并去重，两人的可见性和偏好分别判断。此类成功独占检查分类，即使关闭检查提醒也不会改发任务成功；失败按普通任务处理。 | 增加按作品＋run ID 读取概要的只读接口与深链，复用现有 `content.read` 和运行概要的安全字段。当前 `summary` 只返回最近一次；作者从作品页读指定次结果，无需访问协作者的私人任务或输出。 |

通知的生成以数据库提交为准，读列表无需连接事件源。多实例使用数据库约束和事务协调，可复用当前进程中的刷新提示作加速。遇到费用计量或终态提交确认丢失，按同一事件身份恢复，避免再次调用模型或重跑任务。

## 预算跨档

- 账号按承担人、币种、北京时间自然月分组，月份取调用开始时间。作品按作品、作者承担费用和币种累计。使用现有整数金额比较和 `normal / near / exceeded`，未知金额沿用用量页口径。
- 每个预算配置及周期保存已达到的最高档位。在已计价调用提交时串行更新相关预算状态与收件行；同时命中账号和作品时按固定顺序取得更新权，保证两笔并发入账合计越线也能提醒。直接跨两档只记录最高一档，阈值等于 100% 时同样只收一条。
- 上线及创建、实质修改预算时，用当时已入账的花费建立基线。相同配置重复保存不重新起算。降低阈值造成的历史超线不立即补发，之后进入更高档位可提醒；删除后重设是新配置。账号新月份以正常档起步，迟到结算按原调用归月。作品预算无月度切换。首次部署需区分上线前基线与上线后第一笔增量，避免把第一次真实越线吞掉。

## 接口与工作台

拟在 `/api/v1/notifications` 下提供当前用户的分页列表、轻量未读数、单条幂等已读、打开目标和偏好读写。列表返回通知 ID、类别、服务端安全文案、时间及已读状态，排序用时间＋唯一 ID 稳定翻页。打开操作再次鉴权、标记已读并返回白名单目标（邀请、个人任务、预算或检查运行）；他人通知、失效资源和不存在统一返回 404。偏好写入指定类型，避免两个标签页修改不同类型时相互覆盖。

入口放在登录后的 `AppLayout`，列表按需加载。登录、回到前台、打开入口、完成已读及发现协作权限变更时刷新；可见页面建议每 30 秒只刷新未读数，隐藏页面暂停轮询，列表展开时同步可见项。退出或换账号立即清空旧状态，以会话和请求代次丢弃迟到响应。当前页面获知撤权或目标失效时移除对应条目并重取未读数。

## 迁移与回退

实施时以集成分支实际 Alembic head 分配迁移号，并验证 SQLite 与 PostgreSQL。已有账号无需补写四份默认偏好；发布后开始接收新事件。升级先建表和预算基线，再让具备通知生产能力的实例接手业务写入，明确开始投递的时间。应用回退可停止新通知读写并保留收件数据；含真实收件、偏好或档位记录时，降级迁移须保护这些数据。
