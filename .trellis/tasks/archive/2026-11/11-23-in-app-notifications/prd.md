# TODO #27 站内通知

## 目标与范围

作者和协作者在桌面或手机工作台打开同一个收件箱，就能知道哪些事需要处理，并直接进入对应位置。首版覆盖上线后的站内事件，邮件、系统推送和管理员群发留在本期之外。

## 四种通知

| 类型 | 何时提醒 | 谁能收到、点开后看到什么 |
| --- | --- | --- |
| 协作邀请 | 新的作品或系列邀请进入待处理状态 | 被邀请人打开书架上对应的邀请，仍可按原流程接受或拒绝。发送人和其他成员不收这条提醒。 |
| 后台任务 | 本人后台任务确认成功或失败 | 任务发起人打开对应任务。失败后主动重试是另一次任务，两次结果各自可查。运行进度、待审核、取消及中断不触发此类提醒。 |
| 预算阈值 | 已入账费用首次达到当前预算的提醒比例或额度 | 账号预算通知费用承担人，作品预算通知作者。打开相应作用域和币种的预算。只预估费用时不提醒。 |
| 一致性检查结果 | 本次检查已保存结果并成功收尾，零问题也有结果 | 同时通知检查发起人和作品作者，打开本次检查概要。作者自己发起时只收一条。失败时由任务发起人接收普通失败通知。 |

## 使用规则

- 入口显示当前账号有权查看的未读数。列表按新到旧分页，打开一条可跳转并标为已读，也可单独标为已读。刷新页面、换设备后仍保留已读状态。
- 四种提醒默认开启，每个账号可以分别关闭。关闭仅影响后续投递，仍可查看有权访问的旧通知。重新开启从下一个新事件生效。关闭邀请提醒后，书架上的待处理邀请仍可操作。
- 撤销作品权限后停止投递。原提醒从该用户的新查询、未读数和跳转入口同时消失；账号切换或客户端发现权限已变时清除旧展示。重新邀请使用新轮次。
- 第一次上线从新事件开始。已有待处理邀请仍可在书架处理。原预算已达阈值时以现状为起点，下一次进入更高档位或新预算周期才提醒。

## 可观察的验收条件

| 编号 | 场景与预期 |
| --- | --- |
| A1 邀请 | 作者分别邀请乙加入一本书和一个系列。乙在接受前能从两条通知分别定位邀请，第三人看不到。作者撤回后，该条从列表及未读数消失；重新邀请只显示新轮次。 |
| A2 任务 | 在用户离线期间任务失败，用户下次登录能看到失败提醒。重试成功后可分别打开两次任务。重复处理同一次收尾仍只有一条，事务回滚时没有提醒。 |
| A3 检查 | 编辑者连续做两次检查，一次零问题、一次发现问题。编辑者和作者每次各得一条，两人都可打开第一次的概要。作者标为已读，编辑者的角标不变。作者关闭检查类提醒后，仅编辑者收到下一次结果。两人均开启时，作者自行发起只收一条，第三位成员不收。检查失败时只有发起人收到任务失败提醒。 |
| A4 预算 | 账号月预算 100 元、阈值 80%。累计依次到 79、80、85、100 元，新增提醒数依次为 0、1、0、1。一次从 79 到 105 元只提示已达额度；下个北京时间自然月重新计算。作品累计预算不随月重置，作者代付时协作者看不到作者的预算数值。 |
| A5 已读与偏好 | 两条可见未读中将一条连续标为已读两次，角标均为 1。关闭任务提醒后再完成任务，角标不变，原任务仍可查看；其他类型照常投递。 |
| A6 权限与切换 | 编辑者有一条旧的作品未读时被撤权，后续查询不返回旧条目、标题、目标或计数；直接打开旧地址也无法获取内容。撤权后完成的工作不投递。切换到另一账号后，前一账号的慢响应不能重新填入列表。 |
| A7 交付 | 在桌面与 375px 窄屏，从同一入口查看未读、定位目标、标记已读及修改四类开关。目标在列表打开后失效时，下一次操作给出通用提示并刷新列表和角标。 |
