## 跨章移动

### 预览与提交

- 在作品／源章／场景路由下增加 `POST /move-preview` 和 `POST /move`。预览传目标章稳定 ID 和 `insert_before_scene_id`，空值表示章末。后端确认两章同书、源景活动及插入点属于目标章，再用同一读快照返回两章身份、内容版本、作品规划版本、时间线影响摘要、插入顺序、正文接缝、可能的阻塞项和签名。
- 签名绑定发起者、作品、目标位置、两个章身份、场景 ID、两章内容版本、规划版本和所展示的演变锚点及相关时间线版本。预览期间有变化时请求重新加载。确认携带同一选择和签名。服务端锁内重建预览，按已知错误返回 404 或 409，需作者重新核对。
- 预览按七项展示原章和目标章的有效规划值及来源，变动项明确显示前后值。提交保留原始覆盖模式和数据，包括显式空值。目标章默认值后续变化时，继承项通过同一解析器实时取值。后端汇总受影响的场景锚点和章间位置变化，时间线完整约束在提交事务内统一重验。
- 出现书外或不可读的目标时走现有匿名错误。两章生成状态、批量任务和引用冲突给出可处理的提示。对于结果未知的请求，刷新双章位置和版本确认结果。相同旧条件无写入重放。

### 事务

1. 先获取人工编辑和 AI 可见性写屏障，锁内重验授权。沿用批量修订的模式，按章 ID 升序获取两章锁，检查生成占用、作品归属、章实例条件以及双章版本。整个数据库操作只有一个事务所有者。
2. 操作前为两章保全结构基线。在活动顺序约束内重排，新插入位置按稳定场景 ID 解析。改变原 `Scene.chapter_id`，搬运原分隔和正文片段，保留场景规划绑定。源章成为空章时显式创建一个活动空景。
3. 更新两章投影、字数及内容版本，检查新接缝合法性。跨章提交把两章新版本推进到大于两个原版本的共同值，避免旧场景条件在 SQLite 数字章 ID 删除重用后恰好重新吻合。普通单章写入继续按现有方式推进。
4. 同一事务重验故事位置、重算全部受影响事实，并推进一次规划版本。章节或活动场景集合变化即使正文相同，也可通过内容和规划版本观察。AI 上下文、旧定位及分析是否过期沿各自的版本与指纹规则重新评估。移动改变场景上下文和可用资料范围，按现有可见性写入契约推进代次。
5. 为两章各写一条带备注的结构版本，说明移出或移入及当时对应章节。在同事务登记移动记录、当时的活动规划单元和两章版本序号。审计记录关联两章。任何一步失败回滚两章、版本和归属。提交后只返回必要的章节与场景定位、内容版本和规划版本。

### 场景身份和历史归属

- 建议新增场景移动记录。每次提交登记 `scene_id`、`from_chapter_id`、`to_chapter_id`、当时的 `planning_unit_id`，首条记录标记首次移动。未移过的场景以当前归属作为首次归属。场景删除时移除记录，章删除时置空该记录的相应章引用，保留首条记录及身份凭证。同一个数字章 ID 被重新分配时，旧记录仍为空。记录两章移动产生的版本序号，历史版本被裁剪后仍能判定移入边界。独立备份省略历史版本时，移入版本边界随新书的历史起点重置，历史归属证据仍可用。
- 对现稿读写、历史恢复、AI 采纳和批量撤销，继续使用当前活动归属及各自版本。对历史的只读校验，以当前归属或实际移动记录为依据，并检查历史章、场景持有章、规划单元和类型化引用都属于同书。场景规划单元后续重关联时，备份校验也可用与该单元对应的移动记录证明历史章归属。继续核验区块／标记的持久身份。导入时对各直接 FK 及快照内部 ID 显式重映射。
- 两章普通结构历史都可查看。若单章恢复将拉回当前归属另一章的场景，或通过最近一次移入前的版本使本章的移入场景退场，返回明确的跨章恢复冲突。对仍在本章、与移动归属兼容的版本，继续核对规划代次、锚点和富文档保护。带移动记录的章节可查看旧纯文本版本，并可经现有显式提取入口选定当前目标场景。缺少场景身份的纯文本版本在该章的一键恢复需提示并阻止。
- 原章删除时，随原章清理结构快照并脱钩移动记录中的章引用。校验后脱钩以原章为历史位置的批次明细场景引用，留下原稿快照和已删除章标签。从移动记录收窄需要检查的存续章节。核对实际结构快照及其归属校验证据，若删除会使其他章的历史无法读取，提示先移出受保护场景。普通删章与细纲同步删章走同一检查。整书彻删仍按既有项目生命周期完成。
- 统一连载与搜索的章身份读取。原生场景包括未移过且在本章创建的场景，以及首条移动记录的移出章为本章的场景。章删除后，旧场景即使迁入同数字 ID 的新章，也无法充当新章的原生身份。冻结定稿继续按原章归档，确认定稿仍核验现稿版本和指纹。
- 全书修订历史保留应用时所在章节，场景已移动时其 `matches_revision` 为 false。导入仍可读取历史，整批撤销遇到章版本、身份或范围不合时走原子冲突分支。
- 备份现行作品格式为 v15，应用 schema 为 0064。跨章归属落库后需在实施时核对最新 head 并升级备份格式，提供 v15 → 新格式的兼容路径。旧备份无移动记录，校验等同迁移前。覆盖有版本历史和不含版本历史的独立导入。恢复历史所用的归属和章身份均由新书资料重建。
- 搜索和提及以实时章投影与区间映射读取。新查询跳到新章，旧指纹由现有失效路径处理。标记和场景规划用稳定 ID 查询当前位置。章级分析、自动记忆和定稿差异使用各自的现稿及指纹。位置型锚点沿新时间线重验。

## AI 拆并建议

### 请求和模型结果

- 复用任务引擎的只读草稿模式，以 [设定草稿任务](../../../../../backend/app/services/task_engine/handlers/entities.py#L40) 为参考。请求判别为 `split` 加一个场景 ID，或 `merge` 加同章原顺序的两个相邻场景 ID。发起前冻结章内容版本、规划版本和目标实际归属。沿用 AI 配额、模型绑定、出站门禁及任务属主校验。作业执行期间编辑器可继续写作。
- 服务端为拆分生成有限数量的保存稿段落候选，附短编号和对应的 Unicode 码点。重用手动拆分的合法文本边界、区块／标记映射和保留引用检查。有局部格式时仅给出可安全映射的候选。合并预检使用现有相邻性、引用和富文档检查。
- 出站素材限选中的已保存正文与候选编号。模型输入有明确预算，超限提示缩小场景，完整预览与实际发送使用同一范围与快照。原任务的发起者、作品、章、授权、模型绑定及可见性在各自的真实发送、结果发布和确认路径按现有任务门禁校验，模型请求期间释放写事务。
- 模型返回限定结构的条目 `{candidate_id, reason}`，拆分最多三条，合并最多一条，空列表有效。服务端检查编号存在、去重、类型和长度，再从原快照填充位置。无效结果以任务错误呈现。任务结果保存有界理由、目标、有效性条件和候选，作者可从任务记录重开核对。

### 应用和界面

- 采纳读取已成功的原任务及候选 ID，由服务器取已校验的操作。确认体只接受选中的建议、预览条件、作者在预览里选的标题或元数据方案。新版快照重新检查场景归属、章版本、规划、权限、占用和当前引用。
- 复用现有拆并预检和事务原语，需要时提取内部无提交的共用逻辑。单章结构原子写入，作者确认一次消耗所见内容版本，重复确认不能执行第二次。有正文更改、移动、撤权或预检变化时重新生成或明确重新选择。AI 结果与手动使用同样的历史、审计和逐字符原文断言。
- 在已有场景工具区打开 AI 建议，复用标准任务取消和结果展示。采纳沿用现有合并元数据选择。模型无建议时显示空态，预检阻塞时显示具体引用或格式。用户可在看稿、修改后再重新发起。
- 移动与采纳各用现有编辑器保存屏障。确认前重新确认场景和身份，处理 IME、冲突、本地草稿及多标签变化。成功后刷新目录、当前场景和规划，可用动作跳往目标。别页未保存草稿遇到原场景移出时保留为可查看或导出的本地记录。晚到的任务或请求结果受账号、作品、章、场景及授权代次约束。读者复用只读能力，AI 动作沿用 AI capability。

## 升级与验证重点

- 先冻结章身份、历史归属与迁移契约，再开放移动。上线前备份数据库，按现有单进程任务部署策略协调版本切换。移动后的数据通过新格式还原并保留历史归属，旧程序回退以升级前全库备份为恢复点。
- 重点验证 A → B → C、来回移动、跨章后同章重关联规划、SQLite 同数字章重建、目标章原有或历史定稿、富文档跨章备份和删章、批量修订历史、两端同时保存、同一建议重复采纳。涉及既有任务的数据必须按当前任务权限读取。
