# 场景跨章移动与 AI 拆并

## 目标

作者改稿时可以在同一本书里移动完整场景，并让 AI 帮忙判断哪里该拆场、哪两个相邻场景可以合成一场。需求来自 [TODO #24](../../../../../TODOS.md#24-场景跨章移动与-ai-拆并)。

## 背景

第 7 项已有章内排序、光标拆分、相邻合并和结构历史。场景有独立身份，七类规划项按项继承当前章节或使用本地覆盖。现有合并预览会保护无法安全处理的演变锚点、支线节点和富文档资料。 [独立场景契约](../../../../spec/backend/scenes.md)

## 首版需求

| 需求 | 作者可见行为 |
| --- | --- |
| R1 跨章移动 | 在章节编辑器的场景菜单选择同书另一章，可插到指定场景之前或章末。预览显示源章、目标章、插入接缝、规划和场景演变位置的变化。确认后打开目标位置，也可继续编辑源章。源章最后一景移出时创建一个空场景，让该章仍可编辑。 |
| R2 关联资料 | 正文、分隔、标题、作者摘要、富格式、区块、标记、场景本地覆盖和支线节点随原场景移动。继承项按目标章目前及之后更新的默认值求值，预览逐项显示有效值差异。场景锚定的设定变化保留首尾边界，在目标章重新求值。章级锚点仍属于原章节。全书搜索、提及、阅读与导出从新位置读取现稿。 |
| R3 结构历史 | 两章各有可查看和对比的移动前后结构历史。会牵涉跨章归属的单章恢复显示阻塞原因，作者可通过移动入口移回。删章会使其他存续章节的结构历史无法读取时，提示先移出相关场景。连载定稿和发布记录保留原版本，现稿与定稿产生差异时沿用草稿变更提示。 |
| R4 AI 建议 | 对当前保存场景的段落边界给出拆两景建议，或判断作者选中的同章相邻两景适不适合合并。建议显示位置与理由，允许空结果。发送范围为作者显式选择的已保存正文。 |
| R5 AI 确认 | 展示实际拆并预览，作者一次采纳一条。合并沿用原有元数据选择，拆分沿用原摘要归左等规则。拆并前后整章正文逐字符相同，引用、富文档或已有稿件无法安全映射时提示处理原因。 |
| R6 编辑权限与冲突 | 手工移动沿用现有内容编辑权限。AI 发起和采纳核验当前编辑、AI 权限及原任务执行身份。保存失败、章节生成占用、重新选章、另一处编辑、撤权或请求失败时保留草稿，过期预览须重新核对。 |

## 验收条件

- [x] AC1（R1、R2）将有正文、显式清空的视角覆盖、富格式、作者区块、标记、支线交汇和场景演变的场景移到指定目标位置。场景 ID 及资料一致。两章顺序、字数、规划矩阵、标记时间线、阅读和提及定位正确。
- [x] AC2（R1、R2）覆盖移第一景、移最后一景和移唯一场景，逐字符断言两章投影、首项分隔和 Unicode／CRLF 接缝。源章和目标章的默认值不同时，预览逐项显示差异，移动后继承目标章。再修改目标章默认值验证实时继承，以及显式覆盖和显式空值仍由场景自身决定。
- [x] AC3（R2、R3）两章历史可查看和对比，旧单章恢复与受影响的全书批量撤销安全提示。SQLite 和 PostgreSQL 验证备份预览、独立导入、二次移动以及删章时的历史保护。旧定稿和发布记录可继续查看，已更改的现稿有提示。
- [x] AC4（R4、R5）用可控模型覆盖有效拆分位置、有效相邻合并、无建议、无效候选、取消和异常。查看建议期间章稿与结构零写入，确认才产生结构版本。验证作者区块正文和无关章正文未进入模型输入。
- [x] AC5（R5、R6）拆并预览后的编辑、修改规划或跨章移动导致旧建议失效。覆盖演变锚点、独立规划、富文档边界、双确认和旧任务重开。现有手动拆并继续走相同保护。
- [x] AC6（R6）覆盖双页跨章竞争、目标删除重建、生成中／批量占用、任务撤权、未保存草稿和移动提交中途失败。失败后用独立连接验证两章正文、版本及引用均可继续使用。桌面和 375px 移动编辑页均可完成确认与定位。

## 首版边界

处理同书单场景移动和同章单次拆并。跨作品搬运、跨章合并、全书批量采纳、AI 正文改写、字符级演变锚点和双章一键撤销留作独立需求。
