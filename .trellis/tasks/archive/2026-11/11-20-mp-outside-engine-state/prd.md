# C5 引擎外进程内状态的多进程改造

父任务[总体设计第 6 节](../../../11-20-multiprocess-task-scheduling-deploy-drill/design.md#6-引擎外状态c5)和[原始调研](../../../11-20-multiprocess-task-scheduling-deploy-drill/research/in-process-state-outside-engine.md)定义了范围。基于已验收的 C4 继续，复用 C1 的执行者存活判定。具体方案和开工顺序分别见[设计](design.md)和[实施计划](implement.md)。

## 目标

让备份、灵感生成、项目导入和智能体会话在请求分到不同进程时仍得到正确结果。一个进程停止或重启时，其他进程能判断哪些工作仍在运行，哪些需要收尾。

## 需求与现状

- **R1 备份只执行一次。** 同一条排队备份由一个进程领取并执行，未领到的进程不写状态或通知。现有运行器先查排队行再改运行中，后者可能把前者的运行行改成失败并发邮件（`backend/app/services/backups/runtime.py:131-154,160-181,239-249`）。
- **R2 备份恢复尊重执行归属。** 启动与周期检查保护存活进程的备份、临时目录、GPG 目录和分片上传。已确认失联的活动备份中断并收尾。保留单进程对重启遗留活动记录的中断语义。当前启动会无条件处理全部活动行（`backups/runtime.py:97-109,514-581`）。
- **R3 计划备份受理避免误报。** 并发时只受理当天一条，竞争失败方按正常跳过。当前 `active_slot`、`scheduled_date`、`request_id` 唯一键已拦住重复记录，正常竞争仍记为错误（`backups/service.py:373-493,503-509`）。
- **R4 保护本地副本。** 下载命中别的主机且文件不可访问时，返回明确错误并保留可用记录。仅写入主机确认缺失时标记缺失。当前打开本地文件失败可能永久改变副本状态（`backups/runtime.py:488-512`，`backups/storage.py:140-160,183-197`）。C7 在 README 写入多主机须共享 `BACKUP_DIR` 的要求。
- **R5 灵感生成互斥。** 同一会话同一步骤只有一个生成者，竞争失败方收到原「正在生成」提示。并发状态修改和生成轮次均保留。当前占用存在进程内，保存时整体覆盖 JSON（`inspiration_service.py:93-95,489-499,557-559,588-604`）。
- **R6 跨进程完成项目导入。** 预览和确认可由不同进程处理。全站仍按每用户 2 份、合计 6 份、单文件 100 MiB、10 分钟及原淘汰顺序执行。当前另一个进程读不到令牌，只会返回过期（`project_transfer/importer.py:92-96,1401-1437`，`api/v1/transfer.py:61-93`）。
- **R7 智能体会话操作串行。** SQLite 和 PostgreSQL 上，同一会话的发送、确认、拒绝、撤销和删除不并发执行。外部调用提交 `executing` 再联网期间，其他进程不会重复发出或误判结果。当前主要依赖进程内锁和 PostgreSQL 事务内行锁，活动轮次的部分唯一索引不包含待审核（`agent/service.py:68,331-337,1385`，`models/entities.py:145,804-810`）。
- **R8 周期维护重复执行时结果一致。** 回收站清理、仪表盘采样和用量收尾继续使用数据库侧约束。正常并发无需发出告警或错误，实际故障仍需记录（`recycle_bin_service.py:518-579`，`admin_dashboard_service.py:216-285`，`ai_usage_recording.py:121-146`）。
- **R9 保持单进程兼容。** 保持既有公开接口、正常结果、提示文案、错误码及作品备份格式。R4 注明副本归属与文件缺失的处理规则。

## 验收标准

- [x] **AC1** 双应用测试：手动受理一次备份，两个运行器同时轮询，备份产物只有一份，记录只经历一次运行并成功，通知只发一次。（R1）
- [x] **AC2** 双应用测试：A 执行备份期间 B 启动，A 的备份成功完成，临时目录未被 B 清理。A 失联后，B 把该备份记为中断并清理临时产物。（R2）
- [x] **AC3** 两个运行器同时受理当天计划，只生成一条记录，日志没有「备份调度暂时不可用」这类错误级输出。（R3）
- [x] **AC4** 模拟副本由另一主机写入、本机无文件时下载：返回明确错误，副本记录仍为可用；写入主机上文件确实不存在时才标为缺失。（R4）
- [x] **AC5** 双应用测试：对同一灵感会话的同一步骤同时发起生成，假模型只被调用一次，另一方得到「正在生成」；两轮先后生成的结果都保留。（R5）
- [x] **AC6** 双应用测试：在 A 预览导入、在 B 确认，导入成功且结果与单进程一致；超过有效期或份数上限时的行为与单进程一致。（R6）
- [x] **AC7** 双应用测试（SQLite 与 PostgreSQL 16 各一遍）：对同一会话并发确认同一提案、并发发送与撤销，提案只执行一次，外部工具只被调用一次。（R7）
- [x] **AC8** 两个应用同时运行各周期协程一个周期，数据库结果与单进程相同，日志无新增告警或错误。（R8）
- [x] **AC9** 备份、灵感、项目迁移、智能体相关现有测试文件通过；SQLite 全量分组、失败项复跑与 `ruff` 通过。（R9）[验收记录](research/verification.md)

## 范围边界

- 多主机不共享目录时的跨实例备份下载转发。
- 周期协程的全站唯一运行。
- CPU 并发限流器的全站化。保持每进程各 2 个名额，由 C7 写入文档。
- 缩略图、审计清理预览、全书搜索的无状态令牌，以及已支持跨进程的拆书导入。
- 检索索引缓存、提及匹配缓存等已按库内签名或内容哈希失效的缓存。
