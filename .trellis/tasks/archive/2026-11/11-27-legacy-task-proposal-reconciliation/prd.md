# TODO #34 旧任务与未决提案的安全核对

## 研究目标

让维护者能够根据可核实的证据判断两件事：升级前启动的章节任务是否仍在执行，以及取消智能体任务后，原提案是否仍需人工处理。

## 已知情况

[C8 隔离演练记录](../11-20-collab-migration-deploy-drill/research/verification.md)覆盖了三个场景。

- 从 `0043` 升级前未排空任务。旧章节任务可能无法由本人或管理员安全收尾，章节仍显示生成中。
- 在旧版页面取消智能体任务后，任务已结束，原提案仍显示待确认，确认和拒绝按钮均不可用。
- 升级后取消并重新发起任务，原提案仍可能显示待确认。

这些观察限于演练中的任务类型与观察时段。现有处置以 [0043 升级与回滚步骤](../../../../../README.md#从-0043-升级作品协作) 为依据，有可用快照时优先恢复升级前快照，再分别核对任务、章节与提案。

## 研究验收标准

- [x] 对旧章节任务，列明核实原执行体、任务状态与章节状态所需的证据。给出经验证的恢复条件、操作和复核结果；证据不足时明确停止条件。不得补造原任务身份或绕过执行围栏。
- [x] 对两种提案场景，分别追踪原提案，核实原内容、处理状态及是否实际执行。安全处理须保留原内容，避免误执行或静默清除；取消、重新发起或恢复快照均不能单独证明原提案已处理。
- [x] 为每项结论记录适用版本、任务类型与验证依据，指出仍无法安全恢复的情况。

## 研究交付

真实 0043 快照已在 SQLite 和 PostgreSQL 16.15 上独立升到 0079 并复核。原状态可证且执行环境完全隔离时，旧章节可单独复位，原任务和项目级清理失败记录仍须保留。受测创建角色提案的 18 个旧字段在两条取消路径中完整保留，角色数始终为零。
