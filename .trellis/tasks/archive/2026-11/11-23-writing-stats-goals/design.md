# 写作统计与码字目标设计

需求和作者可见行为见 [prd.md](prd.md)。计量放在服务端成功写正文的事务中。前端负责显示，不上报按键或自报字数。

## 一次保存怎样计字

业务入口显式提供操作者、作品、来源和本次变动场景的前后正文。先通过现有权限、版本和生成任务校验，保留修改前的字符串，然后比较最终要提交的读者正文。多场景分别比较后合计一次。这样场景分隔符和未动的整章内容都不会计入。

1. 采用与 `chapter_service.count_words` 一致的非空白 Unicode 码点。快路径处理相同文本、空串、纯追加、纯删除；其余对齐共同前后缀，再对中间段求编辑差异。每个插入段或替换段只数新侧字符，匹配段与删除段贡献 0。例：`春风吹过山岗` → `暖风吹过山坡` 计 2 字。
2. 先按相同段落缩小长文本的比较范围，再对变动区做字符对齐。用重复汉字、相距很远的两处改动和长篇整段替换验证运行成本与结果。不得把两处改动之间的旧正文整个算作替换。只把字数写入统计表。
3. 在正文提交事务内按「操作者、作品、北京日期」原子累加。相同正文差值为 0。沿用正文版本条件更新和 AI 完成收据处理失败、冲突及回执丢失；只有获得该次写入权的一方计字。服务函数只使用调用方的数据库会话，不自行提交。跨午夜每笔事务固定取一次服务端时间。
4. 已成功写入后再次手动改写，是新一次写作。一次保存前输入又删掉的文字没有进入成稿。粘贴的外部文本按编辑器手写入口处理；无法仅凭文本判断它是否来自外部 AI。

## 写入入口和归属

下表中的路径位于 `backend/app/services/`。章节版本的手写快照会按时间合并，投影刷新也被恢复与拆并共用，均不适合作为统一计量入口。

| 入口 | 处理方式 |
| --- | --- |
| `chapter_service.create_chapter/update_chapter`、`scene_service.create_scene/update_scene` | 只在人工创建或编辑了读者正文时取差异。核对旧章级保存和当前场景保存。新建带正文的章只在创建处计一次。 |
| `rich_document_service.save_document` | 比较旧文档与已校验新文档的 `content`。纯样式、标记和私有区块变化为 0。`rich_document_conversion` 通过同一函数把已有区块转为正文，该入口显式跳过计量。 |
| `generation_service._save_chapter_result` | 章、场景的生成、润色、修订及批量逐章完成以实际保存的变动为准。只比较最终进入数据库的场景；进入待核对分支时尚未写正文。 |
| `rich_document_review._accept_review`、`rewrite_service._apply` | 核对成功或选区采纳时计 AI。按实际落稿差异计数，即使日志记录输出 5,000 字，此次实际新增 2,000 字也只记 2,000。无可信 AI 来源的旧兼容请求保留既有写入行为，不纳入 AI 或手写。 |
| `agent/tools/write_text.execute` | 智能体实际执行局部替换时记 AI，使用该操作的真实账号。工具预览及效果撤销不增加字数。 |
| 导入、版本恢复、批量查找替换、拆并移动、区块内 AI、连载定稿和发布 | 跳过计量。单章删除保留已经完成的每日写作量。 |

人工操作归当前登录账号，生成任务归服务端验证的发起人。作品所有者、模型持有人或管理员身份不能代替实际操作者。现有权限不足、过期任务、回滚都沿用原行为。

## 存储与兼容

| 拟新增记录 | 键与约束 | 用法 |
| --- | --- | --- |
| `writing_daily_stats` | 联合主键 `(user_id, project_id, day)`，手写与 AI 两个非负大整数字段 | 原子插入或加到已有值，不使用「先读总数再覆盖」。只在有效增加时写行。按键前缀及日期范围查趋势。 |
| `writing_goals` | 联合主键 `(user_id, project_id)`，日／周周期、正整数目标、修订号 | 首次设置以版本 0 创建。修改或关闭均校验版本，关闭保留修订号，防止旧页面写回已清除的目标。 |
| `writing_stats_tracking` | 单例，UTC 启用时刻 | 迁移时记录一次；空库初始化也须能建立起点。作品的可观测起点取计量启用与建书时间两者中的较晚者。 |

两张个人表与账号、作品分别建立级联外键，作品进回收站期间随既有授权隐藏，彻删时清理。单书备份按 `project_transfer/registry.py` 的 `NOT_EXPORTED` 记录个人数据排除原因；整库备份保留数据。旧版本和生成人工日志都不足以还原每日的真实编辑量。迁移从实施时的 Alembic head 接续，非空个人数据的降级应提示先备份。

## 读取、目标与工作台

- 在 `/api/v1/projects/{project_id}/writing-stats` 下提供 `GET /overview?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD` 和 `PUT /goal`。读取要求作品 `content.read`，修改本人目标要求 `content.edit`。账号取自认证上下文。跨作品、降权、管理员代管按已有项目访问规则验证。
- 概览返回启用时刻、查询区间、逐日手写与 AI 字数、当前目标及修订号、本期手写量和连续天数。日期范围含首尾，建议默认近 30 天、单次最多 366 天，倒置、超长、未来结束日期返回 422。启用前的点用空值，启用日与今天标注部分日，其余已覆盖日期无记录补 0。
- 目标保存载荷为 `{period, target_words, expected_revision}`。启用时周期取 `day` 或 `week`，关闭时两个值均为 null。冲突返回 409 并允许重新读取。设置或调整目标后，本期之前已经写下的字也算入进度；超过目标可显示实际字数，进度条止于 100%。
- 趋势日期选择只改变图表。目标使用服务器当前日／周单独求和。连续天数从今天或昨天往前数连续的手写日，允许跨月、跨年和超出图表区间，AI 单独产出日视作手写为零。
- 在 `frontend/src/pages/project/SerializationPage.tsx` 的 `StockSummary` 旁展示「我的码字目标」，下方提供日期选择、手写／AI 两条趋势和可读的每日数值。沿用工作台作品切换、账号与权限作用域、请求失效机制。统计加载失败时可单独重试。存稿沿用原接口的 `support_days` 和 `remaining_chapters`，未设日更章数时继续展示原提示。
