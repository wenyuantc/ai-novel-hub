# 笔记栏跨断点丢失未保存内容

## 目标

作者调整窗口尺寸或旋转设备后，可以回到章节编辑页的笔记栏继续编辑同一份草稿。

## 背景

- 浏览器补验期间通过源码排查定位了这个问题。 [TODOS 第 23 项](../../../../../TODOS.md#23-笔记栏跨断点丢失未保存内容) · [排查记录](../11-18-browser-acceptance-backlog/research/targets-categories-notes-skills.md#b4-已知问题todos-第-23-项在代码里的成因)
- `useIsMobile.ts:10` 以 768 px 为断点。修复前，`ChapterEditorPage.tsx:1301` 和 `ChapterEditorPage.tsx:1313` 分别在桌面侧栏和移动端抽屉渲染笔记栏，跨断点会卸载原组件。
- 笔记选择和草稿分别存在 `NoteSidePanel.tsx:37` 和 `NoteEditor.tsx:38` 的本地状态中。卸载时 `NoteSidePanel.tsx:53` 清除传给页面的未保存标记，该份笔记草稿随即失去离页保护。

## 需求

- 保留当前选中的笔记、草稿标题、正文和未保存状态，覆盖已存在的笔记和未首次保存的新建笔记。保留范围是当前章节编辑页的一次访问，受当前账号及作品权限约束。
- 桌面通过侧栏访问笔记，移动端通过辅助面板抽屉访问笔记。草稿由作者显式保存，切换标签、收起面板或跨断点仅改变显示。
- 有未保存修改时，关闭当前笔记、打开另一篇笔记或离开编辑页会要求确认。取消操作后可以继续编辑同一份草稿。

## 验收标准

- [x] 在真实浏览器编辑一篇已有笔记的标题和正文，在 1024 px 与 375 px 之间往返调整宽度。每次打开对应侧栏或抽屉时，确认所选笔记及两项草稿内容一致。
- [x] 从移动端新建笔记并填入标题和正文，收起抽屉后跨到桌面布局，再返回移动端。重新打开笔记栏后可以继续编辑并保存，调整宽度期间笔记写入请求为零，显式保存只创建一篇笔记。
- [x] 跨断点后切换检视标签、收起再打开笔记栏，草稿仍可编辑。尝试关闭当前笔记、切换笔记或离开章节编辑页时显示未保存提示，取消后草稿完整。
- [x] 跨断点后使用笔记编辑器的保存快捷键，确认只提交笔记。只读账号在两种布局下均可查看有权访问的笔记，编辑入口只对具备编辑权限的账号开放。
