## 规划前已核实的现状

- 地点、物品等保存在 `WorldSetting` 中，角色另有结构化字段；当前模型没有独立场景或自定义字段定义。证据：`backend/app/models/entities.py:229`、`:241`、`:476`，`backend/app/schemas/story.py:32`、`:57`。
- 章节上下文直接读取当前世界观、角色、关系及职业挂接，未按目标章节还原。证据：`backend/app/services/context_builder.py:430`、`:479`。
- 整章生成和按分析建议重写共用章节上下文构造入口。证据：`backend/app/services/generation_service.py:279`、`:304`。局部改写和光标续写目前没有设定输入（`backend/app/services/rewrite_service.py:99`），需一并接入。
- 人物关系与职业已有带可选章节号的历史，但部分历史值以名称记录，不能直接假定这些日志是可完整回放的状态快照。证据：`backend/app/models/entities.py:359`、`:441`，`backend/app/services/relationship_service.py:244`。
- 章节分析会更新角色当前状态／存活状态，写入逻辑需与新时间线协调。证据：`backend/app/services/writeback_service.py:57`、`:71`。
- 角色卡也会读取最新组织职位／成员状态，必须随角色状态处理，避免旁路泄漏。证据：`backend/app/services/context_builder.py:377`、`:433`，`backend/app/services/analysis_service.py:717`。
- 新的章节号引用及项目数据必须遵守现有章节编号、项目备份规范，不能在插章或项目迁移后失去关联。证据：`backend/app/services/chapter_numbering.py:65`、`.trellis/spec/backend/project-transfer.md`。

## 来源需求

| 编号 | 要求 |
| --- | --- |
| R1 | 对角色、地点、物品等设定记录变化，并绑定其生效章节或场景。 |
| R2 | 支持追加与替换两种模式；文本类型的自定义字段可以单独记录变化。 |
| R3 | 按目标故事位置计算有效设定，排除该位置之后的变化。 |
| R4 | 角色状态、人物关系、职业阶段均纳入回溯；生成与重写使用目标位置的有效设定。 |

## 本期行为与约束

1. **位置与维护（R1、R5）**：作者可选择已有章节或计划章节号，区分“从本章起”“本章结束后”；详情中按故事顺序展示变化、来源及关联位置，可新增、编辑、删除并查看指定章首／章末的有效结果。关联章删除后提示重新绑定，不按同号新章自动复活。
2. **字段与模式（R2）**：角色描写／状态文本、世界观内容及条目内最小文本自定义字段支持追加／替换；结构化状态使用合法替换。替换只影响指定字段；字段改名保留变化关联，有有效变化引用时不能静默删字段。
3. **写作与分析（R3、R4）**：整章生成、自动续写、按建议重写、局部重写／扩写／缩写／去AI味／光标续写，以及章节分析使用统一的目标章初设定。分析从本章正文得到的变化在本章结束后生效，批量写作逐章使用更新结果。
4. **角色状态完整性（R4）**：存活／处境、关系、职业阶段与挂接／解除均能回溯；同时处理角色卡已有的组织归属／职位／成员状态。后期结构化关系被排除时，不重新启用可能含后期事实的旧关系备注。
5. **编辑与撤销（R3、R5）**：基础修正与剧情变化有明确操作入口。仅保存无关字段不能改变基线；已有变化的字段通过旧入口进行含糊修改时明确提示选择意图。较早章节的新分析可以补录历史，但不能覆盖较晚的有效状态；撤销只撤原变化，保留后续独立变化，原变化被手工改过则提示冲突。
6. **旧资料兼容（用户已选M1）**：保留原档案为待校准基础，旧历史继续查看，不自动重放或补造缺失状态；作者可以校准初始值并补录。新增资料／变化完整记录。变更记录之前的历史准确性不能在未校准时保证。
7. **持久化与权限（R1–R5）**：插章、改号、删章、完整项目备份恢复和新格式智能体撤销必须保持位置／字段／有效值一致；越权操作与并发冲突不部分写入。升级前涉及设定／章锚的旧智能体撤销缺少时间线信息时，明确提示通过新基础设定修正，不能静默破坏新记录；无关的纯正文撤销保留。角色卡可携带明确的最新快照和自定义文本，但不跨作品搬运章节位置。

## 不在本期的范围

- 第7项独立场景及章内精确位置；第4项下拉、引用、按类型配置字段、自定义分类等完整字段系统。
- 角色名字／别名等身份资料、组织树／势力值、职业体系定义的时间化；这些仍为全书基础资料。
- 提及追踪、规划矩阵、跨书共享、全书一致性或修改影响检查，以及旧书历史的自动迁移／全书AI重分析。
- 作者正文、指令、知识库、细纲／大纲、Skill和聊天历史中的自由文本剧透识别；本期保证的是受时间线管理的设定。
- 整章润色仍只按原文和写作要求工作；普通智能体管理对话仍读取最新档案，不暗中根据页面切换历史视图。

## 验收标准

- [x] AC1（R1、R3、R4）：角色在第 20 章晋升后，生成／重写第 5 章仍使用旧职业阶段与当时状态，且不包含第 20 章才生效的设定文本。
- [x] AC2（R1、R2、R3）：为地点或物品先追加、再替换文本后，分别查看变化前、两次变化之间和变化后的章节，得到可预测的有效文本；替换仅影响指定字段。
- [x] AC3（R2、R3）：文本自定义字段可以维护基础值，并单独追加或替换；其他字段不受影响。
- [x] AC4（R4）：关系建立／变化、职业挂接／晋升／卸下及组织职位变化不会出现在其生效位置之前；角色后来的存活状态不污染早期上下文。当前挂接已卸下，早期章节仍可看到旧挂接。
- [x] AC5（R5）：详情页能新增、编辑、删除变化，查看生效章节及选定章节的有效结果；修改后重新生成使用更新后的结果。
- [x] AC6（R1–R5）：插章、直接改号、项目导出导入后，变化顺序、字段关联与有效结果保持正确；删章后关联变化不再生效，同号重建不复活。权限规则与现有设定管理一致。
- [x] AC7（R3、R4）：章节分析写回及撤销与手工变化协同，不因分析较早章节而错误覆盖后续状态。
- [x] AC8（R3、R4）：第20章分析出章末晋升后，重写20章仍使用章初旧境界，21章使用新境界；作者明确设为“从20章起”时20章采用新值。同章多条变化顺序稳定。
- [x] AC9（兼容约束）：升级及旧格式项目导入不改变原当前档案；旧基线标记待校准。作者修正初始值和补录20章变化后，5／21章结果正确；未校准时不宣称旧历史已准确还原。
- [x] AC10（R3、R5）：只改角色姓名不污染基础状态；明确基础编辑与剧情变化各自生效；版本冲突保留输入，快速切换角色／章节不会展示上一请求的旧结果，变化保存不清空基础草稿。
- [x] AC11（R3、R4）：实际模型消息覆盖整章、局部五种操作、自动续写和批量；对应设定区只含目标时点的有效值。旧已保存局部提示词覆盖也收到同一有效设定块。
- [x] AC12（R1–R5）：跨作品备份恢复、字段ID重映射、新格式删除后智能体撤销均保留时间线语义；旧格式不安全撤销明确拒绝且不部分写入。关系建立被撤销后普通／开放API与卡片无幽灵条目，旧审计及仅在历史中使用的关系类型不丢，后续复建正常。
- [x] AC13（R4）：分析运行期间正文或位置已变更时，不自动激活旧结果；同源重试不重复创建变化，重新分析不覆盖人工维护的事件，未再次报告的旧事实明确待复核。
