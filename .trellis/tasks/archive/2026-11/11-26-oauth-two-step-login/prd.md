# 第三方登录与两步验证

首版支持 Linux DO 和 GitHub。作者可以把两家身份分别绑定到自己的 aiNovel 账号，用任一已绑定入口回到原书架，账号开启的两步验证适用于所有登录入口。[父任务](../../../11-26-login-methods-local-mcp/prd.md)

## 当前行为

- 用户名唯一，密码哈希必填，角色和作品依附于本地用户 ID。首次第三方建号需兼容这批已有账号。见 `backend/app/models/entities.py:149`。
- 注册和密码登录成功都会记录最近登录并签发 Cookie。前端收到用户对象后立即进入登录态。加入第二步需要协调记录时间、签发和页面跳转。见 `backend/app/services/auth_service.py:66`、`backend/app/api/v1/auth.py:37`、`frontend/src/stores/auth.ts:89`。

## 登录与恢复验收

| 场景 | 预期结果 |
| --- | --- |
| 配置第三方入口 | 分别验证仅配置 Linux DO、仅配置 GitHub 及两家均配置的情况。登录页展示可用入口，每家均有一次从授权到返回书架的独立验收。 |
| 作者绑定第三方身份 | 绑定前验证当前账号与第三方身份。换入口仍是原用户 ID、原作品和原角色。同名、同邮箱或已绑定他人的身份不能接管旧账号。 |
| 跨平台身份 | 即使两家返回相同的数字 ID，也各自对应原先绑定的账号。作者主动把两家身份绑到同一账号后，两个入口都能打开该作者的同一书架。 |
| 开放注册，首次第三方登录 | Linux DO 和 GitHub 分别用一个未绑定身份授权，可直接创建普通 aiNovel 账号并进入新书架。再次使用相同身份进入同一书架，用户名相同也不能并入他人的账号。 |
| 关闭注册 | 保留已配置的登录按钮。已绑定身份可进入原账号，未绑定身份看到注册已关闭的提示，用户数和绑定数均不增加。禁用账号即使已绑定也无法登录。 |
| 授权中途关闭注册 | 用户在开放注册时跳转第三方，管理员在建号前关闭注册。回调按写入时的有效开关处理，未绑定身份不建号、不获会话；已绑定身份仍走登录流程。 |
| 重复首次登录 | 同一平台身份在两个浏览器同时授权，或收到重复回调，最终只产生一个用户及一条绑定；没有空账号或错误合并。 |
| 自愿启用两步验证 | 新建和升级的普通账号、管理员账号均默认关闭，可直接使用原登录方式。用户主动绑定验证器并成功输入一次动态码（TOTP）后才启用，同时获得一组一次性恢复码供保存。绑定中断时保留原登录方式。 |
| 已启用账号登录 | 从密码、Linux DO、GitHub 三个入口分别登录。第一步完成后，输入有效的验证器动态码或一枚未使用的恢复码才能取得会话。最近成功登录时间只在第二步完成后更新。 |
| 中断与并发 | 取消授权、验证错误或过期有明确提示。合法流程可在另一 worker 完成；同一挑战最多成功一次。验证中重置密码或禁用账号后，旧挑战失效。 |
| 遗失验证器 | 完成第一步后，可用一枚恢复码登录。两个会话同时提交同一枚恢复码时只有一次成功。用过的码失效，其他未用码仍可使用，下次登录仍需完成第二步。 |
| 普通用户遗失验证器和全部恢复码 | 超级管理员核实本人身份后可在后台重置该用户的两步验证。只有普通用户管理权限的账号无法执行。用户须用原有登录方式重新登录，随后可自愿绑定新验证器。 |
| 唯一超级管理员被锁住 | 部署者在运行服务的主机或容器内执行专用恢复命令。命令核验目标为唯一启用的超级管理员后重置其两步验证。远程管理接口不提供这个本机操作。 |
| 重置结果与审计 | 两条路径均使目标的旧验证器、旧恢复码、待验证的登录流程及旧会话失效，保留原账号、密码或第三方绑定、角色和书架。审计可查到时间、目标、结果和操作者（后台超级管理员或部署者本机操作）。成功记录写入失败时，重置也回滚。 |
| 解除绑定或更换设备 | 解除第三方绑定、关闭两步验证或更换验证器均需验证账号控制权，并保留至少一种可用登录方式。 |
| 原有部署升级 | 未配置第三方且未启用第二步时，原注册、登录、改密、退出和受保护页面回跳仍可用。 |
