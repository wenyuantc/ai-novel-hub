# 登录与两步验证实施清单

此子任务可独立于本机 MCP 交付，以下均为实施与验收计划。[需求](prd.md) · [设计](design.md)

1. **迁移现有账号。** 保留本地用户 ID 与密码登录，建立外部身份唯一约束及两步验证、一次性凭据、短期挑战存储。分别在 SQLite 与 PostgreSQL 用带旧用户的数据库演练升级。
2. **接入 Linux DO 和 GitHub。** 实现两家的登录与主动绑定、解除绑定，各自回调对照注册开关测试。覆盖并发首次登录、用户名碰撞、已有绑定和禁用账号。用真实应用分别取得一次从授权页回到原书架的记录。
3. **接入两步验证。** 普通用户、管理员分别验证自愿开启、首次动态码确认、一次性恢复码领取与丢失设备后登录。对密码、Linux DO 和 GitHub 分别检查第一步后无正式会话，第二步成功才写最近登录。跨 worker 重复提交同一挑战或恢复码，只接受一次。
4. **实现两条人工恢复流程。** 在后台用户详情增加超级管理员核实并确认的入口，并提供部署者本机恢复命令。两条路径使用同一事务重置第二步。接入审计动作、读模型和后台显示，并写出本机恢复的部署操作说明。
5. **验收重置与权限。** 普通用户丢失全部凭据后由超级管理员重置；仅有用户管理权限者操作被拒。唯一启用超级管理员由本机命令恢复，目标不满足条件时应拒绝。两种成功路径都核对审计、旧会话和旧挑战失效，以及本人重新登录后书架、角色和绑定仍在。模拟审计写入失败，核对原凭据仍有效且未发生半完成重置。
6. **验证页面与回退。** 从登录页、账号安全设置、管理员用户详情及审计页完成端到端验收。试验停用一家提供方后另一家可登录，并在已有两步验证账号的数据副本上演练回退。

现有后端回归在 `backend/` 运行 `uv run pytest -q tests/test_auth.py tests/test_admin.py tests/test_admin_user_details.py tests/test_admin_audit_logs.py tests/test_rbac_permissions.py`。前端在 `frontend/` 运行 `npm test -- src/stores/auth.test.ts`、`npm run lint`、`npm run build`。上述基线之外，需要新增第三方回调、两步验证、恢复命令与事务失败测试，与浏览器验收结果一同记录。
