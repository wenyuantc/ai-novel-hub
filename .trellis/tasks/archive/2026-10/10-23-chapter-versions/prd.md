# 章节版本与局部改写（P0-1）

> 父任务：`10-23-mumu-parity`。对应差距项：A13 版本历史、A12 局部改写、A17 去 AI 味、A9 字数闭环、A15 生成记录。
> 依赖：无。后续 `analysis-memory`（按建议重写）和 `outline-pro`（批量生成）写入正文时，复用本任务的版本写入接口。
> 技术设计见 `design.md`，执行计划见 `implement.md`。

## Goal

AI 生成、润色、改写都不应该悄悄丢掉作者原来的文字。每章正文要有可追溯的版本历史，能对比，能回滚。在此基础上，作者可以只改写选中的一段，不必整章重写；整章生成的字数也要真正接近目标。

## Background（代码证据）

- `Chapter`（`backend/app/models/entities.py`）有这些字段：`id, project_id, outline_id, chapter_no, title, content, status[draft|generating|done], word_count`。项目里目前没有版本表。
- 生成和润色共用 `generation_service.prepare_chapter_job` / `run_chapter_job`。流式输出结束后直接执行 `chapter.content = text`，整章覆盖。中途失败只回退 `status`，正文保持不变。并发靠原子操作 `UPDATE ... WHERE status != 'generating'` 抢占；生成期间 PATCH 正文或标题会返回 409（`chapter_service.update_chapter`）。
- 手动编辑走 `PATCH /projects/{pid}/chapters/{cid}`，前端用 Ctrl/⌘+S 保存。字数 `count_words` 统计非空白字符，前后端口径一致。`target_words` 范围 300–20000，目前只在提示词里约束。
- `LLMProvider.generate_stream` 只返回文本，拿不到 token 用量。
- 作为对比，MuMu 的重写接口里 `auto_apply` 和 `save_as_version` 都没有实现，版本号永远是 1；生成历史不完整，也没有查看页面。详见 `../10-23-mumu-parity/research/mumu-creation-core.md` §8、§9、§11。

## Key Decisions

- **D1（用户确认）**：整章生成和润色完成后直接覆盖正文，覆盖前的旧正文自动存为版本。局部改写先预览，作者确认后才替换选段。照此推论，批量生成也会直接覆盖并存版本，不引入"待确认"状态；这一条到规划 `outline-pro` 时再确认。
- **D2（用户确认）**：手动保存时：
  - 正文与最新版本相同，不新建版本；
  - 最新版本是手动保存版本，且距它**创建**不到 10 分钟，直接更新那个版本；超过 10 分钟就新建版本（固定窗口，合并不延长窗口，用户在实现后确认）；
  - AI 生成、润色、局部改写、回滚之前，总会单独存一个版本，不参与合并。
  每章保留最近 50 个未标星版本，超出时自动删除最旧的；标星版本永久保留，不计入上限。
- **D3（用户确认）**：整章生成的字数低于目标的 85% 时，自动接着前文续写，最多 2 次。超出目标不截断。编辑器里有开关可以关闭，默认开启。润色不续写。

## Requirements

- **R1 版本记录**：正文每次变化都按 D1/D2 留下全文快照。来源分为：手动保存、替换前快照、AI 生成、润色、局部改写、回滚。每个快照记录来源、时间、字数；由 AI 产生的版本还要关联对应的生成记录。
- **R2 版本列表与查看**：编辑器里可以打开本章的版本列表，列表显示序号、来源、时间、字数、星标、备注。可以查看任意版本全文，可以标星、写备注，可以删除非最新的版本。
- **R3 对比**：任意两个版本之间，或某个版本与当前正文之间，都能做逐字差异对比，用高亮显示增删并统计增删字数。
- **R4 回滚**：可以把任意版本恢复为当前正文。回滚前先保存当前稿，回滚本身也产生一个新版本，因此回滚可以再撤销。章节生成中不允许回滚。
- **R5 局部改写**：选中一段正文后，可以用 AI 改写、扩写、缩写或去 AI 味；也可以不选，在光标处续写。结果以流式预览展示，并附上和原文的对比，作者可以采纳、重新生成或放弃。采纳前如果正文已经变化，系统会拒绝采纳并提示重新选择。预览期间正文只读。单次选区不超过 5000 字。
- **R6 字数闭环**：按 D3 实现。续写进行中，界面提示当前是第几轮。续写失败时保留已生成的正文，并给出警告。
- **R7 生成记录**：每次 AI 调用（生成、润色、续写、局部改写）都留一条记录，包括类型、模型、参数、完整提示词、状态（成功、失败、取消）、错误信息、产出字数和耗时。token 用量字段先预留，暂时为空。每个项目保留最近 200 条，可以在章节里查看。
- **R8 安全**：版本、生成记录、改写接口都要校验项目归属，非所有者访问一律返回 404。

## Acceptance Criteria

- [ ] **AC1（R1/D2）**：10 分钟内连续手动保存 3 次不同内容，只产生 1 个手动版本，且内容是最后一次保存的。距该版本创建超过 10 分钟后再保存，会新建一个版本，中间的合并不会延长这个期限。内容未变或正文为空时，不产生版本。
- [ ] **AC2（R1/D1）**：对一章已有正文执行整章生成，成功后版本列表新增"替换前快照"（如果旧稿还没存过）和"AI 生成"两个版本。生成失败或中途断开时，正文和版本列表都不变，生成记录里留下一条失败或取消记录。
- [ ] **AC3（D2 上限）**：第 51 个未标星版本产生时，最旧的未标星版本被删除。标星版本和最新版本永远不会被自动删除。
- [ ] **AC4（R3）**：选两个版本对比，增删内容高亮正确，增删字数统计正确。
- [ ] **AC5（R4）**：恢复 v1 后正文等于 v1，并新增一个回滚版本，备注为"恢复自 v1"。再恢复回滚前的快照，正文回到恢复 v1 之前的状态。章节生成中执行回滚返回 409。
- [ ] **AC6（R5）**：选中一段执行改写，预览期间正文不变。采纳后只有该段被替换，并新增一个"局部改写"版本。预览后在别处修改并保存了正文，再采纳会被拒绝，并提示重新选择。正文里含 emoji 或生僻字时，选区替换位置准确。
- [ ] **AC7（R6/D3）**：目标 3000 字、首轮只产出约 1500 字时，自动续写，最多 2 轮，界面显示续写进度，最终正文是首轮和续写内容的拼接。关闭开关后不续写。续写报错时，已生成的正文照常保存，并显示警告。
- [ ] **AC8（R7）**：上述每次 AI 调用，在生成记录里都能看到类型、模型、状态、字数、耗时和完整提示词。
- [ ] **AC9（R8）**：另一个用户访问本章的版本、生成记录、改写接口，一律返回 404。
- [ ] **AC10（质量）**：`uv run ruff check . && uv run pytest`、`npm run lint && npm test && npm run build` 全部通过；构建产物的 chunk 小于 1500 kB；原有章节测试不做修改也能通过；SSE 契约 spec 已同步更新。

## Out of Scope

- 基于章节分析的"按建议重写"，归 `analysis-memory`。
- 批量生成的触发和编排，归 `outline-pro`；批量写入时复用本任务的版本接口。
- token 用量统计需要改造 provider 的流式接口，本任务只预留字段。
- 富文本编辑器，继续使用纯文本 TextArea。
- 标题的版本化：版本只管正文，回滚不改标题。
