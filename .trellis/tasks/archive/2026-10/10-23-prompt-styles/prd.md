# 提示词模板与写作风格（P1-6 prompt-styles）

## Goal

让用户能调整 AI 的提示词，并管理可复用的写作风格。对应差距清单 C1（提示词模板）和 A14（写作风格库）。完成后，批量生成弹窗补上风格选项。

## 已确认事实（代码核查，2026-10-26）

- 提示词都写死在 `backend/app/ai/prompts/` 下的 Python 函数里，约 18 个 `build_*_messages`，分布在 6 个服务中：向导 4 个，实体 AI 4 个，章节生成、润色、按建议重写、续写 4 个，局部改写 1 个，分析 1 个，大纲续写和展开 2 个。函数内部用 Python 拼接，带不少条件分支（有细纲才写关键事件、追加模式换一段话等），不是简单的字符串模板。
- 很多提示词要求输出 JSON，解析器依赖固定的结构（例如分析的 OUTPUT_SCHEMA，有伏笔时还会切换成另一套结构）。
- 写作风格目前只有 `projects.style` 一个自由文本字段（上限 5000 字），在项目概览页编辑。它会注入章节生成、润色、按建议重写、局部改写的提示词（"写作风格：…"），向导通过 `format_project_info` 也会带上它。
- 依赖里没有模板引擎（没有 jinja2）。
- MuMu 的做法：约 40 个模板，用 `str.format` 渲染，按用户覆盖。缺陷有四点：字面量 `{}` 一写就坏；不校验变量；前端没有预览；系统默认升级后不提醒。风格是一段自由文本，项目级默认，章节生成时必须选；工坊依赖作者的中央云端，身份可以伪造。

## 需求草案

1. **提示词模板**
   - 每个 AI 功能对应一个模板 key，系统默认随代码发布。
   - 用户可以覆盖、恢复默认、导入导出。
   - 保存时校验：语法、未知变量、必需变量不能删。
   - 编辑时可以用示例数据预览渲染结果，并能和系统默认对比差异。
   - 系统默认升级后，提示已覆盖的用户"默认已更新"，并可以查看差异。
   - 模板机制（Q1 已定）：
     - 使用沙箱化 Jinja2，未定义变量一律报错。
     - 每个 AI 功能的 system 和 user 两段都可以整体编辑，支持 `if` 和 `for`。
     - 参考资料、角色卡、前情等数据块由代码预先拼好，作为变量传入模板。
     - JSON 输出结构和"只输出 JSON"规则由代码提供，内容锁定不可改。它们以锁定占位变量的形式出现在模板中：必须保留且只出现一次，不能放进 if 或 for，位置可以调整。这样默认模板才能逐字复现现在的提示词（现有提示词里这些规则并不总在末尾）。运行时如果缺失，自动补到末尾。预览中以只读方式展示。
     - 每个模板声明必需变量，保存时校验。
     - 系统默认模板的渲染结果与现在的提示词逐字一致，用快照测试保证。
   - 覆盖层级（Q2 已定）：
     - 只有"系统默认 → 用户覆盖"两层。用户覆盖对自己的所有项目生效，可以单独停用（停用后回到系统默认，覆盖内容保留）。
     - 管理员不能修改实例默认，系统默认只随代码升级。
     - 保存覆盖时记下当时系统默认的指纹。系统默认变化后，提示"默认已更新"，可以查看旧默认、新默认和用户版本的三方差异。
     - 每个覆盖保留最近 20 个历史版本，可以回滚。
2. **写作风格库**（Q3 已定）
   - 字段，全部选填：名称、一句话描述、叙事视角、句式节奏、对白比例、描写密度、基调、用词偏好、禁用表达、示例段落（不超过 2000 字）、自由补充。这些字段通过可编辑的"风格段"模板渲染进提示词。
   - 内置 6 个自写预设，只读，可以复制后修改。
   - 选择优先级：生成时临时选择 > 章节覆盖 > 项目默认 > 不用风格。批量弹窗可选"按章节或项目默认"，也可以指定一个风格。
   - 生成记录保存风格 id 和渲染后的风格段。
   - 向导和实体生成只用项目默认风格的一句话描述。
   - 从样文提取风格、用风格试写一段，都是同步流式。提取只出草稿，确认后才保存。
   - 删除被引用的风格时，提示引用数；删除后，引用处回落到上一层。
3. **文件导入导出**：模板和风格都可以导出为 JSON 文件，也能从文件导入（范围已定）。
4. **接入**：章节生成、润色、按建议重写、局部改写、批量生成都按上述优先级解析风格，并注入提示词。现有的 `projects.style` 自由文本迁移为该项目的一个自定义风格，并设为项目默认。

## 范围外

- 实例内共享（工坊）与管理员审核：拆成子任务 `prompt-workshop`（P2，依赖本任务）。

## Acceptance Criteria

- [ ] 覆盖某个模板后，下一次对应的 AI 调用使用覆盖内容；恢复默认后，回到系统默认。
- [ ] 保存不合法的模板（语法错误、未知变量、删掉了必需变量）时，返回 400 并指出具体位置。
- [ ] 预览能用示例数据渲染出完整的 messages，锁定的 JSON 输出段以只读方式展示。
- [ ] 全部系统默认模板的渲染结果与改造前的提示词逐字一致（快照测试覆盖各个条件分支）。
- [ ] 模板无法访问 Python 内部属性（沙箱逃逸用例返回 400 或渲染失败）。
- [ ] 系统默认变化后，已覆盖的模板显示"默认已更新"，并能查看三方差异。
- [ ] 停用覆盖后使用系统默认，重新启用后恢复覆盖；历史版本超过 20 个时裁剪最旧的，可以回滚到任一历史版本。
- [ ] 风格按"临时 > 章节 > 项目默认 > 无"解析，在生成、润色、按建议重写、局部改写、批量生成中都生效；生成记录里有风格 id 和渲染后的风格段。
- [ ] 预设风格不能修改或删除，可以复制；删除被引用的风格时返回引用数，删除后引用处回落到上一层。
- [ ] 从样文提取只产出草稿，不落库；试写流式输出一段正文，不写入任何章节。
- [ ] 向导和实体生成只带项目默认风格的一句话描述。
- [ ] 批量生成可以选"按章节或项目默认"，也可以指定一个风格；断点续跑时沿用同一个选择。
- [ ] 原有 `projects.style` 无损迁移。
- [ ] 模板和风格都能导出为 JSON 并重新导入；导入文件有大小上限和格式校验，导入的模板同样要通过保存时的校验。
- [ ] 跨用户访问返回 404。
