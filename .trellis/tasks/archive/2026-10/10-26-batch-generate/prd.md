# 批量顺序生成（P0-5b batch-generate）

## Goal

按章节顺序批量生成正文，作为一个可断点续跑的后台任务。它解决 MuMu 批量生成的缺陷：会覆盖已写章节，数量只能选 5/10/15/20，失败即终止且不能续跑，没有人工审核点，绕开统一队列，重启后不能续跑。

## 已确认事实（代码核查，2026-10-26）

- 任务引擎：`TaskHandler` 协议、`resource_key` 冲突返回 409、`serial_key` 同键串行。全局并发 4、每用户 2（auto 分析任务也占名额）。重启时运行中的任务标为 `interrupted`，重试会复制 `step_cursor`，但目前没有任何 handler 写入 `step_cursor`。
- 一个任务内可以多次调用 LLM（`outline.expand` 已分批循环），但任务只有一个 `chapter_id`、一个 `resource_key`、一次 `done`。
- 单章生成（`ChapterHandler`）：`resource_key=chapter:{id}`；领取时原子地把章节置为 `generating`，中止时恢复；目标字数只取请求参数（默认 3000），没有使用细纲的 `est_words`；低于 85% 时自动续写，最多 2 轮；覆盖前存 baseline 版本，写入后存 generate 版本；成功后调用 `analysis_service.enqueue_auto`。
- 上下文在任务开始运行（build_job）时组装：前几章给全文，更早的章节给分析摘要；角色当前状态和伏笔提醒取数据库实时值。所以第 N-1 章的分析回写只有在第 N 章开始组装之前完成，才会影响第 N 章。目前生成和分析之间没有任何先后保证。
- 未写章节 = 存在章节行但 `content` 为空。细纲可能还没建章（`chapter_plans.chapter_id` 为 NULL）。
- 前端只有编辑器能触发生成；章节列表 `ChaptersPanel` 没有生成入口。

## 需求草案

1. 在章节列表页发起批量生成，选择范围：起始章到结束章，或者"生成到第 N 章"；默认起点是第一个未写章节。
2. 默认跳过已写章节；可以勾选"包含已写章节"来重写，重写会覆盖并自动存版本（沿用 chapter-versions 的规则）。
3. 目标字数：每章默认取细纲的 `est_words`，没有细纲时用弹窗里填的统一字数；可以选择让统一字数覆盖全部章节。自动续写规则与单章生成一致。
4. 严格按章节顺序生成，每章都基于前面已生成的内容组装上下文。
5. 与分析的配合（Q1 已定）：批量任务内部串行执行，每章生成后在同一任务里分析并回写，再写下一章；分析不另外排队，也不占额外并发名额。项目关闭自动分析（或部署开关关闭）时跳过分析。分析失败只记警告、不阻塞批量，章节保持未分析状态，事后可以手动或一键补分析。
6. 失败处理（Q2 已定）：单章生成失败自动重试 2 次，中间退避等待。仍然失败时，默认暂停整个批量：任务记为失败，并记下失败的章节，重试时从这一章续跑。发起时可以勾选「失败时跳过继续」，这时跳过失败的章节继续写后面的，跳过的章节在结果里列出。
7. 人工审核点（Q3 已定）：审核间隔可设为不暂停（默认）或每 1–50 章。到审核点时任务进入新状态「待审核」，并释放并发名额和章节锁；审核期间可以自由编辑、重写已写章节。任务面板和章节列表提供「继续」和「结束」：点继续后，同一任务从下一章接着写，下一章的上下文在继续时重新组装，审核期间的修改会生效；点结束后，任务以已完成收尾。最后一章写完时不再暂停。
8. 整个批量是一个任务，进入统一任务引擎（受并发上限约束），在任务面板中显示"第 x/y 章"进度，可以取消；取消时已完成的章节保留。
9. 服务重启或中断后，一键重试会从未完成的章节续跑，不重写已完成的章节。
10. 同一项目同一时间最多一个未结束的批量任务（排队中、运行中、待审核都算）。批量运行期间，范围内的章节不能单独生成；其他章节不受影响。
11. 发起前预估耗时并给出提示。

## 范围外

- 范围只覆盖已建章的章节；还没建章的细纲不会自动建章，发起时提示先去大纲页建章。
- 写作风格的选择留给 P1 prompt-styles，届时批量弹窗加一个风格选项。
- 批量过程中新插入到范围内的章节不会自动纳入；范围在发起时按章节 id 定下。

## Acceptance Criteria

- [ ] 默认跳过已写章节；勾选"包含已写"后重写并留有版本记录。
- [ ] 按顺序生成，第 N 章的上下文包含第 N-1 章的正文，以及第 N-1 章分析回写后的角色状态和伏笔（开启自动分析时）。
- [ ] 中断或失败后重试，从未完成的章节续跑，已完成章节不重写。
- [ ] 单章重试 2 次仍失败时，默认停下并记录失败章节，重试从该章续跑；勾选「失败时跳过继续」时继续写后面的章节，结果列出跳过的章节。
- [ ] 审核点按设置进入「待审核」，此时不占并发名额，范围内的章节可以单独生成或编辑；点继续后同一任务从下一章续写，并能用上审核期间的修改；点结束后任务以已完成收尾；待审核期间不能再发起新的批量。
- [ ] 目标字数默认取细纲的 `est_words`，没有细纲时用统一字数；勾选覆盖后全部章节使用统一字数。
- [ ] 发起前的预览列出将生成的章节、跳过的已写章节、预计耗时和警告（例如范围内有章节正在生成）。
- [ ] 服务重启后，运行中的批量标为已中断，正在写的章节恢复原状态；待审核的批量不受影响。
- [ ] 同一项目不能同时有两个批量任务；批量期间范围内的章节单独生成返回 409。
- [ ] 取消后已完成章节保留，正在写的章节恢复原状态，并保留已输出的文本供查看。
- [ ] 分析在批量任务内执行，不会因为每用户并发上限而死锁；分析失败只记警告，批量继续。
- [ ] 关闭自动分析的项目，批量过程中不做分析。
