# 管理员首页与全站统计：技术设计

状态：用户已批准，已完成实现及本地全范围检查，两笔工作提交已完成并快进合并main，任务已归档；后续普通推送已获用户授权。对应 `prd.md` 的 R1–R7、AC1–AC12；冻结HTTP字段未变，内部执行身份同时覆盖Task、Hub及输出路径。PostgreSQL实跑与本地标准构建目录权限的限制见检查报告。

## 1. 边界与数据流

```text
业务表 → SQL 聚合 → overview API → 总览 / 工坊待办
业务表 → 后端定时采样 → 每日规模快照 → history API → 规模趋势 / 净变化 / 数据表
Task 创建与状态事务 → 独立任务统计记录 → tasks / history API → 在途、累计、每日结果、24h 异常
现有管理员认证 → 每一个 dashboard API 与页面路由
```

复用 FastAPI、SQLAlchemy、Alembic、React、AntD 与现有主题，不新增消息队列、统计平台或图表依赖。保留单进程任务调度约束。统计读权限不扩展管理员对他人任务正文、模型凭据、私有资源的访问。

## 2. 模型与迁移

新增迁移 `0025_admin_dashboard`，父版本 `0024`。模型放在独立 `models/dashboard.py` 并经 `app.models` 导出。

| 存储 | 核心字段与约束 |
| --- | --- |
| `admin_dashboard_tracking` | 单例记录，持久化 UTC `started_at`、固定 `timezone=Asia/Shanghai`；首次初始化后不随重启改写 |
| `admin_dashboard_daily` | 北京时间 `day` 唯一、UTC `captured_at`、用户/作品/章节/正文总量、工坊 pending 数；数量列非负，字数使用足够大的整数类型 |
| `admin_task_statistics` | 不可复用 UUID 主键、kind、origin（baseline/new）、observed_at、created_event_at、当前观察状态、finished_event_at、removed_at；结束统计按真实结束时间索引，创建统计按创建事件时间索引 |
| `tasks.statistics_key` | 可空 UUID 字符串、唯一索引；新任务由 Python 默认生成，旧任务初始化时填充；不改变公开 TaskOut |

统计表不引用 Task/User/Project 外键，不存用户名、作品名、任务标题、输入、正文、输出、错误内容或模型配置。统计身份绑定 UUID 而非可复用整数 task_id；保留计数所需的最小元数据。

升级采用直接增加可空列和唯一索引，避免重建 SQLite tasks 父表；迁移不导入运行时模型/常量。后台初始化在接受流量和启动恢复前，幂等建立起点、赋予存量任务统计身份并标记 baseline。已有任务的历史新建/终态不回填成上线后事件；尚未结束的 baseline 任务之后产生的真实终态照常记录。展示初始化存量说明，不与“上线后新建”混为完整上线前历史。

## 3. 任务统计事务契约

`task_statistics_service.py` 是持久化统计记录的唯一写入方，提供初始化、记录创建、记录状态/终态、标记移除的窄 helper。除拥有独立会话的初始化外，helper 不 commit、不创建后台补写任务；使用调用方现有事务。

必须接入：通用 create/retry、自动/批量分析、记忆索引入队、领取、paused 继续/提前结束、三种取消分支、引擎正常结束/失败/中断、启动恢复。完整入口清单见 `research/statistics-evidence.md`。

约束：

1. 先用原状态的条件 UPDATE 判定迁移成功，再在同事务更新对应 UUID 的统计；未命中不能增加结果数量。
2. 新建以 UUID 唯一约束幂等；同一任务 paused→queued→running 不新增记录，失败 retry 新 UUID 计新任务。
3. 终态只接受一次。并发取消、结束和旧 finalize 不得把已有终态覆盖成第二种结果；必要时收紧原 finalize 的状态守卫，但不改变资源锁、回调时机或对外响应。
4. 创建/终态统计失败时整个原业务事务回滚；不得把统计唯一键等异常误映射为“资源已有任务”。不得在 HTTP 成功后或 prune 之后补写。
5. 单条删除、清理、自动裁剪、作品 purge/expire、用户删除，在原事务里按 Task.statistics_key 标记 removed_at；统计行不删除，已经记录的终态时间不修改。
6. 尚未结束即被级联移除的记录保留移除标识，不虚构成功/失败。当前在途从实际 Task 表统计，避免历史记录变成“幽灵运行中”；累计新建与结束结果可以不相等。
7. 原UUID还必须贯穿Hub、运行执行体、领取/输出/stream及close/cancel/recover/forget收尾。刷新只允许原UUID，批量删除只使用标记阶段捕获的UUID集合，不能因整数ID复用跨到另一任务。
8. 取消执行体不能打断章节结果原子保存中的活SQL游标。只保护有界保存事务，提交前取消完整回滚，commit已开始的极晚取消等待保存获胜并产生成功终态；不屏蔽LLM等待，不以锁超时/重试掩盖未释放事务。真实复现与回归见 `research/bug-analysis.md`。

任务每日新增按 `created_event_at` 分日；四种结果按 `finished_event_at` 分日。最近 24 小时采用服务端统一 `as_of` 的滚动区间 `(as_of-24h, as_of]`，分别计 failed、interrupted。UTC 查询边界由北京时间日期换算后传入，不依赖数据库服务器时区或非兼容的日期函数。

## 4. 规模快照与采样

`admin_dashboard_service.py` 持有统一规模聚合查询；用户、作品、章节、字数、工坊 pending 用独立标量子查询，在同一 SQL 语句读出，避免 join 放大和单个响应内部口径漂移。不应用启用账号或作品生命周期过滤。作品即使在删除协调中，只要尚未物理删除仍计入总量。

独立采样器复用回收站清理器的 start/stop 模式：初始化后立即采样，随后每 60 秒用独立 session 采样。按当前北京时间日期 upsert 当日最后成功值，跨日建立新记录，不回填漏采日。采样不依赖是否有人打开首页。

失败不写零、不覆写已有成功记录；安全日志可排查采样异常，重启恢复后只写当前日期。停止时取消并等待采样协程后再 dispose 数据库，不遗留后台会话。`captured_at` 始终表明真实采样时间；历史“日值”明确是最后一次成功采样，不承诺停机期间的午夜终值。

## 5. API 与类型边界

新增 `api/v1/admin_dashboard.py`，统一前缀 `/admin/dashboard` 并注册到现有 api_router。每个端点独立要求 `AdminUser`，路由只调用 service，不做 ORM。

| GET 路径 | 响应契约 |
| --- | --- |
| `/overview` | `as_of`、`tracking_since`、固定 timezone、用户/作品/章节/字数/pending 数及口径标识 |
| `/tasks` | `as_of`、`tracking_since`、初始化存量数、上线后新建数、实时 queued/running/paused、累计四种真实结束结果、最近24h failed/interrupted；不返回任务内容 |
| `/history?days=7\|30\|90` | 默认30；日期范围、tracking_since、timezone、每天 `{day, captured_at, totals|null, tasks|null, partial}`，以及比较日期和净变化；非法 days 为422 |

Pydantic schema 是唯一传输契约，TypeScript 在 `api/types.ts` 镜像。日记录中缺失用 null，不用0。上线前的 totals/tasks 都为空；上线后没有规模采样时 totals 为空；如果当日已有任务事件，仍返回已记录的 tasks 数量并标记 partial，不因采样失败抹掉事件；既无采样也无任务事件的日期 tasks 为空，不假装完整的零活动日。有采样的已观测日期才允许展示没有事件的0。首日、当日及观测范围不完整的日子标记 partial，文字说明“已记录”与全天完整数据的区别。

规模净变化为所选范围首日与末日的有效采样值之差，响应明确实际比较日期；缺少任一端点或只有一个历史点时返回 null，而不是替换成零或用更短区间冒充完整区间。中间缺口单独披露。单日零流量只有在统计覆盖可确认时显示0；不能确认的日段为无记录。

三个请求独立失败，使 overview、任务、历史可分别加载和重试。每个响应带自己的时间；不同请求不是同一数据库快照，不伪装为同一原子时刻。

## 6. 前端体验

- 新增懒加载 `/admin/dashboard` 与 `AdminDashboardPage`，放在现有 RequireAdmin / AppLayout 下；增加侧栏、账户菜单入口及面包屑文案，不改变普通用户登录后的个人作品入口。
- 信息顺序：标题/刷新与更新时间 → 平台规模紧凑网格 → 工坊待办及24h异常 → 实时/累计任务摘要 → 时间选择、规模趋势、任务趋势与历史表。
- 使用现有 AntD、AutoGrid、useIsMobile、主题 token/usePalette。90 点折线/柱状 SVG 只为本页面服务，不造全站图表框架；图表包含语义标题/图例，提供可展开的 HTML 数据表和键盘可读信息，不只依赖颜色。
- 规模图按指标切换，避免账号数和字数硬塞同一坐标轴；缺失值切断线段，只有一个点也可展示。任务新建与结束分别显示，不暗示同日必须对齐。
- 用户/作品/回收站/日志跳到已有管理页；作品总量标注“含回收站”，提供正常作品与回收站两个明确入口。工坊链接为 `/workshop?tab=review`，最小修改 WorkshopPage 解析并同步允许的 tab；普通用户不能通过查询串进入 review，非法 tab 回退 browse。
- 任务监控未交付，不设置 `/admin/tasks` 链接；不为章节或字数创建虚假的全站明细页。
- 请求全部经 api 层；需要中止的 GET 直接复用现有 `request(..., {signal})`，不改造公共 client。状态限页面本地，避免增加管理员全局缓存。
- 手动刷新所有区块，失败区块可单独重试。60秒轮询可关闭、隐藏时暂停、重新可见时刷新后恢复；同一区块不累积并发请求。切换 days、卸载、登出或失去管理员资格后，中止/失效旧请求并清理计时器；旧数据可以保留，但标明上次成功时间及过期状态。
- 日期轴使用后端北京时间 day 原样，不用浏览器本地时区再次分日；采样时刻沿用服务器时间解析并明确展示时区。

## 7. 兼容、发布与回退

部署前备份数据库，先执行迁移，再以单进程启动新版。统计起点在首次初始化持久化；重启不重置累计、不补造历史。新增表不进入作品备份。

旧版本代码若继续写库会绕过统计，因此不支持新旧应用同时调度；回退旧应用前先停止新版采样与引擎，并接受回退期间统计不完整，不得声称无损连续。持久化统计表存在任务记录或日快照时拒绝直接 downgrade，要求显式备份/处理后再降级；空库可完整回退。

主要风险是任务入口遗漏、终态竞态、SQLite迁移副作用、历史缺口伪零及前端旧响应。对应验证必须覆盖 AC7–AC12。技术细节若导致产品范围或准确性承诺改变，回到规划，不用“以后修复”替代契约。
