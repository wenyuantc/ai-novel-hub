# 知识库与向量剧情记忆（P1-9 knowledge-base）

## Goal

统一建设检索基建，并在上面做两个功能：

- **知识库（B8）**：用户上传参考资料（设定集、资料摘录等），系统分块建索引；生成时按相关度检索并注入上下文。
- **剧情记忆（B7）**：把章节分析产出的摘要、情节点等变成可检索的记忆。写后面的章节时，召回前面相关的旧情节，弥补"前情提要"按预算截断后丢掉的久远内容。

## 已确认事实（代码核查，2026-10-26）

- **AI 配置**：`model_type` 目前只有 `text` 和 `image` 两种，没有向量模型（embedding）。提供方有 anthropic、gemini、openai_compat 三种，其中 Anthropic 不提供 embedding 接口。
- **数据库**：生产部署用 `postgres:16-alpine`，不带 pgvector；测试用 SQLite。
- **章节分析**（analysis-memory）：每章一条，含摘要、情节点、钩子、角色变化、伏笔。
- **上下文组装**（`context_builder`）：最近 2 章给全文，更早的章节给分析摘要（没有摘要就用正文前 200 字），超出预算按优先级裁剪。章节很多时，久远章节会被整段裁掉。
- **后台任务引擎**：已有，适合做"文档解析 + 建索引"这类长任务。
- **提示词**：已模板化，新增的数据块需要作为模板变量传入。
- **MuMu 的做法**（研究 §7、§8）：Chroma 本地向量库，用 470MB 的本地模型。知识库只支持 txt/md/json，每块不超过 420 字、块间重叠 60 字，可调 top_k、min_score 和上下文上限，有检索调试框。缺陷有这几条：
  - 记忆库的距离度量配错、向量没有归一化，0.6 的阈值基本不命中，总是退回取前 5 条；
  - 知识库结果和记忆混在同一个占位里；
  - 章节检索的查询语句把整个角色块都拼进去，噪声很大；
  - 用户不能编辑或钉住单条记忆；
  - 不支持 PDF、DOCX、EPUB，没有关键词混合检索。

## 需求草案

1. **检索基建**（Q1 已定）：
   - **向量来源**：AI 配置新增 `embedding` 模型类型，支持 OpenAI 兼容的 `/embeddings` 接口和 Gemini。
   - **存储与计算**：向量先归一化，再以 float32 二进制存进数据库；应用内按项目用 numpy 计算余弦相似度。不引入 pgvector，SQLite 与 PostgreSQL 行为一致。
   - **关键词检索**：同时提供中文字符二元组 BM25。有向量模型时两种结果混合排序，没有时只用关键词。
   - **更换模型**：换了向量模型后，自动提示重建索引；重建完成之前只用关键词检索。
   - **分数与阈值**：分数有界，阈值真正生效。
2. **知识库**（Q2 已定）：
   - 每个项目一个知识库，可以上传、删除、重建索引，并显示处理状态；解析、分块和建索引由后台任务完成。
   - 支持 txt、md、json、docx、epub、pdf（pdf 只取文字层，不做 OCR）。单个文件不超过 20MB，每个项目最多 200 个文档。
   - 按标题和段落分块，每块约 500 字，相邻块重叠 80 字，并记录每块所在的标题路径。
   - 每个文档有"参与注入"开关。
   - 默认自动注入这些 AI 调用：章节生成、按建议重写、批量、大纲续写与展开、向导、实体生成、灵感模式。项目级有总开关，召回条数（top_k）、最低分数和注入字数上限可以调整。
   - 提供检索调试框。
   - 注入时附带声明："仅供参考，与项目设定冲突时以设定为准"。
3. **剧情记忆**（Q3 已定）：
   - **自动生成**：章节分析成功后，从分析结果自动生成记忆，不额外调用 AI。包括章节摘要、重要度 ≥ 3 的情节点、强度 ≥ 6 的钩子、角色状态变化、伏笔的埋设与回收，并记下章号和相关角色。
   - **重新分析**：重新分析时替换该章的自动记忆。按"类型 + 内容"匹配，保留原有的钉住和屏蔽标记。
   - **用户操作**：可以钉住或屏蔽任意记忆，也可以手动添加、编辑、删除手动记忆。
   - **查询组成**：本章标题、梗概、细纲的关键事件与叙事目标，加上出场角色的名字。
   - **召回范围**：只从本章之前、且前情里没有给全文的章节召回；已在前情中出现的摘要不重复召回。
   - **注入方式**：单独作为"相关旧情节"块注入，与知识库分开。默认 8 条、上限 1500 字，钉住的优先，按章号排序。
   - **注入位置**：章节生成、按建议重写、批量、大纲续写与展开。
   - **记忆页**：可以筛选、做检索调试、钉住和屏蔽，以及管理手动记忆。
4. **降级**：检索失败或没有配置向量模型时，不阻断生成。

## 范围外

- 扫描版 PDF 的 OCR、rerank 模型、本地向量模型。
- 跨项目共享的知识库。
- 保存上传的原始文件：只保存解析出的文本，重建索引时从这份文本重新分块。

## Acceptance Criteria

- [ ] 上传文档后，后台任务完成解析和建索引，状态可见；失败时可以重试；删除文档时一并删除它的索引。
- [ ] 检索调试框能返回命中块及分数，分数有界且阈值真正生效（用测试覆盖"阈值以下不返回"）。
- [ ] 章节分析完成后，该章的记忆进入索引；重新分析时替换旧记忆；删除章节时移除它的记忆。
- [ ] 生成第 N 章只召回第 N 章之前的记忆；记忆与知识库在提示词里分块注入，各自受预算约束。
- [ ] 没有向量模型或检索出错时，生成照常进行，提示词中不出现空的检索块。
- [ ] 支持 6 种格式（txt、md、json、docx、epub、pdf 文字层），超过 20MB、超过 200 个文档或类型不支持时返回 400；每块约 500 字、重叠 80 字，并带标题路径。
- [ ] 没有向量模型时只用关键词检索，结果仍然可用；配置向量模型后混合排序；更换向量模型后提示重建，重建完成前不使用旧向量。
- [ ] 文档关闭"参与注入"后不再被召回；项目总开关关闭后不注入知识库。
- [ ] 钉住的记忆优先注入；屏蔽的记忆不会被召回；重新分析后，钉住和屏蔽标记按"类型 + 内容"保留；手动记忆不受重新分析影响。
- [ ] 已在前情中给出全文或摘要的章节，不会再以摘要记忆的形式重复注入。
- [ ] 跨用户访问返回 404。
