# 管理员操作日志

## 目标与用户价值

让平台维护者能够追溯管理员对用户、他人作品及共享资源的敏感操作，识别真实操作人、时间、对象和结果，定位误操作与责任归属。

优先级 P0；状态 `completed`。来源为 2026-10-30 管理员功能缺口盘点；用户于 2026-10-31 请求启动此现有任务。用户已于 2026-10-31 在最终规划摘要后回复「开始」，批准实施；任务已通过 `task.py start` 激活。

## 背景与现状

- 用户管理写入集中于 `backend/app/services/admin_service.py:87`，多个入口自行提交事务；`backend/app/api/v1/admin.py` 的创建用户和重置密码入口尚未向服务传入真实管理员。
- 管理员以真实身份维护他人作品，不能冒用所有者。人工权限与严格拥有权边界见 `.trellis/spec/backend/admin-projects.md`，本任务不扩大权限。
- 章节版本和工坊审核记录是业务历史，不能代替统一审计。`backend/app/services/version_service.py:91` 会合并手动版本，`:48` 会裁剪旧版本；`backend/app/services/chapter_version_service.py` 允许删除非最新版本。版本关联不是每次操作的不可变全文快照。
- 当前账号仅区分管理员与普通用户，尚无超级管理员角色。现有管理页提供筛选、分页及破坏性操作确认的参照。

## 功能需求

### R1：首批操作覆盖

| 类别 | 本期覆盖 | 范围条件 |
|---|---|---|
| 用户管理 | 创建、启用/禁用、角色变更、重置密码、删除 | 现有管理员入口，包含管理员对自己的合法操作 |
| 作品资料 | 修改资料/状态、删除作品 | 维护他人作品；级联删除作为一次操作摘要，不为每个子对象造事件 |
| 章节维护 | 手工创建、从大纲批量建章、修改/删除、选角调整、版本标星/备注/删除/恢复 | 维护他人作品；批量操作记录受影响数量及有界 ID 列表 |
| 工坊管理 | 通过/驳回、直接发布或管理员提交时自动通过、分类/标签修改、下架/恢复、删除 | 管理员管理动作，不含点赞、下载、导入到本人资源 |
| 全局 Skill | 创建、导入、修改、整体替换参考资料、删除、恢复内置 | 不含私有 Skill 日常维护或复制为私有副本 |
| 审计清理 | 按日期范围清理 | 仅管理员；清理事件本身受保护 |

同一入口可能承载普通行为与管理行为，必须按上述范围判断。未知或已删除目标的失败请求仅保存安全目标标识，不额外暴露不可见私有资源的信息。

### R2：记录与查询

- 记录真实操作人 ID/用户名快照、服务器时间、动作、目标类型/ID/名称快照、相关作品与所有者标识、结果及安全摘要。
- 支持按操作人（历史用户名或 ID）、目标类型/ID、动作、时间和成功/失败组合筛选、稳定排序、分页和详情。
- 用户或业务对象改名/删除后仍能识别历史事件；删除业务对象不得级联删除审计。
- 查询、详情、清理预览和执行仅限当前有效管理员；未登录或普通用户不能读取审计信息。

### R3：变更摘要与已有版本关联

用户于 2026-10-31 确认：
- 采用字段变更、状态/布尔值、正文前后字数等摘要，不在审计中另存正文全文或完整差异。
- Skill/参考资料/工坊模板正文同样只保留字段与数量摘要。
- 有已有业务版本时保存关联标识；明确提示版本可能合并、裁剪或删除，不能将变化后的版本当作操作时刻的确定快照。
- 没有版本或版本被删时，摘要、操作人和目标仍能独立识别。

### R4：结果一致性与失败范围

用户已确认：记录已认证管理员在范围内的业务拒绝和系统异常，仅保存脱敏原因或安全错误类别；未登录、普通用户越权、参数校验失败不纳入，不扩展为全站安全日志。

- 业务修改与成功审计一起提交或回滚，不以 HTTP 状态推断业务事务结果。
- 业务失败不留下成功审计；写失败审计不能重新提交已回滚的业务修改。
- 提交后的响应构造失败不得把已经成功的业务操作再记为业务失败。
- 数据库不可用或进程终止时无法保证失败记录落库；保留安全运维错误信息，不承诺独立于数据库的无损保障。

### R5：敏感数据边界

按字段白名单构造审计。密码、密码哈希、模型密钥、平台 Key、JWT/Cookie、加密凭据、原始请求及异常详情不得写入或经审计接口返回。重置密码仅记动作，不记旧值、新值、长度或哈希。

### R6：保留与手动清理

用户已确认：
- 长期保留、不自动过期；提供按明确日期范围手动清除入口，替代此前不提供清空入口的建议。
- 仅管理员；先展示日期范围、预计可删除条数、受保护条数和不可恢复提示，再二次确认；取消不删除。
- 清理仅依据日期范围，明确作用于该范围内全部可清理记录，不隐式继承列表其他筛选。
- 清理本身记录真实操作人、范围、实际删除数量；成功及失败清理记录均不能被后续清理删除。
- 删除与成功清理留痕同事务，任一失败共同回滚。
- 界面明确时区与日期边界；并发情况下预计与实际数量可能不同，执行后展示实际条数。

## 验收标准

- [x] AC1（R1/R2）：两名管理员先后维护同一他人作品/章节，能区分真实操作人、目标及顺序，不误记为所有者；同一合并版本也保留独立事件。
- [x] AC2（R1）：覆盖表逐项有成功和代表性失败记录；普通用户、本人日常创作和排除项不误采集。
- [x] AC3（R2）：组合筛选、同时间稳定排序、分页、空结果和失败重试有效；改名/注销管理员的历史事件仍可查询。
- [x] AC4（R2）：未登录/普通用户不能查询、看详情、预览或执行清理；删除操作人/所有者/业务对象不使历史记录无法识别。
- [x] AC5（R5）：带测试凭据的请求后，数据库审计行和列表/详情均不含凭据原文、密文、哈希或原始请求/异常详情。
- [x] AC6（R3）：正文仅记字段与字数摘要，有版本时展示关联；合并/裁剪/删除版本后摘要保留，且提示关联版本已变化或不可用。
- [x] AC7（R4）：业务拒绝或提交前系统异常记失败且无业务写入；审计写入失败阻止业务提交；提交后的响应异常不篡改业务结果。
- [x] AC8（R6）：无自动过期；清理日期边界正确，不误删范围外记录；取消/非法范围/失效预览不删除；展示预计与实际数量。
- [x] AC9（R6）：权限、二次确认及保护规则不能被直接 API 绕过；反复清理同范围仍保留全部清理事件；删除与留痕原子提交。
- [x] AC10：原有用户管理防护、会话失效、跨用户隔离、章节字数与版本规则、工坊审核和 Skill 权限不退化，不使用他人的模型/任务。

## 不在本期范围

- 全站普通用户行为、登录安全事件、审计读取采集及上线前历史回填。
- 其他人工设定模块（世界观/人物/组织/关系/职业/伏笔/大纲/知识库/剧情记忆）、封面和未来管理功能的逐项审计接入。从大纲建章只覆盖现有章节服务入口，不扩大为所有大纲业务。
- AI、智能体、任务、私有资源、模型配置和平台 Key 的额外管理权限或行为审计。
- 全文差异、替代章节恢复/回收站、自动过期/归档、日志导出、SIEM、独立审计存储、数据库级防篡改。
- 超级管理员或权限分级；另属 `admin-rbac-quotas`。
