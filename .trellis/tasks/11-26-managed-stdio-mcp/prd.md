# 托管本机 stdio MCP 插件

部署者在运行 aiNovel 的服务器或容器内预装插件并登记，作者从可用列表中自行启用。作者可以在管理页试用工具，也可以在自己的作品智能体里使用工具。[父任务](../11-26-login-methods-local-mcp/prd.md)

## 现有入口

- 每条个人插件记录有用户归属、必填 URL、工具缓存和确认偏好。请求头加密保存，现有接口接受 Streamable HTTP 与 SSE。见 `backend/app/models/skills_mcp.py:69`、`backend/app/schemas/mcp.py:24`。
- 前端导入会跳过 stdio，后端也逐项拒绝。远程连接器、管理页试用和智能体执行各有入口。见 `frontend/src/utils/mcp.ts:26`、`backend/app/services/mcp/service.py:238`、`backend/app/services/mcp/client.py:348`、`backend/app/services/agent/mcp_tools.py:182`。

## 首版验收

| 场景 | 可观察的结果 |
| --- | --- |
| 部署者登记 | 部署者安装并登记一项插件后，作者可从列表看到名称与说明。登记属于服务器部署配置，网页及公开 API 均不提供登记或修改启动命令的入口。 |
| 作者自行启用 | 两位作者分别选择同一登记项，各自获得独立的个人启用状态、工具偏好和确认设置。同一作者重复选择只保留一条记录。作者可停用或移除自己的插件。 |
| 输入边界 | 本机插件表单只允许选择登记项。直接调用创建或更新接口时，未知登记项及自定义命令、参数、工作目录或环境变量均被拒绝。粘贴混合 JSON 时，远程项逐项处理，本机项提示从列表启用。保存、导入与打开列表均不会启动进程。 |
| 实际使用 | 已启用的真实示例插件可刷新工具、试用并返回结果。作者的智能体按原确认偏好调用工具。其他作者的私人选择和协作者的会话继续遵循原有权限。 |
| 关闭、下架与接管 | 本机托管关闭、全站 MCP 关闭、插件下架或个人停用后，尚未发出的调用受到阻止。多 worker 接管时，已发出且结果未知的写操作提示核对，避免重复执行。 |
| 生命周期和故障 | 正常结束、插件崩溃、超时、取消、服务退出时可查证进程回收。实例缺少插件或版本不符时显示可操作的错误。用户响应、日志与工具事件不得暴露部署密钥。 |
| 升级兼容 | 原有 HTTP／SSE 插件保留 URL、请求头、工具和偏好，升级后仍可刷新、试用和供智能体调用。 |

首版不包含作者自定义启动命令、在线安装、作者电脑上的桌面桥接或跨会话常驻插件。[技术设计](design.md) · [实施与验证清单](implement.md)
