# 本机 MCP 插件设计

## 部署清单与个人启用记录

采用部署者提供的只读清单。每项有稳定标识、名称、说明、部署版本、预装可执行文件的绝对路径、固定参数与工作目录。插件只获得部署者明确授予的文件、系统权限、环境变量和资源额度。只读挂载清单及程序；部署密钥引用在运行环境中解析。清单未配置时，本机目录为空，远程传输仍可用。

后端提供已登录用户可读的可用插件列表，只返回标识、展示信息和可用性。作者从列表选择某项，服务端按标识查找已登记的定义。已有 `mcp_plugins` 表保存每位作者的选择、工具缓存和偏好。本机行引用目录标识，远程行保留 URL 和加密请求头。约束同一作者对同一目录项至多一条记录，复用个人插件数量上限。数据库存个人选择，部署清单决定允许启动的程序。整库恢复到另一服务器时保留选择；目标节点缺少匹配登记项或版本时，提示部署者补齐后再执行。

创建、修改、试用和导入共用服务端字段校验。工具调用参数按工具 schema 进入协议消息，与启动参数分开。作者端拒收运行命令、启动参数、环境和执行路径字段，远程记录沿用原协议与地址校验。对粘贴的本机 JSON 项给出“请从服务器插件列表启用”的逐项提示。

## 从选择到实际执行

1. 列表和启用操作只读写配置。刷新、试用或智能体调用才按已登记的可执行文件及固定参数创建子进程，直接传入参数数组。进程归当前 MCP 会话所有。管理页操作结束即回收，智能体沿用一轮内同一插件的会话复用，轮次间及用户间独立。现有复用边界见 `backend/app/services/agent/mcp_tools.py:602`。[MCP stdio 传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#stdio)
2. 进程启动前检查部署登记、全站开关、个人归属及启用状态。使用受限运行身份，显式构造环境，限制并发子进程数。按传输类型构造连接，共用已有工具清单解析、参数校验、确认及结果转换。标准输出只承载协议数据，标准错误按容量限制处理并脱敏。
3. 在真正写入工具请求的边界，再核对设置、工具偏好、身份、目标登记版本，智能体调用还须核验执行者租约和已确认参数。发送保护覆盖到实际写入；只把消息放入 SDK 内存队列不足以算作已发送。沿用外部调用记录区分“尚未发出”和“可能已发出”。回包超时、worker 接管等情况下，后者进入结果未知流程。
4. 正常关闭先停止接收新调用并关闭会话，超时或取消时有界等待，最终终止并回收进程树。部署验收包含异常退出的 worker 与容器停止，检查没有继续运行的旧子进程。同一会话中已启动的进程每次发送仍需复核权限。

## 部署、迁移与回退

SQLite 和 PostgreSQL 均验证本机／远程两类数据约束。配置旧远程记录时所需的 URL 和请求头继续保留。每个可处理请求的节点安装同一登记清单与程序版本，工具缓存及提案绑定目录标识和版本，升级或下架时阻止过时提案启动或发送。部署者按现有排空流程更新清单和二进制。本机能力可单独停止，已发送的外部操作保留执行记录。目录、本机可执行文件和部署凭据随部署分发；回退旧版本前须处理已有 stdio 记录并在副本演练。
