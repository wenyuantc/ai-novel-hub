# AI 用量与费用管理技术设计

## 调用计量

新增独立的调用用量表，作为费用查询与预算的共同数据源。`GenerationLog` 继续服务章节历史，任务状态和生成日志不能替代实际调用记录。向量检索、图片生成、灵感会话和模型连通性测试等调用可能没有完整的章节日志或任务 ID。

一次逻辑模型请求对应一条记录。批量按章生成和自动分析分别计量，任务重试、智能体多轮、向量分批和适配器显式重试各有独立记录。请求重定向、图片 URL 下载、获取模型列表、仅本地预检、应用内部缓存直接返回和纯关键词检索不构成额外的模型计量请求。对于 SDK 内部重试，核对实际适配器配置和请求钩子，确保重复计量和请求被漏计均有回归覆盖。外部工具、MCP 或检索本身的服务调用与模型请求使用不同接口，费用范围以本应用发出的模型请求为准。

| 数据 | 约束 |
| --- | --- |
| 调用身份 | 服务端生成稳定的尝试 ID，重试数据库更新时复用。合法重发使用新 ID。关联实际发起人、承担费用的模型配置所有者、配置实例、Provider、模型、任务类型。作品、章节和后台任务仅在确有归属时关联。用任务执行轮次或稳定身份辅助关联，避免整数 ID 复用造成误归属。 |
| 发送与结果 | 记录 UTC 调用时间、是否可确认发送、成功/失败/取消/中断及用量。请求发出后，即使内容未保存、任务被取消或权限已撤销，也保留计量。拒绝发生在发送前时不形成费用。 |
| 用量 | 分项保存输入 token、输出 token、图片张数及各自来源。保留提供方明确返回的零。缺失、非法或无法归类的字段为空。流式累计字段取最终有效值，分段增量按适配器契约累计。 |
| 计价 | 使用发送时可证明的配置与价格版本，保存币种、参与计价的数量、估算金额和计价状态。模型缺价、关键用量缺失或发送状态不明时保留记录并返回缺口原因。 |

普通文本 `generate_stream` 的消费端继续接收文本增量。用量从适配器解析后送入单次调用的计量作用域。智能体已有的 `usage` 事件保持兼容，并汇入同一记录。图片张数在模型响应解析后捕获，后续下载或图片校验失败不抹去已确认的用量。向量优先接收接口用量；未返回 token 时标记未知，或在存在明确估算方法时标为估算。统一输入、输出的计量口径并保留各家返回差异，防止把总量、缓存或思考 token 叠加两次。

计量身份在业务入口完成校验后绑定到调用，从模型绑定和执行上下文取值。受控分支沿用 `ai_dispatch` 与 `collaboration_ai_guard` 的真实请求钩子及冻结绑定。个人同步调用、灵感、模型测试和检索适配器显式接入同样的计量边界。构造 Provider、任务预检和缓存检查时不记用量。计量作用域随每次调用建立和清理，覆盖异步生成器提前关闭、嵌套向量调用与并发任务。

准备记录与结果更新用短事务。首先定位各入口可提交的发送边界，在模型操作开始时保留最少的尝试凭据，并在实际发送或得到响应时补充观察结果。计量写入放在发送授权租约之外，避免重新取得作者或任务锁，避免 SQLite 持有其他写事务时开启第二个写入。已发送的调用由尝试 ID 条件更新，计量写入重试不会触发模型重发。若进程中断留有未确认的尝试，按时间收尾为中断、发送状态待确认，汇总显示缺口。观测器、传输租约和内容写回分别收尾，保留当前任务的授权及撤权语义。

代码入口可从 [Provider 契约](../../../backend/app/ai/providers/base.py)、[真实发送钩子](../../../backend/app/services/ai_dispatch.py#L479)、[协作模型绑定](../../../backend/app/services/collaboration_ai_guard.py#L124)、[生成与分析](../../../backend/app/services/batch_service.py#L1428)、[智能体轮次](../../../backend/app/services/agent/runner.py#L1011)、[向量分批](../../../backend/app/services/retrieval_service.py#L183)和[模型配置测试](../../../backend/app/services/ai_config_service.py#L306)追溯。

## 价格与预算

- 单价由配置所有者维护。以 `AIConfig.instance_key` 和对应 Provider、模型及模型类型匹配定价。配置切换为另一模型时价格应重新确认。计价基础为文本输入／输出每百万 token、向量输入每百万 token、图片每张。基础单价按模型类型显示。数据仅来自用户配置及调用计量。
- 币种随价格版本写入调用快照。按币种汇总并各自配置预算，人民币和美元可分别查看。精确计算使用十进制定点数，传输金额用十进制字符串。定义并测试统一的精度、舍入、零与空值、输入上下界。SQLite 和 PostgreSQL 的存储与聚合应给出同样的金额。全站与个人 API 共用计价、筛选与合计逻辑。
- 账号预算统计由账号承担且发生在当月的费用，包含跨作品及无作品归属的调用。用北京时间计算月初和下月月初，转换为 UTC 半开区间查询。预算额度和阈值配置持续生效，月初变更查询范围即可。跨月调用按发出时间归属，历史无需重算。
- 作品预算统计该书中由其作者承担的费用，跨月累计。记录发送时的作者承担归属。协作者用本人模型时，该次费用归协作者账号预算。用作者授权模型时，费用同时更新作者账号与该书预算的进度。两条进度分别计算，全站总额仍按调用 ID 汇总一次。
- 提醒根据已知累计金额与阈值计算，展示正常、接近阈值或达到上限，以及缺价或未知用量导致的统计缺口。缺失金额不能充当零。达到阈值后可在预算页及有权查看的批量预估中看到提醒，并可正常发起任务。

## 查询与权限

| 入口 | 主要行为 |
| --- | --- |
| 个人用量页 | 展示本人发起的调用及本人承担费用的调用。按发起人与费用归属分别投影字段，调用维度可按作品、模型、任务类型、时间范围筛选，可按章节查明细。使用作者授权模型的协作者能看本人用量和费用承担说明。模型名、价格、金额和预算等受限字段应在筛选、分组、排序和分页前屏蔽。 |
| 作品及账号预算 | 作者设置本书预算，任何用户可设置自己的账号预算。作者可核对其授权模型费用所对应的调用元数据。作品预算权限来自作品的实际所有权，管理员的全站权限为独立只读入口。 |
| 批量生成预估 | 扩展现有 `POST /projects/{id}/batch-generate/preview`。复用章节范围、分析开关及执行侧模型解析，按章节目标字数、可得的输入规模和价格估算生成与分析金额。明确重试、额外检索等是否包含。预览只读，不调用模型、不占用额度。在使用作者模型的协作者视图提示作者承担费用，金额仅在可查看时返回。 |
| 管理后台全站页 | 提供独立页面、导航及 `/api/v1/admin` 下的用量接口。沿用动作级 RBAC，为全站用量定义专门的读权限。可按真实发起账号、费用承担账号、作品、模型、任务类型、时间筛选分页明细与全站汇总，范围包含无作品归属及未知用量。API 字段白名单涵盖调用时间、标识、状态、用量、来源、币种和费用等元数据。 |

汇总和明细从相同授权投影和筛选条件查询，使用一致的查询视图，提供稳定排序和服务端分页。现有后台权限按照 [RBAC 规范](../../spec/backend/rbac-quotas.md)接入，导航、页面、API 和权限变化后的迟到响应都需要覆盖。管理员可读范围来自全站用量权限，作品管理员路径与调用内容权限维持原有规则。提示词、正文、密钥、连接端点、鉴权信息和供应商原始响应均不纳入用量表与用量 DTO。

批量弹窗当前只用范围和字数作为预览请求键。增加费用后，模型、风格、附加要求和 Skill 等影响估算的输入应进入请求和请求代次校验。保存、切换账号／作品或关闭弹窗时，作废相应的旧请求结果。[预览服务](../../../backend/app/services/batch_service.py#L180) · [批量弹窗](../../../frontend/src/components/batch/BatchGenerateModal.tsx#L97)

## 迁移与回退

- 以当前 Alembic head 为基础新增用量、定价和预算存储及索引。为查询确立账号、作品、调用时间和稳定分页键。所有归属字段以可防止账号、作品或配置 ID 复用的方式绑定。删除资源时沿既有生命周期规则解除身份关联，历史账号累计不会因删章、清理任务或清空作品回收站被重算。已删除或无归属标识使用显式状态。
- 新表记录计量覆盖起点。旧生成日志的 token 继续可见于既有历史视图。历史的价格、发送完整性及某些归属不可核实，作品备份导入会重新生成日志身份并清除模型来源。新计量和预算不从这些日志重建。单书备份导入沿用既有隔离，整库备份需验证新表是否随数据库快照恢复。[单书备份约定](../../spec/backend/project-transfer.md) · [日志导入](../../../backend/app/services/project_transfer/importer.py#L1609)
- 更新前在 SQLite 和 PostgreSQL 隔离库验证向前迁移、旧数据查询和恢复。应用回退须使用能识别 `ai_usage.read` 的版本，保留 0061 的历史计量及定价快照。直接运行旧权限目录的应用会导致内置超管目录校验失败。涉及删除计量表的降级只在已核对备份并明确保留要求后进行。

## 分时单价补充设计

- 在已交付的 0061 之后新增迁移。现有单价作为固定价或启用分时模式后的高峰价，可空的时段配置保存时区、每日开始与结束时间及空闲档单价。单价接口沿用同一入口和乐观版本检查，版本覆盖两档价格与时段。旧客户端省略时段字段时保留已经配置的时段。
- 复用现有按次计量的 `UsageRecorder` 和发送时刻 `ModelUsage.dispatched_at`。尝试开始时冻结完整的定价规则，收尾时按记录的发送时刻选档，在同一写入事务中保存选中的档位、单价和估算费用。发送时刻缺省时沿用记录的观察时间口径。价目版本和时间按次处理，避免长响应或重试跨边界后误用其他档位。
- 批量预览使用同一个选档函数，按预览时刻估算并展示档位。预算与全站汇总直接使用已选价记录中的金额。档位随单价在查询投影中一起受权限约束，旧用量记录照常展示已有单价。
- 单价请求中的 `off_peak` 对象包含 `timezone`（默认 `Asia/Shanghai`）、`start`、`end`（本地 `HH:MM`）及 `input_per_million`、`output_per_million`、`per_image` 中适用的字段。显式 `off_peak: null` 恢复固定单价，省略该字段继续沿用既有时段。明细 `price_period` 使用 `fixed`、`peak` 或 `off_peak`，缺少可信档位时为空。批量预览还返回分时规则的 `price_timezone`。

## 缓存命中输入计价补充设计

- 模型价格和空闲档增加 `cached_input_per_million`，省略保留同币种的已有命中价，显式 `null` 清除。定价版本覆盖实际配置的命中价。迁移保留旧调用金额。历史记录存可空的 `cached_input_tokens` 与整数纳货币单位单价 `price_cached_input_nano`，明细 API 按原有模型价格权限返回 `cached_input_per_million`。
- 文本适配器将供应商用量归一为总输入量和其中的缓存命中量。命中数须在零和输入总量之间，零与缺省单独表示。请求按触发时冻结的价表和发送时段选价，普通输入量为总输入减命中量。未提供命中价或有效命中数据时保留普通费率估算口径。Anthropic 缓存读取为命中，缓存写入沿普通输入口径估算。
- 批量预估继续按普通输入价计算，配置了当前档位的命中价时明确提示实际命中可能改变金额。本地应用复用缓存且没有发出模型调用的路径沿用原计量边界。

## 多个空闲时段补充设计

- 分时规则仍在现有 JSON 中存储。`off_peak.start`、`end` 表示第一条，新增可选 `additional_windows: [{start, end}]`。省略附加时段字段沿用已有附加区间，空数组显式删除附加区间。只有一个时段时保持原存储形状和版本指纹。快照随每次尝试冻结完整时段。
- 后端定价存储与选档统一校验整个每日时间表。将跨零点区间按日界拆开检查重叠，以半开区间判定相邻。前端弹窗将第一条与附加区间映射为可编辑列表，保存时提交完整列表和共享空闲单价。
